# 世界书导入与编辑流程

本文记录世界书编辑、导入和上下文边界。当前作者入口是条目正文及右侧同类/表格/关系/管理，旧快速导入和高级编辑保留兼容。作者操作见[设定与资料](../user-manual/03-worldbook.md)，数据 owner 与本机文件/知识能力见[当前架构](../engineering/current-architecture.md)。以下导入合同继续有效，不表示用户必须从高级设置开始。

## 1. 入口定位

左栏按当前作品组织，默认提供正文、构思、设定、资料、素材分类文件夹，可自行移动内容或创建文件夹；可切换作品，中央使用一排原样式标签打开不同内容。“文件目录”可混放章节、构思、设定、图片与资料，图标旁显示类型；资料和项目文档明确标为只读。目录中的人物与完整设定页编辑同一条目。点击人物先打开正文详情，“浏览设定”再打开集合；“属性”按需展开模板与字段。属性未保存时先保存或取消，正文与字段不一致时仍由作者选择只存字段还是覆盖正文。

目录“+”可在所选文件夹中新建设定或导入资料；新建设定后直接编写正文，导入沿用资料浮窗。重复导入不改变已有资料的位置。同一份来源的条目和归档记录在目录中只显示一个入口。

文件夹新建、重命名、移动和顺序调整在目录中完成；选中项下方的更多操作提供移动、上下调整及“关联内容”，触控不依赖右键或拖拽。移除文件夹会把内容移到上一级，不删除原件。章节的叙事／导出顺序仍在“章节顺序”中调整。跨类型关联是查阅关系，不会直接成为世界事实或模型上下文。

结构化设定、地图及条目页通过顶部“当前作品”选择另一本书；本书资料页通过左侧作品导航切书，手机先展开“作品导航”。切换保留当前的设定/资料/地图/条目栏目，重新读取目标书的世界书关联，并清除上一书的条目、地点定位；不修改关联本身。未关联的书显示空状态。条目页有未保存修改时先确认，保存或批量操作期间不允许切书。

- 常驻资料：`/settings/sources?bookId=...`，首页及正文的作品导航“资料”与设定分区均可进入。支持搜索、类型筛选、原文预览和移出；添加确认后关闭浮窗并刷新本书资料列表，未绑定资料库的新书在确认添加时建立随书资料库。项目模式的添加在当前页面打开原生模态浮窗，不新开页签；资料页标题“添加资料”；助手的同一浮窗使用“添加文件”，拖入提示和确认按钮对应文件文案。其余为目标书、关闭、输入/队列、底部确认。旧本书添加链接重定向资料页并打开浮窗。
- 本地可组合工作区（2026-10-10）：正文／助手和作品导航打开资料时使用公共参考组，资料内容接收显式 bookId/worldbookId；旧资料路由复用同一内容组件。主区与旁区分别保留资源标签；章节在主区复用原正文编辑器，旁边仍可查阅另一章，原可编辑双栏保留。来源原文分批读取，引用携带来源修订、分块及归档文本的 UTF-16 范围，不用拼接显示文本反推偏移。移到主区或返回不会卸载正文请求所有者；助手同书请求已由宿主持有，切页继续收取结果，采用仍要求有效编辑绑定。原导航抽屉中的完整设定可在主区或正文旁编辑，沿用连续编辑与原字段保存；显示移动不新建资料或世界书。漫画／编导工作台在中央时，可通过顶部“打开内容”选择同书来源并指定主区或旁边。已撤掉新增模块横排和常驻“对照设定／对照资料”按钮；日常设定仍从正文原有右栏进入，其“查看与管理”在同页打开资料。完整设定当前使用内容目录与条目编辑，旧连续分区保留在“创作基调”；旁区可直接编辑表格，关系工具在右栏显示图谱。窄屏按内容查看，制作工作台与原输入仍保留。详细实现与剩余范围见[实施记录](../agent-runs/composable-workspace-20261010.md)。
- 日常入口：`/authoring` 右侧“角色 / 设定”
  - “角色”按一人一条 `worldbook.entries[type=character]` 直接编辑，并提供结构化 AI 补全候选。
  - “设定”默认列出当前落笔处命中的非角色条目，可切完整目录；直接编辑条目并提供待采纳的 AI 完善候选。
- 完整设定：`/settings/structured` 与工作区“本书设定”复用内容工作区。
  - 先选人物、地点、势力、世界规则等内容，再用详情、表格或关系图查看；条目可原地修改，不必跳高级管理。正文右栏角色／设定的“展开设定”会定位当前条目。
  - 设定右栏可直接查看表格和关系图，表格可放大到主区；关系图留在右栏，默认显示当前条目及直接关联，可切换全部设定。右侧工具轨只显示图标，悬停或键盘聚焦时显示名称。节点显示名称与类型，支持缩放、重置和点击定位。管理中的类型、别名与 AI 参考方式采用无框行编辑；移动不创建另一份设定。伏笔沿用原结算台账，“创作基调”保留原连续分区编辑和 AI 候选。
  - 世界书目录包含“世界地图”，打开现有地图工作台。设定右侧“场景与经历”读取本书有效场景锚点和明确引用的世界历史，可返回对应正文或地点地图。本章场景表示本章末段记录，不等于光标所在场；出场顺序不自动认定为人物当前位置。未落图地点仍需原地图流程确认，不按同名自动绑定。正文提及继续在底栏显示，和场景记录分开。
  - 切换与关闭前检查保存；版本冲突保留输入，载入最新需作者确认。详情草案独立存于原未保存条目草案机制，不属于工作区布局。
- 快速入口：`/settings/worldbook`
  - 目标：选择预设、迁移文本，或用 AI 建立轻量创作基调。
  - 能力：预设导入、小说文本导入、AI 基调初始化；不负责生成完整实体世界。
- 高级设置：`/settings/worldbook/advanced`
  - 目标：精细化维护与运营。
  - 能力：条目编辑、注入参数、分组管理、SillyTavern 导入导出。

## 2. 普通入口标准流程

### 方式 A：预设导入
1. 选择世界类型预设。
2. 点击生成预览。
3. 检查条目数量与分组。
4. 导入世界书。

### 方式 B：小说文本导入
1. 粘贴文本，或上传 TXT/MD 文件。
2. 点击生成预览。
3. 系统优先走 AI 提炼；若失败，使用本地提炼兜底。
4. 预览确认后导入。

### 方式 C：AI 建立创作基调
1. 输入至少 8 字的世界前提或创作方向。
2. 选择大类风格；不再设置目标条目数。
3. AI 只返回世界概述、情绪基调、写作风格、叙事视角、风格示例、禁写边界和一致性规则，不生成角色、地点、组织、事件、历史或任务。
4. 客户端确定性建立 `rule / style / forbidden` 三条常驻基础条目，并把文风、视角、基调、禁忌和一致性写入结构化设定的“创作规则”分区。
5. 确认预览后创建世界书，页面直接进入结构化设定；用户再逐项完成世界观、故事、角色以及需要核验的历史地理内容。

默认的一键基调初始化不调用网页检索。真实历史、地理、制度和技术资料应在对应结构字段的后续生成与审阅流程中按需处理，不能由一次大包生成替代。

## 3. 同名冲突策略

原有整包导入的目标约定是：同名时显式选择以下一种策略：
- 自动重命名后新建：保留原数据，不覆盖。
- 保持同名直接新建：允许并行同名资产。
- 覆盖同名世界书：替换旧条目，适合“整包重导”。

当前“新建世界书”页的 JSON 导入实际提供“独立新建”与“按名称和类型并入已有世界书”两项，2026-10-04 已取消默认勾选，须作者明确选择，并显示现有/导入条目数；深链进入也先加载已有索引。该入口尚未统一为上述三项，不提供整包覆盖。预览兼容 SillyTavern 的 `comment/key/world_name` 字段，原始导入数据不因预览而改写。

覆盖前建议确认：
- 现有条目数。
- 导入条目数。
- 条目变化量（正负变化）。

## 4. 结构化设定与高级设置

写作冻结上下文同时读取绑定库的顶层世界背景和入选条目。世界概述、文风、禁写边界、示例以 `worldbook-foundation` 记录正文哈希依赖，编辑或更换绑定会使旧结果过期；不以当前全局 active 库回退。`rule/style/forbidden` 保持创作规则身份，普通来源仍是资料。叙事 compiler 保留当前正文和必要背景，provider 不再对已入选内容二次截断；这条链路与预设/文本/AI 导入写入方式无关。


- Authoring 右侧“角色 / 设定”是当前世界书条目的日常编辑视图；`/settings/structured` 与工作区设定视图共用条目正文编辑、表格和关系图；旧分区字段收在“创作基调”，不是独立于世界书的第二份真源。
- 完整设定工作区：左侧作品目录不变，中间写条目正文；右侧提供同类设定、场景与经历、表格概览、关系与管理。表格可放大到中间；关系图保持在右栏，中央正文和底栏继续保留。人物保留角色模板，地点、组织及规则等无既有模板时从自由属性开始；已有属性和正文投影冲突仍由作者选择。
- 新建设定统一使用名称＋类型浮窗，默认当前类型；创建后进入正文。无关联库时建立并关联本书设定库；同名需明确“同名新建”，取消不创建条目。管理保存检查条目基准；复制产生新ID，保留内容与属性。删除前显示条目关联和地点的地图／历史引用影响，确认后检查条目指纹及设定库版本；目前为永久删除，界面明确不可撤销，不提供假回收站。
- “地理环境”是叙事概述，不再直接作为地图地点来源。世界观分区的地点目录以独立 `location` 条目维护城市、城镇、区域、河流和路线；地图只消费这些正式条目、显式关系和 geo-history。
- “从概述整理”使用 `setting-places.v1` 生成带原文证据的待审地点草稿。草稿必须逐项编辑、采纳或忽略，不能一键自动写入；采纳一项只推进该地点的 revision guard，不使同批其他无关草稿过期。
- 手工编辑地点必须保留既有 `mapBinding` 和来源证据。删除地点先显示地图绑定、历史与关系引用影响，不级联改写其他条目。
- 一键基调初始化只预填创作规则，不自动填角色、地点、势力或历史。
- AI 结果先进入草稿审阅；采纳或手动保存后直接 upsert 当前世界书中的对应条目，不再需要额外“转条目”。
- 字段 AI 按固定优先级生成：世界概述、顶层禁写边界与常驻条目 > 当前字段修订基线与其他已确认结构字段 > 关键词命中及同类已有条目 > 本次补充要求。补充要求只能填空，不能推翻已有事实。
- 已有条目不会整库塞入请求：每次按目标分区、字段类型、关键词和有限字符预算选取；作者生成会稳定读取相关条目，不受体验运行时的随机触发概率影响。
- 整个分区批量生成时，后一个字段会读取本轮前面已生成的草稿作为约束；所有结果仍先停留在审阅态，不会因批量请求提前写入世界书。
- “创作基调”的待审草稿可以逐项采纳，也可以点“全部采纳”一次保存本节草稿；两种操作均核对生成时的世界书版本，写入失败保留原草稿。“从概述整理”的地点草稿仍逐项确认。内置“雾潮暮湾”预设已将误入文风关键词的“雾港”改为“暮湾”；既有作品中的作者设定不自动改写。
- 普通模型响应中的 `reasoning/thinking` 块不会作为设定正文。结构化设定主链使用服务端固定 `setting-field.v1` / `setting-section.v1` schema，优先原生 JSON Schema，其次强制单工具，再其次 JSON object；响应中的 reasoning、refusal、截断和协议不支持分别归类，不能进入草稿。旧 `<setting-content>` 仅作为历史 fixture/兼容解析，不再是生产字段生成协议；不支持可靠结构化输出的渠道明确显示能力错误，不静默回退为普通文本。
- 设置页的“测试连接”除了文本探测，还会用不写入世界书的合成 `world.origin` 请求验证结构化设定链；结果会显示结构化是否可用、实际降级模式、协议、reasoning 状态与延迟。模型列表能返回不等于结构化设定可用。
- 结构化草稿记录生成时的 worldbook revision；若生成期间世界书发生更新，结果不会进入草稿；若采纳时 revision 已过期，也必须重新生成。这样不会用旧上下文覆盖用户刚保存的内容。
- 对生成草稿只有部分认可时，在同一审阅区填写修改意见，例如保留、删除、补充哪些事实，再点击“按意见修订”。修订请求使用 `setting-revision.v1`，同时发送正式字段、当前草稿、当前版本之前的有限历史版本和意见；当前草稿与本次意见优先，历史版本只作为找回既有事实的参考。AI 返回该字段的完整新正文，不返回 patch、思考或直接写入条目。草稿会保留有限版本链，可在上一版/下一版之间比较和回退；手动编辑会从当前版本建立新的分支。修订期间如果草稿哈希或 worldbook revision 变化，结果会被丢弃。世界书条目管理仍只负责最终采纳后的 upsert，不重复提供 AI 修订入口。
- 自动创建的空世界书描述只是管理占位，不属于世界设定，也不会进入模型上下文。世界概述、已有设定和本节补充要求均为空时进入“首条设定模式”：允许直接生成第一条正式世界书条目，但要求作出单一、具体、可继续约束后续内容的选择，不输出通用模板或备选方案。单项生成与整节生成共用当前分区的补充要求。
- 从小说片段提炼时，原始文字会作为世界书的 `sourceDocuments` 保留，提炼条目记录对应资料 ID；结构化设定页可展开查看原文。普通 Pinax/SillyTavern 往返会使用扩展字段保留这层资料与条目关联。
- 每次字段/分区操作只编译一次世界书上下文，读取全局约束、当前/其他已确认设定、相关条目和有限的相关原文摘录；动态字段放在提示后缀，固定约束保持前缀以利用 provider 缓存。原文按设定项、补充要求、条目名称与关键词选择；提炼条目与原文明示事实冲突时，以原文为准，不把压缩条目当作唯一资料层。整节默认一次请求返回全部字段，单字段失败不会丢弃已通过字段；若响应中已有部分草稿，仅对未通过本地校验的字段再发起一次定向修复，仍失败的字段保留字段级错误；采纳前仍不写入正式世界书。
- 结构化设定项使用稳定引用 `section.field` 映射到唯一条目。`rule/style/forbidden` 为常驻条目；角色、地点、事件、势力、任务和普通设定保持选择注入。运行时不再整块注入 `structuredSettings` 摘要，只消费世界书匹配到的条目以及既有顶层基础约束。
- 结构化角色字段中的“主角 / 重要配角 / NPC”是来源分类，不是角色条目名称。每个解析到姓名的人物分别 materialize 为一个 `type=character` 条目：`entry.name` 是人物姓名，默认 `injection.group` 为“角色”，背景、性格、外貌与其他资料同时保存在正式 `content` 和角色编辑元数据中。Authoring 角色面板与高级世界书页编辑的是同一 entry，不维护第二份角色库。
- 聚合角色文本解析只在旧数据首次迁移，或用户明确从兼容入口再次保存该字段时运行；Authoring 日常新建、编辑与 AI 补全均直接读写当前人物 entry。已由 Authoring 编辑过的条目不会再被旧 `structuredSettings` 投影在载入时反向覆盖。
- 用户从 Authoring 删除结构化派生角色时，世界书记录对应来源与人物键的 tombstone，后续普通载入不得令其复活；只有再次显式保存该结构化角色字段，才清理该来源 tombstone 并按最新字段重新逐人生成。旧版“主角 / 配角 / NPC”聚合条目在可解析姓名时拆为逐人条目，已编辑内容优先保留为手工角色卡。

- 条目精修：统一维护 `name/type/keys/content/mode/group`。
- 分组运营：创建、重命名、迁移、删除、清理空分组。
- 生态互通：导入与导出 SillyTavern 世界书格式。
- 世界书维护工作台：高级条目管理中的“AI 处理世界书”支持“新增设定 / 审查整理 / 完善选中”三种模式。自然语言请求先生成候选操作，不要求先建空条目；审查整理的本地预检覆盖相似条目对、缺少触发词、过长正文和占位名称，并为单条目保留完整 `issues` 集合。候选必须逐项审阅后才写入。模型不能直接删除或覆盖条目，合并、改写和新增都沿现有条目 CRUD 执行。
- 审查目标按每批最多 2 个条目发送给模型，避免把整本世界书或多个长正文放进一次请求；批次失败会保留其他批次结果，并明确提示未覆盖目标需要重新审查。
- 审查重点会先参与本地预筛；相似度不足或与重点无关的条目不会仅因为同属一个类型就进入模型。
- 维护候选只带真实条目 ID，并记录生成时的 `worldbook.updatedAt`。采纳前如果世界书已变化，候选整批失效，必须重新审查；避免用旧模型上下文覆盖刚保存的事实。

## 5. 质量检查建议

导入后建议进行三步自检：
1. 搜索关键词命中率是否正常。
2. 关键角色、地点、事件是否均有条目覆盖。
3. 进入体验页进行至少 1 轮剧情生成冒烟。
4. 联网生成的世界书检查研究来源是否随世界书保存，条目是否只引用存在的来源编号。
5. 若生成结果包含 `claims/conflicts`，确认冲突已处理且导入前研究审阅状态为 `ready`。
6. 对已有世界书使用条目管理的“审查整理”，对自然语言扩写使用“新增设定”；不要在体验页 Agent 中执行全局写入。

### 5.1 结构化生成渠道 Gate

结构化设定的本地协议夹具可用以下命令验证，不访问网络，也不会把 dry-run 标记为真实发布通过：

```bash
npm run smoke:structured-settings -- --dry-run --output /tmp/pinax-structured-settings-gate/report.json
```

真实 Gate 使用脱敏后的 provider 配置文件分别执行三条渠道。配置文件只在本机读取，报告只保留 provider、model、protocol、mode、请求次数、延迟、usage 汇总和错误码，不保存 API key、提示词或草稿：

```bash
npm run smoke:structured-settings -- \
  --config /path/to/minimax.json \
  --config /path/to/openai-compatible.json \
  --config /path/to/anthropic-compatible.json \
  --output /tmp/pinax-structured-settings-gate/report.json
```

只有真实配置完成三条渠道的单字段 10 次与整节 5 次，并满足报告中的 `releaseReady`，才可以关闭 S7。`fixtureReady` 只表示 dry-run 夹具通过，不能替代真实渠道 Gate。

本书添加资料浮窗按文件/粘贴文字切换输入，待添加列表逐份显示读取结果，统一确认加入本书。切换方式保留输入及队列。更多选项包含 JSON 世界书导入、可选基础设定生成和本地归档管理；普通资料追加不要求运行模型。全局新建世界书不受此布局收整影响。

浮窗关闭或Esc保留按书隔离的输入和归档队列，不把资料写进世界书；读取期间可关闭取消，正式保存期间禁关。入书成功清除该书导入草稿，通知承载面更新当前资料。焦点留在浮窗内，关闭后回触发器。切书/离开时卸载浮窗，迟到的读取/恢复结果不更新新窗口。

本地文件默认上限：PDF 100MB，其他支持格式50MB；显式调用参数maxBytes仍优先。拖入整个添加窗口显示松开提示，文字拖拽不触发文件导入；忙碌时拒收新文件。大小限制与本地归档总容量/模型上下文独立，PDF逐页读取并清理页和文档资源，批次串行处理。

助手输入框的添加文件复用本书资料浮窗；入书成功回执携带本书来源身份，助手选为source参考。发送时从当前书sourceDocuments重新解析参考及工具快照，不持久化一个会过期的复制文本；资料已移除时拒绝发送过期参考。删除对话或取消参考不会删除本书资料。


### 工作区中的完整地图与条目管理

作品导航的“更多”可打开地图或高级条目管理，放在中央或正文旁边。返回正文不会自动丢弃条目草稿；关闭或切换作品前仍需保存或处理待审结果。同一条目在另一处更新后，旧草稿保存会被拒绝，确认重新载入可读取最新条目。地图调整显示位置保留缩放与观看中心；地形依旧属于现有世界树，并非自动为每本作品复制一份。
