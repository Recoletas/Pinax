# 世界书导入与编辑流程

本文档定义“普通入口 + 高级设置”的标准操作链路，适用于产品演示、内容运营与日常开发回归。

## 1. 入口定位

- 主要入口：`/settings/structured`
  - 目标：按世界观、故事、角色和创作规则逐项建立可维护设定。
  - 能力：字段级编辑、单字段 AI 草稿、分区 AI 草稿、转为正式条目。
- 快速入口：`/settings/worldbook`
  - 目标：选择预设、迁移文本，或用 AI 建立轻量创作基调。
  - 能力：预设导入、小说文本导入、AI 基调初始化；不负责生成完整实体世界。
- 高级设置：`/settings/worldbook/advanced`
  - 目标：精细化维护与运营。
  - 能力：条目编辑、注入参数、分组管理、SillyTavern 导入导出。

## 2. 普通入口标准流程

### 方式 A：预设导入
1. 选择世界类型预设。
2. 点击生成预览。
3. 检查条目数量与分组。
4. 导入世界书。

### 方式 B：小说文本导入
1. 粘贴文本，或上传 TXT/MD 文件。
2. 点击生成预览。
3. 系统优先走 AI 提炼；若失败，使用本地提炼兜底。
4. 预览确认后导入。

### 方式 C：AI 建立创作基调
1. 输入至少 8 字的世界前提或创作方向。
2. 选择大类风格；不再设置目标条目数。
3. AI 只返回世界概述、情绪基调、写作风格、叙事视角、风格示例、禁写边界和一致性规则，不生成角色、地点、组织、事件、历史或任务。
4. 客户端确定性建立 `rule / style / forbidden` 三条常驻基础条目，并把文风、视角、基调、禁忌和一致性写入结构化设定的“创作规则”分区。
5. 确认预览后创建世界书，页面直接进入结构化设定；用户再逐项完成世界观、故事、角色以及需要核验的历史地理内容。

默认的一键基调初始化不调用网页检索。真实历史、地理、制度和技术资料应在对应结构字段的后续生成与审阅流程中按需处理，不能由一次大包生成替代。

## 3. 同名冲突策略

当待导入世界书与现有世界书同名时，必须显式选择策略：
- 自动重命名后新建：保留原数据，不覆盖。
- 保持同名直接新建：允许并行同名资产。
- 覆盖同名世界书：替换旧条目，适合“整包重导”。

覆盖前建议确认：
- 现有条目数。
- 导入条目数。
- 条目变化量（正负变化）。

## 4. 结构化设定与高级设置

- 结构化设定是当前世界书条目的日常编辑视图：按世界观、故事核心、角色设定和创作规则分区维护，不是独立于世界书的全局配置。
- “地理环境”是叙事概述，不再直接作为地图地点来源。世界观分区的地点目录以独立 `location` 条目维护城市、城镇、区域、河流和路线；地图只消费这些正式条目、显式关系和 geo-history。
- “从概述整理”使用 `setting-places.v1` 生成带原文证据的待审地点草稿。草稿必须逐项编辑、采纳或忽略，不能一键自动写入；采纳一项只推进该地点的 revision guard，不使同批其他无关草稿过期。
- 手工编辑地点必须保留既有 `mapBinding` 和来源证据。删除地点先显示地图绑定、历史与关系引用影响，不级联改写其他条目。
- 一键基调初始化只预填创作规则，不自动填角色、地点、势力或历史。
- AI 结果先进入草稿审阅；采纳或手动保存后直接 upsert 当前世界书中的对应条目，不再需要额外“转条目”。
- 字段 AI 按固定优先级生成：世界概述、顶层禁写边界与常驻条目 > 当前字段修订基线与其他已确认结构字段 > 关键词命中及同类已有条目 > 本次补充要求。补充要求只能填空，不能推翻已有事实。
- 已有条目不会整库塞入请求：每次按目标分区、字段类型、关键词和有限字符预算选取；作者生成会稳定读取相关条目，不受体验运行时的随机触发概率影响。
- 整个分区批量生成时，后一个字段会读取本轮前面已生成的草稿作为约束；所有结果仍先停留在审阅态，不会因批量请求提前写入世界书。
- 普通模型响应中的 `reasoning/thinking` 块不会作为设定正文。结构化设定主链使用服务端固定 `setting-field.v1` / `setting-section.v1` schema，优先原生 JSON Schema，其次强制单工具，再其次 JSON object；响应中的 reasoning、refusal、截断和协议不支持分别归类，不能进入草稿。旧 `<setting-content>` 仅作为历史 fixture/兼容解析，不再是生产字段生成协议；不支持可靠结构化输出的渠道明确显示能力错误，不静默回退为普通文本。
- 设置页的“测试连接”除了文本探测，还会用不写入世界书的合成 `world.origin` 请求验证结构化设定链；结果会显示结构化是否可用、实际降级模式、协议、reasoning 状态与延迟。模型列表能返回不等于结构化设定可用。
- 结构化草稿记录生成时的 worldbook revision；若生成期间世界书发生更新，结果不会进入草稿；若采纳时 revision 已过期，也必须重新生成。这样不会用旧上下文覆盖用户刚保存的内容。
- 对生成草稿只有部分认可时，在同一审阅区填写修改意见，例如保留、删除、补充哪些事实，再点击“按意见修订”。修订请求使用 `setting-revision.v1`，同时发送正式字段、当前草稿、当前版本之前的有限历史版本和意见；当前草稿与本次意见优先，历史版本只作为找回既有事实的参考。AI 返回该字段的完整新正文，不返回 patch、思考或直接写入条目。草稿会保留有限版本链，可在上一版/下一版之间比较和回退；手动编辑会从当前版本建立新的分支。修订期间如果草稿哈希或 worldbook revision 变化，结果会被丢弃。世界书条目管理仍只负责最终采纳后的 upsert，不重复提供 AI 修订入口。
- 自动创建的空世界书描述只是管理占位，不属于世界设定，也不会进入模型上下文。世界概述、已有设定和本节补充要求均为空时进入“首条设定模式”：允许直接生成第一条正式世界书条目，但要求作出单一、具体、可继续约束后续内容的选择，不输出通用模板或备选方案。单项生成与整节生成共用当前分区的补充要求。
- 从小说片段提炼时，原始文字会作为世界书的 `sourceDocuments` 保留，提炼条目记录对应资料 ID；结构化设定页可展开查看原文。普通 Pinax/SillyTavern 往返会使用扩展字段保留这层资料与条目关联。
- 每次字段/分区操作只编译一次世界书上下文，读取全局约束、当前/其他已确认设定、相关条目和有限的相关原文摘录；动态字段放在提示后缀，固定约束保持前缀以利用 provider 缓存。原文按设定项、补充要求、条目名称与关键词选择；提炼条目与原文明示事实冲突时，以原文为准，不把压缩条目当作唯一资料层。整节默认一次请求返回全部字段，单字段失败不会丢弃已通过字段；若响应中已有部分草稿，仅对未通过本地校验的字段再发起一次定向修复，仍失败的字段保留字段级错误；采纳前仍不写入正式世界书。
- 结构化设定项使用稳定引用 `section.field` 映射到唯一条目。`rule/style/forbidden` 为常驻条目；角色、地点、事件、势力、任务和普通设定保持选择注入。运行时不再整块注入 `structuredSettings` 摘要，只消费世界书匹配到的条目以及既有顶层基础约束。

- 条目精修：统一维护 `name/type/keys/content/mode/group`。
- 分组运营：创建、重命名、迁移、删除、清理空分组。
- 生态互通：导入与导出 SillyTavern 世界书格式。
- 世界书维护工作台：高级条目管理中的“AI 处理世界书”支持“新增设定 / 审查整理 / 完善选中”三种模式。自然语言请求先生成候选操作，不要求先建空条目；审查整理的本地预检覆盖相似条目对、缺少触发词、过长正文和占位名称，并为单条目保留完整 `issues` 集合。候选必须逐项审阅后才写入。模型不能直接删除或覆盖条目，合并、改写和新增都沿现有条目 CRUD 执行。
- 审查目标按每批最多 2 个条目发送给模型，避免把整本世界书或多个长正文放进一次请求；批次失败会保留其他批次结果，并明确提示未覆盖目标需要重新审查。
- 审查重点会先参与本地预筛；相似度不足或与重点无关的条目不会仅因为同属一个类型就进入模型。
- 维护候选只带真实条目 ID，并记录生成时的 `worldbook.updatedAt`。采纳前如果世界书已变化，候选整批失效，必须重新审查；避免用旧模型上下文覆盖刚保存的事实。

## 5. 质量检查建议

导入后建议进行三步自检：
1. 搜索关键词命中率是否正常。
2. 关键角色、地点、事件是否均有条目覆盖。
3. 进入体验页进行至少 1 轮剧情生成冒烟。
4. 联网生成的世界书检查研究来源是否随世界书保存，条目是否只引用存在的来源编号。
5. 若生成结果包含 `claims/conflicts`，确认冲突已处理且导入前研究审阅状态为 `ready`。
6. 对已有世界书使用条目管理的“审查整理”，对自然语言扩写使用“新增设定”；不要在体验页 Agent 中执行全局写入。

### 5.1 结构化生成渠道 Gate

结构化设定的本地协议夹具可用以下命令验证，不访问网络，也不会把 dry-run 标记为真实发布通过：

```bash
npm run smoke:structured-settings -- --dry-run --output /tmp/pinax-structured-settings-gate/report.json
```

真实 Gate 使用脱敏后的 provider 配置文件分别执行三条渠道。配置文件只在本机读取，报告只保留 provider、model、protocol、mode、请求次数、延迟、usage 汇总和错误码，不保存 API key、提示词或草稿：

```bash
npm run smoke:structured-settings -- \
  --config /path/to/minimax.json \
  --config /path/to/openai-compatible.json \
  --config /path/to/anthropic-compatible.json \
  --output /tmp/pinax-structured-settings-gate/report.json
```

只有真实配置完成三条渠道的单字段 10 次与整节 5 次，并满足报告中的 `releaseReady`，才可以关闭 S7。`fixtureReady` 只表示 dry-run 夹具通过，不能替代真实渠道 Gate。
