## 2. 成熟产品里值得采用的规则

- **VS Code：按上下文展示，同类操作放一起。** 官方指南和示例把打开操作放前面、复制相关操作放一起；特定类型的命令只出现在对应对象上。[1]
- **Apple：右键给当前对象的常用操作。** 菜单应短，通常不需要标题；仍应有可见入口。子菜单限制一层，危险动作放末尾。[2]
- **Microsoft：命令列表与内容浮窗分开。** 常用动作可直接显示；表单、确认和其他内容用对话框或浮层，不塞进命令菜单。[3]
- **W3C：菜单必须能用键盘完成。** 按钮打开后移入菜单，方向键选择，Esc 关闭并恢复焦点；不能只加一个 `role="menu"` 就算完成。[4][5]

平台差异不直接照搬：Apple 不推荐在上下文菜单里显示快捷键，VS Code 官方示例则显示快捷键。Pinax 桌面只标真正已实现的少量常用快捷键，触屏不标；不会编造一排快捷键作装饰。Apple 倾向隐藏不可用的上下文项；Pinax 对不适用类型直接隐藏，对保存中等短时原因保留灰置项，并给出具体原因。

## 3. 先分清三种入口

1. **常驻操作**：当前任务的主动作，例如发送、停止、采用修改、当前面板关闭。保留现有明确入口。
2. **面板更多**：只处理当前面板或文稿范围。不会在助手更多里放书稿导出、在写作更多里放返回首页。
3. **对象右键**：处理指针下的章节、条目、会话、回答、标签。与该对象可见的“…”使用同一份动作定义和权限判断。

没有把所有小字改成图标：触发器可以是图标，菜单项用清楚的短文字。操作可发现性由可见“…”、悬停／聚焦提示和已有主入口保证，右键只是捷径。

## 4. 右边的两个「更多」具体怎么改

### 助手更多

保留现有工具条位置和“完整助手／资料／对话”入口；右端“…”打开：

```text
新建对话
查找当前对话
────────────
运行日志
```

- 从现有 `startConversation`、`toggleSearch` 和日志对话框接入，不新建第二套会话状态。
- 查找移入这里后，移除工具条重复的独立查找图标；对话列表继续用于切换与管理历史对话。
- 新建不会清空或删除原对话；忙碌时沿用原拦截。空会话下查找灰置，原因是“当前对话没有消息”。
- 生成权限继续在输入区；参考与技法继续在输入区；“调整后重答”属于具体回答，不塞进这个菜单。
- 不新增“清空所有记录”、存储键、提示词等调试入口来填菜单。
- `AuthoringRunLogDrawer` 只负责日志对话框，将触发菜单交回助手父组件管理。

### 写作更多

桌面触发器只留水平省略号，悬停显示“更多写作操作”。不要再堆成图标一行、文字一行。

```text
导出当前章节
导出整本书
导出章节分镜
导入书稿…
────────────
✓ 自动联想
────────────
创作指引
```

这是已有功能的整理：自动联想用勾选状态表达，避免“开／关”重复长标签。桌面校对、查找等仍在现有工具条。手机收进更多的写作工具放在第一组，过长时菜单内部滚动，不出现横向按钮网格。

原菜单其他功能的去向：

| 原操作 | 固定去向 |
|---|---|
| 新建书稿 | 首页新建作品／作品选择入口 |
| 备份与恢复 | 现有设置及首页入口 |
| 素材库、素材收件箱 | 本书素材入口；收件箱若未有可见入口，须先补在素材页，再撤原入口 |
| 回到冒险 | 工作区导航中的跑团与冒险 |
| 返回首页 | 顶部产品图标 |

替换菜单前核实这些入口实际可达；不以精简为由删掉唯一入口。

## 5. 右键菜单：只保留当前对象的高频操作

本节按作者要求重新收简，取代此前过长的文件夹菜单。上一版把能力清单当成菜单，加入查找、排序、折叠、刷新、管理等操作，还额外设计新功能，偏离了快捷操作的用途。

**普通文件夹只留五项：**

```text
新建          ›
导入文件…
──────────────
重命名
移动到…
移除文件夹…
```

“新建”内放章节、构思、设定、文件夹，只用这一层子菜单。默认的正文、构思、资料、素材文件夹沿用相同菜单。菜单不放标题、说明文字、重复图标或“更多操作”子菜单。

其余对象同样做减法，不只缩文件夹菜单：

| 对象 | 保留的右键项（分号为分隔线） |
|---|---|
| 已绑定世界书 | 新建设定…／导入文件…；更换世界书… |
| 人物／地点等自动分类 | 新建人物…（随类型变化）；“其他设定”用新建设定… |
| 目录空白处 | 新建 ›／导入文件… |
| 章节、构思 | 在双栏打开；重命名…／移动到…／导出…／删除… |
| 设定条目 | 在旁边打开／复制名称；移动到…／删除设定… |
| 导入来源 | 打开原文／在旁边打开；移动到…／移出资料… |
| 只读项目文档 | 在旁边打开／复制路径（确有路径时） |
| 对话 | 重命名…／归档或取消归档；删除对话… |
| 用户提问 | 复制／编辑提问… |
| 助手回答 | 复制回答；重新生成／调整后重答…／从这里另开对话 |
| 内容标签 | 关闭／关闭其他标签／关闭右侧标签；在目录中显示 |
| 批注 | 定位正文／编辑批注…；删除批注… |
| 图片／视频结果 | 下载原件（有原件时）／打开原链接（有链接时）；移除或删除（按现有能力） |

单击已能完成的普通“打开”不重复列入；来源“打开原文”是明确的定位操作，保留。不可用类型不展示相应动作。少于三项也不补内容凑数。复制文件夹、任意剪切粘贴、收藏等尚无完整能力的操作不摆占位。

### 删出菜单的操作放在哪里

- 查找继续用左栏搜索；本轮取消新增“文件夹范围搜索”。
- 展开／折叠用目录箭头；刷新用现有目录刷新入口。
- 排序继续复用目录拖动，不再多加“排序”子菜单。正式替换前保留目录管理中的上移／下移入口，供键盘操作使用；不能只剩拖拽。
- 世界地图从已有地图条目打开；表格、关系图和管理继续在设定工作台。
- 正文提及、关联内容、来源详情和历史版本留在对应工作台现有入口；会话技术信息与提示词留在现有详情／日志入口。正式替换前逐项核实入口可达，不靠菜单减量删除功能。

### 行为仍要准确，说明不塞进菜单

- 新建、导入、移动都针对被右键的目录。打开时捕获 `bookId + folderId`，提交前重新检查；不使用随后改变的“当前选中项”。空白处固定指向作品根部。
- 新建／重命名文件夹用行内输入，Enter 确认、Esc 取消。移动打开目标选择器；重命名或移动归档不改变稳定 ID、资源所属或章节叙事顺序。
- “移除文件夹”沿用现有语义：只去掉这一层，内容与子文件夹移到上一级。确认框说明影响，不能改称含混的“删除”。
- 默认目录仍可整理；已绑定世界书不套普通目录的改名／移除。自动分类不具有真实目录身份，不能移动或删除分类；新建传对应 `initialType`。
- 导入复用参考来源导入流程；书稿导入仍走既有专用入口。创建成功、归档失败时保留原件并允许重试归档，不能重新导入一遍；目标消失时让作者重选，不静默落到另一作品。
- 右键只指定对象，不自动切换中间工作台。真正打开内容时才走保存／离开检查；文本区保留原生复制等行为。
- 重新生成仍更新原会话版本；从这里另开对话始终 fork。菜单精简不改变两者语义。

### 正文与输入框

浏览器原生右键包含复制、剪切、粘贴、拼写等能力。网页无法直接向它追加自定义命令。首轮保留文本区原生菜单，Pinax 的批注／询问助手等继续使用现有选区工具条；对象菜单用于目录行、标签、批注容器、消息外部操作区。

在回答文字中已选中一段时，保留原生复制选区；右键消息操作区才打开整条回答菜单。不能因为要复制一句话，却把整个回答复制出去。触屏文本长按也继续用于文字选择，手机通过“…”操作对象。

## 6. 统一菜单外观与交互

以下数值是 Pinax 的设计选择，不是声称某产品规定了这些尺寸。

- 一列文字，宽约 220–260px；桌面行高 32px，触屏至少 44px；内边距 5px。
- 圆角 8px；菜单行小圆角 4px；一条浅边线与短阴影。使用现有 raised／hairline／text／selected token 的明暗值。
- 普通项用文字，不每行强加图标。勾选、子菜单方向、确实可用的快捷键占固定窄列，不挤压文字。
- 默认不加“章节操作”等可见大标题，也不附每项说明。只有批量选择确需说明影响数量时才加标题。
- 组内稳定排序，组间一条线；通常 1–2 组，不为少量命令硬分组。当前对象菜单只为新建使用一层子菜单。
- 只将破坏性动作标红；普通选中用中性底色，深色模式不出现亮蓝色整块。
- 更多菜单对齐触发按钮右下方；右键菜单靠指针；边缘碰撞时换边并限高。测量实际内容，不猜菜单高度或混用缩放后的坐标。
- 点击菜单外、Esc、目标删除、切书、原对象滚出可视范围时关闭。点击外部可同时落到外部目标；不加吞掉第一次点击的透明全屏层。
- Enter／Space 打开并聚焦首项，方向键导航，Home／End 到首尾，Esc 回到触发处；对象行支持 Shift+F10。手机从“…”得到同一动作集合。
- 弹出重命名、移动等对话框时，焦点交给对话框；不要先强制回到菜单按钮再跳过去。

## 7. 接入方式与保护

先提炼小型共享菜单，不建设全应用命令平台或任意插件命令 SDK。

建议两部分：

- `WorkbenchActionMenu.vue`：渲染菜单、定位、遮挡、键盘、关闭与焦点恢复；不直接写书稿或世界书。
- 领域动作适配：同一处定义对象有哪些操作，再同时供右键和“…”使用。调用现有 owner，不复制保存逻辑。

最小动作形状：`id / label / group / visible / enabled / disabledReason / checked / destructive / children / run`。`children` 只允许一层。快捷键文字只来自实际已注册命令。

打开时冻结 `bookId + resourceType + ownerId + viewId/sessionId/messageId` 等目标，以及触发方式、锚点与需要的修订。资源动作、会话动作、布局动作保留各自身份，不塞进一种含糊的“当前对象”。

执行前由领域 owner 再检查目标仍存在、项目相同、修订和权限有效。右键 B 时不能先打开 B 来改变当前编辑会话，也不能忽略 B 去操作 A。目录定位只改变定位；需要真正打开时才调用已有保存／离开检查。

关闭其他标签按当前组取快照，逐个经过现有守卫；遇到拒绝即停止并保留未关闭项。不会宣称所有关闭是一个不可分割事务，也不为了关标签而取消任务。

共享菜单由外壳统一管理同时打开数量。脱离 overflow 裁切，但保持主题变量与缩放一致；若从原生 dialog 内触发，需要挂在该 dialog 内的菜单宿主，不能盲目 Teleport 到 body 后落到 top layer 后面。

## 8. 实施落点与验收（不是已实现）

优先落点：助手更多／会话行与目录行。把目录大表单退到“移动…”和“关联内容…”的专用浮窗，先统一命令层；随后接标签、设定条目和批注。媒体只有已存在且校验通过的动作才接。

需要接线的现有能力包括：目录移动和文件夹重命名、章节重命名／导出／双栏、会话管理、回答重答与 fork、日志、设定删除、资料移出。章节非当前目标导出／历史、批量标签关闭和资源类型能力适配需要补充实现。不存在的复制／回收站／跨作品剪切不放占位菜单。

验收关注：

1. 中间编辑 A、右键 B：打开菜单不切章，导出／重命名等准确指向 B，A 草稿与焦点不丢。
2. 同一对象的右键与“…”内容、顺序、禁用原因一致。
3. 重新生成仍在原会话；fork 才新建会话。消息所选文本仍用原生复制。
4. 对话菜单不撑高列表；第一层没有存储键；日志仍能查看本轮和作品记录。
5. 删除、归档、只读、待采用、运行中及保存失败各自按原规则处理。
6. 85%／100%／125% 缩放、视口四角、390px、明暗模式：菜单不裁切、不挡住触发对象，不横向滚动。
7. 鼠标、触控、Shift+F10、方向键、Esc、Tab 及对话框返回都能完成操作。
8. 菜单打开后切书、删除目标或完成异步请求，旧菜单不能写入新对象。
