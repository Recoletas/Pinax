## 1. 先复现，再按层修复

用户反馈“随便打几个字母也全给记历史里”。静态看到两个可能来源：

- `Authoring.vue/saveCurrentChapter()` 成功保存后对变化节点生成 block history，使用 `manual-save` 标签；`writingBlockHistoryContract.js` 仅要求前后文本不同。
- `authoringObserverDerivation.js/deriveMemoryFromDelta()` 把至少 6 字符的句子取前两句、最多 80 字，再由 `runObserverMemoryDerivation()` 建立 pending 候选；随后 memory history 保存候选修订。它是本地摘句，不是语义事实提取。

正文里程碑快照已有独立 500/1000/2000 字策略；`memoryTriggers` 已拒绝直接 keystroke/cursor-move 类型。不能据此说问题不存在，也不能只延长 debounce：需要追踪成功保存、离章 boundary 与候选修订的完整链。

在隔离真实 UI 执行 `a → asdfgh → 删除 → 中文短句 → 切章 → 刷新`，分别记录恢复副本、正文版本、block history、pending/active/stale、memory revisions、ledger proposals/facts、任务与 provider 请求增量。不要读取用户真实书稿来猜原因。

## 2. 六层数据的产品语义

| 层 | 记录条件 | 默认展示/作用 | 本夜调整 |
| --- | --- | --- | --- |
| 防丢稿保存/恢复副本 | 已有即时或短周期安全机制 | 默认静默；确有旧恢复稿才提示 | 不因降噪降低保存可靠性 |
| 正文编辑版本 | 已保存的有界编辑会话、里程碑、手动/操作前保护点 | 给作者恢复内容 | 连续微改合并、标签真实；重要的一字否定修改可保留，不以字符阈值全删 |
| 记忆候选 | 有资格的来源经有效提取，或作者显式记录 | 待审阅 | 无意义输入不产出候选；本地摘句不再冒充事实 |
| 已确认事实/作者偏好 | 作者采纳，通过来源/范围/版本检查 | 适用范围内召回 | 一条正式生命周期；偏好不混为故事事件 |
| 修订/决定审计 | 真实创建、采纳、拒绝、更正、撤回、来源失效 | 按需展开，可追溯 | 保留不可变证据；默认按对象/决定分组，真实数量仍可查看 |
| 故事时间/角色知情 | 明确事件时间和知情来源 | 历史或角色视角查询 | 记录时间、故事时间、知情时间不互相代替 |

编辑会话合并的初始设计：同一书/章/稳定节点的连续普通保存形成一组，保留起点和最新恢复点；空闲/离章/手动版本/采纳/恢复等边界封组。具体窗口用复现数据校准。跨节点、主副栏、撤销链与操作前保护点不能盲合并。缓存/存储要有容量和过期策略，不能只把刷屏数据藏在 UI 下继续无限增长。

已有历史默认保留；可做只读聚合。清理旧噪声须有来源/类型预览及可恢复方案，不能按“英文/短句”批删用户数据。已确认事实与决定账不压缩到失去原证据。

## 4. 提取任务的完整合同

```text
已持久化来源 + 稳定边界/显式请求
  → 本地资格判断与增量合并
  → 冻结范围/来源版本/已知实体/预算
  → 生产 dispatcher / provider
  → schema + 引文 + 实体/关系/否定/时间验证
  → 待审提案（原文与结果并列）
  → 采纳/拒绝/修改后采纳
  → 唯一事实 owner 提交
  → 本书、时间、视角过滤的生产 reader
```

- 自动资格不只看长度：输入法组合中、空白、未保存、无新变化、连续重复和已处理版本不调模型。`asdfgh`/`aaaaaa` 样本应为零候选；英文正文、缩写、人名、“他死了”“门没锁”等不能被语言/长度一刀切拒绝。
- 很短且语义不确定的输入可累计到稳定上下文，显式“提取/记住”可立即处理。自动触发与手动提取边界对作者可理解，不每键触发，也不要求所有用户手工点按钮才有记忆。
- 新任务以书/来源/版本或内容指纹/选中块/提取配置版本去重；权限、来源变化与配置变化必须使旧缓存失效。拒绝标记按 claim+证据版本保留，不能全局永久封禁同名实体。
- 状态区分待处理、处理中、部分完成、没有事实、已完成、失败、已取消、来源已变化；进行中的任务刷新后先对账或标中断，不能假称自动续跑成功。
- 429 按 Retry-After/退避上限处理；401/403 不盲重试；超时/网络未知允许显式重试并防重复提交。取消/切书/换来源后迟到结果不进入当前项目。
- 本夜建议默认并发 1、单 job 最多 8 块、单块最多 1 次格式修复，具体 token/时间/总调用预算写入配置与回执；超限内容显示剩余范围和继续操作。自动任务需冷却与每会话总预算，不悄悄全书重提取。
- 检查引文属于冻结原文且支持该命题；“甲说乙死了”只能提炼为来源于甲的报告，不能忽略传闻语气。关系未知、人物重名、否定、假设和时间含糊进入待核对/无产出，不能造关系补空值。
- 新提案复用既有账本/候选 owner，先给出 legacy candidate→proposal 的单向适配与去重设计；禁止同一结果分别写两套候选、两个审核按钮决定不同真值。旧候选仍可查，不强制迁移用户数据。
- 明确区分“摘录已保存”“候选待审”“事实已采纳”。模型关停或出错时保留原文与任务信息，不能退回本地前两句并显示提取成功。

## 6. 质量与故障验收

建立不少于 24 个独立标注片段，先冻结期望再跑；不能拿模型生成的参考答案自动判同一个模型。至少覆盖下列类别，使用确定性替身穷举故障，真实模型抽测覆盖语义问题。

| 样本/反例 | 硬要求 |
| --- | --- |
| `a`、`asdfgh`、`aaaaaa`、空白/纯格式/未完成 IME | 正文安全保存；不生成事实或持续待审噪声；无逐键模型调用 |
| “他死了”“门没锁”、英文短事实、NASA 等合法缩写 | 不因太短或是拉丁字母永远丢弃；需上下文的代词明确待消歧 |
| “莉娜没有钥匙”与“莉娜拿到了钥匙” | 正反语义保留；作为不同事件/时间或冲突待审，不能都摘要成“钥匙” |
| “甲谎称乙死了”“如果明天封城”“他梦见城破了” | 报告/条件/梦境不升格为作者确定的当前事实 |
| 别名、两个同名人物、跨块指代、反向关系 | 稳定实体引用与关系方向可核对，不猜出跨书人物 |
| 未知日期、两种纪年、迟录历史、相互矛盾来源 | 不填当前日期假装故事时间；保留未知与待裁决 |
| 拒绝后相同来源重跑、同一文件重复导入 | 不重复提案/事实/审计风暴；新证据可重新审阅 |
| 来源中含“忽略指令/自动确认”等文本 | 作为不可信资料，不能改变工具权限、预算和确认流程 |
| 429、401、超时、坏 JSON、截断、单块失败 | 有界重试/部分完成/错误解释，无摘句伪成功 |
| 任务中编辑/撤销/切书/刷新、双标签采纳 | 作用域和版本围栏有效；重复提交幂等；保存失败零半写 |
| 事实已采纳→助手/推演→撤回→再次请求 | 生产 payload 的包含/排除真实变化，引用可定位，不只测 projector |
| ZIP 新域中途失败与旧包缺域 | 补偿后原有资料/媒体/事实不丢；旧包不清空新增域 |

确定性硬门禁：跨域泄漏、无证据正式事实、未确认事实提前召回、取消后错误写入均为 **0**；噪声片段提案 **0**。短事实和负例必须检查正确性，不能以“全部不提取”通过。

真实 LLM 建议先抽 12 个已标注片段、最多 12 次初始请求，最多 3 次有记录的修复请求；启动前确认现有授权渠道和限额，预算未就绪先完成全部确定性链路。记录模型/配置、输入输出 token、延迟、提案数、引文命中、人工判定准确率/召回率、否定/传闻错误及跳过原因。固定小样本目标：可用提案准确率 ≥90%、显式可提取事实召回率 ≥80%、关键否定/传闻错误 0；这是本夜验收目标，不是通用质量承诺。没有真实结果则真实质量状态必须 not-run，结果不达标则 partial 并交错误样本。

复用 memory-history、memory-ledger、memory-ledger-continuation、ABC integration、F2 review/search/history 和 ZIP smoke；新增噪声/提取质量脚本，核心断言并入现有测试，遵守 20/200。截图覆盖默认历史、提案+引文、冲突修正、失败恢复，读写性能与真实模型质量分开报告。
