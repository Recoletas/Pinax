# A 线：跑团生产闭环与战役连续性（48 项）

> 上级计划：[跑团 / 联机 / 漫画夜间总计划](./nightly-20260919-roleplay-online-comics.md)  
> 范围：只做跑团 runtime、组件、专项脚本、fixture 与本线回执；不接管联机房间，不重写通用 Agent 平台。  
> 完成定义：不是“KP 类存在”，而是生产入口能安全完成、恢复、继续和收集一局；真实模型质量与确定性工程分开验收。

## A1. 真实同伴端口与角色知情（A07–A12）

| ID | 任务 | 验收证据 |
|---|---|---|
| A07 | 查明当前 production provider 安装点，将模型同伴接入现有 companion actor 端口；默认关闭/fixture，不增加未经授权调用 | 真实生产 consumer 可达；provider 缺失返回 typed unavailable，不降级成偷偷替玩家行动 |
| A08 | 接入现有项目/记忆的角色知识 reader：按 book/session/branch/actor 与 story time 投影，作者秘密默认排除 | 同一事实对主持、角色甲、角色乙有不同可见结果；provenance 与 completeness 可检查 |
| A09 | 定义并校验 CompanionCandidate：actor、intent、targetRefs、knowledgeRefs、resourceExpectation、publicRationale；拒绝多动作或越权状态写入 | 畸形 JSON、未知 actor/target/ref、伪造资源与作者秘密均明确失败 |
| A10 | 候选目标必须来自当前公开 projection；目标消失、场景切换或 revision 改变后旧候选 stale | 迟到候选不能进入结算；UI/回执能区分 stale 与 provider failed |
| A11 | provider 取消、超时、空文本、截断、重复 id、迟到响应和切书响应形成统一终态 | 每类反例只有一个终态，零正式写入；取消不自动重发可能收费请求 |
| A12 | 角色知识不足时走“公开信息内保守候选”或等待真人，不允许扩大到作者权限；输出泄漏扫描只是补充，不替代输入隔离 | 至少 12 个秘密边界样本零泄漏；扫描命中时保留低敏诊断，不保存敏感全文 |

阶段 Gate：固定响应下，模型同伴候选可从生产入口到动作确认；知识隔离反例全绿。无模型额度继续 A2，不阻塞。

## A2. 外部生成与本地落盘之间的崩溃窗（A13–A18）

| ID | 任务 | 验收证据 |
|---|---|---|
| A13 | 在外部请求前持久化 request intent：run/step/attempt、inputHash、providerKey、预算占用和可重放性；不保存密钥 | 刷新后可识别 running/unknown，不把未收到结果写 completed |
| A14 | provider 返回后先记录 resultHash/低敏 metadata，再提交可见叙述；保存失败保留“结果已返回、待保存” | 重试保存复用同一结果，不再次调用 provider；无法恢复正文时明确需要人工重试 |
| A15 | 结算结果与叙述解耦：相同 command/effectKey 只能掷骰、扣资源、增线索一次，叙述可基于同一机械结果重试 | provider 两次不同措辞不产生第二份机械副作用 |
| A16 | 覆盖四个精确崩溃点：请求发出后、响应收到前；响应收到后、结果保存前；结果保存后、UI ack 前；采纳后、收集正文前 | 重启/刷新后分别进入 unknown、recoverable、completed-awaiting-view、completed-awaiting-collect |
| A17 | 连续双击、键盘回车重复、两个标签页快速确认同一候选，必须由 command version/idempotency fence 保护 | 同 effectKey 只产生一份骰子/资源/历史；冲突方得到可解释结果 |
| A18 | storage quota、transaction abort、旧 schema、损坏 checkpoint、删除中的 session、切分支后的迟到 callback 均失败得正确 | 不覆盖新状态、不跨分支落盘、不吞错；恢复按钮指向真实可执行动作 |

阶段 Gate：故障注入矩阵逐个给状态快照和持久记录；“try/catch 无报错”不算通过。

## A3. 跨会话战役与支路隔离（A19–A24）

| ID | 任务 | 验收证据 |
|---|---|---|
| A19 | 建立/补齐 campaign 目录与稳定 identity：campaign/session/branch/scenario/ruleset/revision，不以当前页面变量作为唯一真源 | 重开应用可列出并继续；同书多战役、无书独立战役不串 |
| A20 | checkpoint 保存场景、规则版本、动作序号、角色/资源/线索/目标、角色知情、未决请求及出处 | 导出→清空→恢复后关键字段等价；未知字段按策略保留或只读拒绝 |
| A21 | 分支 fork/switch/archive：从冻结 checkpoint 分叉，后续回执、资源、角色知识和结局只进入本支 | 两支路各跑 5 步后切换，状态/历史/待回应零串线 |
| A22 | 场景转换必须携带显式原因、已兑现/未决线索、失败推进和可进入条件；结局后不能继续消耗动作 | 调查/社交/危险 fixture 都能走到至少两种不同终态 |
| A23 | 角色加入/离开/死亡或失联后的知识与资源语义明确；新角色不自动继承全队私密信息 | 角色换班、离场再回归、共同线索/个人秘密矩阵通过 |
| A24 | 旧版本/未来版本兼容：可安全迁移则一次性迁移并备份，不可安全理解则只读/拒绝；绝不静默丢未知字段 | 当前→旧 fixture、未来字段 fixture、损坏 fixture 三类结果明确且可回滚 |

阶段 Gate：同一 campaign 两次会话、两条支路、一次导出恢复完整走通；内存对象对比不能代替真实持久层。

## A4. 有界 KP 与长跑质量（A25–A30）

| ID | 任务 | 验收证据 |
|---|---|---|
| A25 | 固化每回合阶段：读取公开态→收集真人/同伴意图→校验→确定性结算→叙述→同伴反应→持久化→等待；各阶段可中断恢复 | trace/receipt 能定位阶段，恢复不跳过真人确认 |
| A26 | 所有循环有硬上限：provider 轮次、候选修复、叙述修复、工具调用、token/时间预算；耗尽后保留已结算事实并给安全收尾 | 恶意 fixture 无无限循环；预算不因刷新清零 |
| A27 | 失败推进不是“失败=无事发生”：按规则生成代价、暴露、资源消耗或新困境，但不能凭空改写未授权事实 | 三类场景各至少 4 个失败样本，变化可继续玩且有来源 |
| A28 | 主持不得替玩家决定关键选择；同伴只能操控其角色；NPC 行动可由 KP 提议但仍走同一规则/资源/幂等合同 | 12 个 agency 反例零越权；叙述不得与机械结果相反 |
| A29 | 做 20 轮代表旅程：含同伴、NPC、线索、资源、失败、场景切换、刷新、分支和结局；人工复核重复/停滞/秘密泄漏 | 逐轮表与最终 campaign 状态；不是只断言没有异常 |
| A30 | 做 100 轮确定性 endurance：随机种子固定，周期性刷新/故障/恢复，检查事件单调、存储增长、重复 effect 与悬挂请求 | 统计耗时、记录数、最大 payload、零重复副作用/跨支路泄漏 |

阶段 Gate：20 轮产品旅程与 100 轮工程长跑分开报告；fixture 质量通过不等于真实模型叙事通过。

## MiniMax 临时不可用时的继续队列

用户已授权现有 MiniMax 文本渠道，A44 是必跑真实 Gate。渠道临时不可用时不阻塞 A07–A43/A45–A48：固定响应至少覆盖合法单动作、非法多动作、未知目标、作者秘密诱导、空响应、截断 JSON、重复 id、迟到响应、429、超时、取消、响应成功但本地 quota failure。必须先证明“不会错误落盘、不会重复副作用、可以恢复”；渠道恢复后补跑 A44，不能用 fixture 永久代替真实长局。

## A 线拒收条件

- 模型直接改骰子/资源/线索或绕过 command version。
- 角色 reader 实际仍读取作者全量设定，再依靠输出正则“防泄漏”。
- provider 返回成功但保存失败时重新生成；或 unknown 被当 completed。
- 只跑 service eval，没有从生产跑团入口、真实 IndexedDB/持久层和收集正文出口走通。
- 用 100 轮无异常宣称叙事质量成熟；真实 provider 未跑却写“AI KP 已验收”。
- 未完成任务板仍因阶段提交、专项全绿或时间未到而停止。
