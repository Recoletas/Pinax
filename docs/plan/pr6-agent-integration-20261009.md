### 产品边界

- 助手：讨论、查资料、安排多步任务、提出正文和设定修改；运行中可停止，结果可审阅、采用和撤销。
- 推演：围绕当前正文位置或场景运行，保留半自动操作。有效草稿在正文目标位置预览，右栏提供控制；目标失效时保留草稿并允许重新定位。
- 批注、校对、补全：保留轻量入口和针对性任务，不要求用户先进入助手。
- 模型配置和请求出口可以统一；任务是否需要多轮工具调用由任务契约决定，不能让取名、单次润色等操作无条件进入自主循环。
- 公网版保留浏览器作品数据的现有归属；本机文件工作区是明确启用的能力。服务器目录不能充当所有免登录用户共同的作品库。

## 3. 实施顺序

### S0：冻结输入并准备隔离整合

1. 记录远端 main、PR head、工作区差异与未跟踪文件清单；备份原历史和完整 WIP，验证可恢复。
2. 在隔离工作树准备整合，不在用户正在使用的工作区直接解决大面积冲突；不启动或重启用户服务。
3. 将现有 UI 成果整理为可独立核查的提交；保留其真实作者。贡献者的原提交保留历史，不压成维护者署名的一个大提交。
4. 列出冲突清单和最终行为归属。重点为 Authoring.vue、工具栏、资料入口、欢迎页、ComicStudio、i18n、推演调用与共享文档。

出口：原始数据与 WIP 可恢复，整合工作树可构建，待合内容边界明确。

### S1：先修资料与本地文件一致性

主要位置：`shared/worldbookFileContract.js`、前后端 `localMirrorService.js`、`worldbookFileRepository.js`、`server/routes/localMirror.js`、世界书 store。

- 统一条目序列化及稳定 ID，避免标题被用作身份。
- 同步请求声明作用域、基准 revision 和幂等 ID；按书串行提交，拒绝旧版本覆盖新版本。
- 文件保存实现准备、校验、提交和恢复过程。不能把“单个文件 rename 原子”当成“整个项目更新原子”。
- 非托管文件和手工编辑的文件保护规则明确；仅删除本次更新范围中明确删除的受管内容。
- 文件真源的权限错误、解析错误、版本冲突与首次迁移分开处理。出错时保留可恢复副本，禁止静默把旧缓存回写覆盖文件。
- 公网禁用本机文件能力；自托管显式绑定后启用。旧浏览器存档无需先迁移才能继续写作。
- 检索索引、正文、资料引用都以 bookId/worldbookId 和内容版本确定归属。

出口：条目往返、部分同步、并发保存、失败恢复、旧版迁移、公网隔离通过。

### S2：补齐可部署的 Agent 运行基础

主要位置：`storyAgentRuntime.js`、`modelRouting.js`、`kitModelGateway.js`、`textModelAgentProvider.js`、`server/routes/storyagent.js`、运行包构建脚本。

- Pinax 保留统一模型网关；助手使用完整 Agent 执行，结构化单次请求仍遵守原结果格式、预算、流式和取消合同。
- 固定 Kit 来源、提交版本、依赖锁文件及兼容协议版本；本地构建运行包，带上必要依赖和许可信息，服务器仅解包启动。
- 明确进程所有权、健康检查、退出清理、启动超时；服务端密钥只留服务端，公网用户不得改全局模型。
- 内核中断时明确结束任务并保存已得到的结果，避免无限等待或未经说明切换另一套执行语义。
- 为工具循环设置步数、时间、输出和费用预算，提供停止、失败归因、超限结束与必要的局部重试。
- 核对工具输入 schema、允许的资源范围和读写权限；资料中的文字不能改变工具权限，任意文件与 shell 操作不暴露给公网任务。
- 在与生产相近的 2 GB 内存约束下记录启动、空闲、单任务及受限并发占用，确定并发上限。未测量前不承诺可部署。

出口：无仓库外隐式依赖的冷启动、真实文本请求、真实工具调用、停止和异常结束均可验收。

### S3：把助手接成完整的操作闭环

主要位置：`agentEngine.js`、`piNarrativeAgentBridge.js`、`authoringAgentTurn.js`、`authoringIntegration.js`、`useAuthoringKnowledgeAssistant.js`、现有 proposal / checkpoint 能力。

执行链：请求 → 冻结当前书与目标 → 检索 / 工具调用 → 回答或修改建议 → 作者审阅 → 持久化 → 更新现有界面 → 采用回执。

- 为任务和工具记录稳定身份、阶段、输入输出摘要、错误和耗时；用户可查看工具操作与来源。界面不依赖模型内部思维链。
- 讨论、查阅和写作任务使用一致的会话及任务管理；入口意图提供默认工具范围，允许 Agent 在权限内组合检索和检查。
- 对话回答、引用、生成稿和修改建议分开存储；不能把所有自然语言都作为可写入正文的内容。
- 正文建议支持插入和范围替换；角色、设定、大纲建议支持已有字段更新及新建条目。多目标任务按明确的变更组审阅，组内要么完整提交，要么保留原状态。
- 写入前校验目标身份和相关内容版本，采用重复点击幂等；成功保存后再标记已采用。保存失败保留建议，不显示假成功。
- 撤销只撤销该次采用；若后续已有编辑，展示冲突并允许审阅，不能整章回滚覆盖新内容。
- 切书、切会话、关闭面板、停止和刷新都不得让旧请求写进新目标。刷新后恢复任务状态与已保存结果；无法续接时标为中断并提供重试，不能假装仍在运行。
- 默认确认后写入。为用户明确授权的指定范围自动应用保留权限接口；不能把“完善 Agent”解释为默认获得全书写权限。

出口：查阅、编辑正文、修改人物设定、停止恢复、冲突保留、采用撤销六类流程成立。

## 4. 前后端接线接口

下表是需落实的语义合同；实现优先扩展现有桥、存储和 proposal 模块，不另建第二套并行系统。字段命名可随现有协议调整，但含义不能省略。

| 合同 | 必要信息 | 责任 |
| --- | --- | --- |
| RuntimeCapabilities | 协议版本、运行器是否可用、允许工具、本机文件能力、支持的恢复方式 | 服务端返回真实能力；前端据此开放入口 |
| AssistantRunRequest | bookId、sessionId、requestId、意图、目标及基准版本、引用、工具范围、预算、授权范围 | 前端冻结归属；服务端验证并启动任务 |
| RunEvent | runId、递增 seq、事件类型、阶段、载荷；工具事件带 callId | 桥接适配现有 SSE；终态唯一，重连去重，迟到事件不污染新任务 |
| SourceReference | bookId、sourceId、revision、片段位置、摘录、显示标题 | 检索层返回可定位出处；助手打开原文，过期来源明确提示 |
| ChangeProposal | proposalId、runId、目标类别与 ID、基准内容、操作、修改内容、依据、状态 | 内核提出变更；现有工作台负责展示和审批 |
| AdoptionReceipt | proposalId、幂等键、写入前后版本、持久化结果、撤销所需信息 | 文档写入层产生回执；助手和各面板读取同一份状态 |

事件至少涵盖开始、阶段、工具开始/完成/失败、文本增量、引用、建议、等待确认、完成、失败和取消。先与 Kit 实际协议核对；缺失事件需补协议或明确由桥层派生，不能仅给前端添加永远收不到的监听器。

任务完成与作品修改成功是两个状态：回答生成完成不意味着已写入作品。公网任务的访问凭证与书的 UI ID 分开校验，不能只靠知道 bookId 就读取别人的任务。

## 5. 界面怎么接

| 用户操作 / 结果 | 呈现位置 | 交互要求 |
| --- | --- | --- |
| 与助手讨论、发起任务 | 当前助手侧栏与全屏助手 | 共用对话与任务；可停止、新建、切换和删除会话 |
| 导入或引用资料 | 资料页与助手加号的现有浮窗 | 保留文件/章节入口，导入后引用同一本书的资料 |
| 检索命中 | 助手回答内 | 简洁出处，可打开原文定位；不把整份资料堆进回答 |
| 正文插入 / 改写 | 正文工作台的目标位置 | 无框草稿或差异审阅，采用、放弃、撤销；助手提供定位入口 |
| 人物 / 设定变更 | 工作台右侧现有角色 / 设定面板 | 在受影响条目展示待审修改，保留目录、选中态和无框编辑 |
| 大纲变更 | 当前大纲面板 | 定位对应节点，审阅后写入，不新增一套文本框表单 |
| 有待审结果 | 对应入口的小圆点或数量 | 状态来自未处理建议，采用或放弃后同步消失 |
| 工具过程 / 错误 | 助手的可展开操作记录 | 平时显示当前动作；展开查看工具、出处和失败原因 |

全屏和侧栏是同一助手的两种呈现，不产生两套会话。当前正文 UI 负责内容定位，Agent 不直接操作 DOM。PR 新增的 dock、卡片式设定和首页本地项目 UI 逐项适配当前界面，不整体覆盖已确认的布局。

推演空输入时仍从正确正文末尾继续，显式插入位置保留；草稿保持中间预览、暗色无灰带、右栏可返回定位；停止、目标变化和核对失败后都保留输入及已生成内容。采用后的现场识别只生成待确认候选，沿用使用时识别与作者确认入场规则。

## 7. 完成界限

本轮整合完成意味着：现有 UI 连得上真实 Agent，资料安全、任务有归属、工具受控、修改可审阅采用撤销、异常结果可恢复、运行器可打包部署。
