# D 线：全产品长期行为、故障与视觉巡检 Agent（64 项）

> 上级计划：[2026-09-19 夜间总计划](./nightly-20260919-roleplay-online-comics.md)  
> 状态：**计划，未启动 agent、工作树、服务、负载、修复、提交或推送。**  
> 目标：遍历当前可达功能，模拟至少 5,000 个独立用户的长期行为，用真实浏览器抽样验证交互并产生大量截图，同时验收真实生成文本与图像质量；小问题在严格边界内自行修复，大问题进入短句式报告。  
> 定位：D 是巡检/修复线，不是 O 集成线。A/B/C 仍各自负责跑团、联机、漫画的功能实现；D 不替它们合并或宣布整夜完成。

## 1. 为什么必须分层模拟

“5,000 个用户”不能等价为同时启动 5,000 个 Chromium：那主要测到的是测试机内存，而不是 Pinax。D 线采用三层负载，并在报告中分别标注，不混成一个数字。

| 层 | 规模 | 目的 | 不能冒充 |
|---|---:|---|---|
| L1 领域/存储长期游走 | **≥5,000 个独立 persona，≥1,000,000 次动作，虚拟 180 天** | 找跨书串线、revision 倒退、孤儿引用、重复副作用、存储膨胀、备份恢复和长期状态腐化 | 不冒充真实浏览器用户或并发在线人数 |
| L2 协议/服务负载 | 先 smoke，再 50/200/1,000 VU 等级；只打本机隔离服务 | 找 HTTP/WebSocket 限流、队列、重连、SQLite、TTL 和资源释放问题 | 不攻击公网，不冒充真实用户体验 |
| L3 浏览器旅程 | ≥24 个隔离 profile/context、≥240 次完整 session，覆盖三尺寸与亮暗主题 | 找真实 DOM、路由、焦点、IndexedDB/localStorage、刷新、布局和交互问题 | 不用 24 个浏览器称作 5,000 人 |

这一组合遵循 Grafana k6 的[网站负载建议](https://grafana.com/docs/k6/latest/testing-guides/load-testing-websites/)：大部分负载用协议级模拟，少量浏览器负责前端真实性；smoke、average、stress、spike、soak 分开执行，不直接从零冲到最大负载。D 默认复用现有 Node/Playwright 工具，不因计划本身新增 k6；只有本机确认可用且无需扩大依赖时才采用，否则实现等价的有界 Node runner。

## 2. 全功能覆盖清单

D 必须从路由、活动栏、设置入口和生产 service 生成清单，不靠记忆枚举。最低覆盖：

1. 首页：空书架、多书、搜索、排序、网格/列表、新建、导入、继续写作、删除/恢复边界。
2. 创作工作台：书/卷/章、正文编辑、自动保存、文本块、选区、批注、助手、推演、现场、人物、大纲、历史、查找替换、撤销、Zen、离页恢复。
3. 设定与资料：快速导入、创建工作区、结构化设定、高级世界书、资料绑定/移除/预览、跨书隔离、记忆审阅。
4. 地图：初始化、缩放/平移、地点、绑定、配置迁移、空/长/错误状态。
5. 素材：创建/编辑/筛选/来源回跳、图片、批量动作、跨书切换、画布关联。
6. 卡片画布：卡片、关系、排序、时间线、导演/视频出口的真实可用与失败状态。
7. 漫画：页面/画格、分镜、图片候选、排字、QA、导出、恢复。
8. 体验/跑团：会话、输入、人物、规则、资源、分支、恢复、历史、收集到正文。
9. 联机：旧联机入口及 feature flag 下 C2-3 邀请/审阅；权限、断网、重连和服务重启。
10. 设置与运维：主题、缩放、模型连接、写作偏好、备份/恢复/清理、诊断导出、使用指南。
11. 桌面兼容：若环境可用，项目创建/打开/只读、关闭恢复和打包前检查；否则单列 external/not-run。
12. 兼容入口：旧 `/writing`、`/notes`、`/poetry-lab`、旧 worldbook/map 路由重定向，不能形成第二状态。

每个功能最少覆盖 `empty / regular / long / loading / partial / error / stale / cancelled / recovered` 中适用的状态，以及当前作品、另一作品、删除对象、旧 schema 四类身份边界。不存在的状态要写 `not-applicable`，不能用空页面截图凑覆盖。

## 3. Persona 与长期行为模型

至少 12 类 persona，按种子确定性混合：初次写作者、回访作者、百万字长篇、频繁导入者、资料密集型、地图型、素材/画布型、漫画型、跑团型、联机房主、联机审阅者、移动/弱网用户。每个 persona 拥有独立 user/workspace/storage identity，不能共享当前书快捷变量。

虚拟 180 天中按权重执行 80–600 次动作：创建/导入作品、切书、建卷章、输入/删除/粘贴、等待自动保存、刷新/关页、历史/恢复、设定与资料修改、地图和素材、生成 fixture 结果、批注/助手采用撤销、跑团、漫画、备份恢复、存储清理、主题/缩放、断网重连、归档删除。每 5–30 次动作推进虚拟时间；每个 persona 至少一次重新启动、一次失败注入和一次备份/恢复校验。

用户已明确授权现有 MiniMax 文本、生图和图文模型调用。百万动作主体仍使用固定 adapter，保证规模、故障注入和可重现性；另设真实模型抽样层，至少执行 240 次文本生成/改写/推演、60 次图片生成，以及 100 张产品截图的图文理解审查。发现结构错误、内容泄漏、视觉不一致或恢复问题后可继续扩样，不设费用上限。真实调用必须走现有生产 adapter、使用原创 fixture、记录 request/receipt/保存终态；禁止把密钥写进浏览器/日志，也禁止对 MiniMax 做并发压力或无限重试。联机负载只连接 D 自己启动的 loopback 服务。所有长跑都记录 seed、persona、action index 和最短重现序列，以便失败能从百万动作缩减到十几步。

真实模型与确定性层分开计数：fixture 负责证明“失败得正确”，MiniMax 负责证明真实协议、真实返回形态、内容质量、图片保存和图文审查确实可用。图文模型的审美意见只是第二审阅者；D 仍须实际查看代表图，不能把模型评分直接写成视觉通过。

## 4. 缺陷分级与自行修复边界

| 级别 | 示例 | D 的动作 |
|---|---|---|
| P0 | 数据丢失/跨书泄漏、秘密泄露、重复收费/副作用、备份破坏、安全绕过 | 立即停止相关破坏性场景，保留最小证据；不自行做架构修复，写短报告并继续其他独立域 |
| P1 | 主流程不可完成、常见恢复失败、页面不可操作、大面积 UI 崩坏、服务持续泄漏 | 写报告；只有修复明显且同时满足“小修条件”才可处理，否则不扩范围 |
| P2 | 局部状态错误、单一按钮/焦点/溢出、明确 null guard、错误提示和可恢复性缺口 | 满足小修条件则先写复现，再自行修、定向复验并提交 |
| P3 | 对齐、字级、间距、hover/focus、边框噪声、颜色 token、局部深色/窄屏不协调、错字 | 可按视觉规范成批小修；必须有前后截图，不能顺手重设计整页 |

**小修必须同时满足：** 稳定复现；根因明确；最多 3 个生产文件、约 120 行净改动；不改 schema/migration、依赖、权限、协议、计费、数据 owner、路由身份或全局视觉方向；可独立回滚；不在 A/B/C 当前写锁内；定向 Gate 与完整门禁可通过。相关小修按页面/根因合并成少量 commit，不为每个像素建一个提交。

**大问题包括：** 数据模型/迁移、跨域事务、权限/密钥、模型计费、协议兼容、全局导航/主题重设计、需要新依赖、超过 3 个生产文件或影响多个产品域。D 只交最小复现、影响、证据和建议 owner，不擅自扩大修复。

若问题落在 A/B/C 写锁中，D 即使认为是小问题也不直接改；在报告标 owner、种子和建议 patch，继续巡检。A/B/C 冻结后，D 可在一次性只读工作树复验其 tip，但不能把自己的分支变成夜间合并树。

## 5. 截图、trace 与磁盘治理

Playwright 支持全页/元素截图和 buffer；Trace Viewer 能回放动作、DOM snapshot、网络、console 和页面状态，适合只在失败时留完整证据，见[官方截图文档](https://playwright.dev/docs/screenshots)与[Trace Viewer](https://playwright.dev/docs/trace-viewer-intro)。视觉像素比较只用于捕捉变化，不用于自动判定“高级感”。

### 5.1 截图矩阵

- 视口：1440×960、1024×768、390×844；必要时补 200% 缩放。
- 主题：亮色、暗色；涉及系统跟随时另测一次切换。
- 状态：首屏、展开菜单/抽屉、编辑中、长内容、空、加载、错误、恢复、危险确认、完成。
- 交互：default、hover、focus-visible、pressed/selected、disabled、busy、error。
- 每轮允许捕获 500–1,200 张，但只保留有审查价值的子集。

### 5.2 人工/视觉审查维度

每批 12–24 张，逐张检查：信息所有权、视觉中心、主副栏比例、有效留白、对齐基线、字号层级、正文宽度、按钮层级、图标语义、边框/卡片噪声、暗色中性度、悬浮/焦点、空状态、长文本、滚动、遮挡、横向溢出和页面间协调。自动化只负责测几何、对比、overflow、重复标题和 a11y；“廉价感、拥挤、空、割裂”必须由截图审阅给出一句具体原因。

### 5.3 保留与删减策略

所有产物只能放在 D 自己的 `tmp/product-audit/<run-id>/`，每个 run 带 manifest/hash/状态。删除器复用现有 artifact 安全模式：校验 realpath、拒绝 symlink、拒绝项目根/`tmp` 根和非 `product-audit` 子目录；**绝不碰源码、用户目录、浏览器真实 profile、`.env` 或其他 agent 产物。**

- 硬上限 2 GiB；到 1.5 GiB 立即整理到 800 MiB 以下再继续。
- 成功旅程的视频、trace、console 全量日志在统计提取后删除；失败 trace 最多保留最近 20 个，单个上限 50 MiB。
- 截图长期只留：基线代表图、P0/P1、每个已修问题的 before/after、每个页面最终亮/暗/窄屏代表图。相同 hash 只留一份。
- P2/P3 未修截图保留最近两轮；已关闭且结果与代表图重复的删除。
- 每完成 100 张截图或每 30 分钟执行一次 dry-run prune；达到高水位才 `--apply`。删除前后记录文件数/字节/保留理由。
- 原始事件只保留低敏 JSONL 摘要；正文、模型密钥、邀请 key、用户路径和完整 IndexedDB 不进入产物。

## 6. 简洁报告格式

最终 `summary.md` **不超过 100 行**，用短句，不写测试过程散文。固定结构：

```text
# 全产品巡检
基线：<sha>；运行：<时间>；范围：<已覆盖>/<总数>
规模：5000 persona / 1000000 actions / 240 browser sessions / N screenshots
结果：P0 x；P1 x；P2 x；P3 x；已修 x；未复现 x

## 大问题
| ID | 级别 | 页面 | 问题 | 最短复现 | 证据 | 建议 owner |

## 已自行修复
| ID | 修复 | 文件 | 验证 | commit |

## 未覆盖
| 项目 | 原因 | 下一步 |
```

P0/P1 或跨域大问题各建 `issues/BUG-xxx.md`，每份最多 15 行：现象、影响、最短复现、证据、根因范围、建议 owner、禁止的危险修法。百万动作原始结果、截图 manifest、性能曲线留 JSON/CSV，不塞进汇报正文。重复根因合并为一条问题并列受影响页面，不能用 30 张截图制造 30 个 issue。

## 7. 生成文本与图像质量 Gate（Q01–Q12）

模型调用成功、JSON 可解析、图片可解码只属于工程 Gate，不能据此判质量通过。本组 12 项与 D01–D64 同为必做；最终共有 **64 个执行任务 + 12 个生成质量 Gate**。

| ID | 质量任务与通过条件 |
|---|---|
| Q01 | 列出所有真实生成入口：续写/改写/校对/助手、设定补全、资料提取、推演、体验/跑团、漫画脚本/提示词、生图；没有入口不得漏测。 |
| Q02 | 建原创盲测语料：至少 12 类故事场景，含短/长文本、双人/多人、强约束、否定约束、秘密、事实冲突、中文标点、连续多轮和漫画连续性。 |
| Q03 | 每个文本入口用多个 fixture/repetition，累计 ≥240 次真实 MiniMax 调用；记录模型、参数、延迟、输入/输出 hash 和功能终态，盲评时隐藏配置。 |
| Q04 | 文本硬规则自动检查：空/截断/控制文本、JSON/工具泄漏、作者秘密、未授权人物/事实、禁用动作、格式与长度；关键泄漏和越权必须为 0。 |
| Q05 | 文本人工量表：指令遵循、相关性、事实/人物一致、因果、可读性、语言自然度、重复/套话/机器腔、可直接采用程度，各 1–5 分并写一句理由。 |
| Q06 | 长链退化：至少 3 组 20 轮故事与 10 组连续改写，检查名字/关系/伤势/地点漂移、前文遗忘、越来越短/长、重复收尾和语气同质化。 |
| Q07 | 建生图盲测集：人物单图、双人互动、固定道具、室内/室外、昼夜、动作、复杂构图、漫画连续四格、深色场景和明确负面约束。 |
| Q08 | 真实生成 ≥60 张：至少 12 组提示，每组多样本；其中 ≥16 张组成连续画格，≥8 张用于失败后的定向修复/重生成对照。 |
| Q09 | 图片工程检查：MIME、尺寸、解码、透明/方向、保存、缩略图、刷新恢复、重复结果和只重试保存，全部与审美评分分开。 |
| Q10 | 图片质量量表：提示词遵循、主体数量/身份、人物与道具、动作、场景、构图、清晰度、明显结构缺陷、无关文字/水印、风格一致，各 1–5 分。 |
| Q11 | 连续性与修复：比较相邻格人物外观/服装/伤势/道具/地点/时间/方向；修复结果必须与旧图并排，证明目标问题改善且未制造更大问题。 |
| Q12 | MiniMax 图文模型批量盲审全部 60 张和代表文本，但 agent 必须实看全部失败、全部边界样本及每组至少一张；两者分歧进入人工复核，不能自动取模型意见。 |

最低质量阈值不是营销分：文本硬规则/秘密/控制泄漏 0，整体中位数 ≥4/5，“无需实质重写即可采用”≥80%，明显事实/人物矛盾 ≤2%，重复套话/机器腔严重样本 ≤5%；图片解码与保存 100%，关键主体/道具/场景遵循 ≥90%，重大结构/构图缺陷 ≤10%，非预期文字或水印 0，连续性中位数 ≥4/5。阈值未过就写 fail/partial 和最差样本，不通过筛掉坏结果后只报最好图。

报告只增加一张简表：入口、样本数、硬失败、质量中位数、可采用率、最差问题、证据目录。详细逐样本评分留 CSV/JSON。提示词或局部解析的小缺陷符合“小修条件”可自行修复并复跑同一盲测集；需要换模型、改全局 prompt 架构、知识权限或多阶段生成的，作为大问题报告。

## 8. 连续执行与安全规则

- D 启动自己的临时 Vite/Express 服务和测试数据库，使用动态端口并记录 PID；不得启动、重启或杀死用户已有 5173/生产服务。结束只关闭自己确认过的 PID。
- 负载只打 loopback/隔离环境。任何负载目标不是批准的本机地址立即拒绝；MiniMax 只做正常节奏的已授权功能/质量调用，不做并发、stress、spike 或 soak 压测。绝不对 GitHub、公开站点或生产部署施压。
- 先 1 persona/1 browser smoke，再 50、500、5,000；每级检查内存、磁盘、错误率和不变量。P0 或磁盘高水位先停当前场景、整理证据，再继续其他域。
- runner 每 1,000 persona 或 50,000 动作写 checkpoint。进程退出后从 seed offset 继续，不重跑已通过百万动作来填时间。
- 浏览器不可用时继续 L1/L2、fixture、报告和 artifact 管理；服务不可用时继续 L1/L3 静态/本地能力；A/B/C tip 未冻结时审 current main，不能空等。
- 一批截图完成、一个小修提交、某个路由全绿、达到 5,000 persona 都不是停止理由。覆盖矩阵、视觉审阅、故障缩减、产物清理、报告和完整门禁全部结束才可收工。

## 11. 停止条件与拒收条件

D 只有在 D01–D64 和 Q01–Q12 均有唯一状态、所有本地可做任务结束、MiniMax 真实文本/图片质量抽样完成、合格小修复验、产物完成清理、报告生成且完整门禁通过后才能结束。单个模块失败不阻塞其他独立模块；记录断点后继续。需要真实设备、Electron 或真人审美确认的项目可标 external/not-run，但不能借此跳过确定性替代项。MiniMax 临时网络故障时先做其他队列并持续有界重试，不能直接取消真实 Gate。

以下任一情况直接拒收：

- 用 5,000 次请求、5,000 次动作或同一用户循环冒充 5,000 个独立长期用户。
- 同时启动成千完整浏览器导致机器交换，却没有领域/协议分层和可重现 seed。
- 只访问路由首屏，没有操作、错误、恢复、跨书和长期状态。
- 截很多图但未实际分批查看；用 pixel diff、axe 或 DOM 存在冒充美观验收。
- 只证明模型返回非空/图片可打开，不评文本事实、因果、语言、退化与图片提示遵循、结构缺陷、连续性；或只挑最好样本报告。
- 截图/trace 无限增长，或清理脚本能触碰项目根、用户 profile、其他 agent 目录。
- 为了自行修复小问题而改 schema、协议、权限、依赖、全局主题或 A/B/C 写锁。
- 汇报堆长日志、测试过程和截图列表，却没有简短的大问题、复现、影响和 owner。
- 对公网、生产环境或 MiniMax 等第三方 provider 做并发压力/soak；授权的是正常功能与质量调用，不是攻击性负载。
