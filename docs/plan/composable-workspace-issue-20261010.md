# 可组合创作工作区：整合正文、资料、助手、跑团、漫画与视频

关联：[#3 资料导入与 Agent 工作流](https://github.com/Recoletas/Pinax/issues/3)。该议题继续负责资料处理与 Agent 能力；本议题负责这些能力进入工作区后的打开方式、状态归属、任务连续性，以及其他创作页面的整合。

## 1. 要解决的作者任务

作者正在写一章小说，想查阅一份导入资料，打开其中的人物设定，让助手修改指定段落，再把其中一个场景做成漫画或分镜。这个过程应该围绕同一份作品连续进行，不能每打开一种功能，就重新选择作品、离开正文、丢失阅读位置，或中断正在运行的任务。

跑团也需要查资料、看人物和使用生成能力，但推进游戏会话与修改书稿是不同操作。漫画、视频同样需要自己的画布、镜头和版本管理。统一工作区应让这些内容相互打开和引用，同时保留各自的工作流程。

目标是建立一套常驻、可组合的创作工作区：功能负责内容，宿主负责放置、导航和生命周期。首页继续保留；现有页面逐步成为可嵌入的内容视图，旧地址仍可使用。

本 issue 是详细设计与实施约束，不包含 PR 划分。作者已要求执行；2026-10-10 本地完成公共宿主、资料阅读和跨模块参考／视频任务基础，整份计划尚未完成，续做已接助手独立会话与同书切页任务连续性。2026-10-11 已进一步实施主／旁独立资源标签、原正文编辑器切章、快速打开、单人跑团常驻与旧链接关闭回程。当前版的重点是同书连续使用两组内容；任意嵌套分组、跨书并行、独立联机连接服务和外部插件接口仍不属于已交付能力。具体实现、验收与剩余项见[实施记录](../agent-runs/composable-workspace-20261010.md)。

调研日期：2026-10-10。源码基线为 `44466ab1b63b4dfde6c40f98997fad00a6c5de29`，同时检查了当前本地工作区。助手权限、正文修改、现场整合及部分 UI 修复存在尚未提交的本地修改，实施前必须在实际接手提交上重新核对，不能只照公开 main 覆盖。

设计阶段做了源码调用链与官方产品资料调研。实施阶段已验收部分宿主、查阅、移动端和任务连续性场景；真机输入法、共享撤销与完整后台会话仍未验收。下文保留整份设计条件，当前证据以实施记录为准。

### 当前已有的基础

| 范围 | 现有实现 | 本次需要补齐 |
|---|---|---|
| 应用外壳 | `AppShell.vue` 提供标签、导航和设置弹窗，内容由一个路由组件承载 | 外壳管理内容组；打开旁边内容不再必然卸载当前页面 |
| 工作区标签 | 按作品和功能页去重，另存临时选区、光标、滚动 | 区分具体资源与视图实例，支持同类资源独立打开 |

| 正文与双栏 | 已有双栏编辑、来源选择、保存与输入组合处理 | 提炼编辑会话；不能直接复制完整写作页来实现任意多开 |
| 资料 | 已有导入浮窗、来源档案、分块、检索及原文查看 | 拆开页面导航与内容；来源定位、长文阅读、任务归属需要完善 |
| 助手 | 侧栏与展开模式共享写作页所有者；已有工具、任务日志和恢复接口 | 页面之外的任务会话、明确的修改目标、可见的后台状态 |
| 助手本地改动 | 已补权限、结构化修改提案、原位审阅、自动采用范围、撤销；现场并入推演 | 迁移时保留这些合同，不倒退为聊天框输出改稿 |
| 跑团／联机 | 会话、分支、叙事状态及房主权限各有现有实现 | 正在查看的资源与正在推进的会话分离，避免隐藏视图等于退出房间 |
| 漫画／插画 | 已有页、格、候选、素材、生成状态及失败保存保护 | 画布与任务解耦，稳定定位页／格，跨模块引用可追踪 |
| 视频 | 已有分镜、镜头生成、版本历史、查询恢复及素材归档 | 明确恢复期限与取消语义；展示位置改变不能重发任务 |

### 从代码中发现的具体约束

- `AuthoringDualPane.vue` 有自己的文稿、脏状态、编辑历史和延迟保存；主文稿更新在副栏不脏时同步。现有机制是主栏／副栏的协调，不能据此承诺任意多个窗口同时编辑安全。
- `guardWorkspaceExit()` 除了检查保存，还会执行取消或放弃候选等离开操作。因此不能把它原封不动用在移动、折叠视图上；检查与真正离开后的清理需要拆开。
- 助手当前上下文主要来自主栏章节和选区，并非任意获得焦点的编辑器。助手组件卸载会取消任务、撤销授权；服务端连接关闭也存在中止上游的路径。已有任务恢复接口不等于请求能脱离页面自动持续执行。
- 跑团目前以单个当前会话驱动，切会话会取消生成；体验页卸载还涉及联机清理。不能挂载多个完整体验页假装已经支持多个并行跑团。
- 漫画已有“结果未知，不自动重发”的保护；视频停止等待也不保证供应商已经停止生成。这些差异必须保留。
- 视频服务端任务记录目前在进程内 Map 中，并有过期时间；浏览器记住任务 ID 不代表服务端重启后可以恢复。

## 3. 外部产品调研结论

| 参考 | 值得借鉴的机制 | 在 Pinax 中的取舍 |
|---|---|---|
| [Obsidian 标签和分组](https://help.obsidian.md/tabs) | 内容可在标签组间移动，固定标签避免被新内容替换，部分视图有位置限制 | 支持旁边打开、固定和移动；不要求每种大型编辑器都能塞进窄栏 |
| [VS Code 自定义布局](https://code.visualstudio.com/docs/configure/custom-layout) | 编辑器组与辅助视图区分，移动和重置有命令入口 | 拖拽之外提供按钮、菜单和键盘操作；保留清楚的默认布局 |
| [VS Code 自定义编辑器](https://code.visualstudio.com/api/extension-guides/custom-editors) | 文档与多个视图分离，多视图编辑需要显式处理修改传播和撤销 | 把编辑会话独立列为边界，不能只做资源 ID 和布局状态 |
| [Foundry 场景](https://foundryvtt.com/article/scenes/) | 个人查看的场景与对全体生效的活动场景不同 | 查阅场景不改变当前跑团；查看角色不改变控制权或知情范围 |
| [Unity 工作区](https://docs.unity3d.com/Manual/CustomizingYourWorkspace.html) | 窗口停靠、最大化及保存布局服务于具体工作 | 漫画、视频可有不同默认布局，共享同一导航与资源引用 |
| [Krita 导航与工作区](https://docs.krita.org/en/user_manual/getting_started/navigation.html) | 画布与辅助面板分工，工作区可以保存 | 漫画以画布为主；人物参考、脚本、素材放旁边，避免把画布当普通表单 |
| [Premiere 工作区](https://helpx.adobe.com/in/premiere/desktop/get-started/tour-the-workspace/what-are-workspaces.html) | 面板布局围绕不同制作任务组织 | 视频围绕镜头列表、预览、版本和生成组织，不复刻尚未具备的完整剪辑器 |
| [Vue KeepAlive](https://vuejs.org/guide/built-ins/keep-alive.html) | 缓存组件有激活、停用与淘汰生命周期 | 只作为实现手段；不能承担保稿、任务恢复和任意移动保证 |

共同结论：统一的是资源、导航和工作连续性；具体创作工具保留适合自己的信息结构。增加一套拖拽布局不等于完成整合。

## 4. 整体界面和使用方式

### 4.1 一套外壳，按当前工作调整内容

- **首页**：继续承担作品展示、上次使用和最近资源入口。恢复位置失败时明确说明，不偷偷打开另一部作品。
- **顶部**：承担工作区标签、当前项目和全局导航，不在每个嵌入页面里重复一套。
- **左侧**：显示当前主要工作的资源目录。写作时保留现有卷／章、构思与关联资料结构；漫画时可切为篇章／页，视频时可切为分镜／镜头，跑团时显示会话／分支。返回写作恢复原章节目录。
- **中央**：承载当前主要内容，可有受控的分组。正文、来源、完整助手、漫画画布、视频预览、跑团记录均可成为主内容。
- **右侧**：承载对照阅读、人物／设定、助手和检查工具；合适的内容可展开到中央。宽度不够时提供展开，不强行压缩复杂画布。
- **底部**：只有漫画或视频等确有需要时显示序列／镜头区域，不给普通写作永久增加一栏。
- **浮窗**：继续用于导入、重命名、项目选择和短配置；需要长时间对照的来源原文、抽取审核与任务结果放入工作视图。

不要把“正文、助手、设定、资料”等全局导航再次塞进正文的章节列表；不要借宿主改造重新把完整设定页改成一堆文本框。大纲、角色、设定沿用现有连续编辑、目录和选中样式。

### 4.2 作者能理解的操作

常用操作为“打开”“在旁边打开”“移到主区”“固定”“关闭”“恢复默认布局”。第一次打开采用该内容的合理默认位置；明确选择过的位置可以记住。

“固定”表示这个视图继续展示当前资源，不被后续点击替换；不表示锁定内容、保存成功或授予修改权限。上下文面板则可以跟随当前章节，界面必须让作者分得清这两种行为。

右侧助手、推演、批注继续区分：助手处理多步任务；推演围绕当前正文和确认后的现场半自动推进；批注保持轻量、贴近选区。不能因为三者都调用 AI，就合并成一个通用聊天面板。

### 4.3 视觉和交互约束

采用现有主题、材质、选中态和图标体系，统一标题、工具按钮、留白和滚动边界。新宿主不增加一圈圈嵌套边框、重复标题和卡片容器。

所有弹出菜单按实际触发点、缩放和可视窗口定位；右栏窄宽、暗色模式、手机键盘弹起时仍可操作。内容滚动、自动跟随输出与窗口尺寸变化必须分开，不能因恢复布局把作者拉回底部。

## 5. 必须明确的五种状态

| 对象 | 身份和职责 | 不应承担的东西 |
|---|---|---|
| 资源 | 哪本书／哪个世界的哪一章、来源、漫画页、镜头或会话 | 不包含屏幕位置和临时焦点 |
| 编辑会话 | 未保存内容、修订、保存协调、修改传播和撤销边界 | 不因右侧移到中央而重建 |
| 视图实例 | 一次打开的窗口；选区、滚动、缩放、局部展开 | 不另存一份互不一致的正式内容 |
| 布局 | 分组、顺序、尺寸、激活项、固定和折叠 | 不存书稿、模型密钥、任务授权和生成结果正文 |
| 任务会话 | 发起目标、输入快照、权限、运行状态、结果与取消能力 | 不把“当前右栏”或“此刻 URL”当任务目标 |

同一来源的两个阅读视图可以有不同滚动位置。同一文稿若允许两处编辑，必须共享可协调的文档变更，并定义撤销行为；不能只让它们各自保存到同一个 Repository。

ProseMirror 的 EditorState 同时含文档、选区和插件状态，直接全量共享也会把视图间不应共享的状态绑在一起。具体实现需依据[官方状态模型](https://raw.githubusercontent.com/ProseMirror/website/master/markdown/guide/state.md)设计事务传播；在验证前保留现有受支持的双栏范围，新增重复编辑方式可先只读。

## 6. 最小接口约定

以下是拟定合同，不是声称仓库已经有这些 API。优先用现有服务适配，不先造一个全功能插件 SDK。

### 6.1 资源引用

统一引用需要表达：

- 资源类型与稳定 ID；子资源如章节、来源分块、漫画格、镜头也有稳定 ID。
- 明确的归属范围：作品、世界或跑团会话。不能假定 `bookId === worldbookId`，也不能要求独立跑团先创建小说。
- 必要的来源修订／内容指纹，以及定位信息。
- 显示标题可以更新，但标题、页序号和镜头排序不是资源身份。

项目身份复用现有项目连接关系，不新建一套覆盖各 store 的“全局项目数据库”。旧媒体存在作品 ID／世界书 ID 混用时，按已知关系解析；无法确认归属的记录提示关联，不能静默迁入当前作品。

### 6.2 内置视图注册

宿主只需知道视图类型、创建入口、资源参数、标题、允许位置、最小尺寸、重复打开策略，以及以下能力：

| 能力 | 语义 |
|---|---|
| 打开／定位 | 已存在时按固定与复用策略聚焦，或创建明确的新实例 |
| 聚焦 | 改变键盘操作对象，不修改既有任务的目标 |
| 移动 | 改变位置，保留编辑会话与任务，不触发离开清理 |
| 保存／恢复显示状态 | 仅轻量选区、滚动、缩放等；校验资源和修订是否仍适用 |
| 关闭前检查 | 返回允许、需保存、需作者决定或拒绝，并给出原因 |
| 关闭后释放 | 释放该视图订阅、DOM 和计时器；是否结束任务由任务策略决定 |

只读来源、正文编辑、助手先验证这套合同，漫画／视频／跑团用同一合同表达自身限制。不要为了统一命名把它们的业务服务搬进宿主。

### 6.3 编辑与任务适配

编辑能力通过现有正式写入入口提供：读取目标快照、提交修改、校验修订、保存、撤销和定位。助手不直接写任意 store；布局组件也不提供第二条写入旁路。

任务适配器提供任务摘要、归属、进度、打开结果及实际支持的操作。操作能力必须明确区分：取消请求、停止等待、恢复查询、重新生成、重试保存。统一展示不能把所有模块强制塞进一个新的生成执行器。

宿主可以汇总进行中任务，但不复制各领域的任务真源。无可靠进度时显示具体阶段，不制造百分比。

## 7. 保存、关闭、焦点与任务生命周期

### 7.1 布局操作要先检查，再提交

把现有离开流程分为检查／必要保存，以及确认离开后的清理。纯移动、放大、隐藏不执行放弃候选或取消任务。

关闭最后一个编辑视图、替换其资源、切换项目时，必须执行对应检查；后台标签也不能绕过。批量关闭先收集检查结果，再提交操作，不能关了一半才发现有保存失败。

异步保存或确认结束后，要重新确认目标视图与布局版本仍有效，避免迟到的“允许关闭”关掉新打开的内容。输入法组合期间，移动／关闭应延后或明确阻止，不能保存半个组合输入。

### 7.2 三种目标不能混用

1. 当前键盘焦点所在视图。
2. 下一次助手请求准备使用的目标。
3. 已经发出任务冻结的目标与授权。

例如中央修改第 8 章，右侧打开第 3 章证据：点击证据不应将第 8 章改稿任务指向第 3 章。下一次请求若切换目标，应在输入区清楚显示；已有任务保持原目标。

隐藏的编辑器不能继续响应全局撤销、删除和空格快捷键。选区、正文查找、批注及修改候选必须绑定具体编辑会话，不能再只依据 `main/dual` 判断所有情况。

### 7.3 任务行为

| 动作 | 默认行为 |
|---|---|
| 移动、隐藏、展开视图 | 已发出的任务不重发，不因位置变化而取消 |
| 关闭有任务的视图 | 有常驻任务所有者时允许后台继续且保留可见入口；否则提示取消或阻止关闭 |
| 切换作品 | 未完成归属隔离前沿用保护；实现后结果仍属于发起作品，授权不转移 |
| 明确停止 | 调用模块真实取消能力，并展示是否只是停止等待 |
| 刷新或重新打开 | 只恢复实际可恢复的任务；未知结果不自动重新提交付费生成 |

不先删除 busy guard。先让资料在同一常驻宿主内打开，再确认请求所有者不会被销毁；需要跨页面存活的部分才提取成任务会话。

## 8. 各模块整合方案

### 8.1 正文、设定与助手

正文保留原编辑器、章节目录、保存和撤销。角色、大纲、设定可作为关联内容或固定资源打开；完整编辑仍采用现有连续文稿形式，侧栏与中央共享业务内容，不复制整页导航。

助手侧栏与完整页订阅同一对话／任务会话，切换不重发请求。对话历史、新建对话、进行中任务是不同对象；“重新开始”新建空对话，历史仍可查阅。

正文修改继续在正文对应位置审阅；助手显示摘要和跳转入口。设置修改进入对应内容视图；结果提示可以有未查看标记，但标记不等于已经采用。自动修改只在作者已授权范围内执行，仍经过修订检查、持久化和撤销。

推演继续围绕当前文稿、插入位置和已确认现场。打开资料、人物或换视图不重新识别整个现场，也不把候选事实自动写进正式世界状态。

### 8.2 资料导入、阅读、检索与抽取

资料管理继续位于现有资料体系。导入采用原地浮窗，文件／粘贴队列属于明确作品；切换显示位置不重新读取文件。读取中关闭是否取消、保存中能否关闭，沿用并显式表达现有保护。

拆开四种内容：资料列表、来源原文、检索结果、抽取审核。列表用于管理，原文用于持续阅读，检索结果显示命中及证据，抽取审核再进入人物／设定／文风样本的采用流程。

现有本地检索包含词法匹配，不应称作已经接上外部向量数据库。RAG 是检索后提供上下文的流程，外部索引可以是后续适配；工作区整合不以引入外部数据库为前提。

需要同时修正来源定位合同：

- 原文显示目前有分块拼接、换行和 trim；检索读取的 `startOffset` 与档案使用的 `locator.start` 存在字段不一致。静态检查已确认此差异，实际错误范围还需定位用例验证。
- 命中携带来源 ID、修订／指纹、分块 ID 和来源自己的定位信息。共享分块不表示共享来源位置，不能只取该分块第一个归属。
- 写清坐标单位和文本规范化规则：JS UTF-16 偏移、Unicode 字符位置、PDF 页码不能混用。
- 来源变化时先核对修订；可按引文及上下文尝试重定位，失败就说明失效，不把旧偏移当成当前证据。
- 长文按分块或窗口阅读，避免一打开就在面板中拼接全部正文。PDF 页级定位仅在解析结果确实保存该信息时提供。

[W3C TextQuoteSelector](https://www.w3.org/TR/annotation-model/#text-quote-selector) 的引文及前后文可作为定位设计参考；借用思路不代表已实现完整标准。

文风和语料提取复用来源归档、任务与审核。提取结果保留依据、范围和版本，经采用后成为可引用样本；索引刷新不能覆盖作者正式设定。

### 8.3 跑团与联机

跑团的主资源是会话、分支与消息，世界书提供关联资料。默认布局以叙事记录和行动输入为主，旁边放角色、场景和资料；不得把跑团改成正文编辑器的一个模式。

区分“正在查看的场景／历史”和“正在推进的会话”。切到人物资料、查看另一分支、展开地图，都不自动切换活动会话或追加一轮剧情。

当前单会话运行机制先保留：一个活动会话可推进，其他会话可只读查看。后台自动推进默认不开始新一轮；已发出的单轮请求按明确会话归属处理。多会话同时生成属于另一个能力，不能由多标签暗中开启。

联机连接与视图挂载分离后，收起记录或打开资料才可以不离开房间。主动离开、房主权限丢失、断线恢复仍走现有流程。公共资料视图不能绕过房主权限或暴露角色未知信息。

跑团片段进入书稿时使用已有导入边界，记录会话／分支／消息引用并处理重复导入；不能把整个游戏状态直接覆盖正文或世界书。

### 8.4 漫画与插画

漫画以篇章、页和格作为导航，中央画布承载编辑，侧边放脚本、角色参考、素材和候选。点击正文来源可以在旁边打开，不离开当前页；返回画布保留格选择和缩放。

页、格、生成阶段和版本必须用稳定 ID 绑定。改页序、选中其他格或移动画布不会改变进行中的生成目标。旧修订结果返回时留作候选，不能直接覆盖新脚本或新选图。

保留已有请求去重、结果未知、保存失败重试和候选采用机制。“重试保存”不重新生图；刷新后无法确定生成结果时，明确显示未知并由作者选择后续操作。不要宣称浏览器侧记录实现了供应商端恰好执行一次。

文字编辑、拖动与脚本修改需要纳入统一关闭检查；画布卸载前的回调不能作为唯一保稿保障。导出使用明确的页／版本快照，进行中的新结果不应悄悄改变同一份导出。

插画复用现有素材和生成服务。插入正文、成为人物参考、用于漫画格或视频首帧，是不同采用动作；修改一份来源不能自动替换所有已采用素材。

### 8.5 分镜与视频

当前视频能力是分镜组织和镜头生成，工作区应围绕镜头列表、脚本、预览、版本和生成参数整合。没有相应媒体处理能力时，不做看起来能剪辑、拼接和导出整片的空壳时间轴。

每次生成固定作品、文稿／分镜版本、镜头 ID、输入指纹和输出版本。排序改变不改变镜头身份；旧版本片段可以查看或选择，但不冒充当前脚本的生成结果。

分开表现几种状态：提交中、生成中、停止查询、供应商已取消、结果未知、文件归档失败。按钮只提供渠道实际支持的能力。面板关闭后能否继续查询，由常驻任务适配器决定，不由组件是否可见决定。

本地 sessionStorage 的任务 ID 与服务端进程内记录都有局限：记录过期或服务重启时应解释任务不可查询，保留已知供应商引用和已归档素材，不自动重新生成。

视频链接可能过期。正式素材归档继续走已有下载与媒体存储流程；只有实际保存成功才显示已归档。重新下载与重新生成是不同操作。

### 8.6 其他页面

构思、地图、关系图、历史、文档与备份保留原领域所有者。适合嵌入的内容接资源引用和视图合同；地图、复杂关系图优先中央展开，右栏只做合适的预览。

应用偏好继续使用共享设置弹窗。大量备份冲突处理、资源整理可以展开为工作页，不强行堆叠多层模态。未迁移页面继续走旧路由，不要求一次性重写全部页面。

## 9. 跨模块使用链

| 使用链 | 应发生的事 | 不应发生的事 |
|---|---|---|
| 正文 → 查资料 → 助手改稿 | 打开证据，任务仍针对指定文稿，修改在正文审阅 | 焦点转到资料后把资料当改稿目标 |
| 小说场景 → 漫画 | 选定来源片段，建立有修订的改编引用，审核脚本后生成 | 每次打开画布重新调用模型 |
| 漫画／插画 → 视频 | 明确选择图像与镜头版本作为输入 | 素材变化后自动重生成所有镜头 |
| 跑团 → 书稿 | 选择片段，经导入确认形成文稿内容并保留出处 | 切换会话就改写小说或正式世界状态 |
| 来源更新 → 既有产物 | 标记所依据版本已变化，允许查看差异与主动更新 | 静默覆盖已经采用的设定、图片或视频 |

统一提供“查看来源”和“在旁边打开”。跨模块引用不等于建立自动执行链，付费生成和正式修改仍按实际授权触发。

## 10. URL、布局恢复与平台适配

旧地址继续由适配层转换为打开／定位资源的工作区操作。工作区管理布局，URL 表达可分享的活动资源；不要让路由和布局各自维护一套互相覆盖的激活状态。

明确用户导航与纯布局操作的历史语义：主动打开另一资源可进入浏览历史；拖动、调整宽度、滚动不制造历史条目。前进／后退涉及离开资源时仍走保护。

布局数据版本化、校验并允许重置。未知视图或已删除资源显示可关闭的占位；重置只影响位置，不删除书稿、来源、候选、任务记录或权限配置。恢复轻量选区时检查文稿版本，无法精确恢复则回到安全阅读位置。

手机使用相同资源与任务合同，但默认单个主要内容区；通过切换、抽屉或全屏查看资料／助手。桌面和手机布局分开保存，不把三列缩成三条窄缝。切换断点不能复制任务或编辑会话。

公网浏览器、本地服务和桌面文件能力仍由现有平台适配边界提供；可移动视图不意味着网页获得任意磁盘访问能力。

## 11. 性能、扩展与布局实现选择

### 不把所有视图永久挂载

运行任务与显示组件分开后，非活动重型视图可以按策略暂停渲染或释放。编辑会话必须先安全保存／保留，再允许回收；不能依靠 KeepAlive 缓存永远不被淘汰。

检查隐藏后的监听器、轮询、媒体播放、ResizeObserver 和键盘事件。反复移动和打开关闭不得累积订阅。资料大文件、漫画画布和视频预览分别设定懒加载与资源释放策略。

### 布局库取舍

现有 Vue 外壳和双栏可以支持初始的分组、宽度调整与按钮移动。如果确实需要成熟的跨组拖拽，再用真实编辑器比较 Dockview 与现有方案。

[Dockview 渲染策略](https://dockview.dev/docs/core/panels/rendering/)区分仅可见时挂载与持续保留 DOM，涉及滚动、尺寸观察和媒体行为；不能只看示例拖动顺滑就选型。[许可说明](https://dockview.dev/docs/overview/licence/)也区分开源核心与部分高级能力，应按实际需求核对。

选型必须检查输入法、撤销、隐藏任务、菜单定位、手机退化和无障碍操作。未完成这些验证前，不在 issue 中锁死依赖，不以更换框架解决生命周期问题。

### 内置扩展先行

本轮注册可信的内置内容视图。Skill、Tool、工作区视图与可执行第三方插件分别处理；注册视图不自动获得全部书稿权限。

暂不建设插件市场、任意远程 JavaScript、微前端、跨窗口进程通信或新的通用数据库。也不顺带要求统一重写所有模型执行链、实现多人正文协同或完整视频剪辑引擎。

## 13. 验收条件

以下是整份计划的验收目标。部分查阅与布局场景已在本地基础实现中验证；完整证据和未覆盖范围见实施记录，工程构建通过不能代替实际交互验收。

| 场景 | 预期结果 |
|---|---|
| 正文未保存时打开资料 | 不卸载编辑会话，原选区与滚动可继续；没有第二套全局导航 |
| 来源从右侧移到中央再移回 | 阅读位置保留，不重导入，不重发模型请求 |
| 保留写作目录后切换漫画再返回 | 漫画显示页结构，返回恢复原卷／章结构和选择 |
| 同一来源多视图 | 可以独立滚动，内容与修订保持同一真源 |
| 同一章受支持的双编辑 | 交替输入、保存、撤销不会用旧稿覆盖新稿；明确撤销范围 |
| 真机中文输入组合中移动或关闭 | 不截断文字、不保存半个输入；延后／阻止行为清楚 |
| 保存失败后关闭活动或后台编辑标签 | 均保留内容，提供重试，不绕过保护 |
| 批量关闭中有一项被拒绝 | 不发生不可解释的半关闭和候选丢失 |
| 保存等待期间再次切换资源 | 迟到检查不会关闭或覆盖新目标 |
| 第 8 章改稿时查看第 3 章证据 | 提案、授权和写入仍属于第 8 章 |
| 修改请求发出后正文变化 | 采用阶段识别过期，允许查看结果，不静默覆盖新稿 |
| 助手展开、收起、移位、打开资料 | 同一会话和请求连续；记录可滚动，阅读位置不被抢走 |
| 切书后旧任务返回 | 结果留在原作品，不能污染新对话、正文或设定 |
| 重开助手或刷新 | 只恢复真实可恢复的任务；新对话与历史区分，未知请求不重发 |
| 来源修订变化、重复分块、中文和 emoji 定位 | 显示正确来源与文本；无法定位明确失效 |
| 大文件原文与导入浮窗切换 | 不反复整文件解析，不串书，保存／关闭状态清楚 |
| 跑团查看历史或另一场景 | 不改变活动会话、角色控制权，不新增剧情轮次 |
| 联机中隐藏会话视图 | 在支持常驻连接的实现中不离房；角色权限、断线和房主转移仍有效 |
| 跑团片段重复导入 | 可识别来源与重复，不复制整套会话状态进书稿 |
| 漫画生成时换页、重排格、改脚本 | 结果绑定原稳定目标，过期结果只作为候选 |
| 漫画结果未知、素材保存失败 | 不自动二次付费生成；保存重试不等于重新生成 |
| 视频生成时关面板再打开 | 能恢复则恢复查询，不能恢复则说明；不自动重复提交 |
| 视频停止等待、服务重启、任务过期 | 如实区分状态，不宣称供应商已取消或任务必可恢复 |
| 镜头重排、脚本更新、旧片段选择 | 稳定 ID 正确，旧版本标识明确，归档与链接状态不混淆 |
| 来源到漫画到视频的连续操作 | 可回到出处，已采用内容不因上游修改自动覆盖 |
| 旧书签、前进后退、失效资源、损坏布局 | 正确定位或给出占位；重置布局不删除正式数据 |
| 手机、200% 缩放、暗色模式、键盘与触控 | 核心操作可达，无需拖拽；菜单、焦点和输入法不遮挡关键内容 |
| 反复打开、隐藏、移动和关闭 | 没有重复订阅、请求、快捷键响应或持续增长的编辑器实例 |

视觉验收按小范围实际页面进行：先确认正文＋来源＋助手的默认布局，再确认漫画、视频、跑团的工作布局。记录截图结论并及时清理临时截图，不用全面重画后的成品迫使作者接受方向。

## 14. 需要实施时确认的决定

方向已明确：保留首页和写作目录；一套宿主；资料与助手可并排；媒体和跑团保留专用工作方式；旧路由兼容；正式写入、权限与撤销不绕开。

以下决定需用现有实现和原型证据收敛：

- 多编辑视图的撤销是按编辑会话还是按来源视图区分，哪些重复编辑先限制为只读。
- 现有 Vue 宿主是否足够，或是否采用 Dockview；不能先选库再修改产品需求适配它。
- 哪些任务能可靠脱离视图继续，哪些仍需关闭保护；跨项目并行暂不默认开放。
- 历史媒体归属不明确时的关联方式，以及旧来源定位信息不足时的兼容策略。

这些选择不得阻止先打通“写作中查资料，查看证据后回到原段落，由助手完成指定任务，再在原位置处理修改”的核心过程。
