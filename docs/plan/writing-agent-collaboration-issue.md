希望结合 NovelPedia 和 Storyflow 的经验，完善 Pinax 现有的资料导入和 Agent 工作流。具体背景、代码入口和接入方向见附带说明。

## 1. 资料导入

目前已有浏览器端文件解析、章节识别、来源归档和分块，支持将资料提取为世界书条目。但世界书 AI 提取仍是单次请求，只使用传入文本的前 12,000 个字符，并允许模型在信息不足时补全，尚不适合完整、忠实地处理长篇资料。

希望改善：

- 分块分析与跨章节汇总，整理实体、别名、关系等，保留原文依据。
- 区分资料提取和创作补全，让覆盖范围、失败部分和不确定结果可见。
- 接好重试、来源更新和结果复用，避免反复处理全文。
- 扩展语料/文风分析，使结果可用于后续审稿和改写。

Utopia 本身已有摄取与提取机制，Pinax 也已借鉴其记忆和事实处理方案。这次重点完善导入链，分析结果接入现有设定与事实流程，记忆系统不另立重构任务。

## 2. Agent 工作流

目前资料问答主要是预先整理上下文后请求一次模型；推演已有按需 `history_lookup`，每步最多一次；审稿和改写已有方法、定位、补丁及撤销能力。

希望在这些基础上完善按任务查阅、补查、检查和改稿的连续流程，并衔接任务状态、取消及恢复。交互上保留自动助手、半自动推演、轻量批注三种方式，共享能力但保持各自节奏。作者明确授权后可在指定范围内自动改稿，接回现有采用和撤销流程。

产品方向、接入接口和前端由我这边负责。希望你继续完善资料处理、文件操作、RAG 和 Agent 工作流，内部实现可以自行设计；接口如有建议先一起讨论。可以分 PR 向 Pinax 的 `main` 提交，我来审查合并。首批优先考虑长篇资料导入，以及助手如何查阅和使用导入结果。
