## 1. 结论与范围

UI/UX 与有趣性是并列目标：日常写作要顺手、耐看、可持续；需要灵感时，作者能轻松试探人物和情节，看到自己的选择带来不同后果。先修工作台与高频交互，再完成一个有吸引力的试演闭环，最后扩展连锁影响。

当前具备目录、角色、设定、大纲、双栏、资料助手、历史、方向规划、可编辑草稿和撤销事务。主要短板集中在信息重复、阅读空间、移动覆盖层、相近入口的不同语义，以及看到故事反馈之前的操作负担。不能再以功能数量或自动化通过代替体验判断。

调研轮仅修改计划与交接文档，后续实施回执见第 8 节。实施阶段保留主题2（内部 `legacy`）的蓝白档案语言、已确认的 420–440 CSS px 右栏与目录比例、正式数据所有权、显式采纳和恢复机制。主题1、地图扩建、多窗底座、联机扩面与多模态扩功能不列为本轮前置。

## 4. 设计硬约束与参考合同

1. 正文为持续写作的主工作面；工具的价值是帮助当前任务。先处理位置、字号、密度和操作顺序，再考虑装饰与动效。
2. 同一状态和同一主动作各有一个主要展示位置；允许快捷入口，但名称、目标对象与作用范围一致。
3. 桌面右侧资料工作面保持已确认外宽与目录比例；目录收起是已有阅读方式。覆盖态不得挤压底层正文；桌面固定栏允许重排，但必须保住语义落笔位置。
4. 角色/设定继续读写绑定世界书的同一条目；角色字段直接编辑与自动保存不改为提交表单。常用查阅优先，高级 AI 配置按需出现。
5. 同级目录、标题、字段、按钮共用现有排版标尺；小屏按任务重编排。暗色、键盘与 reduced-motion 随每片检查，不留到最后补。
6. 作者可自行写、改意图、编辑生成稿、放弃和撤销；不得因使用推演被迫走多轮规划或采用模型结论。
7. 生成、采用、保存与正式事实分别表达。内部 fingerprint、manifest、原子事务留在诊断；来源失效、未保存等作者需要处理的状态保留。
8. 一个代表性区域先出前后截图，用户确认后扩展；自动化、视觉与真实文本体验分别记录结论。

参考交互合同：章节/大纲/角色/设定从现有目录快速切换；详情连续编辑；双栏章节与便签保留真实可编辑状态；目录收放不丢选择；打开临时工具记录活动主/副稿，关闭回到该稿的光标、选区和滚动位置；保存和撤销继续归原编辑 owner。移动端沿用已有 sheet/副稿能力，目录与详情的呈现候选需单独截图确认。Windows 独立新窗口能力不做失效入口。

## 5. 实施切片与顺序

主依赖为 A0 → A1 → A2 核心片 → A3 → A4 → A5。A2 的低风险后续完善不阻塞 A4 样板验证，具体交付次序见第 11 节；不等待所有 UI 细枝末节结束才接触趣味性，也不跳过内容层级就扩展玩法。每片交付可复验结果再进入下一片，不进行整页重写。

### A0：补齐真实写作旅程基线（G1.5 / F2）

- 用现有五章 fixture、无世界书纯文本、长角色/长目录三类资料，完成“打开稿件→写几句→查角色/设定→切章/双栏→回原稿”，以及“选区批注→改写→采用→撤销”“查找→跨章定位→返回”“历史恢复预览→取消”。
- 记录一次任务的入口、点击数、等待、活动文档/选区/滚动、困惑点；截图之外做连续操作。生成链先用明确标注的 deterministic mock 检验状态，不把 mock 文本当质量证据。
- 输出最多十个按阻碍程度排序的问题，每项绑定复现条件、截图、文件 owner 和验收；将本次 UX-01～10 校准为确认/推断/未复现。
- 验收：三条高频旅程可复现，区分实测失败与产品改进建议；已有通过项不重复立为待开发功能。

### A1：稿面与覆盖层稳定（G1.5 / F2，首个实现片）

- 先修 UX-01：390 角色和双栏覆盖层不改变底层稿面宽度；关闭恢复原文位置。再复核 640/720/759/980/1180 邻近状态，确认当前 CSS 与 JS 断点的职责，不机械统一所有断点。
- 桌面核对右栏打开的 caret/选区锚点；双栏试用现有目录收放，改善按钮语义与会话状态保持，以 440px 外宽内更舒适地读稿。是否改默认展开仅作视觉候选，不先写死。
- Owner：`Authoring.vue`、`Authoring.block-native.css`、`AuthoringDualPane.vue`、`AuthoringWorkspaceToolRail.vue`；只在复现定位需要时触及 Notebook 几何。
- 验收：覆盖层前后底稿宽度差 ≤1 CSS px；关闭选区与活动文档不变，滚动误差 ≤2px（无编辑时）；固定栏重排保持同一语义落笔锚点可见。正文、目录、sheet 与软键盘不争夺滚动。
- 交付：1440 双栏目录开/关、390 角色开/关前后对照。先确认这一片再扩面。

### A2：日常工具的层级与密度（G1.3 / G1.5 / F2）

- 分三小片顺序做：角色/设定/大纲目录与空字段；当前场简要索引与右侧详情的信息归属；助手、查找、校对、历史的任务反馈与返回。
- 保留现有目录搜索、真实文件夹、直接编辑、自动保存和目录收放；高频内容优先，触发词/注入配置降为按需展开。长名称能查明完整对象，移动不能依赖 hover。
- 空白态提供直接开始写的明确入口与现有导入路径，世界书配置为可选；不额外建立一套 onboarding 项目真源。
- Owner：各 `Authoring*Panel`、`AuthoringKnowledgeAssistant`、`AuthoringSceneRail` 与页面接线；统一标尺用现有 token，不新增主题或组件框架。
- 验收：同一当前场不再左右完整重复；关工具回到原编辑面；选区批注、跨章查找与历史取消可继续写；空/短/长内容均有可解释密度。每小片各给桌面、390 前后截图。

### A3：统一推演入口与可读结果（G1.3 / G1.5 / F1）

- 正文接续处作为主要入口；左侧人物、地点、事件入口带上具体意图进入同一工作面。首要输入为“接下来想怎样”，支持“直接写成草稿”和“先试方向”，作者选定路径后只突出一个主动作。
- 用当前已授权人物/事件提供具体起点；没有依据时保留自由输入和补充来源入口。类型/说话人仅在必要时展开，旧快路径仍能直接生成。
- 生成反馈说明当前可理解的阶段，失败原位重试；Ghost 以可编辑正文为中心，边界/单元预览按需展开，复用现有整体采用、编辑与撤销。
- Owner：`Authoring.vue`、`AuthoringBlockComposer`、`AuthoringSceneLaboratory`、`AuthoringBlockDraft`。统一的是可见旅程，不额外复制 session、provider 或采纳链。
- 验收：相同意图从不同入口进入后目标一致；直接写不增加必经规划请求；方向路径能返回修改意图；取消/迟到/失效零正式写入；作者能看懂草稿是否已保存。

### A4：人物与情节试演样板（G4.6 / F1）

- 先做一段“撒谎 / 坦白”真实场景：作者改变一个人物选择，看到两至三个行动方向，各有具体人物反应、眼前所得与代价；选中后可改一句自己的要求再展开正文。
- 短反应先作为现有方向结果的表现原型；若需要新输出字段，先更新方向合同、预算和校验，再接 UI。不得为每条方向默认生成完整正文，也不将预览当作已发生事实。
- 修改意图创建新的受控请求/方向快照并重新检查依据，禁止直接篡改已冻结方向 fingerprint。方向组合与平行长分支留到此样板验证之后。
- 用三类小样本：关系压力（撒谎）、物理条件（钥匙烧毁/藏起）、无世界书的普通稿件。每类比较旧路径与新样板各一份，首轮共六份即可；记录模型、耗时、失败与原文依据。
- 作者按 1–5 分评价“人物可信、走向有差异、我的想法能介入、愿意继续试”。建议推进标准：至少两类样本达到后三项各 ≥4，且无明显违背原文事实；低分先改样板，不扩功能。小样本仅服务产品取舍，不宣称统计结论。
- 验收：至少一次作者改意图后得到可解释的不同反应；等待没有新增必经模型轮次；采用与放弃均能自然返回写作。

### A5：普通稿件可用的条件试探（G4.6 / F3，后续）

- 先覆盖无显式因果关系的情况：明确当前证据边界，提供仅针对当前段的受控试写或继续补充关系的路径，不把“未找到确定影响”作为整项功能的尽头。
- 后续才评估至多三条带精确原文位置、引用和理由的“待确认影响建议”；与确定影响分开展示，作者确认只授权本次试验，不自动新增永久因果边。
- 这是 F3 合同增量，必须先定义候选转为可改目标的授权、source revision 与 scope fingerprint。当前候选只有排除/保留不改，不得仅增加一个按钮绕过它。
- 批量保留/排除可减少重复点击，但仍保留查看依据、修改决定和最终范围确认。结果复用现有分组 Ghost、跨章定位与采用/撤销 owner。
- 验收：有关系、无关系、候选被排除、资料变化四类旅程均可解释；任何未确认推测都不写成世界事实，实际改动范围与作者选择一致。

## 9. 二轮目标体验与统一设计合同

### 9.1 产品目标：一个安静的稿面，一个可以试故事的地方

默认状态先让作者继续写。资料、批注、推演均围绕当前书、章和落笔处展开，不要求在功能页间反复搬运上下文。作者遇到犹豫时，可以提出一个想法，试出不同的具体后果，再决定是否改稿；离开试演时原稿和位置都在。

**优先解决的不是功能数量，而是四种体验断点：**

1. 看内容之前要先扫描标题、状态、图标、配置和统计；双栏章名被挤压是已收到的直接反馈。
2. 查资料/改资料/让资料参与本次推演没有稳定的信息层级，当前场和助手尤其明显。
3. “直接生成”和“先试方向”不在同一条可发现旅程，作者意图又难以在方向上继续修改。
4. 没有结构化世界书或显式因果关系的普通稿件，不能自然体验有趣的条件试探。

### 9.2 信息应出现在哪里

| 信息/任务 | 主要位置 | 常态展示 | 按需出现 / 禁止重复 |
| --- | --- | --- | --- |
| 当前作品 | 作品页签 | 书名 | 项目级操作进入页签菜单，不在每个工具内重复书名卡头 |
| 当前章/对象名 | 主稿标题、当前资料详情标题、副稿标题 | 名称优先、正常名称完整，长名可换行 | 保存正常不与名称争空间；严重错误不能隐藏在菜单 |
| 章节/便签/大纲/资料检索 | 左目录或对应副工作台目录 | 文件式索引、搜索、选中对象 | 类型/字数只在真正有价值处出现；不是每项加摘要和标签 |
| 当前场摘要 | 左侧当前场 | 当前时间、关键人物/地点、未决事的轻索引 | 右侧不重复整套四行；没有资料不显示伪造状态 |
| 当前场详细判断 | 右侧现场 | 对象用途、待安排意图、可定位依据/本章故事线 | “改变既有事实”与“仅本次试演”不能用同一个含糊勾选框 |
| 试演意图/方向/稿件 | 目标正文单元之后 | 一句作者意图、当前阶段、当前主动作 | 来源详情、结构拆分、诊断按需展开；不另开推演主路由 |
| 采用后反馈 | 刚采用的正文边缘 | 一条成功/待保存提示，必要时列真实现场变化 | 不以单元计数、协议名取代作者关心的结果 |
| 历史/比较 | 历史工作面或既有副阅读面 | 版本身份、原因、可阅读的内容差异 | 预览不改稿；版本不是新的正文章节 |

### 9.3 八条视觉硬约束

1. 名称与可阅读正文优先于保存状态、类型、计数和操作。副窗标题当前双行方案先验收，不推广成所有工具都增加一行工具条。
2. 既有440px级副工作面及约62/38分配保留；通过收放与任务重编排改善可读性，不擅自加宽所有右栏。
3. 正文、资料内容和生成稿保持连续开放的阅读面；方向比较/风险审阅才使用有限边界，不把每段装成卡片。
4. 排版从当前 catalog/title/body/control/meta token 取值；13–14px级索引/操作、14–16px级资料阅读作为原型检查起点，正文仍尊重作者排版设置。重要内容不靠9–11px微字承载，不全仓盲目统一字号。
5. 桌面支持内容优先的紧凑目录，手机按“目录→详情→返回”组织任务；不把桌面双列缩成两个小滚动区。触控目标遵守现有44px门禁，不靠缩小点击区减轻视觉重量。
6. 同一任务只有一个明显主动作；图标保留文字可访问名称、键盘焦点、触屏可发现路径。常用动作不只靠 hover，危险动作不与采用并列强调。
7. 使用现有浅蓝白、墨蓝与低面积来源/风险信号；颜色不能独立表达已采用/未采用/失败。不新增主题、字体框架、大图背景、常驻动画或游戏HUD。
8. 打字、选择、滚动、开关工具期间稿面位置稳定；动效只解释真实展开/采用位置，reduced-motion关闭位移动画。暗色不依赖降低文字对比来制造“安静”。

### 9.4 一条完整试演旅程

```text
继续写正文
  └─ 在落笔处输入“我想让她隐瞒发现，但别显得突然不信任他”
       ├─ 直接试写 → 一份可编辑试稿
       └─ 先看走向 → 2–3种具体行动/反应/所得/代价
                       └─ 选一项，补一句自己的要求 → 一份可编辑试稿
                              ├─ 改稿后采用 → 正文保存 → 继续写 / 撤销
                              ├─ 保留为构思 → 原稿不变
                              └─ 改意图再试 / 放弃 → 原稿与位置不变

改变已经写下的条件
  └─ 输入变化 → 查看有依据的后文影响
       ├─ 有明确影响 → 选择范围 → 修改稿逐处审阅 → 采用/撤销
       └─ 无明确影响 → 仅试写当前目标（显式转入局部重写）
```

这里的“试稿”只是用户语言候选，底层仍沿用 Ghost/session/adoption；不把整个系统改名。“推演下一段/推演本场/普通推演/按此推演”的统一文案在 A3 代表图和找入口任务后冻结，不在文档阶段作全局重命名。

- **结果**：先回答、再按需依据；保留自由建议/作品事实、过期来源、缺失信息和错误的区别。长回答保留阅读位置，生成完成不强制滚到底。
- **Owner**：KnowledgeAssistant；查询session与AuthoringEvidenceEnvelope不重建。
- **验收**：查一条设定、问全书、自由建议、查看依据返回、失败重试、停止六态；无额外默认provider请求、无跨书资料。390键盘下输入和停止可见。

### A2-5：搜索、校对、批注与历史的“先看后改”（P1 / M–L）

- **搜索**：范围和搜索词同层；结果以章节名、命中上下文和定位为主。保留跨章“回到原处”；替换前说明当前章/全书及数量，取消不改稿。
- **校对/批注**：原文、建议、理由清楚分层；只突出当前处理动作，批量数量与采用边界就近显示。采用后能确认改了哪里，忽略不等于删除原文；编辑过程中结果过期必须重新核对。
- **历史新增体验**：先补前三条之外的“查看更早”，再提供只读版本预览；第二小片才加前后比较。恢复仍先建恢复前保护点，不能以预览owner直接写存储。
- **比较布局**：桌面复用现有阅读/副窗能力；手机原稿/旧稿顺序或切换阅读，不塞两个窄列。比较算法采用现有文档/文本能力，长章节先量性能；不为了diff引入另一编辑模型。
- **Owner**：ReviewPanel、SearchPanel、页面history部分、writingSnapshots与原Notebook恢复入口。
- **验收**：预览/取消正文hash不变；恢复只改目标章且旧AI结果失效；同章副窗未保存时不覆盖。小批/大批校对与替换各有失败、取消、stale路径。

### A2-6：排版、键盘、空态与跨页返回（P2 / M，可穿插后续）

- 审计现有专注、段落聚焦、打字机、排版持久化入口及实际效果，不重复开发；查找、拖选和改稿期间不能被自动滚动抢位置。快捷键先列已有清单并提示可发现位置，不默认做新命令系统或Vim模式。
- 默认0.85缩放与1档位均检查正文/工具字体，重要操作不能缩成难辨小字；浏览器200%用有效视口测试并补真人原生缩放，不把应用zoom白名单绕过当产品支持。
- 空项目、空章、无绑定、无结果、无网络分别给一个合理下一步。直接写与导入是可选路径，不强迫先完善设定或跑AI。
- 从Authoring打开完整设定/素材/地图保留项目、来源与返回锚点；只补经复现的返回断点，不搬完整地图/画布进侧栏。旧Experience退役另需书面批准。
- **Owner/验收**：TypographyStore、Notebook、工具栏、现有导航接线；20分钟写/查/改连续试用，记录位置修复和意外模式切换。纯写作路径零模型请求。

### A3-1：统一可发现的试演入口（P1 / M，依赖A1-R与A2-3）

- **首屏结构**：先看落笔位置及一句作者意图；默认直接试写，一个明确生成动作；“先看几种走向”作为可见的另一条路径，不强制先做方向规划。
- **来源入口**：从人物、地点、事件进入同一工作面，预填具体意图与生效范围；不会点击人物就静默生成。改写当前目标保留原文对照，不与续写目标混淆。
- **渐进设置**：行动/对白/内心/转场、说话人、导演注按必要程度出现，切换后保留作者文字；作者知道自己在续写、重写还是影响后文。
- **无现场**：允许自由试写；起点缺依据时标为通用写作建议，不虚构“我已了解你的角色”。有选区时将它作为受控来源，不扫全书假装理解。
- **Owner**：BlockComposer、SceneLaboratory、页面entry handlers；先做展现/入口适配，不合并底层session实现。
- **验收**：从正文进入可在两次明确动作内启动直接试写（不含输入及首次provider配置），不新增必经模型轮次；不同入口的目标和权限一致；切换路径不丢输入。

### A3-2：等待、失败和取消的可理解反馈（P1 / M）

- 用“整理参考/试几种走向/写成试稿/保存修改”等作者语言替代冻结现场、启动正文模型等术语；这不是把真实阶段合成伪百分比。
- 生成中保留意图摘要与停止，允许继续查看依据；运行期间编辑意图要明确取消/创建新请求，不能悄悄改变冻结输入。
- 错误发生在原任务位置；区分未生成、生成失败、草稿已保留但目标变化、已采用尚未保存。重试保存不得重跑模型，方向失败不得丢掉原稿。
- **Owner**：BlockComposer、SceneLaboratory、TransientNotice与原状态owner。
- **验收**：loading/error/retry/cancel/late/stale/persist-failure矩阵；没有假进度、迟到落盘、重复采用或请求风暴。记录实际耗时，不承诺不受控provider的秒级完成。

### A3-3：草稿阅读与采用主次（P1 / M）

- 生成结果先是一份可读、可改稿件；顶部一条“尚未写入正文”即可。单元预览、段落边界、字符统计进入“调整结构”，高级能力保留，不要求普通作者学习writingUnit。
- 默认一项明确采用动作；放弃、恢复生成稿、结构调整次级。跨段重写与局部改字不得用同一句“采用”隐藏实际范围。
- 采用后反馈说明“已加入正文/已替换此处”；有真实现场/大纲变化才附一行可展开变化。保存失败保持明显且可重试，撤销沿原事务，不加独立undo栈。
- **Owner**：BlockDraft、AdoptionImpact、InterventionGhost及现有adoption owner。
- **验收**：长稿阅读、手改草稿、拆分边界、采用、保存失败、一次撤销/重做、仅取消各有用例；收起结构不改变最终单元边界或派生效果。

### A4-1：把“方向表”做成可信的故事选择（P1 / M，趣味性首个样板）

- **样板情境**：莉娜发现总册被动过。作者想让她隐瞒，但保持她与艾德加原有关系的可信度。所有具体场景材料来自fixture或作者明确提供；下面内容是设计示意，不是本轮模型成果。
- **呈现候选**：①借整理账册支开他，保住秘密但失去当场求证机会；②只展示装订线的异常，得到帮助但让出部分判断权；③说出一个错误编号试探他，获得反应但可能暴露怀疑。区别来自行动/信息分配/代价，不是同一行为的三种语气。
- **第一小片**：利用既有action/gain/cost改善短标题和具体程度，少解释、多可观察动作。最多2–3项，比较整项后突出选中项；其他方向可重新看，不生成三个长篇占满稿面。
- **第二小片条件**：真实样本仍觉得抽象时，才加入1–2句有来源边界的短反应；先定字段长度/总预算、来源ref、假设标记、parser与降级，不能前端补写不存在的对白。
- **Owner**：SceneLaboratory、SceneDirectionSet、SceneDirectionPlanner及已有provider结构化合同。
- **验收**：三项不能仅换措辞；事实/假设可辨认；缺依据宁可指出不确定。样板让作者能解释每项为何不同，而不是仅读懂“所得/代价”标签。

### A4-2：作者能改方向，而不只是选答案（P1 / M，依赖A4-1）

- 选中方向后提供一句“我还想改……”或“按这个方向，但……”输入；可以要求不让某人入场、保留秘密、改变目的，原意图与补充要求可回看。
- 小改也不直接修改已冻结direction对象。以原方向引用+作者新要求创建新受控意图/请求，重新核对target revision和授权资料；更换角色/事实视为新试验，不能沿用旧结果的采用许可。
- 新结果显示作者要求如何影响行动，若冲突说明冲突而非忽略；保留旧试稿直到作者选择替换/保留。首轮只支持一条补充要求，不做复杂可视化方向拼接。
- **Owner**：SceneLaboratory、SceneLaboratoryRun、RunSession/intent接缝；新增字段遵守共享任务目录。
- **验收**：作者改一句后有可解释的不同结果；取消新请求保留旧稿；来源变更时禁止旧许可写回。确认路径不暗中多跑第二组方向。

### A4-3：保留另一种尝试与轻量比较（P2 / M–L，样板有价值后）

- 显式“留作构思”复用现有exploration document和推演夹，保留来源位置、原意图、创建时间及正文；作者可改名、编辑、删除。没有操作不自动给每次生成建档。
- 先支持当前稿与一份保留试稿比较；需要时用已有双栏/阅读能力展示，手机按顺序切换。不同时维护无限分支树，不伪装成另一个已发生世界。
- 从构思再次试写必须重新读取来源和生成新的session，不能恢复旧fingerprint为可采用状态；没有旧来源也能读稿，但明确不能直接原位采用。
- **Owner**：IdeaShelf、现有exploration repository、DualPane与来源ref合同。先核实可表达字段，不擅自新增与桌面P3冲突的localStorage真源。
- **验收**：保留/取消/重新打开/来源删除/同名/容量失败可解释；不改原章，未采用假设不进入正式世界事实。

### A4-4：从关系变化和线索兑现中增加趣味（P2 / M，后验探索）

- 本章故事线先改善阅读：显示可辨认的节拍名称、未决问题及其来源，点击回原文；不默认铺满重复摘要、微字号分类和“改变这里”。
- 用已有明确关系提供低频、按作者请求出现的起点，如“这条线索现在兑现会怎样”“从艾德加的视角试这一段”；无依据只做自由建议，不生成虚假的关系分数或承诺事件。
- 人物试探、换视角、线索提前兑现复用 A3/A4 意图和结果面，不分别做新页面。首轮只选**一个**最有价值的起点扩展，其他留候选。
- **Owner**：LivingStoryProjection、SceneRail、相关意图和权限适配；地图/完整图谱/多代理角色引擎不作为依赖。
- **验收**：作者能从一个已有故事要素进入试演并返回；实际作用范围明确，来源定位正确，无词法提及自动升级因果。

### A5-1：无确定影响时仍可局部试写（P1 / M）

- 将“未发现确定影响”表达为“没有足够依据判断后文，不代表变化不会影响故事”；保留作者输入及目标。
- 提供显式“只试写这里”：转入已有局部rewrite任务，传递条件变化作为作者要求，说明不改后文。若目标是单node而既有rewrite以unit为单位，先展示实际原文范围并确认，不把unit重写伪装成精确一句改写。
- 原F3 session不被标为范围审阅已通过，也不创建假impactGroup；当前段试稿采用仍走既有重写和快照保护。
- **Owner**：InterventionComposer、页面rewrite adapter、BlockComposer；优先复用，不放宽RehearsalScope guard。
- **验收**：无世界书/零显式关系也可完成“变化→局部试稿→采用/放弃”；后文hash不变，转回原F3仍保留输入。可在A3-3后提前交付，不等待A5-2。

### A5-2：带证据的待确认影响建议（P2 / L，必须先定合同）

- 针对普通长稿，在作者主动请求时给最多三条可能受影响的位置：精确引用、章节/段位置、为什么可能关联、是否为推测；与确定影响分区，不把模型语气当置信度数值。
- 复用F2检索与evidence envelope，先按目标范围与时间截止查证，不复制全书检索器，不把未来未知情节默认传给当前续写。
- 合同需新增明确的“本次授权改写此候选”决策；现有keep＝保留不改，不能换标签偷渡为采用。冻结目标revision、引用、作者决定、范围fingerprint并记录如何撤销。
- 批量排除/保留减少审阅点击，但修改范围必须可逐处检查；确认只授权本次，不写永久因果边。
- **Owner**：InterventionSession/Rehearsal/Adoption、CausalSandbox、F2 evidence接缝与组件。
- **验收**：假相关、相似措辞、同名角色、引用过期、候选全排除、跨章冲突矩阵；未授权目标零写入。若真实样本错误多，停止扩展，保留A5-1局部能力。

### A5-3：多处修改的可读比较与安全返回（P2 / M，依赖A5-2或已有确定影响）

- 按章节/目标组织改前改后，先定位当前处，再显示剩余数量；保留整体采用和逐组采用，解释保持不改的部分。
- 跨章查看期间保留原稿回程；部分已采用、部分失败、手改其中一组后的状态必须逐组准确，不以一个总成功提示掩盖。
- **Owner**：InterventionGhost、原多组/umbrella receipt、主副稿定位与history；不新增跨章事务实现。
- **验收**：只采用一组、全部采用、部分stale、保存失败、用户继续编辑后撤销拒绝均有可读反馈。撤销不能为了成功回滚作者后续手写内容。

## 11. 执行节奏、验收与决策

### 11.1 建议交付顺序

| 波次 | 交付包 | 用户可感知结果 | 进入下一波的条件 |
| --- | --- | --- | --- |
| 0 | A0-R + A1-R | 现状证据校准、小高度输入遮挡修复、双栏标题与回原稿确认 | 没有阻断写作/丢稿问题；标题代表图方向明确 |
| 1 | A2-1 + A2-2 + A2-3 | 资料好找好读，手机不挤，当前场不重复 | 角色/设定代表片及手机连续查阅可用；视觉仍不合适就留在本波 |
| 2 | A3-1 + A3-2 + A3-3 | 一句意图进入试演，等待与结果易懂 | 直接写作不增规划请求，Ghost/取消/保存/撤销可靠 |
| 3 | A4-1 + A4-2 + A5-1 | 第一套真正可玩的“改选择→看后果→再改”样板，普通稿不被拒之门外 | 真实小样本显示差异与作者控制感，且不违背原文 |
| 4 | A2-4 + A2-5 + A2-6 | 助手、历史、长时间写作与跨页回程收口 | 高频旅程可连续完成；状态和结果对照清楚 |
| 5 | 从A4-3/A4-4/A5-2/A5-3择优 | 保留试稿、线索试演或跨章影响中的一项扩展 | 由样板实际价值决定，不能因为列进计划就全做 |

波次是交付优先级，不是必须大批修改后一次验收。每包先做一个代表区域或一个纵向流程，再扩面。安全性缺陷始终插到队首；非阻断的助手/历史完善可在样板等待用户反馈时推进，但不得多人同时改页面owner。未获得明确多代理请求，本计划按单owner执行。

**工作量判断**：A0/A1收口与纯层级调整多为S–M；手机任务流、历史比较和方向编辑为M；推测影响授权属于L。第一轮只承诺完成下一包的闭环，不预先承诺全部计划的日历日期。每包基线冻结后给出工作量与风险估算；真实provider和用户视觉确认是外部等待，不纳入伪精确工期。

| 主次 | 1440/390代表图对照，先让用户说首先看到什么 | 名称、正文或当前任务先被识别，状态/工具不抢主位；不以主观代理评分替代用户 |
| 内容压力 | 空/短/长字段，8/20/40字标题，同名对象，长目录 | 完整对象可辨认，重要内容不不可逆裁切，零页面级横滚；虚拟化先测再决定 |

| 可操作性 | Tab/Shift+Tab/Enter/Esc，鼠标/触摸、IME | 关闭回焦、顺序合理、焦点可见；组合输入不误采用；移动主动作44px可达 |

### 11.3 有趣性检验：少量真实样本，明确停止条件

首轮三类任务：人物关系压力；物理条件变化；没有世界书的普通稿。每类旧路径/新路径各一份，共六份，固定模型、采样设置、来源和意图，记录实际请求次数/等待/失败。预算事先确认，不在计划调研轮请求真实模型。

先由Codex检查原文事实与结果差异，再请用户只看少量代表对照；顺序打乱以减少“新版应该更好”的暗示，不要求用户完成长评分表。每份记录：

- 人物行为是否可信，能否从原文解释；明显违背事实直接失败。
- 不同选择是否带来不同反应/信息/代价，而非同义改写。
- 作者补一句要求能否改变结果，还是仍只能挑模型答案。
- 是否愿意继续试一次；不想继续时具体是等待、无差异、难用还是文字不可信。
- 保留/采用/放弃后的实际写作是否顺畅；采用率仅为诊断，不能诱导作者接受模型稿。

1–5分可作轻量记录。建议门槛沿A4：至少两类样本的差异、控制感、愿意再试均≥4且没有明显事实矛盾；低分先改样板，不扩分支管理、关系玩法或跨章建议。六份样本只支持局部产品选择，不作统计显著、模型排名或“所有小说都有效”的结论。延迟只记录真实分布；若新增步骤增大等待，说明新增价值，不隐藏请求。
