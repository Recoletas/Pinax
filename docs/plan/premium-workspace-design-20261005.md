## 看过哪些产品，具体学什么

下表的“观察”来自实际查看的官方图片；“用于 Pinax”是设计判断。没有运行这些产品的原生客户端，宣传图也不能证明实际控件尺寸、性能或完整交互。

| 产品 / 一手资料 | 实际观察 | 用于 Pinax |
| --- | --- | --- |
| [Linear，2026-03-12 改版](https://linear.app/now/behind-the-latest-design-refresh) | 查看新旧侧栏与分隔线对比；非当前导航退后，图标装饰减少。官方同时强调跨页面操作位置一致 | 导航保持清楚但少争注意；统一标题、工具切换和操作的摆放规律 |
| [Bear 官网桌面图](https://bear.app/) | 导航、列表、稿面连续分区；列表以标题、摘要、时间建立层级，正文很少被外框包围 | 章名成为目录主信息；稿面维持连续，次要计数轻一些 |
| [Craft 官方 Style 面板图](https://www.craft.do/images/content/blog/craft-update-3-4-2/styling_panel_drag_and_drop.jpeg) | 文字 tabs、连续字段行、组间细线；另查看助手输入区菜单，模式和模型在就近菜单中选择 | 右栏用统一面板和分组留白；配置集中到输入附近，结果直接阅读 |

推荐以 **Linear 的工具秩序、Bear/Craft 的文字排版** 为主要依据。Figma 补充右栏组织方法，Apple Notes 补充字级与动作分组。沿用 Pinax 的中性蓝灰和现有图标体系；这些参考不构成另一套主题。

## Pinax 现在差在哪里

在现有 5174 页面、隔离浏览器中，创建同一本书并分别查看 85% 和 100% 缩放的 1440×1000 截图；没有修改用户浏览器的数据。

| 元素 | 调研时 CSS 字号 | 85% 时等效显示尺寸 |
| --- | --- | --- |
| 作品标题 | 15px | 12.75px |
| 项目导航 | 14px | 11.9px |
| 章名 | 13px | 11.05px |
| 工具名称 | 11px | 9.35px |

默认缩放来自 [themeStore](../../src/stores/themeStore.js)。表中为优化前尺寸，按应用缩放计算，未计操作系统缩放；字体栈为系统无衬线，未发现字体栈错误。作者此前认为 100% 太大，应保留缩放偏好。

我的视觉判断是：

- **文字普遍细小，层级不足。** 目录的章序、章名、计数和操作挤在相近字级里；单纯增加留白，主要文字仍不够稳。
- **两边尚未形成同一套控件秩序。** 左侧项目导航、目录行，右侧工具轨、标题和输入，各自有设计，但对齐、字重和动作位置还不够连贯。
- **右侧存在多个注意中心。** 工具轨、面板标题、辅助入口、空白提问区分散出现；切换工具后，内容组织还缺少共同规律。
- **面层关系偏概括。** 大块浅蓝底和两块白色圆角面已经建立分区，内部细节的分量却没跟上，容易像初步框架。

这些是对当前截图的判断；缩放影响已经核对，但不能把廉价感全部归因于 85%。

## 第三片的约束

先做左右栏的排版与控件切片，使用真实目录和工具结果。固定作品导航、目录独立滚动已经实现，继续保留。共同标题和操作规则稳定后，再延伸到设定、资料与媒体面板。

1. **字号与密度分别处理。** 保留用户缩放；先按屏幕实际显示约 13–14px 的主要导航、约 12px 的次级文字试排，控制行高和边距。这是 Pinax 的试排目标，不是其他产品的规范。
2. **让章名承担目录主信息。** 章序较轻，长标题可读；计数降一级。新建贴章节标题，逐章动作在悬停或键盘聚焦时就近出现，手机仍有可达入口。
3. **统一两侧标题与动作基线。** 同类标题、图标、关闭与更多菜单使用同一字重、间距和尺寸；同一功能只保留一个主要呈现位置。
4. **右栏有稳定的组织顺序。** 当前工具与必要上下文在顶部，结果连续阅读，编辑或输入动作贴近内容；待采纳、失败和来源继续清楚显示。九类工具保留可见名称与明确选中状态。
5. **减少无意义的视觉边界。** 普通列表和回答按留白分组；输入、候选修改、弹层等需要明确边界的对象使用已有 token。背景、稿面、浮层各有稳定角色。
6. **把交互态一起排好。** 普通、悬停、按下、选中、键盘焦点相互可辨；提示可读且不盖住邻近动作，收起面板后焦点和草稿仍归原对象。
7. **用实际状态审阅。** 比较 1440/900/390、亮暗、85%/100%，以及长章名、18 章目录、长回答、来源展开、待采纳和错误状态；缩窄后主要动作仍可达。
