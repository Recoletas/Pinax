## 二、Pinax 的具体问题

在本地 5174、隔离浏览器中实际新建作品、填写正文，再往返助手、设定、资料、资料导入、漫画、视频和首页；查看桌面、短视口及手机截图。没有调用模型，也没有修改作者浏览器数据。

1. **完整目录依赖首页。** 首页列出正文、助手、设定、资料、地图、灵感、视频、漫画；正文左栏只剩前四项。首次从正文进入漫画，本轮实际经过“首页 → 漫画”；已有漫画页签后可以直接切换。问题是入口会随页面消失，并非所有操作都需要很多次点击。见 [LibrarySidebar](../../src/components/authoring/LibrarySidebar.vue)、[ProjectWritingNavigation](../../src/components/workbench/ProjectWritingNavigation.vue)。
2. **全局导航存在断点。** [AppShell](../../src/layouts/AppShell.vue) 的导航抽屉初始关闭，没有打开触发器，ActivityBar 被放在屏外且 `inert` 的抽屉内。它不能承担当前的功能发现入口。
3. **进入不同区，要重新找导航。** 正文是左栏四项加目录、右侧九类工具；设定/资料改成顶部作品选择与四分区；漫画、视频换成自己的工具和对象列表。导航与内容操作缺少共同的摆放规则。
4. **名字与任务不一致。** 本书资料点击“添加资料”后，内容标题是“本书资料导入”，页签却是“创建世界书”；首页的“视频与编导”打开后叫“画布”。页面保留了作品 ID，但视觉上容易被理解为换了范围。见 [资料入口](../../src/components/worldbook/WorldbookSourcesPanel.vue)、[页签合同](../../src/services/workspace/workspaceTabContract.js)。
5. **首页起步动作不够明确。** 空库有八个灰置创作入口，主区域有三段说明；“和助手构思”藏在新建按钮下拉里。已有作品后，“继续最近的书稿”只有书名，始终进入正文，不能说明上次在处理哪一章或哪个工具。
6. **页签与文档之间还有一层。** 目前页签按“作品＋功能区”去重，章与章共用一个写作页签，正文/全屏助手也共用它。它已有恢复能力，但暂时不具备 Obsidian、VS Code 的文档级页签语义。

900×700 首页侧栏中的帮助、备份等底部入口需要滚动；390px 首页完整导航默认收起。手机已有“继续最近书稿”入口，本轮没有发现该入口必须滚动才能看到。后续重点是让核心任务有持续可达的位置。

## 三、建议的共同工作区

所有创作区共用以下五个区域，页面内容在其中切换。

| 区域 | 职责与呈现 |
| --- | --- |
| 作品与全局入口 | “首页”、当前作品选择和快速打开固定可达；切页签后，当前作品跟随真实页面范围 |
| 内容目录与功能导航 | 正文左栏只管理当前书的章节、构思和当前场；跨功能入口放顶部“导航”抽屉，首页保留作品功能入口；内容目录独立滚动 |
| 中央页签与内容 | 保留打开的工作，不再给每个页面加一套全局导航；当前对象的标题与编辑动作就近呈现 |
| 右侧助手与工具 | 当前对象、任务、结果和输入位置稳定；助手可展开到中央完整视图，与侧栏共用会话 |
| 必要状态 | 保存、未采纳修改、任务运行和失败以就近状态呈现；重要结果有定位入口 |

第一片被作者否定后，低频的灵感、地图、漫画、视频收入“更多工具”弹出列表；作者随后明确否定正文左栏中的四项功能入口，这些入口只在顶部导航和首页等功能选择位置呈现。没有新增工具中转页面。跑团与联机使用明确的全局入口与会话名称，不能暗示它们天然属于当前书。

桌面的顶部“导航”展开带文字的功能入口；正文左栏保留内容目录，不再重复模块菜单。手机用明确按钮打开导航，并保留当前作品/当前对象的识别。收起侧栏后，首页、功能查找和助手入口仍可达。

快速打开可按名称找章节、人物、资料和工具；它是额外路径。搜索内容、导航到对象与执行会修改数据的动作要有不同反馈。

## 四、首页怎样方便继续工作

**默认仍进首页。** 有作品时，第一屏按以下顺序排：

1. **继续上次工作**：显示作品名、具体章节或工具、上次使用时间；直接恢复该位置。例如“暮港来信 · 第三章”或“暮港来信 · 漫画第 2 页”。
2. **最近打开**：最近使用排在前面，显示少量记录；明确作品归属，允许固定常用项。关闭页签后记录仍可找回；已删除对象清理或说明原因。
3. **全部作品**：默认按最近使用排序；书名与最近修改仍可作为显式排序选项。作品很多时优先使用紧凑列表，封面书架继续作为切换选项。

“使用时间”和“修改时间”分别记录：打开资料、看漫画或讨论构思都算使用，不应改写书稿修改时间。首版以最近使用为主，不加入难以解释的频次评分。已有作品时，新建和导入保留，视觉优先级低于继续工作。

空库首页直接显示“开始写作、和助手构思、导入书稿”。空书正文同样提供可执行入口；短引导按真实完成的动作推进，可关闭和重新打开。界面不要求新手先理解世界书、配置模型或学习命令面板。

## 五、简洁感与质感如何落到细节

官方 Obsidian 图中，正文与右栏以浅面色和细线分区，右栏主要是连续列表；VS Code 图中，相邻导航、列表与编辑面有稳定边界。对 Pinax 的设计判断是：

- 外壳、列表和内容使用连贯面层；普通列表、回答和字段主要靠排版分组。弹层、输入和待采纳修改有清楚的边界。
- 建立作品名、对象标题、列表文字、辅助信息四种角色，统一基线、字重和间距；尊重已有缩放偏好。
- 强调色集中于当前导航和主要动作；避免助手、作品分区和工具同时出现多个强选中背景。
- 顶部作品信息、页签、对象标题分别承担范围、打开状态和内容身份；同一信息只在需要的位置重复。
- 长标题、滚动、加载、空态、失败、键盘焦点与悬浮提示使用共同规则，切区时控件位置可预期。

这些是下一轮样片的视觉约束，不能仅凭调研就声称质感已经达标。

## 六、实施顺序与复用边界

**第一片：共同导航与首页。** 在现有 Vue 中先覆盖正文、资料和漫画三种差异大的页面，做共享作品范围、完整入口、名称一致和最近工作首页。复用 [workspaceTabsStore](../../src/stores/workspaceTabsStore.js) 的作品索引、路由与 `lastActiveAt`；增加独立且有限的最近工作记录，因为关闭现有页签会删除它。记录只存导航信息，内容仍归现有 repository。

这一片同时补所覆盖对象的定位与恢复适配。当前通用恢复只提取 `chapterId/focus`，漫画选页仍是组件内状态；首页承诺恢复“漫画第 2 页”之前，必须先让页面接受、保存并校验相应定位。对象失效时给出说明，不悄悄换成另一页。此处解决直达位置，第三片才扩展文档级页签。

**第二片：减少跨页中转。** 将添加资料留在本书资料流程，世界书关联细节在需要时说明；共同导航逐步覆盖设定、灵感、视频和助手。完成作品切换、回正文与未保存修改的交接后，再延伸视觉细节。

**第三片：按内容打开页签。** 当前页签先保留；需要多章/多资料并行时，再扩展章节、资料与漫画页的对象身份。刷新恢复到明确对象；光标和滚动的跨会话恢复另行设计，现有临时往返账本不等于持久恢复。助手展开/收起仍回到原稿，不新建会话。

下一片的出口是：从任一已覆盖页面能找到其他核心区；不回首页也能打开漫画；首页继续上次与最近记录直达正确作品/对象；导航名称一致；1440/900/390 的实际内容截图可读，主要动作与关闭入口可达。先审阅这一片，再推广其布局。

本方案聚焦前端结构，沿用现有作品、世界书、任务和保存归属，也沿用作者确认采纳。资料/RAG 与 Agent 核心继续按[合作范围](./writing-agent-collaboration.md)推进。

## 2026-10-06 缩进、右侧面板与首页续修

作者明确章行要像速记一样表达目录层级：卷标题不动，章节文字向内缩进。四个工具保持原来的编辑/目录 owner，只统一内边距、标题、按钮和窄栏空态。用户提供的暗色角色截图是直接证据：浅蓝主按钮仍用白字，根因是组件写死了前景色；应使用成对的 accent/ accent-text。导航触发器和首页入口复用产品 PNG 图标，不另画标志。批注“版本”实际是章节历史快照，改称正文历史并说明用途，速记视图不展示章节恢复动作。

首页恢复已有书封面，默认书架；删除浏览器保存/不同步提示。继续入口与历史合并成单一最近打开列表，保留对象精确返程和不可用提示。使用旧 BookLibraryCard 与现有 recent store，不新增数据源。

参考：[VS Code 主题颜色](https://code.visualstudio.com/api/references/theme-color)的树层级/按钮前景与背景分开定义；[Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout)搜索摘要明确用缩进表达层级；[Material 色彩角色](https://m3.material.io/styles/color/the-color-system)搜索摘要强调配对颜色。后两页正文要求 JavaScript，本轮不把搜索摘要写成已完整阅读。实际尺寸来自 Pinax 和作者截图，不当成产品规范原值。


## 20:34 反馈后的外部工作区续修

作者第二次截图明确导航目标是抽屉标题标识，上一轮修改触发按钮和首页行属于误判；角色空白状态贴顶也被否定。此次先冻结六项约束：

1. 产品图标放在抽屉标题，恢复导航触发器/首页行的功能图标。
2. 角色空态在内容区上段留出呼吸空间，不贴顶；编辑表单位置不移动。
3. 资料始终有页面标题，空态与已导入列表共用一个内容轴；添加、搜索、原文预览职责清晰。
4. 视频先聚焦场景输入，有节点后显示编导/时间轴；生成配置和结果保持现有归属，不增加中转页。
5. 漫画保留页目录、主画面、当前格的工作模式，用统一工具栏和页边留白突出纸页。
6. 跑团以回合与行动输入为主，开场选择/规则收起为按需调整；指引使用短说明、一个下一步和明确关闭，避开主操作区。

定位：资料是查阅/管理面，漫画和视频是编辑台，跑团是叙事/行动面，指引是短暂提示。桌面优先阅读内容，手机按顺序组织；中性连续面与成对主题颜色，控件不争主角。此次以小切片改现有组件，不改正文目录架构。

一手调研：[Notion 导入](https://www.notion.com/help/import-data-into-notion)区分导入目的地、格式和导入结果；[Runway 视频](https://help.runwayml.com/hc/en-us/articles/37327109429011-Creating-with-Gen-4-Video)按输入→配置→结果组织任务（该文已标明旧模型，借鉴流程而不沿用规格）；[Clip Studio 页管理](https://help.clip-studio.com/en-us/manual_en/570_pages/Page_Manager.htm)保留缩略页目录与编辑页的关系；[Foundry 指引](https://foundryvtt.com/article/tours/)明确步骤、关闭与继续，[跑团入门](https://foundryvtt.com/article/tutorial/)区分世界/会话与实际游戏。实际查看 Clip Studio 左侧页目录图、Runway 模型选择器图、Foundry 指引管理图；它们只作为结构证据，不复制素材或旧皮肤。已查看本地资料、漫画、视频、跑团、写作指引亮暗基线，发现空态缺标题、空时间轴常驻、多组开场入口、指引小字压缩等问题。

作者进一步明确完整设定页只恢复旧结构、保留当前材质。对照 `782b03e0^` 最终连续文稿 CSS：小标题/中性分隔线、无底色无圆角的自动增高编辑区，完整内容轴；不恢复旧渐变、底纹或技术样式，不回退新的保存/草稿保护和切书绑定。当前表单式底色与 880px 居中轴撤回。
