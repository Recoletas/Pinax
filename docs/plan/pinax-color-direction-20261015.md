# Pinax 配色与顶部标签：重新定方向

日期：2026-10-15，第二轮调研修订。作者已否定上一轮顶栏装饰蓝线，并明确蓝色只是参考，不是指定主色。本文件包含研究与分阶段实施记录；下方建议中，工作区外壳的中性方案已本地实施，其余仍需逐区域比较。上一版“默认以低色度蓝作为主要操作色”的判断撤回。

## 先说当前界面的问题

这属于平面设计的色彩、对比、面积、节奏与编排，也涉及交互状态。当前的问题并不能靠更换一个蓝色解决。

1. 顶部资源标签已有独立白色面、轮廓与字重，新增蓝色底线重复表达选中，像给已经成形的控件贴了一条装饰。
2. 活动标签、目录文件、左右工具和主要动作同时争用蓝色。各处面积虽小，反复出现仍会产生碎片感。
3. “我正在查看”“键盘焦点在哪里”“这是可点击链接”“这是主要动作”用了相近颜色，却没有明确不同的表现。
4. 灰色主要围绕几个近似色取值，内容、输入、选中、悬停之间的角色关系还不够清楚。把正文和文字全部压灰也会失去阅读对比。
5. 图标质感不能只归因于线宽。轮廓复杂度、光学大小、前景对比、按钮底块及其圆角也会一起影响结果。

本轮先撤掉被明确否定的顶栏底线，并把活动标签图标还原为中性色。标签位置、大小、现有功能、目录行距和首页显隐逻辑保留。

## 推荐的Pinax方向

保留作者已经认可的布局、目录间距和当前材质，采用接近中性的白灰外壳、墨色文字与有限的强调色。先以中性控件成立为基准，再在真实页面判断强调色是否有帮助。蓝色、青色或其他色相都不预设为必要条件。

作品封面、插画、漫画和地图提供内容色彩。界面本身仍需要足够的明度层次，不能靠内容图片掩盖控件问题；也不自动从每本书封面提取整套主题，避免换书就改变操作识别。

### 三种方向的取舍

| 方向 | 适合之处 | 代价与建议 |
| --- | --- | --- |
| 近中性白灰＋墨色动作 | 阅读稳定，能衬托多种作品封面，沿用当前布局最自然 | 必须细分选择、悬停和禁用，避免一片灰。推荐作为基础方向 |
| 微暖白＋暖灰＋少量有色动作 | 可提供较柔和的阅读气氛 | 暖意过强容易像泛黄纸张，与漫画、视频和地图不协调。仅作同布局对照候选 |
| 中性基底＋可辨认的单一强调色 | 关键操作更容易扫到，可形成品牌识别 | 分散到标签、目录、工具、输入框时容易嘈杂。先试有限位置，不同时建立彩色图标体系 |

推荐第一种作为基准，第三种用于比较关键动作的辨识度；第二种只比较色温，不增加纸纹、棕色边框或复古装饰。本轮不确定最终色号，也不新增主题选择器。

### 一、从明度、色温和面积建立层次

| 角色 | 应有的视觉关系 |
| --- | --- |
| 正文／设定正文 | 最干净的阅读面，保留原正文字体和原稿面宽度 |
| 顶栏与左侧导航 | 比阅读面略沉、色温一致，形成连续外壳；不用逐层画重边框 |
| 输入区域 | 能发现可输入位置，主要依靠留白和轻微底色差；真实聚焦再增强边界 |
| 当前选择 | 比悬停更稳定的中性底色，配文字重量／形状区别 |
| 浮层 | 与底面有明确层次，阴影只用于实际覆盖关系 |
| 文字 | 主文字保持阅读对比，辅助文字退后；不能把工具文字都压成浅灰 |

明度决定先看哪里；色温决定相邻面是否协调；色度、面积和重复次数共同决定颜色是否抢眼。低饱和颜色铺满整页也会形成强烈色偏，小面积高饱和颜色则不必然廉价。没有通用的“60／30／10”比例可替代实页判断。

浅色不必发蓝或发黄，深色不必把所有面板抬成一块亮灰。亮暗分别组织表面和对比，不机械反相；也不通过继续压低所有图标对比来制造柔和感。

### 二、让动作、焦点和选择分别成立

- **主要动作**：发送、采用等当前关键动作，可以使用墨色实底／浅色文字，深色反向，也可以试单一强调色。具体配对要核查正常、悬停、按下和禁用；一块区域不放多个等重的实底按钮。
- **普通操作**：中性色图标和文字，悬停显示轻底色，保留工具提示与键盘焦点。新建等操作是否成为主动作取决于所在场景，不能全站一律染色。
- **链接与定位**：允许使用强调色，但配合下划线、来源标识或悬停反馈辨认，不能只靠颜色。
- **键盘焦点**：清晰、仅在实际聚焦时出现，不能用常驻装饰线代替；实际焦点和选中同时存在时也可区分。
- **选择**：目录和标签优先通过表面及文字对比表达；工具轨在窄空间另行比较底面与边缘标记，不继续堆叠。
- **状态**：待审、警告、失败有独立语义和文字。尤其审阅中的新增／删除应与普通操作强调色区分，不能只靠红绿表意。

### 三、各部位如何落地

| 部位 | 建议调整 | 保留的内容 |
| --- | --- | --- |
| 顶栏 | 外壳连续，活动标签用中性面与名称对比；清点相邻横线，优先去掉重复边界，不用彩线补层次 | 标签结构、关闭、拖动和资源身份 |
| 左目录 | 默认中性色图标，靠轮廓和名称辨类型；若试类型色，只比较少数必要类型，不能同时给所有活动项上色 | 已认可的行距、缩进、文件夹与展开行为 |
| 右工具轨 | 图标光学大小／笔画一致，选择与悬停分明；避免每个按钮都包一块圆角色底 | 工具顺序、纯图标提示、右栏位置 |
| 助手／推演 | 区分消息内容、编辑输入、操作与运行状态；引用和审阅信息有自己的层级 | 现有运行与采用逻辑、面板位置 |
| 设定与资料 | 内容正文保持干净，属性按需出现；右栏与正文工具共享表面规则 | 原件所有者、关系图在右栏、已有保存链路 |

顶栏不能把每一条线都删掉：内容组边界、可拖动分隔及真正的标签结构仍需可辨。重点是相邻区域是否已由背景差／间距表达边界，避免再叠一条同等强度的线。具体哪些边界删除，要在原布局截图中逐处确认。

### 四、下一步比较方法

先在相同布局、相同内容上比较两份实际页面：A为近中性外壳＋中性主要动作；B保持A的所有布局与明度关系，只给关键动作与链接加入一种候选强调色。微暖版本只作为额外色温对照，不同时改圆角、字体、宽度或图标，避免无法判断是哪项造成改善。

按顶栏＋左目录的小范围开始，再看正文＋助手、设定右栏、首页封面、资料导入。每个画面同时看正常、悬停、选中、键盘焦点、禁用与错误，亮暗分别看。通过标准是内容先被看到、关键动作易识别、选中与焦点不混淆、长时间阅读无明显色偏；最终审美判断交给作者，不以单个对比度数字替代。

## 实施记录：中性工作区外壳（2026-10-15，仅本地）

- 新增独立的chrome、selected／selected-hover、focus及action前景／背景token；浅色导航接近中性灰，深色导航与输入分层，保留原阅读底色。
- 顶部标签去重复底部分隔及活动标签描边的颜色，边框占位保留，避免改变尺寸；活动白／黑底面和名称继续表达当前项。
- 左活动栏与目录选中改为中性底面，移除活动栏彩色边线；目录图标按轮廓辨认，去掉两组重复类型配色规则，删除无消费者的旧类型色token。
- 写作与设定右工具轨共用中性选中、深浅主题及6px圆角，去彩色边缘标记；现有提示、待审点和工具顺序保留。设定这里只修改CSS，不触碰原件、保存或图谱逻辑。
- 助手输入去静态阴影，实际聚焦使用独立焦点色；发送及悬停采用墨色／浅色配对，禁用与停止仍有独立状态。没有发模型请求。
- 原稿面宽度、目录行高／缩进、区域位置、首页／文章显隐规则保持；手机继续使用原工具带。

## 返修：标签按下闪蓝与深色强调色（2026-10-15，仅本地）

作者反馈上一轮变化不明显，并指出标签切换瞬间闪蓝、深色蓝色不协调。此前“静态图已看”没有覆盖按住鼠标的瞬时状态，不能作为该问题已解决的证据；本轮补实际按下状态。

原因与修复：

- 顶部标签的`:active`、关闭按钮及旁区标签仍引用旧`--nav-focused`，其值为accent混色。共享导航变量改为中性选择／按下，并让标签直接读取工作区状态token；触控标签禁用原生点击高亮，键盘焦点保留。
- 共用`control-primary`此前仍取全局accent作为实底。现在主按钮取工作区action，前景统一取配对的`control-accent-text`；已同步推演／干预输入、重答、设定管理与字段确认、名称插入、扩展等现有消费者。没有只改背景而留下旧前景色。
- 深色链接／信息强调色从`#a8c7fa`收敛为`#96b1c6`，对应hover、light、archive及hairline配对同步；选择不再取蓝色混色。没有全局取消警告、危险或证据链接颜色。
- 完整助手空白输入区曾用更高优先级规则重新加蓝底／外光，本轮一并去除；按钮与输入焦点统一工作区焦点色。
- 创建浮窗的遮罩跟随主题，输入使用显式焦点，避免深色浏览器默认白色粗框。布局、稿面、目录间距及所有任务写入逻辑保留。

实页证据：1440×900按住标签150ms后，浅色底`rgb(217,219,218)`、深色`rgb(58,61,66)`；修复前分别为蓝色混合值`color(srgb 0.829059 0.890235 0.933725)`与`color(srgb 0.177765 0.19698 0.229804)`。查看亮暗完整助手、侧栏助手、创建浮窗及390×844浮窗。浮窗仅填写合成名称以查看可用／悬停状态，未提交创建或调用模型。构建及lint等最终结果记入LOG，未运行自动测试，不提交／推送／重启。
