## 1. 这次交付什么，为什么不会再是两小时短单

两条独立队列，各以约 8h 为运行上限，**不是精确工时承诺**。核心目标是早晨能验收两个完整变化：

- **U：写得稳，也能玩一次完整的“改要求→再试→采用/放弃”**。先关选区/IME/搜索返回缺口，再做现有试演的作者追加要求、失败与旧稿保留闭环，不再仅调几处折叠和文案。
- **K：从离线函数走到现有资料助手的受控接入候选**。先补授权快照和真实源映射，再在默认关闭的窄接缝验证来源、未知、过期和回退；不是再写一遍 K0–K4，也不是造数据库。

每线有必做、目标、已列明储备。执行本计划时，储备包也属于范围，满足前置即可继续，不用等用户醒来逐包批准；但本文列出的外部门禁不能自动跨越。完成必做项不是停止条件，卡住某包不等于整线停工。

**容量校准，不再伪装估时精确**：U 有 6 个主包 + 3 个储备包，K 有 6 个主包 + 3 个储备包。按首次安全复验、跨层接缝和真实浏览器取证估算，每线主包可能需 5–9h，储备另有约 3–6h；这是粗略任务容量，不是实测生产率。启动 60–90min 后用实际完成速度重估；若仍可能 2h 耗尽，立即转入已列明储备，而不是把重复测试算作新工作。

最低可合并交付是安全底线，不是成功终点：U 至少 U01–U03 收口；K 至少 K21–K23 收口。晨间应逐项写出目标包是否做到；只达底线必须标“部分交付”，不能称整轮完成。

## 4. 接续、转向与冻结协议

每包状态只能是 `queued / running / done / blocked / deferred / not-needed`；not-needed 必须有现状证据和等价验收结果，不能凭“感觉已经不错”略过用户路径。

每包循环：读进度 → 核对前置/写集 → 复现或基线 → 最小实现 → focused/专项 Gate → 自审 diff → 记录结果 → **自动领取下一个就绪包**。

- 每包结束更新进度；长包每 30min 写一次。记录墙钟起止、实际操作区间、等待/工具耗时和产物，不以“会话存在多久”冒充有效工作。
- 60–90min 做一次容量检查：主包提前通过即取储备；不等预定整点。只可推进本计划列明的独立包，不自行新增领域。
- 连续 30min 无新证据，必须换诊断方法；一个疑难包最多 90min 后形成最小复现和转向说明。后续若有新证据可再开一次有界修复，不机械重复失败命令。
- 普通阻断只阻断依赖它的包。U 的 IME 问题未解，可以做静态层级/只读评测；不能放行受影响的输入新玩法。K 授权门禁不通过，I0 不接线，转 K-R 包。
- 发现越权、正式数据误写、旧书串写或不可恢复输入丢失，立即隔离本包，优先恢复基线安全行为；该路径不得标 ready。安全事件不会授权全仓库重写。
- T+6h 后停止领取新功能包；允许修复本轮回归、完成矩阵、整理证据和提交。预计剩余时间不足“实现 + 专项验证 + 全量验证”时，不开下一包。
- 正常提前结束仅有：所有主包和所有就绪储备已完成；或者其余全部有具体外部阻断且无独立任务。必须逐项列出耗尽/阻断理由，标“提前队列耗尽/部分交付”，不静默结束。
- 冻结后任何代码修改使旧验证失效：重跑受影响 Gate + 最终 verify。摘要绑定代码 tree 和测试命令，不靠“昨天绿过”。
- 截止时只隔离自己的未完切片，不丢作者/其他线数据；不得用删测试、改成 skip、私有函数补选区或降低安全断言制造通过。

- `history-node:` 与 `history:` 必须经项目/世界书/具体对象映射，禁止只换前缀；query 所指实体来自可信目标/来源集合，不从模型自报身份扩大范围。
- facts、excerpts、hypotheses 不混排升级；无时点/角色知识资料通过现有 missingInformation/不足说明表达。不能映射的来源 typed 拒绝，不伪装 worldbook-entry。
- 验收：round-trip 来源定位与 revision、同一来源去重、预算裁剪、来源删除/换绑、旧稿隔离；legacy/rich 分开报。给出与旧 F2 的差异表，指出接入实际增加了什么，不用重复回答冒充收益。

### K24 · 受限 I0 接入（目标，门禁通过才能做）

本计划获批准执行时，仅批准下述窄 I0 工程接缝；这不是全量 K 合同、历史工具或新权限的签收。启动 owner 必须先在任务板确认该范围和 K 写集；未确认则只做 K23 与储备，不临时修改上位合同。

- K21–K23 全过且桥接有实际收益后，由 K 作为唯一 owner 修改现有 F2 session 的准备/对账接缝，默认关闭新能力，保留原路径。U 不修改这些文件，故不需要等 U 整夜结束。
- **仅作者视角、已有 F2 授权集合内的精确世界书/历史资料**。不开放角色秘密问答、任意历史时点、未来正文、未采纳假设、整库动态工具查询，不把 I0 顺手升级 I1。
- 默认关闭时无新增读取、生成请求或行为变化；使用现有开关约定或明确的默认 false 依赖参数，测试可启用，不新增设置页。若需要无法容纳的 shared/schema 修改，阻断 I0 并转 K-R，不自行扩合同。
- 不增加第二套 provider 调用：结果继续进入既有 evidence envelope、源定位和 stale 对账；仅实际进入 prompt 的证据可标已参考。
- 权限/无效来源被拒时不能通过旧路径偷偷重新补全同一被拒资料。运行故障可回退原路径，但必须保持原授权范围并标明降级。
- 验收：开/关同一 fixture 对照；正常查询、未知、拒绝、无绑定、换书、换绑、关闭、迟到、来源删除/修改；实际 prompt、来源列表、debug 均不泄漏；原 F2 不回归。

### K25 · 接入生命周期与性能（目标）

- 覆盖 liveSource 未保存正文、主/副章、through-target 与 whole-book 分离、项目 revision 变化、缓存/scope 销毁。无明确 cutoff 的源不加入有 cutoff 的回答，不能以 excerpt 绕过。
- 100/1k/10k 样例测“reader/clone/freeze/scope/query/bridge”分阶段冷/热成本；I0 启用与关闭对照，记录查询 p50/p95、序列化大小和内存口径。复用现有预算，不新增 Worker/全局缓存掩盖问题。
- 验收：K 原 eval + 新桥接矩阵全过，1k 有界查询 p95 目标 ≤100ms；不达标先给瓶颈与回退结论。独立浏览器源跑既有 F2 资料助手 Gate，记录开/关结果。

### K26 · 对作者可验收的交付（目标，也是收口）

- 不新增 UI：给出在现有资料助手中“查一条已授权资料→查看原出处→改掉来源后旧答案失效”的隔离演示；能力开关默认仍关闭，晨间再决定是否启用。
- 三条可复跑命令：正常来源、未知时间、拒绝越权；源未变/已变各一例。无真实模型时用明确 mock，展示的是证据闭环而非回答质量。
- 全量 verify、K eval/benchmark、F2 受影响 Gate；I0 未成则交 K21–23 的精确模块和阻断，不伪造“已接入”。

## 8. 完成条件、交接与晨间验收

worker 交付 `docs/agent-runs/<run-id>/<u|k>/{progress,summary,verification}.md`；图片/JSON/log 在自身 worktree 的 tmp。摘要不超过约 1200 中文字，但测试详情必须可追溯。

- summary：实际完成/没完成；作者能感知什么；安全遗留；第一条验收动作；下一包。
- progress：每包状态、时间、写集、转向原因，主包/储备不得省略；有效时间与等待分开，无法测准就写未知。
- verification：BASE、最终代码 tree、最终 HEAD、命令/exit/分母、mock 拦截计数、来源根与端口、截图、所有失败。报告写完后只允许文档补记；再改代码必须重验。
- 交付前本地提交按 concern 收口，不堆 WIP；如果有未提交文件，列全 tracked/untracked 及原因，不能交一个 SHA 却漏掉实际页面代码。不得把失败藏到“适配债务”后称全绿。
- 结束前停止自己的测试进程，释放本线写锁并标 `frozen`。冻结后不在原目录悄悄再改；新想法写 deferred，晨间新开包。

**晨间先看失败，再看截图，约 25–35min：**

1. 5min：核对两线冻结、HEAD/tree/工作区、主包/储备状态；发现仍有写入就不合。
2. 10min U：长标题双栏→查找结果→关闭→加批注；再跑“要求→方向→追加一句→取消保旧稿/采用撤销”，看390和720×450。
3. 10min K：默认关闭旧路径仍可用；隔离启用后看正常来源、未知、拒绝、改来源后失效。确认 legacy/rich 差距，不要求用户读整个查询引擎。
4. owner 串行合并 U、K 到独立候选，检查写集冲突，重跑 full + I0/F2/Journey 交叉回归；两线独立绿色不等于合成绿色。没有用户明确请求不 push。
5. 再决定：新视觉是否接受、I0 是否允许启用、真实模型样本/费用、手机目录详情方向。自动化通过不替代这些判断。
