# Pinax：资料、助手与 Agent 接入说明

日期：2026-09-30 · PR #4 后续合作附件

本文确定前端的大致安排和双方需要对接的能力。产品方向、接入接口和正式前端由 Pinax 作者负责；贡献者继续完善资料处理、文件操作、RAG 和 Agent 工作流。以下接入约定的字段名和传输形式在联调时确认。

前端首版已在本地接上完整助手、侧栏、空白书构思入口、引用预览和按作品保存，暂时使用现有问答与审稿能力。本文的文件管理、RAG、任务恢复及新工作流接口仍待贡献者实现和联调。

## 1. 现有基础与本次目标

Pinax 已有资料解析、原文归档和分块、结构化世界书、参考 Utopia 的本地事实账本，以及正文批注、改写候选、采用和撤销。作品主要保存在浏览器 localStorage / IndexedDB。

目前资料提取仍主要使用一次模型请求，世界书提取入口只取传入文本的前 12,000 个字符，并允许补全信息。需要完善长篇分块分析、跨章节汇总、来源追溯和更新处理。记忆账本先复用，遇到实际缺口再调整。

按 2026-09-30 的只读审阅，PR #4 提供了 Node/pi-agent 适配器、资源快照工具、任务转录和独立 beta 面板。文件管理、完整资料 RAG 和正式正文修改接入仍是后续工作；当前快照查询不能代表全文分析或检索已经完成。

目标是让作者可以导入资料、讨论故事、查阅原文，并让助手在指定范围内检查或修改文本。较长任务交给助手，推演保留作者参与，批注和选区操作继续保持轻量。

## 2. 前端安排

### 资料管理放在现有资料页

入口继续使用「设定 → 资料」，按当前作品组织文件，支持目录、标签或集合等基本整理。具体视觉和组织方式由 Pinax 侧实现。

资料列表呈现文件名称和处理状态；详情可以查看原文、章节、分析结果和引用位置。解析成功、分析完成、检索可用分别表示，不能把上传完成显示成全文已处理。

分析结果包括人物及别名、地点、组织、关系、事件，以及可选的语料/文风分析。每项结果尽量保留原文依据；无法确定的内容标明不确定，创作补充与原文提取分开。

提取出的设定进入候选，作者选择新增、合并或忽略。参考资料不会因被导入或检索而自动成为本书设定。资料更新后显示受影响的分析或索引，支持继续处理失败部分和复用未变化的结果。

### 助手提供完整页面和工作台侧栏

作品内提供「工作台 / 助手」入口。完整助手页用于构思、讨论设定、资料研究和较长任务；工作台侧栏用于边写边问、处理选区和继续同一任务。

两种展示共用作品会话、任务和结果。切换展示不重新请求、不清空输入，也不改变运行中任务的目标。返回工作台时恢复原章节和编辑位置。

布局关系如下，表示信息位置，不是最终视觉稿：

```text
当前作品                                      工作台 / 助手
──────────────────────────────────────────────────────────
可收起的会话列表 │ 对话、引用、任务进度 │ 按需打开原文或结果详情
                 │ 任务范围与输入框   │
```

未打开详情时不常驻第三栏。手机以单页对话为主，原文和结果详情在同一页面切换；进入正文或设定后可以返回原会话。

### 空白作品可以从助手开始

新建作品提供「和助手构思」和「直接写作」。已有稿件仍可走导入。进入助手前先建立作品归属，书名可以稍后确定。

空白助手先让作者输入一句想法，也提供少量起点，例如想人物、使用已有资料、尝试开场。助手按当前信息提出必要问题或少量方向，不要求先填完整世界观和设定表。

讨论后可以整理人物、生成大纲或尝试开篇。设定和正文结果都明确显示保存或采用动作；作者随时可以进入工作台自行写作。

### 检索与修改各有展示位置

| 内容 | 展示位置 | 可执行的动作 |
|---|---|---|
| 回答、检索片段和出处 | 助手对话 | 追问、展开原文、打开完整资料或定位正文 |
| 正文修改候选 | 工作台对应正文位置 | 查看差异、采用、忽略；已采用内容可撤销 |
| 设定修改候选 | 工作台右侧设定区域 | 查看条目变化，新增、合并或忽略 |
| 资料分析及文风报告 | 资料页 | 查看依据、继续处理、供后续写作任务使用 |
| 任务进度和需要作者决定的问题 | 所属助手会话 | 停止、选择、继续或重试 |

助手保留结果摘要和「查看修改」「查看设定建议」等定位入口。红点表示未查看的新结果，查看后清除；尚未采用或忽略的候选保留数量或状态。失败直接说明原因，不能只用红点表示。

## 3. 接口需要表达的信息

接口由 Pinax 侧确定，贡献者可提出实现建议。这里先约定必要语义，不冻结函数名、URL 或完整 JSON schema；可以沿用当前 HTTP/SSE 桥并逐步扩展。

### 公共信息

| 信息 | 约定 |
|---|---|
| 作品、会话、任务、请求 | 可以明确关联；请求标识区分重试或追问。共享世界书的作品仍各有独立会话 |
| 任务目标 | 区分全书、当前章节、指定选区或条目；任务开始时固定对象和版本，后续追问可明确更新上下文 |
| 资料范围 | 默认本书范围；明确指定资料或条目时据此限制查阅，不自行混入其他作品 |
| 引用 | 指向实际资料、世界书条目、正文或账本证据，包含版本和可打开的位置；展示摘要不代替引用 |
| 修改目标 | 能定位正文对象或设定条目，并携带生成时的版本；不能仅凭一段相似文本定位 |
| 操作范围 | 区分只读问答、提出候选和已授权修改。授权修改要说明对象与范围 |

现有 `sourceRefs`、文档 handle 和版本能力优先复用，不另建一套互不对应的引用。`bookId`、`worldbookId`、`sessionId`、`taskId` 等名称仅作对齐示例，以确认后的接口为准。

### 四类能力

| 能力 | Pinax 提供 | 核心能力返回 |
|---|---|---|
| 资料接入与处理 | 文件或已解析文本/分块、作品归属、来源标识与版本、处理目标 | 处理任务、覆盖范围、进度、失败部分、带依据的分析候选；支持更新和继续处理 |
| 检索与原文读取 | 作品、问题、允许查阅的来源；打开原文时提供引用和位置 | 相关片段、来源类型、标题、原文位置与版本，以及未覆盖或过期的说明 |
| 会话与任务执行 | 会话、作者目标、固定的任务范围、上下文和授权 | 可关联的进度、工具查阅摘要、待作者决定事项、结果及终态；支持追问、取消和恢复 |
| 结果交付与反馈 | 前端对结果的查看、采用、忽略或应用失败反馈 | 稳定的结果引用、结果类型、目标和依据；后续任务能获知实际采用状态 |

文件接入复用现有解析和来源归档；若贡献者的处理模块需要原始文件，由适配层提供对应内容和版本。助手中的附件导入也进入同一资料管理链，不创建聊天专属的另一套资料库。

检索需区分参考原文、已确认设定、正文和历史事实，回答可以显示其出处。RAG 可以使用现有分块和账本，也可以增加索引；是否使用外部数据库由规模和部署方案决定，不作为前端接入的先决条件。

### 状态与恢复

任务至少能区分排队、执行、等待作者、完成、失败、取消；具体状态值由接口确认。进度事件和结果都能关联到所属任务，同一结果重复收到时不应生成两份候选。

停止操作需要停止后端执行并反馈最终状态。流式连接断开与任务取消分别处理，不能只取消浏览器请求。重试也应区分查询旧任务状态、恢复任务与新建一次任务，避免重复执行修改。

全屏/侧栏切换仅改变展示。切书时呈现新书会话，旧书任务继续归属于旧书，结果不能写进新书。刷新后查询真实任务状态，服务无法恢复时明确提示，不能自动重发原任务。

## 4. 修改怎样进入正文和设定

普通任务返回候选，由作者确认后通过 Pinax 现有保存服务写入。候选至少包括目标、生成时的版本、建议变化和必要依据；正文可以附修改原因，设定需区分新增与更新。

作者明确授权自动修改时，Agent 可以连续提出并申请应用限定范围内的修改，Pinax 宿主负责版本检查、保存和撤销记录，并回传实际成功或失败。运行器不能因为模型生成了结果就报告「修改已完成」。

正文或资料在任务期间变化时，候选标为需重新核对，不直接覆盖新内容。前端可要求重新生成或让作者查看差异后处理。多处修改需要说明成功与失败的范围，重试不能重复应用已成功的部分。

这套结果交付能力供助手、推演和批注复用：助手承接较长任务，推演返回可选择的情节结果，批注返回局部修改。它们的操作入口由 Pinax 侧保留，不统一改成聊天流程。

## 5. 文件与数据归属

Pinax 现有保存链继续负责正式正文、设定、资料和作者采用的结果。贡献者提供读取、处理、检索和生成能力；文件操作通过适配层接入宿主。浏览器里的逻辑目录可以映射到未来桌面文件夹，不默认把目录做成服务器路径。

适配器的任务转录、缓存和临时分析文件属于运行数据，需要能关联到同一作品和来源版本。它们不能作为用户作品的另一份独立真源。引用应能回到 Pinax 保存的内容，更新时同步失效或重建相关结果。

公网接入需要共同确认适配器部署位置，以及如何取得浏览器中的当前作品内容。现有 `127.0.0.1:8451` 是本地接线地址，不代表公网已经可用。作品和任务标识负责归属，不代替访问隔离；正式服务需沿用 Pinax 的调用限制，并避免用户读取或操作他人的任务。

## 6. 当前 PR 与后续交付

当前 PR 先收口适配基础：beta 默认关闭；任务和会话明确作品归属；世界书正文读取兼容 `content`；首次任务取消能够停止后端执行；确认 CI 实际执行并提供修订后的验证结果。前述问题来自只读审阅，完整运行验收在修订后进行。

后续按资料处理/检索、Agent 工作流分别提 PR，贡献者提供能力实现、调用示例、联调样例和未覆盖说明，Pinax 作者负责正式前端及结果采用接入。

双方用以下流程联调：

> 导入长篇资料 → 查看处理状态与原文依据 → 确认部分设定 → 助手检索并引用 → 提出正文修改 → 在工作台采用或撤销。

同时覆盖空白作品从助手开始、运行中切换全屏/侧栏、切书后返回、刷新恢复、停止任务和正文变更后的候选处理。正式前端布局和视觉验收由 Pinax 侧完成，底层任务与资料能力由贡献者验证，最终一起检查完整流程。
