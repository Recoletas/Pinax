定位：长期创作工作台；以笔记本/桌面近距离阅读为主；安静、中性、工具化；必须容纳长标题、多标签、长规则和多轮推演，不靠留白填充或压小正文解决。

参考已核实：[VS Code 界面](https://code.visualstudio.com/docs/editing/getting-started/userinterface) 的编辑区与主/副侧栏分工；[Apple 工具栏](https://developer.apple.com/design/human-interface-guidelines/toolbars) 的高频操作分组、少着色、避免重复标题。Apple 以官方 DocC JSON 获取正文。不是复制 Liquid Glass 或声称实现 VS Code 所有面板自定义。手机降级是 Pinax 自身适配，不假称来自桌面截图。

验收约束：

1. 首页标签用已有产品 PNG；工作标签桌面约 36px，活动页背景与下方连通，没有横线穿过底边。关闭、脏标记、溢出菜单和键盘导航保留。
2. 标签负责工作对象切换，页面工具栏只放当前对象操作，不再重复产品大标题；页面切换不添加等待动画。
3. 正文是主区域；推演准备、条件、路线、长回应主要在右栏。正文内保留落笔位置、简短提示和可采用试稿；不复制完整回应。
4. 推演切换不改变冻结作用域、选区和草稿归属；关闭面板不等于丢弃已写内容，采用/撤销继续调用原 owner。
5. 中性侧栏、白/暗色编辑面、细分隔和统一字级；保留可辨认焦点，不堆渐变、彩框与小卡片。
6. 地图/文档/设定使用同一工作区高度与工具栏；地图画布缩放拖动不变，长规则编辑不截断内容或改存储合同。
7. 1440/900/390 检查首屏、长内容和暗色；窄屏允许顺序面板/目录抽屉但必须有回程，不强塞桌面三栏。
8. 先拍共享 chrome 与代表工作台，再扩展局部页面；截图真实查看。视觉改善是待用户判断，不用测试数字代替审美验收。

用户授权直接实施。已核实 [VS Code 树与视图](https://code.visualstudio.com/api/ux-guidelines/views)、[选择/焦点主题语义](https://code.visualstudio.com/api/references/theme-color#lists-and-trees) 和 [Apple 按钮](https://developer.apple.com/design/human-interface-guidelines/buttons)（官方 DocC 正文）：复用图标，命令与内容目录分开；悬停、无焦点选中、有焦点选中分态；按钮需要按下反馈，主要操作通过样式而非更大尺寸突出。

- Pinax 自定尺寸（非官方像素规范）：桌面侧栏基准 240px，目录主字 14px/辅助字 12px，主导航 36px/树行 32px，图标 16px。窄屏保留现有抽屉/分栏断点，触屏命中区扩展。
- 共享 opt-in 导航类是状态 owner；页面只负责布局和目录内容。漫画缩略图、文档摘要、素材复合行可变高，不压成同一种列表。
- 悬停使用中性底色，当前项失焦时灰底、栏内焦点时淡强调色；键盘焦点有轮廓。禁止选中导致边框挤位、悬停抬升/缩放。
- 复用现有 control 七类语义，不引入 UI 依赖；普通/主要/危险动作分层，禁用不接受悬停/按下高亮，减少动态效果偏好受尊重。
