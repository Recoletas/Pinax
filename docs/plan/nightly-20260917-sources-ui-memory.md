## 2. 三线共享的产品边界

```text
书稿正文 ──安全保存/恢复──→ 编辑版本
    │ 已保存且满足提取边界
    ▼
资料原件/正文证据 → 有界提取任务 → 待审提案 → 作者采纳 → 设定条目或记忆事实
                         │                             │
                     状态/失败原因                 版本/来源/时间
                                                       ▼
                                    写作、助手、推演及适用模块的冻结读取
```

原始资料、素材、世界书条目、事实、版本各有既有 owner。统一入口和引用，不把它们全部拷进“万能资料表”。提取提案不能提前成为角色知识；编辑撤销、版本恢复与撤回事实也不共用一个含糊的“恢复”动作。

## 4. 接口先落地，分支依赖不成环

T+45 分钟前交换三个小合同和一份 fixture：

1. **AC-SOURCE-v1**：book/worldbook 归属、source ID/hash/revision、archiveRef/chunk locator、访问/共享范围、删除与来源更新事件。A 提供真实归档 reader，C 校验冻结证据；资料标题相同不等于身份相同。
2. **AC-EXTRACT-v1**：job ID、来源快照、目标 `setting` 或 `memory`、状态、进度、取消、失败重试与产出提案引用。C 负责统一调度/证据基础，A 保留现有设定提取 adapter；统一任务语义，不强行把两类结果改成同一 schema。
3. **B-UI-v1**：图标语义、按钮/输入尺寸、焦点/禁用/等待/错误状态、目录密度与窄屏策略。B 交真实原语/样例，A/C 在自己的 UI 中接用。

这些名称是本计划交接编号，不要求新建三个同名文件或第二套框架。优先补齐现有合同。

依赖按“纯合同小提交 → provider/domain 实现提交 → 页面消费提交”单向推进。比如 C 提取基础先只消费来源接口，A 装配真实归档 reader；C 的 Authoring 最终接入再消费 A 的就绪组件。禁止双方整条分支循环合并。每次交接记录 SHA、包含的依赖、fixture 和接线 owner；生产组合测试必须实际包含这些提交。

## 6. 组合验收：同一份书贯穿三线

使用隔离 profile 的“雾港纪事”合成书与另一书；建共享世界书反例，使用真实路由、repository、IndexedDB 和生产 transport 拦截。最低旅程：

1. 从正文落笔处进设定资料，导入文本、设定 JSON 和一份失败文件；成功来源保留，刷新仍可管理，返回同书同章原位置。
2. 选择资料提取人物/地点，审阅后采纳；人物、设定、地图适用条目和助手引用同一内容，切另一书不串库。
3. 输入 `asdfgh`，等待自动保存、切章再回来；正文保留，记忆候选/语义历史不增加无意义条目，编辑版本也不每次保存刷一行。
4. 写入“莉娜没有钥匙。”和有后文纠正的事件；经模型提取产生有引文的待审事实，未确认前不进入事实召回，确认后捕获生产请求确实使用正确内容与否定语义。
5. 修改/删除来源、切书、取消任务、重复提交；迟到结果不能写错项目，拒绝项不反复弹出；失败保留已完成来源，重试不重复正式事实。
6. 历史查旧时点能看到当时证据；恢复旧正文创建新版本，已确认事实保持审计链并按来源政策待复核，不被静默重写。
7. 导出 ZIP→隔离新 profile 恢复→从实际 UI 读到资料、待审任务、事实及历史；注入中途失败，原库保持可用。
8. 对这条旅程检查 1440/1024/900/390、1440 暗色、200% 缩放、键盘/IME；临时弹层不抢正文输入、不遮确认/取消，关闭回到原上下文。

各线完成前 `npm run verify:full` 必须 exit 0；组合后再跑一次。必要的新增反例并入原核心测试，长链通过显式 smoke/eval 覆盖。已通过后只因代码变化、失败或未解决风险复跑。

确定性 transport 测试证明接线；真实 LLM 样本证明提取质量；截图证明布局；用户确认决定视觉是否满意。四者分开报告，不能互相替代。真实模型仅用启动时已授权渠道与额度；未具备时完成所有离线工作并把质量门禁标未运行，不报告“LLM 提取已完善”。
