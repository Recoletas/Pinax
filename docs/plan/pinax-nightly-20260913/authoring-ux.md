# C 线：从第一次落笔到可靠采纳

从属于[夜间总任务书](../pinax-nightly-storyforge-public-alpha-20260913.md)。C00–C09为主队列，C10–C13为备用。目标480分钟，逐包估算425–585分钟，包含UI接线、截图、集中修复与分线封板；上界超过一晚时按总任务书保核心闭环、缩减低优先精修并如实留残余，不人为等待。

## 1. 本夜八条视觉与交互硬约束

1. 正文和章名仍是主视觉。长章名允许合理换行；已保存、交换、关闭不能占据章名所需空间。
2. 保持现有右栏推演；≤1180继续正文之后的顺序流，不重新引入覆盖稿面的推演层或第二编辑工作区。
3. 一条信息只有一个主要显示位置。后果放既有“局面变化”，对照先给具体差异；不新加常驻账本、密集徽章或技术仪表。
4. 正常首屏的指引只给当前一步和一个明确主动作。可以关闭、主动重开，不能强迫配置AI或完成教程。
5. 操作作者内容前后保持作者意图：输入、手改标题、选区、当前对象不能被异步结果或换工具悄悄覆盖。
6. 只有保存失败、恢复副本、模型失败等需要处理的状态才突出自救；正常“已保存”保持安静，失败提示有具体可执行动作。
7. 按项目现有theme2 `legacy`和token打磨。字体/留白/层级服务阅读；触控主动作≥44px；IME不被Enter、Esc或全局快捷键误截断。
8. 先做一个代表态，再推广同类切片。O必须亲自看截图；几何通过和用户审美确认分别报告。

视觉基准参照仓库[视觉工作流](../../engineering/visual-alignment-workflow.md)。本夜只做既有工作面的小切片，不新增主题、全站导航壳、通用dialog框架或强制遮罩教程。

## 3. 主任务队列

### C00 · 新作者、回访与错误状态基线（20–30分钟）

依赖O00。用合成书/长章名/120章代表样本记录Welcome空库/有书、导入预览、保存失败、备份、推演失败和对照。

首轮优先1440×900、390×844、720×450；每态写明主信息、主动作、返回、未保存草稿owner。基线发现现状已合格可标verified-existing，不做虚假重构；随后直接领取主队列下一包。

完成：4–6张能看到真实操作对象的基线，指出最值得修的具体位置。截图能力不可用时继续流程和状态修复，但不扩写全页CSS或声称整屏视觉通过。

### C01 · 首次指引按书归属，陪作者看到结果（50–65分钟）

依赖C00。当前指引来自query，创建`rehearsal.run`就dismiss；重构为一个小`useAuthoringFirstRun`，只拥有激活书、主动关闭/重开与阶段投影，不拥有正文和推演状态。

阶段依据真实产物：正文存在→人物/现场就绪→已发起试演→收到回应→进入可编辑试稿→已采纳或作者主动结束。打开推演、点击生成、创建run都不能冒充已收到回应或已采纳。可按界面语义把后两步合为一条提示，但不能伪造完成勾选。

回应出现后，提示归右栏的同一个位置，避免稿面和右栏重复。作者看试稿时可看到“这里仍可修改”，采纳动作永远由作者决定；跳过试稿继续纯写作是合法结束。

指引绑定当前书，切到B不带A进度；已关闭的不因刷新重复出现。若持久化关闭偏好，复用现有设置owner，只保存教程偏好，不存一套正文/人物/试演事实副本。已有作品不自动开启。

提供既有更多/帮助里的“继续创作指引”，不增加常驻新导航。重开按真实当前状态计算阶段；找不到原书则回作品选择，不能打开别的书伪续接。

完成：J01/J05含成功与失败路径，第一步模型失败时仍保留明确下一动作；390只显示当前一步，不挡输入。

### C02 · 回访作者优先回到作品（30–45分钟）

依赖C00，可与C01顺序交换。已有作品时，同一Welcome组件调整层级：最近作品是首要内容，主动作“继续《书名》”或准确的“打开书稿”；新建/导入仍可见但从属于当前目标。首次空库保留已有两条主路径。

移动端最近作品必须在第一屏有入口，避免先经过大段欢迎介绍。用现有最近书/章节路由信息，无法恢复光标就不宣传精确续写。书名允许两行、完整可访问名称，不用多层卡片放计数与产品标签。

反例：0/1/3本、长书名、空名、最近书被外部删除、关联库缺失。点继续不新建书、不附first-run、不静默选另一书。

完成：J02在390和1440正常打开预期book/章，返回作者首要动作更短更显眼。

### C03 · 导入预览的异步与手工修改保护（65–85分钟）

依赖C00。当前读取无完整generation/ticket；编码重解析会重置人工书名/章名；手动编码只在warning态可达。

实现可见读取状态和一次性身份：A读取→改选B→A晚返回只能丢弃；取消/卸载后不得复活预览或创建书。反复选择同名文件要有效；确认提交有busy状态、仅一份创建操作，写入失败保留预览可重试。

文件原始名、自动识别名、作者改名分别对待。书名不随编码重解析被覆盖；章名只在确切段落边界/内容对应关系仍成立时保留，不能盲按序号套到新章。结构变化将丢作者编辑时，在当前预览给简短说明和保留/取消路径，不弹多层确认。

手动编码放可折叠“识别不对？调整编码”，正常识别也能打开；失败保留当前文件和作者书名。120章只用简单折叠/分页等现有结构控制高度，确有测量瓶颈才优化，不先建虚拟列表。

确认失败显示在对话框内，不能仅依赖外层短toast。焦点从重新选择回可见picker、从错误回能解决它的控件；关闭回原导入入口。

完成：J03/J04；加空文件、5MB超限、乱码/手动编码、章数极限、quota失败。390/720×450确认动作可达，正常UTF-8/GB18030旧路径不回归。

### C04 · 备份和恢复先说作者的数据（40–55分钟）

依赖C00。复用现有备份plan/确认/回滚。将设置存储区排序为：数据保存位置→导出/恢复→本次结果→按需技术详情。原localStorage key表收进折叠，不在第一次寻求备份时迎面展示。

导入预览使用备份真实metadata表达包含什么、将影响什么；不知道书数就不把键数换名成书数。保留既有旧数据风险确认，默认导出仍排除密钥，仍说明媒体/来源原件不在JSON备份内。

成功反馈用“备份已恢复，可回到书稿”；仅有准确目标时给直达该书，否则到作品列表。当前用户已有数据时不自动恢复覆盖。损坏、版本不兼容、quota失败各给可执行下一步。

完成：J12的真实UI导出→隔离浏览器恢复→打开预期作品并核对一段正文；取消零写入，失败仍保留旧数据。B低敏诊断的字段边界不被UI统计扩张。

### C05 · 保存失败和恢复副本的直接自救（40–55分钟）

依赖C00。当前恢复副本主要藏在版本面板，正常稿面只有状态字。仅错误/检测到恢复副本时，用既有通知owner提供紧凑持久动作：“重试保存”“导出当前正文”“查看恢复稿”。

导出必须获取当前可见且未保存的实际正文，不能再从旧持久化副本读取。查看恢复稿复用原历史面板和恢复事务；展示时间及短预览帮助选择，不自动恢复/删除副本。正常保存成功后退场，不留下醒目“已保存”状态抢章名。

失败通知不能抢焦点、把作者挤离首行或截断输入；模型错误、正文保存错误有不同出口，不能用同一个“重试”执行不相关请求。

完成：拒写→继续保留输入→导出正确文字→恢复/重试→成功退场；刷新后恢复副本入口仍可找到；用户取消不改变正文。正文事务及保护快照owner无复制。

### C06 · 分支后果对照与失败就地回程（65–85分钟）

依赖A02首次DTO；A05/A06达到api-ready即可完成接线，最终纵切与A一起由O验收，不要求双方先accepted才开始。无接口时先继续C03–C05/C07，不空等。只可用合同double做代表片，集成验收必须切成正常服务链。

**真实作者必须能建立本次知情条件。** 在既有推演起点用一处可选“补充本次条件”轻入口，填写一条事实并选择谁已知、谁由作者明确确认不知情；不指定就是未记录。提交只调用A的baseline冻结接口，不写人物数据库、不改变正式设定。已有步后改条件需形成新起点并说明旧路仅供回看，不能把新事实悄悄补进旧路。未配置仍可正常推演，知识对照诚实显示未记录；不能要求用户会编fixture JSON。

每步既有“局面变化”折叠里显示人物名+事实句；普通阅读保持动作和人物回应为主。对照在现有两路内容前增加最多3项关键后果差异，更多按需展开，保留每条来源步跳转。只在区块上一处标“仅在这些走法中”，每行不重复警告。

差异允许无结果，允许“一路未记录”，不能猜成“另一路不知道”。不露kind/ref/fingerprint/ledger等内部字段，不新建表格后台。共同前缀不计为分歧；切路与查看对照零模型调用。

无效后果/模型失败保留旧路、草拟行动、行动者/对象。给一次显式重试和“检查模型连接”入口，打开既有设置后关闭回原行动。stale使用重新起点，不让重试绕过冻结版本；取消不显示为成功或故障警报。

Authoring转稿入口使用A的冻结draftSource，异路已有Ghost继续受保护。C不改rehearsal composable，不从自由文本猜状态。

完成：J06–J10，包含A点转稿后立即切B、比较不同深度和错误设置回程；真实模型质量由A独立判读，C不拿漂亮fixture冒充质量。

### C07 · 设置与导入的键盘和焦点（35–50分钟）

依赖C03/C04。SettingsPopup已有`aria-modal`但缺完整Tab containment、初次挂载焦点与返回。优先复用已有可靠helper；仅必要时加小的可复用函数，不能再创建通用弹窗系统。

首次打开聚焦合理标题/首动作；Tab与Shift+Tab不漏背景，禁用/隐藏控件不入序列；关闭按确切触发器返回，触发器被删除则回安全容器。嵌套模型配置先关闭内层，Esc不得一次全部关闭；组合输入Esc不乱触发。

设置分区有真实role/aria关系和合理键盘切换；短屏body滚动、标题关闭可达；触控关闭≥44px。设置有多个入口时不能只修Welcome来源。

完成：J14包含Welcome、稿面、推演错误三个入口；背景编辑器不接键盘，不出现关闭后光标跳远。

### C08 · 长名称、窄屏与原位帮助的集中精修（35–50分钟）

依赖C01–C07，A接口已接。覆盖1440×900、1280×800、1024×768、900暗色、720×450、390×844。正常阅读、对照、试稿、长行动/错误各选代表态，不拍每种宽度所有排列组合。

看第一眼正文与章名是否清楚；长后果能换行，底部输入和sticky回正文真实处于视口；回读新回应不抢滚动；切其他工具不留推演布局。确认按钮不能靠滚动到不存在的容器才可点。

帮助只放现有更多/帮助内的一层入口：“创作指引”“备份与恢复”“反馈”。解释批注与推演用具体动作两句即可：批注修改已有文字，推演试接下来的人物行动；不铺常驻说明。同步C负责的两份手册，交B准确文案和截图。

真实浏览器200%能测则测；缩视口需写压力近似，不称真机软键盘。支持reduced-motion，合成IME不等于真机中文输入法耐久。

完成：J13/14以及8–12张最终精选号；O逐张看后提出的同类问题集中修正一次。

### C09 · 五条作者旅程、修复与封板（45–65分钟）

依赖C01–C08。完整跑首次创作、返回作品、导入失败恢复、保存/备份自救、推演对照与设置回程五条主路径；检查真实data/route/request结果，不能只断言文案出现。

现有Web beta与rehearsal Gate按最少必要增量维护，保留旧缺陷反例。满足项目skill的分线`verify:full`与UI证据后交O；O对组合树再做最后验证。

summary含状态/前后图/commit/未验项，禁止因所有mock绿就说真实趣味性通过。还有就绪储备时继续领取，T+6:30后收口不再开启新视觉主题。

## 4. 自动续接的储备

### C10 · 原创练习书：没旧稿也能立即试（55–80分钟）

前置：C01/C03/B07完成，首访入口仍保持简洁。利用既有导入/新建路径提供一份原创短场、两人物和明确秘密/承诺冲突的合成样例；点“用示例试一场”才创建独立练习书，不能把样例塞进用户作品。

同一按钮反复点击不重复建库/建书；样例有清楚名字和删除方式；失败回滚仍走既有repository。无Key可写、可改、可看设定；真实推演要配置时诚实说明。

优先提供可下载导入样例与正常推演。若要演示预写回应，明确“预置示例，非实时生成”，不得建立假provider或伪造请求/完成状态；若需要另一个run模式，本夜停止该扩张。

完成：全新浏览器可以主动导入并走向当前场和推演入口，示例资料无权属疑点，B可用于公共演示。

### C11 · 资料目录小屏与人物头像失败反馈（45–70分钟）

前置：C00已完成且C01/C03的页面改动已稳定；主包全部完成或当前主包依赖A而暂无可推进任务时可领取。先拍390长目录/详情/搜索空态，不把既有可用堆叠强改为另一个全屏形态。优先选中项定位、无结果清除搜索、长姓名/长设定可读、当前对象关闭/返回。

人物头像上传遇格式/5MB无效文件当前可能直接return，提供贴近头像的错误/重选；读图中切人物，旧结果不能写到新人物。补实际失败反例而非扩张图片格式/媒体系统。

完成：一位具体人物的图和字段归属正确，截图可见错误出口；原current scene/worldbook保存合同仍不变。

### C12 · Authoring一个纯显示职责的抽取（45–65分钟）

前置：C01已提取指引owner且稳定；核心无视觉红项。候选为现有历史面板显示段：以snapshots/recovery props渲染，emit查看/恢复/删除动作；所有保存恢复事务仍留现有owner。

以责任清楚和独立可审阅为目标，不立“必须减少两千行”指标。抽取后同一选区/恢复/关闭行为可复验，避免新组件因v-if生命周期变化丢草稿或焦点。

完成：一个明确职责离开巨型页面、依赖减少，旧块无重复残留，真实恢复路径仍可走；不进行整页脚本/模板机械拆分。

### C13 · 作者逐项记住已采用的后果（与A11共同，60–100分钟）

前置：A11/O批准及足够早的跨线窗口；本包只能与A11一起成为完整交付。正文真正采用并保存后，在现有采纳反馈/记忆入口给“记住一项变化”，默认无勾选、不自动写。

候选从实际已采用的正文定位，展示来源句并允许改/放弃；选中才进入原pending队列。解决现有普通pending被UI过滤的可达问题，按显式来源提供入口；不让所有历史pending突然弹出。

确认、拒绝、刷新后再审、重复点击和删除原句导致stale全部沿既有记忆流程。用户未选择不写任何记忆；需要看技术ref才能理解的实现不合格。

完成：一条本路承诺可在作者确认后进入已有记忆，另一条未选秘密不写；正文保存失败无candidate。只有enqueue而无审阅入口视为未完成，整片不进入候选版本。
