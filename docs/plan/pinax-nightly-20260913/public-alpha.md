# B 线：可参与、可复现的 Public Alpha 仓库

从属于[夜间总任务书](../pinax-nightly-storyforge-public-alpha-20260913.md)。B00–B09是主队列，B10–B13是自动续接储备。目标480分钟，逐包估算405–555分钟；公开和许可证决定只影响最终发布，不阻塞其他实现。超出截止的主包逐项保留未完成状态。

## 1. 目标与证据

一名陌生开发者按照 README，在干净 Node 环境安装、打开网页、无模型密钥写一段并导出备份；他知道如何提交一个范围清楚的修改，也知道哪些数据不能公开上传。维护者能根据低敏诊断定位到具体构建。CI能够阻断新出现的真实错误。

已查到的现实缺口：

- README 已要求 Node 22.x≥22.13，CI两job还用20；锁定pdfjs-dist6/Electron42已要求22系列。
- ESLint调研输出499文件、259 errors/265 warnings；其中两个Vue顺序规则各86项，重复噪音大；66个no-undef相当部分属于测试/Node环境识别问题。
- `authoringWorldbookBinding.test.js` 重复导入，`ProseEssay.vue` 三处 `createSnapshot` 无定义/导入，是必须进一步复现的正确性问题。
- CONTRIBUTING、SECURITY和Issue/PR模板缺失；已有THIRD_PARTY_NOTICES和字体OFL，不重复从零写。
- `docs/demo` 虽在ignore中，仍有15个tracked图；必须按Git实际公开面清点。
- 低敏诊断只有package版本1.0.0，缺commit；VitePress使用`ignoreDeadLinks:true`，build通过不证明链接有效。

数字是编制时实跑，不是夜间验收结果。每项启动时复核，只修仍存在的问题。

## 2. 文件所有权

B独占：

- `.github/workflows/ci.yml`、新Issue/PR模板；`CONTRIBUTING.md`、`SECURITY.md`、`README.md`。
- `package.json`、`package-lock.json`、`.nvmrc`、`eslint.config.js`、`vite.config.js`的必要构建标识接缝。
- `src/utils/betaDiagnosticExport.js`、一个小build-info helper。
- `THIRD_PARTY_NOTICES.md`的有证据补充；`docs/engineering/public-alpha-*.md`、公共开发/能力说明。
- 一个简短环境诊断脚本、必要的CI smoke协调脚本、有限范围的新增错误检查；优先复用现有脚本，不要求每一门禁都新建工具。
- `src/__tests__/authoringWorldbookBinding.test.js`的重复import修复，不触碰其业务断言。

O00/O01给B以上配置文件单一写权。A/C若需加script或build define，发精确变更建议，由B整合。C独占页面/SettingsPopup/用户手册/原Web beta Gate；B消费公开命令，不同时改选择器。

`LICENSE`保持原样。未知权属素材只做清单和公开阻断项，不从用户项目删除。AGENTS、skill、STATUS结构不属于B任务；需要变更时提交O审查。

## 3. 主任务队列

### B00 · 公开面、运行环境与交付清单（20–30分钟）

依赖O00。记录HEAD、Node/npm、当前与拟公开refs、tracked/ignored目录、CI脚本及现有第三方说明。建立本轮`public-readiness.md`，每项有证据/owner/状态。

区分“源仓库公开”和“过滤过的发行包可发”。公开仓库会带历史与可见分支；过滤一个zip不等于历史已经安全。现有remote地址若含凭据，仅记录host/repo标识，禁止原样输出。

完成：可以看出哪项已证实、哪项待扫描、哪项属于作者决策。不要把readme清单中的check mark当作验证。

### B01 · 当前树与历史的可公开核查（45–65分钟）

依赖B00。使用可用的可靠扫描工具以redact模式检查当前tracked内容及拟公开的全部refs历史；记录工具版本、范围、跳过项和耗时。不要仅搜索`.env`文件名便宣告无密钥。

路径和内容扫描同时覆盖：真实凭据、用户dump/备份、硬编码私人端点、日志、示例稿件及tracked演示图。二进制不能文字扫描时如实说明，精选人工检查将公开的图片。输出规则ID、文件、commit和分类，不输出命中值、前后缀或完整上下文。

没有现成工具时可使用最小本地检查辅助，但必须标“启发式、非完整审计”；不花整晚安装审计平台。单项网络/安装失败30分钟无进展转其他包，后续再收口。

完成：`current-tree / history / binary-assets`分别有结果。疑似泄露列待确认，不自动删除、轮换或rewrite history；公开动作保持阻断，A/C不受影响。

### B02 · 来源许可与当前开放定位（35–50分钟）

依赖B00，可与B01分阶段交错。扩充已有notices的真实覆盖：依赖许可、复制改写、算法启发、字体、人物图、媒体、预设文本、公开截图。优先梳理首屏和发行包会用到的资产，unknown不得猜为原创/AI生成。

在开发文档新增简洁决策页：当前PolyForm NC的准确用语、AGPL与Apache/MIT的影响、何时需要处理外部贡献再许可。只准备对照，不改LICENSE，不预先采用CLA或DCO；明确DCO不转让版权，AGPL允许商业经营。

完成：每个高可见资产有来源证据或unknown负责人；已有OFL/地图notices保留；README当前许可与LICENSE一致。不能因素材来源暂缺就删光演示或替换版权声明。

### B03 · 统一Node与可理解的环境诊断（50–65分钟）

依赖B00。按锁定依赖和现有README统一Node22最低22.13、CI和本地声明；记录实际验证patch版本。必要的engines/packageManager/nvmrc选最少能减少误装的一组，不引入多套工具链。

**B00之后先交B03的启动配置首片，再做长审查。** 当前vite.config的`/api`、`/ws`和`/docs/user-manual`全部硬编码3001；O分配3010–3013不会自动生效。用一个仅dev配置读取的`PINAX_DEV_BACKEND_ORIGIN`参数统一派生代理目标，默认保持现有3001；不可把整份.env或Key透传到前端。O确认首片后交A/C/O使用，核对API确实到本树后端，不能仅测前端页面200。

提供小型只读`doctor`或等价现有命令：检查Node、安装依赖入口、必要端口和server配置存在性；没有模型密钥时说明“普通写作可用，AI待配置”。变量仅输出名称与布尔状态，不记录长度或值。不得自动覆盖.env、自动起服务或自动请求模型。

验证正确环境、过低版本、端口占用、没有Key四种情况。环境报错需给准确下一步，不泛化成“重装所有依赖”。在本线干净临时clone执行一次正常`npm ci`，不复用node_modules、不把`--ignore-scripts`当成功安装。

完成：照README可启动前后端或清楚知道何者可选；原生依赖/下载失败按具体层记录。不得用旧dist证明新源码可运行。

### B04 · 把lint恢复成有用的错误检查（50–65分钟）

依赖B03。先按rule统计基线，正确区分Vue/browser、Node/server/scripts、Vitest环境。去掉重复的组件顺序强制，避免为了style批量搬动数十个Vue文件；保留重要解析、未定义、重复键等检查。

修已确认的重复import。其他热文件错误交A/C对应owner；与UI无关的精确小修由B处理。若存量不能一夜清完，建立可审查的窄基线：逐文件/规则/已知位置或稳定指纹，不用一个总数上限允许旧错消失换新错；新增/改名/未跟踪文件必须纳入，新违规不能自动更新基线。

在临时合成副本验证一个新未定义变量和一个重复import会使门禁失败，然后移除探针；不污染产品代码。不允许全局关掉`no-undef`、`|| true`吞退出码或仅允许清单中的新文件被忽略。

完成：说明减少的是配置误报还是实际代码错误；公共命令能阻止新的correctness问题。禁止宣称“零warning”若只是把warning改off。

### B05 · CI跑到作者主路径（50–65分钟）

依赖B03/B04、C给首访稳定入口。统一CI与本地验证：核心预算、Vite、diff、VitePress由现有verify链执行；加B04的有效lint检查；选一条无密钥的Chromium新建/导入/刷新/备份旅程。

可从既有`web-beta-onboarding-check.mjs`增加有限smoke模式，由C负责原脚本变更；B只写服务/命令协调。若现有脚本强依赖本地fixture，先补合成播种和可配置BASE/OUT_DIR，不能把用户缓存目录带到CI。

进程只起本job端口，记录PID，ready检查后开始，finally停止自己服务。默认所有模型请求mock或拒绝，任何未匹配provider请求让job失败。GitHub PR运行不需真实Key和手稿。

CI在干净checkout中无参数`git diff --check`可能什么也没检查；PR要显式获取正确base并执行base→HEAD范围检查。B04差分lint用同一个基准，新增文件和改名必须覆盖；push job按其事件明确范围，缺基准要报错或执行可解释的全树检查，不能静默当无变更成功。

失败产物为脱敏短日志/截图，成功保留摘要；以约5–10分钟的CI浏览器切片为目标，不让每个PR跑全量数百UI探针。故意破坏一个核心断言必须得到非零退出，复原后再验证。

完成：本地同一命令能重跑；远端workflow尚未实际跑时明确“本地等价命令通过，GitHub运行待push”。

### B06 · 外部贡献与安全反馈入口（35–45分钟）

依赖B02。新增CONTRIBUTING、SECURITY、Bug/功能模板和PR模板。贡献指南链接仓库现有代码地图/skills，不复制多套命令或要求每个小文案变更运行真实模型。

贡献说明五件事：解决的作者任务、入口、读取资料、临时/正式写入、验证范围。UI需前后截图，模型功能需分开报告mock/真实样本，不要求上传私稿、API Key、全量浏览器dump。

安全反馈渠道只写已存在的联系入口。若GitHub私报尚未启用、维护邮箱未知，精确列为公开前设置项；不凭StoryForge的SECURITY捏造Pinax已启用的功能或邮箱。

完成：陌生贡献者能选一个provider/导入/文档小任务并知道入口与门禁。另存5个本地good-first-issue草案，每个有文件、收益、验收，禁止自动发到GitHub。

### B07 · 公共README与能力分级（45–60分钟）

依赖B02/B03/C关键交付。README用户与开发入口分清：一句价值、真实操作截图、15分钟闭环、数据边界、安装、贡献、许可；不铺十几个平级产品，不写虚构用户数、性能或社区规模。

能力表覆盖写作/导入/备份/设定往返/推演/人物IF/地图/媒体/协作/桌面。用“可用/实验/未验”加证据解释，不用测试总数替代成熟度。部署维持现有main→server-version方式，说明生产适配但不开发完整Web运维线。

C负责`docs/user-manual/01-quickstart.md`和`10-beta-guide.md`按实际UI更新；B核对README与之无冲突。VitePress允许dead links不等于文档正确，本夜新增/改动链接必须直接解析；公共根页中指向不存在材料的链接必须修掉或诚实移除。

计划编制时已实测PLAN/LOG/旧current看板17处历史断链，均在HEAD基线存在。公共入口指到这些历史材料时，优先换成现存归档/提交链接或撤下无效引用；没有材料不虚构内容。B13再扩展历史索引清理，别把本夜新增链接通过误写成全仓链接全绿。

完成：截图来自本夜合成项目实际版本；只能打开书稿时不宣称恢复精确光标；当前许可不称OSI开源；未生成的发行URL不写“下载”。英文短入口可做，但不要求整站翻译。

### B08 · 构建身份与低敏诊断（30–45分钟）

依赖B03，C不改其pure helper。编译期注入白名单build info：packageVersion、短commit SHA、构建channel；无.git的源码包明确unknown，不把本机路径、branch私名或环境变量整体注入前端。

诊断接入该信息，现有隐私边界保持：无书名、作品ID、正文、模型配置秘密、URL query/hash、提示词或模型回复。Settings显示如果需要，由C做一处绑定，不让B抢UI文件。

验证相同源码身份可核对、不同源码构建可区分、zip无.git不崩溃；本地工作树未提交时可以声明dirty状态，但不把本机修改内容打进元数据。

完成：一次内测反馈能映射候选版本，package现有1.0.0不擅自改为“稳定版”。候选标签名称写说明，夜间不创建发布tag。

### B09 · 干净环境与公共候选封板（45–65分钟）

依赖B00–B08。在最终候选源码的干净clone/隔离目录执行README命令，确认正常npm ci、doctor、verify、无Key浏览器smoke。优先对最终组合树验证；本线早期环境验证不需要在没有依赖变更时重复下载多次。

产出源码SHA、构建命令、产物hash/文件清单、实际Node/npm、门禁结果、现有许可、未验项。能打一个明确过滤范围的本地包，但不得因此声称Git仓库历史审查已完成。

完成分线自审与`verify:full`，交O README预览、环境证据、Public Alpha checklist；公开/换证/素材权属/安全渠道尚有决策时逐项留出，不阻塞其他已合格的工程改进。

## 4. 提前完成后的储备

完成：真实页面至少一条旧实现可复现错误、三条修后可走；只改相关路径。若源文件已被其他line修复，记录证据接B11。

### B11 · 首访和Authoring实际初载诊断（45–70分钟）

前置：B05/C09基本可用。测生产构建冷加载请求、route chunk与JS体积；记录同一设备/缓存条件下基线。只有证据显示地图、媒体等非首访必需大依赖进入初载，才修最小惰性边界。

### B12 · 依赖小修与源码可达性清理（45–60分钟）

完成：真实缺陷/不必要初载/确定孤儿至少一种有闭环证据，或清楚给出未变更原因；不把零修改清单包装成代码优化成果。

### B13 · 公共文档和演示复现加深（40–60分钟）

前置：B07及C截图完成。做一个1分钟演示脚本与准确英文短入口、整理合成旧/新格式备份样例、把链接检查覆盖到Public Alpha关键阅读路径。维护者命令、安装路径和允许贡献范围相互一致。

## 5. B线的验收用语

- “源码可公开风险核查完成”必须写扫描范围；当前树通过不等于全部历史通过。
- “本地CI等价命令通过”不等于GitHub Actions已执行。
- “依赖带许可文件”不等于全部图片/示例文字的权属已确认。
- “Public Alpha候选就绪”不等于已发布、已换许可证或能承诺生产服务。
- 无模型密钥下写作、导入和备份应可用；AI不可用的提示不能成为首次写作的硬阻断。

summary先列真正阻断公开的项，再给本夜已改善的工程事实和精确候选。保留当前许可证，在用户决定公开动作前准备好所有可审查材料。
