## 1. 本轮必须改变的交付方式

目标不是“已有事实表”，而是作者写作、检索、跑团、备份时真正使用同一个可追溯的记忆系统。
首批回执里的“A01–A18 completed（含 partial）”不能作为整线完成判据。接线与验收未完成就是 partial，模块接口存在只能证明模块已实现。

本次明确扩成 **48 项续跑任务、8 个连续工作阶段**：

1. 首批可靠性修正与实际验收。
2. 生产读取、归档、备份完整接线。
3. 永久历史和规模查询。
4. 角色知情与信息来源。
5. 来源变化、增量提议与过期治理。
6. 时间冲突与实体消歧。
7. 作者审核工作台和真实检索质量。
8. 候选真源迁移准备、恢复与发布验收。

阶段 1–3 是下一批交付必做；4–7 是接续主队列，不再只写“有空再做”。阶段 8 含需要单独批准的迁移开关，不允许为了完成任务数强制迁移用户数据。
如果阶段提前完成且剩余窗口可覆盖下一包的实现、验证和回滚，就按序继续；单次 worker final 不代表整线关闭。
不承诺一个固定夜窗完成全部 48 项；剩余任务必须有精确状态和下一动作，而非以“P0 完成”归零。

## 3. 目标数据流与唯一 owner

```text
正文/设定/会话已提交来源
  → 冻结来源版本 → 增量提议 → 作者审阅 → 正式事实版本/决定账
                                             ↓
历史时点 + 作品范围 + 角色视角 → 只读检索 → 冻结模型引用清单

已提交跑团回合 → 会话 durable outbox → 永久回执账 → 分支历史阅读
```

- proposal、canonicalFact、sessionEvent、derivedClaim、authorPreference 继续分层。
- A 是事实/证据/记忆的唯一数据 owner，负责生产reader、历史桥接和全域备份装配；C 是动作/规则/会话运行态 owner。夜间不设 O，白天 Codex 统一审查合并。
- A 必须完成 memory 域生产适配器、分页、来源解析和备份参与器及其真实装配，不把接线留给白天。
- `projectMemoryReader`、明确列名的 knowledge source adapter 和统一 ZIP 写锁按调度修订直接交 A；不得扩大到未登记共享文件。
- session coordinator 由 C 操作，A 不旁路写 gameStore；跨域契约由 A/C 在首个检查点冻结。

被共享锁挡住时，A 继续 AX13/AX15/AX19 等域内任务；共享门禁保持 blocked，不能把功能称已接通。

### 恢复事务合同

- 导出捕获 schema、scope、snapshotSeq、引用表和媒体/来源版本；导出过程中改稿不改变已冻结内容。
- 导入先校验再写；ID 冲突、scope 不合法、seq 元数据不匹配、证据缺失给具体预览。
- sequence 元数据应覆盖导入数据最大 seq，不能恢复后分配重复序号；导入不同导出时点同一事实涉及已作废元数据时有明确冲突策略。
- 补偿必须包含本次改过的可变 meta，不只删除新增事实；补偿失败留下可诊断恢复状态，不假报成功。
- 敏感原文、请求密钥不进入公开日志；测试仅使用合成书稿。

## 7. 阶段四：角色认知，不再把作者全知交给角色（AX19–AX24）

### 最小模型

新 `knowledgeEvents` 记录：id、scope、characterRef、claimVersionRef/evidenceRef、kind、storyTime、recordedSeq、sourceCharacterRef?、sourceEventRef、visibility、supersedes?。
kind 至少区分 witnessed、told、inferred、belief-retracted；“知道”与“相信”不能由同一个布尔字段概括。
作者确认事实不自动生成任何角色知情记录；角色被告知假消息，可以“相信一个非正式事实的说法”，但不能把假消息提升为 canonicalFact。

| ID | 实施内容 | 接受条件 |
|---|---|---|
| AX19 | 知情事件 schema/来源/范围 ADR与实现 | 知情时间独立于记录时间和事实有效时间；无证据不自动添加人物 |
| AX20 | 获知/被告知/推断/撤回命令 | 都有 actor/source/理由；幂等；撤回不删除旧认知史 |
| AX21 | `readCharacterKnowledge` 权限投影 | 仅该角色该分支该时点可见；无记录返回 unknown，不回退全库 |
| AX22 | A/C 角色上下文连接 | C 提可信 viewerRef，A 返回有界知识块；GM资料不穿透 player payload |
| AX23 | 作者可视化知情时间与来源 | 人物详情可查看“谁告诉他/何时/来自哪一场”；缺来源可见但不伪造 |
| AX24 | 认知反例矩阵与分支继承 | 甲见真相、乙听谣言、丙不知；同书异支路不能共享新知情 |

本阶段不做默认自动全图传播。传话是明确事件；“甲知道且甲认识乙”绝不推出“乙知道”。
冲突消息保留多个 belief/evidence，UI 显示不同来源，不简单覆盖为最新一句。
匿名/全知作者视角与角色视角必须显式不同，不能调用失败就偷偷切全知。
