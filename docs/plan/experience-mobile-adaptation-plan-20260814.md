# 体验页与写作页移动端适配计划

## 1. 目标与边界

目标是让 `/experience` 和 `/writing` 在手机浏览器和微信内置浏览器中分别形成稳定的阅读/输入流和编辑/批注流：正文与编辑器是主内容，输入和批注工具按需出现，不遮挡、不抢焦点、不制造额外滚动层。

本轮只处理体验页、写作页及体验页复用的在线模式，不重做主题、不改变桌面端的信息架构、不重写叙事运行时，也不把所有桌面控件简单缩小。

涉及的主要入口：

- `src/pages/Experience.vue`
- `src/pages/OnlineExperience.vue`
- `src/components/GamePanel.vue`
- `src/components/InputArea.vue`
- `src/components/experience/NarrativeTurn.vue`
- `src/components/writing/WritingNotebookEditor.vue`
- `src/components/writing/WritingInlineCompletion.vue`
- `src/pages/Writing.vue`
- `src/styles/themes/kao.css`
- `src/styles/experience-reading.css`
- `src/pages/Writing.global.css`
- `src/pages/Writing.scoped.css`
- `src/styles/main.css`

## 2. 调研结论与当前问题

### 2.1 代码现状

当前已经有 `100dvh` 变量和 `980px/640px` 断点，但移动端仍然沿用桌面工作台的竞争关系：

1. `ws-layout` 在 `980px` 以下变成单列，右侧索引只是移到正文下方，并没有变成按需打开的移动面板。
2. `ws-topstrip` 在 `640px` 以下换成两行，阅读区、操作区和会话信息同时占据首屏高度。
3. `ws-center-stage` 虽然使用 flex，但输入区和正文滚动区的实际高度、底部安全区和键盘出现后的可视高度没有形成明确契约。
4. `InputArea` 包含快捷操作、上下文信息、导演注、命令菜单、角色面板等多个层级，移动端仍会把桌面工具带入正文底部。
5. 触屏下消息操作被强制显示，正文旁边容易出现额外的操作图标；右侧索引、弹窗和对话面板也缺少统一的移动打开方式。
6. 体验页正文同时受到 `GamePanel`、`Experience.vue`、主题 CSS 和阅读样式的影响，必须先确认最终计算后的字体、宽度、行高和滚动容器，不能只改单个媒体查询。

### 2.2 截图暴露的问题

截图中的主要问题不是单纯的“宽度不够”：

- 顶部宿主浏览器区域、应用标题栏、体验页工具栏连续占高，正文起点过低。
- 正文左右留白和字号比例不适合手机，单行承载字数少，阅读节奏被切碎。
- 底部快捷操作、输入框和发送区占据较大面积，且与正文形成覆盖风险。
- 输入区上方的快捷按钮密度高，移动端仍以桌面横向工具条的方式排列。
- 右侧索引在移动端不可见或只能通过滚动找到，不符合“当前信息按需查看”的使用路径。
- 长文本滚动时没有明确的底部预留空间，最后几行容易被输入区或系统手势区域遮挡。
- 手写感字体在小屏上需要实测；如果最终计算字体过大或字面过窄，不能靠继续缩小字号解决，应优先换回可读的正文字体栈。

### 2.3 写作页现状

写作页已有章节书架和检查器的移动抽屉，但编辑器内部的高频操作仍按桌面定位：

1. 空格命令菜单由编辑器内部定位，窄屏时容易贴边、被键盘顶出视口或被底部输入法覆盖；一级菜单和子菜单同时存在时也会超出屏幕。
2. 选中文字后的“批注/素材”浮动工具条通过 `Teleport` 使用固定坐标，选择位置靠近屏幕边缘或键盘上方时没有稳定的翻转和边界收敛。
3. 批注编辑器、批注创建器和改写候选目前依赖桌面右侧边注栏；移动端若继续压缩，会造成文本、引用、输入框和按钮全部挤在一个窄面板里。
4. 右侧检查器在移动端虽然可变成底部面板，但打开状态、编辑焦点和键盘高度没有与正文选择状态形成统一契约。
5. 选区操作需要兼容触摸长按、系统选择菜单、滚动后失效和编辑器重新渲染，不能只依赖鼠标 `mousedown` 和一次固定坐标。

### 2.4 外部规范依据

- `dvh` 适合表示动态可视视口，浏览器地址栏和键盘变化时不应继续把固定 `vh` 当成真实可用高度。[MDN viewport units](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Values_and_units/Numeric_data_types)
- 刘海、圆角和底部手势区域应通过 `env(safe-area-inset-*)` 预留，不能只依赖固定的 `bottom` 数值。[MDN env()](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/env)
- 交互控件至少满足 WCAG 2.2 的 24px 最小触控目标和足够间距；主要移动按钮按 44px 左右的可触区域设计。[W3C WCAG 2.2 target size](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/)
- 小屏布局应满足 reflow，不能要求用户横向滚动来完成阅读和输入；移动端面板必须提供单指可完成的替代操作。[W3C mobile guidance](https://www.w3.org/TR/wcag2mobile-22/)

## 3. 设计决策

### 3.1 单一阅读流

移动端只保留一条纵向主流程：顶部轻量状态栏 -> 正文滚动区 -> 输入工具。人物、地点、事件、世界书详情、设置和联机成员都不常驻正文旁边，改为按钮打开的 bottom sheet 或全屏 sheet。

不要在移动端同时保留“右侧栏缩到正文下方”和“悬浮输入栏”两套结构，避免重复内容和滚动层级。

### 3.2 输入区采用布局占位，不覆盖正文

首选让输入区作为 `ws-center-stage` 的最后一个 flex 子项占据自身高度，正文滚动区通过 `min-height: 0` 消化剩余空间。只有在键盘弹起时，才根据 `visualViewport` 调整可视高度和滚动定位。

如果某个状态必须使用 fixed/sticky 输入 dock，必须同时给正文滚动容器提供等高的 `padding-bottom`，并用末尾元素可见性测试证明最后一段可见。

### 3.3 桌面和移动端保留同一视觉语言

保留主题2的蓝白、细色条、等高线和活页档案感。移动端只减少装饰和层级，不新增一套颜色、卡片或大面积渐变。正文不使用卡片包裹，工具面板才允许使用轻量 sheet 表面。

## 4. 分阶段实施

### M0：建立移动端基线与结构盘点

**任务**

1. 固定测试尺寸：`320x568`、`360x800`、`390x844`、`412x915`，补充横屏 `844x390`。
2. 覆盖空会话、正常三回合、长正文、生成中、生成失败、设置打开、索引打开、联机体验八种状态。
3. 用浏览器计算并记录：`scrollWidth/clientWidth`、正文滚动容器高度、输入区高度、底部最后一段的 `getBoundingClientRect()`、固定层与安全区距离。
4. 确认实际生效的主题、字体、阅读字号、行高和滚动容器，清理重复规则前先画出选择器优先级。
5. 将移动端截图基线存入临时验收目录，不把临时截图和日志混入产品文档。

**出口标准**

- 能明确指出截图中的每个遮挡、空白、横向溢出和不可达控件对应的 DOM/CSS 所有者。
- 确认当前问题属于 `Experience.vue`、`kao.css`、`GamePanel` 还是 `InputArea`，不靠全局 `!important` 试错。

### M1：重排移动端工作区骨架

**任务**

1. 在 `760px` 左右建立明确的移动工作区规则，`980px` 只负责平板过渡，不让手机继续继承桌面两列语义。
2. 移动端 `ws-layout` 使用稳定的动态视口高度：优先 `100dvh`，保留 `100svh`/`100vh` 回退；应用外壳和内容区不得重复计算一层视口高度。
3. 顶部工具栏收敛为一行：页面名、会话短名、索引按钮和更多操作。阅读节奏、设定、切换会话进入更多 sheet，不在首屏横向挤压。
4. `ws-center-stage` 变成唯一主滚动工作区：正文滚动，输入区不参与正文滚动；禁止 body、页面外壳、正文三层同时滚动。
5. 右侧索引在移动端默认卸载视觉占位或隐藏，不再排在正文下面；通过现有“索引”入口打开 bottom sheet，全屏高度不足时允许 sheet 内滚动。
6. 在线模式沿用同一移动骨架，聊天悬浮层和成员面板按照同一层级规则处理，不能遮住发送区和顶部按钮。

**出口标准**

- 390px 宽度下正文占据主要宽度，无横向滚动。
- 右侧索引不再制造空白区域；打开和关闭不改变正文滚动位置。
- 空会话首屏能看到输入区；有长正文时正文仍能独立滚动到末尾。

### M2：重做移动输入区与键盘行为

**任务**

1. 快捷操作分层：首屏只保留“继续/发送/对话模式”等高频操作，场景、心理、上下文详情、世界书查看等放入横向可滚动工具条或更多 sheet。
2. 输入框设置合理的 `min-height` 和 `max-height`，根据内容增长但不把正文挤出屏幕；超过上限后输入框内部滚动。
3. 发送按钮与输入框成为同一行的稳定布局，加载、失败、未配置 API、自动推进等状态不改变按钮位置。
4. 增加 `env(safe-area-inset-bottom)`，处理 iPhone 手势区；不要用固定 `bottom: 86px/150px` 这类只对单一设备成立的补偿。
5. 监听 `visualViewport.resize/scroll` 或使用等价的集中式 composable，仅在键盘弹起时调整输入 dock 和滚动定位；组件卸载时移除监听。
6. 聚焦输入框时保证当前输入行可见；发送后恢复正文末尾可见；关闭键盘后不产生跳回顶部或额外空白。
7. 桌面端保留提示词详情等能力，移动端默认折叠，不删除能力，只改变入口。

**出口标准**

- 键盘打开时输入框、发送按钮和最后一段正文均不被遮挡。
- 长输入可以滚动，输入区高度变化不会造成页面横向溢出。
- 发送中、失败、重试、API 未配置四种状态下输入区结构不跳动。

### M3：正文阅读密度和角色表达

**任务**

1. 以最终计算值重新校准移动正文：字号、行高、段间距、首行缩进和左右内边距分别设定，不使用 `vw` 直接缩放字体。
2. 移动端正文列宽使用 `width: 100%` 配合固定安全内边距，避免桌面 `max-width`、纸面阴影或多余外层 padding 叠加造成窄栏。
3. 保持叙述、动作、心理和对白的轻量差异；角色名只在说话人切换时出现，不为每句台词重复加标签。
4. 触屏设备不默认显示每段消息操作菜单；改为点击消息后显示一次性操作入口，且不会改变正文行高。
5. 生成中、通知、压缩完成和错误信息使用独立的低高度状态行，不能插入大块空白或盖住正文。
6. 重点检查中文引号、内嵌单引号、斜体、强调和未识别 marker 在移动端的换行，禁止出现横向溢出。

**出口标准**

- 390px 下正文不出现“每行几个字”的窄栏效果，连续阅读不需要频繁滑动。
- 对白、叙述、心理在不增加大色块和边框的前提下可区分。
- 文字操作不会常驻堆在正文边缘，也不会遮挡后续段落。

### M4：索引、弹层与联机状态

**任务**

1. 将现场索引、设置、会话切换、速记、角色选择和提示词详情统一为移动 sheet 入口；每次只打开一个 sheet。
2. sheet 使用动态高度和安全区，标题栏固定，内容区独立滚动，关闭按钮保持 44px 左右触控面积。
3. sheet 打开时禁止底层正文继续滚动；关闭后恢复原滚动位置和焦点。
4. 在线聊天默认无消息时隐藏；有消息时使用低透明度、可收起的底部面板，并为输入区预留空间。
5. 右上角不再堆放房间、成员、复制链接等长文本；这些内容放入联机 sheet，顶部只保留状态和入口。

**出口标准**

- 索引和联机面板能从 390px 屏幕完成打开、浏览、关闭，不遮住顶部返回/设置入口。
- sheet 内滚动不会带动底层正文，返回键/关闭按钮行为一致。

### W1：写作页编辑器移动骨架

**任务**

1. 在 `720px` 以下把写作页明确分成“章节入口 + 编辑器 + 工具入口”三层，章节书架和批注检查器都按需打开，不在正文下方保留隐藏但占位的列。
2. 编辑器成为唯一主要滚动容器，编辑器外壳使用动态视口高度和底部安全区；输入法出现时只缩短编辑器可视区，不移动文档的业务坐标。
3. 顶部编辑工具栏在手机上只保留当前模式、保存状态、章节入口和更多按钮；字体、查找替换、素材、批注等低频操作进入横向工具条或 sheet。
4. 编辑器底部为输入法和安全区预留空间，避免最后一段文字、行内续写候选和光标被系统键盘挡住。

**出口标准**

- 390px 下编辑器正文没有横向滚动，章节切换不会让编辑位置跳到顶部。
- 打开键盘后当前光标行可见，关闭键盘后文档滚动位置保持稳定。
- 桌面端的章节书架、编辑器和检查器三栏不回归。

### W2：空格命令菜单适配

**任务**

1. 保留现有命令层级和键盘操作，不为移动端复制一套命令逻辑；把菜单定位改为基于编辑器可视区域的边界计算，而不是只依赖光标坐标。
2. 菜单靠近底部或键盘时自动向上展开，靠近左右边缘时收敛到屏幕内；子菜单在手机上改为同一 sheet 内的二级视图，避免横向飞出屏幕。
3. 一级菜单保留最常用的四项，其他结构/格式命令进入二级列表；每个项目保证足够触控面积，支持点击、上下选择和返回。
4. 空格触发菜单时不吞掉中文输入法组合态，不在输入法候选词阶段误打开；点击编辑器其他位置、滚动、按 Escape 或选择命令后正确关闭。
5. 处理菜单与软键盘、浏览器底部工具栏、编辑器底部状态栏的 z-index 和可视高度关系。

**出口标准**

- 320/360/390px 下菜单完全可见且不产生横向滚动。
- 中文 IME 组合输入、空格触发、命令选择、子菜单返回均不丢字、不误插入空格。
- 键盘打开时菜单不会被键盘遮挡；命令选择后编辑器焦点恢复到原位置。

### W3：选区、批注与改写面板适配

**任务**

1. 选中文字后的“批注/素材”工具条在移动端采用两段式策略：选区附近只显示轻量入口，完整操作在底部 sheet 或编辑器底部工具条中完成，不能遮住选区上下文。
2. 统一处理触摸长按选择、Selection API 变化、滚动后坐标失效、选择为空和编辑器重新渲染。选择范围以 `from/to + blockId/nodeId` 为真源，不以屏幕坐标保存批注目标。
3. 批注创建器移动端改为底部 sheet：显示短引用、批注输入框、添加/取消；键盘打开时 sheet 内部滚动，提交后恢复编辑器选区和滚动位置。
4. 已有批注、编辑批注、删除、按批注改写和多候选选择统一进入批注 sheet；候选内容使用纵向差异阅读，不在 390px 屏幕并排展示原文和候选。
5. 批注检查器的“批注/版本”切换保留，但移动端默认从底部入口打开；打开检查器时锁定底层编辑器滚动，关闭后恢复原位置。
6. 行内续写候选在移动端改成靠近光标的可收起条，候选过长时内部滚动，不覆盖当前编辑行。

**出口标准**

- 选区靠近顶部、底部、左右边缘时，批注入口和编辑表单都可见、可点。
- 添加批注、编辑批注、采用改写、忽略候选、删除批注后，正文选择和滚动位置不发生意外跳转。
- 触摸长按、复制、系统选择菜单与应用批注入口不互相抢占。

### W4：写作页真实设备验收

**任务**

1. 覆盖 `320x568`、`360x800`、`390x844`、`412x915`，包括键盘关闭/打开、竖屏/横屏和微信内置浏览器。
2. 录制空格命令、一级/二级命令、长按选区、选区批注、批注输入、改写候选采纳六条操作路径。
3. 检查编辑器、命令菜单、选区工具条、批注 sheet 的 `scrollWidth`、可见矩形、焦点归属和底部安全区。
4. 只补充写作页移动端必要的浏览器 smoke，不把整套桌面编辑器测试复制到移动端。

### M5：真实设备验收与收口

**任务**

1. Playwright 使用相同状态矩阵截图并执行溢出、遮挡、焦点和触控目标检查。
2. 至少在 Android Chrome 和微信内置浏览器验证：首次打开、输入法弹起、输入长文本、发送、生成中、错误重试、打开索引、旋转屏幕。
3. 用 `prefers-reduced-motion` 验证 sheet 和状态动画不会影响阅读；不把视觉动画测试扩展成全站审计。
4. 做一次性能检查：长正文滚动帧率、输入法弹起时布局抖动、sheet 打开时是否重复挂载大组件。
5. 只保留必要的移动规则，删除同一选择器的旧补丁和死断点，更新 `docs/STATUS.md` 与计划状态。

## 5. 验收指标

### 必须通过

- 320/360/390/412px 宽度无横向滚动。
- 长正文最后一段、输入框、发送按钮在键盘打开和关闭后都可见。
- 正文只有一个滚动容器，底层页面不会和正文争抢滚动。
- 右侧索引、设置、会话切换、联机成员在移动端均有明确入口。
- 主要触控目标不小于 44px 可触区域；次要目标至少满足 24px 且有间距。
- 空会话、正常会话、长会话、生成中、失败重试状态没有布局跳变或大块无意义空白。
- 桌面端现有两列工作区、正文宽度和索引功能不回归。
- 写作页空格命令菜单、一级/二级菜单和中文 IME 不互相干扰，菜单不被键盘或屏幕边缘截断。
- 写作页选区批注、素材收集、批注创建、改写候选和检查器在移动端都有可达入口，且不丢失 `blockId/nodeId` 目标。
- 写作页打开或关闭批注面板后，编辑器选区、光标和滚动位置保持稳定。

### 不作为本轮门槛

- 不要求所有组件在移动端都同时可见。
- 不要求 100% 还原某个手机系统或微信版本的浏览器顶部区域。
- 不为每个手机型号写独立断点。
- 不把所有桌面设置删除，只把低频功能移动到 sheet。
- 不用“截图像素完全相同”替代可读性和交互验收。
