# N-B：全产品图标、按钮和布局审查与优化

状态：计划，未执行。遵循[今夜总计划](./nightly-20260917-sources-ui-memory.md)。此线是 UI 线，不是上一轮漫画 B 线。

目标是作者能快速认出动作、看清当前内容、在各页沿用同样的操作习惯。全面审查覆盖所有现有入口；实施按严重度和组件家族推进，保留已经合适的区域，避免每页重造一套风格。

## 1. 参考研究要形成可执行判断

已核实：2026-09-17 读取 Microsoft Fluent 官方 Button 正文，确认单一高强调动作、密集工具条低强调、图标/文字状态、Close 与 Cancel 区别。IBM Carbon 仅收到部分正文且请求超时，需要重读。下表其余是本夜待核实研究对象，不声称已对最新客户端完成调查。

| 官方来源 | 研究内容 | Pinax 应用问题 |
| --- | --- | --- |
| [Microsoft Fluent](https://fluent2.microsoft.design/components/web/react/core/button/usage) | 按钮/工具栏层级、状态、图标与具体标签 | 资料操作、AI 生成/停止/重试、目录工具的主次和反馈 |
| [Apple HIG](https://developer.apple.com/design/human-interface-guidelines/) | 工具栏、侧栏、图标语义、弹层与键盘焦点 | 写作辅助区、关闭/固定/返回及窄屏重排 |
| [Google Material](https://m3.material.io/) 与 [NotebookLM 帮助](https://support.google.com/notebooklm/) | 尺寸/目标区域、自适应；来源选择、引文和工作区关系 | A 的资料库、来源预览和选择参与模型；不照搬聊天首页 |
| [IBM Carbon](https://carbondesignsystem.com/components/button/usage/) | 高密度列表、批量工具条、按钮组与复杂状态 | 资料/记忆/历史的扫描、选择和批处理 |
| [Notion 帮助](https://www.notion.com/help) | 内容目录、行内动作、更多菜单、来源/状态的渐进展示 | 全书目录、速记/素材及工具发现性 |
| [Linear 文档](https://linear.app/docs) | 紧凑列表、命令入口、快捷键/反馈 | 长目录、查找、切换对象和统一交互尺度 |

研究交付不是品牌截图拼贴：对每个被采用模式写“现有问题 → 官方证据 URL/日期/平台 → 采用的具体行为 → Pinax 适配 → 不适用部分 → 验收”。至少深入核实三个官方体系；其余列未查或不适用。涉及布局的结论必须看实际图像或官方客户端，只有文字资料时不编造像素尺寸。

不安装全新 UI 框架来模仿外观；沿用 Vue、Lucide 和现有 token/控件。当天用户给出的截图和纠正优先于旧规范：保留中性石墨暗色、紧凑标签、无重复页眉、连续稿面与低装饰密度；不恢复已删除的主题/渐变/路由动画。

## 2. 审查覆盖清单

以 router、弹层注册与实际入口建立清单，不能只数页面文件。每行记录桌面/窄屏/暗色、空/正常/长/失败/忙碌、键盘状态和是否实际查看。

| 面 | 重点审查 |
| --- | --- |
| 首页/书架、标签、全局设置/菜单 | 书名截断、切换/关闭/返回、标签溢出、主要入口与焦点 |
| 正文及大纲/角色/设定目录、双栏 | 控件密度、编辑区占比、目录文件夹、展开/固定/关闭、活动编辑面 |
| 批注/改写/版本、助手/生图、现场/推演 | 重复输入/动作、按钮状态、可采用结果与只读内容区分、焦点/滚动归还 |
| 结构化设定/资料导入/高级条目 | 来源与结果主次、搜索/新建/批量操作、空态与错误恢复；A 落地 |
| 记忆/历史/事实审阅 | 状态命名、时间/来源、差异比较、分页；C 落地 |
| 素材/速记、画布/漫画 | 文字与缩略图密度、选中工具、重复页索引、导出/缺图/失败 |
| 地图、体验/跑团、联机兼容页面 | 专业工具是否遮内容、模式/范围、移动交互、已知 nested-interactive/对比度 |
| 文档、偏好、备份/存储管理、所有弹窗/菜单 | 导航、字段、确认/取消/危险动作、状态同步、关闭和返回 |

地图渲染算法、跑团规则和漫画生成不归本线；UI 问题可以修，底层功能缺口记录为原域 backlog。

## 3. 本夜控件合同

1. 按钮文案说明下一动作，区分“导入书稿/添加资料”“删除原件/移出资料”“关闭/取消”“重新生成/重试保存”“恢复正文版本/撤回事实”。相同动作同名、同图标；相同图标不承担无关动作。
2. 高风险或不熟悉动作保留文字；关闭、展开等成熟图标可图标化，但有可访问名称、键盘焦点和提示。不能靠仅 hover 的 tooltip 成为唯一发现方式；触屏同样能识别。
3. 一个任务区域的主动作明确；目录新建、筛选、更多是次级。不要机械全站套“每页一个蓝按钮”：正文里可以同时有多个工具，按当前任务关系分组。
4. 尺度从现有原语冻结，小/常规/触屏少量规格即可；图标视觉框与命中区分开，触屏主操作建议至少 44px 命中区，不把所有桌面按钮强拉成 44px 高。
5. 覆盖 rest/hover/focus-visible/active/selected/disabled/loading/error；hover/选中不能导致文字或内容几何跳动。禁用原因可发现，执行中防重复提交，取消能真正停止对应任务。
6. 焦点只保留一套清楚的边界，文字/必要图标对比度按 WCAG 核验；状态不单靠颜色。键盘和屏幕阅读器语义正确，修复嵌套交互控件。
7. 列表/详情连续，长标题省略后可查看全名，长内容换行；主稿面保持可读宽度。没有意义的第二目录、重复标题、数量和套框只保留一个显示位置。
8. 以现有 1440/1024/900/390 与 200% 缩放行为为基线；辅助栏在窄屏按任务重排。手机不把桌面三栏缩小挤在一行，桌面也不无理由退化为手机布局。

此为初始合同；正式尺寸和具体组件选型在 NB03 的实测后冻结，不能把研究对象截图的物理像素直接当 CSS px。

审查优先级：S0 数据误操作/不可用 → S1 找不到动作/焦点丢失/窄屏遮挡 → S2 层级、图标/尺度不一致 → S3 小间距/装饰。先解决前三类，再精修 S3。

## 5. 证据要求与后续队列

全审清单含问题 ID、入口、状态、截图、严重度、建议、owner、结果。不强制每页改动；“审过，无须改”是有效结果。未实施的 S2/S3 保留明确位置与下一步，不能用几张首页图代替全审。

重点改动同时交同视口/同数据/同滚动/同展开状态的前后原图，记录实际查看结论。自动截图不等于视觉通过，DOM 几何和 axe 不代替看图。全页覆盖以代表状态取样；通用控件家族跑完整状态矩阵，避免无意义截图组合爆炸。

复用 `workspace-refinement-check.mjs`、`workspace-consistency-smoke.mjs`、`settings-linkage-check.mjs`、现有 ui-audit 与功能回归；沿用既有失败反例，不为截图通过放宽断言。全局 token 修改后复验资料、记忆、写作和既有复杂页面。

P0/P1 完成后可深化高分屏图标渲染、长目录性能、辅助技术及少见屏幕布局；不新增主题、完整 UI 框架或自主大改首页。最终报告分开写工程通过、视觉已查、用户待确认。
