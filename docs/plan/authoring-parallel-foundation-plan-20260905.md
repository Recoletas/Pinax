# Authoring 体验主线与设定／历史能力支线并行计划

日期：2026-09-05。状态：调研与计划交付；实现待启动。本文不授权自动运行 worker、请求付费模型、迁移用户数据或调整现有 UI 工作。

上位路线：[产品整合路线](./pinax-integrated-product-roadmap.md) G1.2（设定）、G3.1–G3.4（历史/世界状态/角色连续性）、G4.6（按需上下文）；体验执行真源继续是[UI/UX 与故事试演计划](./authoring-ux-and-story-play-plan-20260905.md)第9–12节。事实依据见[本轮调研证据](./authoring-parallel-foundation-research-20260905.md)。不新建产品级主线，不改既有 A0–A5 优先顺序。

## 1. 决策摘要

**当前夜间执行裁剪**：[第四轮任务书](./authoring-overnight-round4-20260908.md)接管第三轮未完成项；K 不重造知识底座，复验最新终态修复，补跨层取消/预算、IF 冻结输入与薄只读对象适配。默认关闭窄 I0、既有 F2 授权范围不扩大；IF/helper 先纯逻辑，再由单 owner 移交 U 消费，不新建数据库/历史写入/I1。第三轮保留历史；第四轮仅计划待执行。

1. 同时最多两条产品实现线：U＝现有体验主线；K＝只读设定/历史能力支线。集成负责人是职责，不默认第三个并行实施者。
2. U 继续完成六波体验交付，不等待完整数据库、历史系统或新工具循环。K 先完成“一个项目、明确实体与时间、返回有出处资料”的独立切片。
3. K0–K4 不写 Authoring、store、旧上下文合同、存储或模型目录，不创建第二个全书搜索器。首轮只有显式调用的纯函数/只读 adapter 和离线验证脚本。
4. 查询能力通过后，先在单一窗口补接一项历史资料能力；接口、证据权限和 UI 接线由集成 owner 串行完成。
5. 长期历史账本、事实写入、存储迁移与大规模页面拆分排在后续 Gate。工程风险现在测、相关职责逐块拆，不等“功能全做完”才处理。

**首个用户收益目标**：作者仍在原落笔处写作；涉及旧事时，系统能引用确实可用的旧事；没有证据就说明不知道；改变人物选择时，不把未采用的试稿写成过去发生过的事实。

## 2. 当前架构判定与不应重复开发的部分

| 已有基础 | 真正缺口 | 本轮决策 |
| --- | --- | --- |
| 世界书独立 entry、只读绑定快照、地点 v2 身份 | 人物/旧历史引用不完全同域；名称不等于身份 | 建只读身份对照，不换全项目 ID |
| 历史节点、有限 state delta、因果报告与回滚 | 记录窗口不完整；故事时间与修订时间未统一 | 先声明覆盖范围，不承诺任意历史回放 |
| F2 问答读取历史；旧 history_lookup 已存在 | Authoring manifest 工具授权尚无历史域 | 分清问答与正文生成，完整授权后才接正文 |
| 单一冻结 session、依据 receipt、revision stale | 新查询需要同样的权限/失效/预算语义 | 复用原 pipeline，不从工具直接读 live store |
| 正文/探索仓储、桌面 adapter | 页面整包保存协调重、长期账本归属未定 | 先测量及梳理；不新建持久化真源 |
| A3/A4/A5 已规划统一试演、改方向、普通稿局部写 | 页面主次和连续试验体验待落实 | 由 U 做；K 不增加新 UI 入口 |

不可把 canonicalFacts、研究 claims、记忆、历史摘要混成同一种“已确认事实”；也不可把正式设定认定为所有角色都知道的公开知识。技术上有来源不等于语义上足够支撑当前断言。

## 4. K 支线的最小领域合同

### 4.1 先分开四种问题

| 维度 | 表达的问题 | 明确禁止 |
| --- | --- | --- |
| 故事有效时间 | 故事第十年谁控制城门 | 将 Date.now/事件 ts 当故事年份 |
| 作者记录/修订版本 | 作者何时把城主甲修正为乙 | 覆盖旧版本后声称能回放旧认知 |
| 稿件可用位置 | 当前落笔处允许读到哪些正文 | 把第十章顺序直接换算成故事第十年 |
| 角色认知/视角 | 这个角色此时知道哪件事 | 把世界事实、叙述者知识、角色信念合并 |

另有分支作用域：runtime branch、Authoring intervention、探索试稿不是同一个分支系统。首期只识别调用方明确提供的来源作用域，不实现分支合并。

### 4.2 身份、事实与资料片段

- 正式实体优先使用 `{worldbookId, entryId, kind}`；地点与地图 v2 的稳定叙事身份保持同义，地图对象 ID 只作空间引用。
- 旧 runtime 人物/历史地点通过显式引用表对照；同名只给消歧候选，不自动合并。两本书绑定同一本世界书仍要按 project 分别授权，不能共享正文/运行时历史缓存。
- 既有正文、世界书长文本先作为 `source-excerpt`，不正则拆成“结构化事实”。只有明确结构字段/既有合法事实可转为 typed assertion。
- typed assertion 保留实体、predicate、标量/对象引用、原始状态、来源定位与 revision。没有时间、权限或认可证据就明确标 unknown，不补默认的“永恒、公开、confirmed”。
- `sourceAuthority`（来自哪里）、`reviewState`（是否认可）、`temporalStatus`（何时成立）、`visibility`（谁可读）分别表达；一个 canonical 标签不能替代四者。
- `facts`、`excerpts`、`hypotheses` 分开输出。默认生成资料中不含未采纳 hypothesis；用户明确把试稿作为本次参考时，也只按非正式来源授权，不改变真伪。

### 4.3 拟议接口轮廓

以下是 K1 要冻结的应用内合同草案，不是新增 provider 工具 schema；字段最终名在 K1 确定，禁止先向现有 shared 合同追加。

```text
queryKnowledge(request, context)
request:
  schemaVersion, projectId
  entityRefs[], questionKind: entity-context | fact-at-time | history-causes
  storyTime?: { timelineId, eraId?, ordinal?, precision, label? }
  authorRevision?: revision            # 首期仅支持实际保存的版本
  manuscriptCutoff?: stable target     # 独立于 storyTime
  perspective: author | character(entityRef)
  sourceScope?: explicit source scope  # 不是任意 branchId 字符串通行证
context（由受信应用边界创建，模型不可设置）:
  frozen authorized snapshot, exact readable refs/fields
  source revisions, query-scope revision, fixed budget, AbortSignal
result:
  status: ready | partial | unknown | conflict | unsupported | denied | aborted
  facts[], excerpts[], conflicts[], coverage, dependencies, fingerprint
  diagnostics: bounded low-sensitivity reason codes
```

**固定语义**：

1. 先权限过滤，再实体匹配、时间过滤、排序和截断；隐藏项的标题、引文、ID、总数、缓存内容和诊断不得泄露给无权视角。
2. 调用方不可通过 request 中自报 project、视角或 branch 扩权。首期是同进程只读应用能力，不声称构成独立多用户安全边界。
3. 时间只对同一已声明 timeline 的可比值排序；未知纪年、模糊“很多年前”、缺少区间端点不擅自换成 Gregorian 日期。`unknown end` 与 `open-ended` 必须不同；边界采用明示半开区间并测边界点。
4. 角色视角需明确 knowledge/visibility 依据，缺失返回不足；不能把“库中没记他知道”推断为“他肯定不知道”。缺少角色认知数据的历史片段不进入其私有视角模型输入。
5. author 视角能查看被授权资料，但“供作者查阅”不自动变成“当前角色可使用”；后续生成集成需要冻结本轮叙述视角政策，未知时不支持角色限制生成。
6. 缺旧版本返回 unsupported；有限事件窗口返回 partial/history-window-truncated，不生成虚假的完整回放。未知、矛盾、无结果、读取失败分别编码。
7. 来源变更、权限变更、删实体、改时间或跨书触发重新查询。依赖不仅是已返回项 revision，还包括有界查询范围的 revision，防止漏掉新加入的矛盾事实；无关书变动不使本查询失效。
8. 第一版每次最多8个明确实体、24个输出项、12,000字符；超限返回截断与覆盖说明，不伪称完整。此为拟议安全上限，不是测得最优值。没有模型自动分页或隐式扩大搜索。
9. 纯读零保存、零归档迁移、零 activeWorldbook 切换、零 provider 调用；取消后不继续发布结果。索引只存在调用内，跨请求缓存待证明必要再加。

## 5. K0–K4：现在可独立推进的实现包

### K0：冻结基线、数据对照与合成样例（P0 / S）

- 前置：实际 UI owner/包号、main SHA、允许/禁止写集记录清楚。U 无需停工。
- 交付：补齐 E03/E05/E06/E09 的逐字段对照、实际读者/写者、来源 ID 与状态转换；合成样例包含两个项目共用世界书、同名人物、一个旧地点 alias、两段时间、未采纳试稿。
- 文件：K 目录的 fixtures 只通过参数提供数据；脚本目录保存短 inventory/fixture 说明，不读用户小说或真实存档。
- 验收：fixture 字段哪些是现有数据、哪些是未来合同必须标明；当前 schema 不支持的时间/认知不能伪装成生产字段；旧地点重映射不会创造新身份。
- 停止：发现需要修改主 store 才能只读时，退回依赖注入快照，不擅自增加迁移。

### K1：身份、时间、可见性与返回状态合同（P0 / M）

- 依赖 K0。在 `contract.js`、`identity.js`、`time.js` 实现纯校验与规范化；不增加框架或 package 依赖。
- 冻结第4节语义及版本号；unknown 不变 false，conflict 不自动挑最新，记载时间不冒充有效时间。
- 验收：同名/别名歧义、跨世界 ID、跨 timeline、未知精度、区间端点、缺视角授权均有输入与精确预期；纯函数不修改输入。
- 交接：一页合同摘要 + 最小调用样例 + unsupported 清单；集成 owner 签收后 K2/K3 不再自行改变形状。

### K2：现有数据只读适配（P1 / M）

- 依赖 K1。`sourceAdapters.js` 消费调用方传入的绑定快照、世界书 entry、geoHistory、明确关联的受限 runtime 快照/因果报告。
- 复用已有来源定位及地点身份规则；缺稳定 history ID 不以数组序号建立长期身份。旧 fallback ID 可以只读展示，但不得成为可采纳长期证据。
- 不调用 active gameStore 来猜当前书的历史；无法证明书与 session 对应时排除 runtime 来源。
- 验收：正式条目/历史/研究建议/记忆分类正确；改名保持明确 ID；删除与 tombstone 不复活；源 revision 变化可检测。读前后所有输入 hash 和 storage 写入计数不变。
- 退路：只有 excerpts 可用也算真实阶段结果，但必须说明“未具备时点事实判断”，不能宣称数据库完成。

### K3：有界查询与解释（P1 / M）

- 依赖 K2。`query.js` 实现显式实体/时间过滤、有限因果引用遍历、覆盖说明、取消与确定性输出。
- 第一版精确实体查询不需要新全文检索；需要按自然语言找资料时继续复用原 narrative resource tokenizer/ranker，通过后续 adapter 接入，不复制一份。
- history-causes 只追明示且授权的因果边，至多2跳/24项；时间相邻、人物同名和词语相似不是因果。截断、循环、孤儿引用分别报告。
- 验收：同输入结果稳定；全部 returned ref 可在授权快照反查；事实之间冲突不被 authority 排序悄悄吞掉；未知的问题返回有原因的不足。

### K4：独立安全、兼容和负载门禁（P1 / M）

- 依赖 K3。新增显式离线 eval 脚本，不启动服务、不要求 U 接线；K 目录没有现有 production import。
- 至少覆盖第9节矩阵；用实际旧结构与拟议丰富结构两组样例分别报告 supported/unsupported，禁止拿未来 fixture 通过冒充旧档兼容。
- 记录100/1,000/10,000条合成资料的冷建索引、查询、取消、内存与输出大小；记录 Node/CPU/数据规模，初始性能数据不作手机保证。
- 初始接入门槛建议：1,000条有界样例查询 p95≤100ms；若超过先分析，不能加 Worker/缓存掩盖语义问题。真实浏览器长任务与移动性能留 I2/E0。
- 交付：可运行命令、结果JSON、简短失败列表、变更树/基线 SHA、允许写集核对；不提交巨大日志或真实正文。
- 完成含义：只读能力可供接入，**不是产品功能已上线**。若 U 尚未准备好，K 到此停止扩张，允许交付关闭状态的独立模块。

## 6. I0–I2：必须由主线协调的接入窗口

### I0：先接只读资料面，不新增玩法界面（P1 / S–M）

- 前置 K4 通过，U 的资料面合同稳定（通常 A2-1/2完成，或 A2-4 明确释放文件）；不要求全部六波完成。
- 集成 owner 审核 source ref 映射、runtime 绑定和当前视角政策，把 K 接到既有 F2 knowledge session/证据 envelope；优先消费已有历史证据通道。若现有 F2 接入收益不足，保留离线结果，不硬加入口。
- 列明 `history-node:` 与 `history:` 转换所需作用域；重复 ID 必须拒绝歧义，不能仅靠前缀替换。
- 验收：原问答路径可回退，未知显示可理解；源定位、换书/换绑/关闭/迟到/刷新保持正确；未授权数据不进入 prompt、来源列表或调试面。

### I1：历史资料进入正文推演的完整授权链（P1 / L）

- 前置 I0 语义通过、U 的 A3-1/2/3接缝稳定；一次只开放“当前地点的一项相关旧事”，不同时开放整个 runtime/politics/geo。
- 唯一 owner 审核并修改所需 reader → context compiler/profile → manifest block/source kind → tool authorization → kernel catalog → resource index → provider serialization → actual-use receipt → stale reconciliation 的完整链。具体文件以 K0 和当前 import graph 再核对；不能仅加 tool registry。
- 历史内容不得伪装成 worldbook-entry 绕过现有授权。新增 kind 需版本兼容策略、未知版本 fail-closed、所有消费者一致；共享任务目录只有确实新增任务时才追加。
- 本轮可查询资料必须在生成前冻结为有界授权集合；工具只在集合内检索，不因关系链接扩权、不读 live 全库。未来若需工具动态拓展，另开授权合同任务。
- 新能力默认关闭，由集成 owner 选既有 flag 机制；关闭时不加载新数据、不额外调用 provider，原 U 直接试写与 A5-1 保持可用。
- 验收：实际序列化与 receipt 能证明所用历史；工具未消费不能标“已参考”；取消、重试、预算耗尽、来源变化、存储失败零越权/重复采纳。正文采用不自动确认历史事实。

### I2：同一故事样板的真实收益验证（P1 / M，外部预算待确认）

- 复用 U 的“隐瞒/部分坦白/试探”样板与既有趣味评测，不再发明第二套 UI 演示。另补物理限制与无世界书普通稿作为对照。
- 相同模型/参数/作者意图：旧路径与新历史支撑各一份，共三类×两份；先离线 fixture/mocked transport 验证权限，再经用户确认渠道/费用上限执行真实模型。预算用尽或失败即停，不自动扩大样本。
- 记录事实矛盾、角色越知、不同方向的真实反应、作者追加要求是否有效、实际等待/工具次数/费用和愿不愿再试。不能以采用率催促作者接受模型稿。
- 明显越权、未来信息泄漏或正式数据误写任一次即失败；小样本至少两类方向差异与控制感获用户认可才扩大。质量不提高或等待明显不值得，则关掉 I1，保留 U 和只读查询。
- 六份结果只支持局部决策，不宣称统计显著、所有小说有效或历史系统完成。

## 7. 后续历史、数据库与工程优化：有条件排队

### H0：长期事实/历史账本设计（P2 / M；K4后可文档研究，不并行写库）

2026-09-16 更新：用户已明确授权开始数据库优化，旧“不写库”阶段约束不再阻塞本轮。Web 先采用 Dexie 交付记忆版本归档及备份，见[实施边界](../engineering/memory-history.md)；完整事实表、有效时间查询及认知时间仍未完成。

- 决策问题：哪些变化需要永久保存、哪些只是运行时缓存；故事时间/作者修订/角色认知如何分别记录；一书还是共享世界拥有事实；谁是唯一 writer。
- runtimeEvents 200条只是运行窗口，不能直接取消上限后称永久账本。源事件被裁剪时只能保留已知快照或报告不完整；不反向编造缺失历史。
- 必须和桌面 P3 协调：浏览器 IndexedDB/既有 localStorage 边界与桌面 SQLite adapter 用同一语义接口。先选清楚权威所有者，不为每个视图建一份数据库。
- 产出 ADR：身份、事实版本、事件、来源、修订、删除/撤销、历史覆盖、恢复与迁移策略；先锁一个存储目标的纵切，其他平台诚实标 unsupported。

### H1：一地点、一事件的可写历史闭环（P2 / L；H0+I2通过后）

2026-09-16 更新：记忆候选的提议/确认/修订/恢复/历史备份纵切已实施，组合验证通过（209 次修订浏览器 smoke、verify:full 20/200，exit 0）。永久运行事件、结构化实体事实和角色认知传播不属于已交付范围。

- 示例：“十年前守城承诺 → 当下不信任 → 本次选择是否改变关系”。事实、角色信念、作者假设分开；不能把承诺必然推导成不信任，需作者明确关系或标候选。
- 只做一项事实/事件的提议、原文证据与差异审阅、作者确认、版本追加、当前投影更新和安全撤销；正文变化与世界变化分开确认。
- 事实确认与其索引更新有原子性/恢复策略；重复请求幂等、冲突拒绝、断电/刷新可恢复、拒绝过的同一候选不马上复活。
- 扩展前做 copy-first 备份、迁移预检、校验计数/hash、失败恢复及旧档继续读取；用户数据不在未授权研究中迁移。最小账本成立后再考虑世界时间推进/事件链，不做文明模拟。

### E0：性能与数据风险基线（P1 / S–M；可以只读诊断，不占第三条实现线）

- 使用合成10万/50万/100万字与多书样例，测打开/切章、一次保存、跨章查询、Ghost采纳、失败恢复、内存和序列化；同时记录全书数组写入与页面反应链的成本。
- 先测主线程长任务与真实设备，不从文件行数断言性能差。性能预算以基线+用户设备确定；发生丢稿/越权优先止血，不等样板。
- 工程工作的可用时段是 K 等待 U 接入或用户反馈时；若要改产品代码，仍占 K 的唯一实现槽位，不能偷偷开第三线。

### E1：按责任抽离 Authoring（P2 / M，每次一块）

- 在对应 U 切片冻结后，按保存/持久化协调 → 推演 session生命周期 → 采纳事务适配 → 资料面板状态的顺序评估。已有 composable/transaction 优先复用，不复制新owner。
- 先为旧行为建立行为测试，再挪责任；不同时改 UI、schema、模型策略。核心断言是同一操作调用次数/持久化次数/取消和撤销结果不变，不以拆出多少文件验收。
- 共享热点一次只有一个写者，当前 U 未释放就延期。停止增长热点比立刻降到任意行数更重要。

### E2：存储/缓存/加载优化（P2 / L；E0定位后择一）

- 全集合保存确为瓶颈时，才设计按文档 revision 提交与 adapter 迁移；迁移保持单真源、备份、恢复、跨窗并发冲突，不永久双写两库。
- 索引构建确为瓶颈时，才增量索引/Worker；缓存键必须包含项目绑定、来源revision、查询范围、时间、视角与权限，切书不复用。
- 首屏/面板加载确为瓶颈时，才做 lazy loading 与包拆分；不得把未完成的异步加载表现为“没有资料”。每包独立测前后数据。

## 10. 交接、回退与扩展停止条件

每个包交付：`base SHA / 结果 SHA或快照 / 写集 / 接口变化 / 验证命令与退出码 / 不支持项 / 回退方式 / 下一包`。只有集成 owner 更新主状态；未来若用户明确启动多个worker，再按[协作工作流](../engineering/agent-orchestration-workflow.md)建立实际任务看板，本轮不登记不存在的运行worker。

- K未接入时：删除/不合并其独立提交即可，用户数据无变化。
- I0/I1异常时：关闭新增能力并回退接入提交，旧U可用；已经生成但未采用试稿保留可读，不保留旧采用许可。
- H1以后：代码回退不等于数据回退，必须先有版本兼容、备份与恢复演练，禁止用旧程序打开不兼容的新格式。
- 发现自动事实写入、权限旁路、重复权威源、无法说明时间覆盖或需要修改U热点才能维持K时，立即停止该包扩展。
- 真实样板显示“资料更复杂但文字无改善”时不扩历史玩法；优先查引用是否实际使用、人物意图是否清晰以及等待成本，不默认更换整个Agent架构。
