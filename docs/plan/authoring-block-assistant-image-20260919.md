# 文本块显示、助手前端与生图工作台：调研及实施计划

日期：2026-09-19。状态：**计划，未实施，视觉方案待小切片验证**。核查基线：`c030793`。承接[产品主计划](./pinax-integrated-product-roadmap.md)和[助手写作 Skills 计划](./assistant-writing-skills-20260919.md)。本文细化作者看得见、操作得了的交付；助手 S06–S12 沿用原编号，不另算一份实现。S13–S22 保留原队列。

## 1. 本次交付目标

三条完整操作旅程必须能在正式页面完成：

1. 作者看清当前文本块的起止，打开块菜单，把这块送去审稿或生图；关闭工具后回到原光标。
2. 作者在助手中选择“审稿”，输入目标，查看可定位意见，由意见生成修改候选，比较后采用并可撤销。全程无需复制粘贴。
3. 作者从正文或角色打开生图，确认画面描述、风格与参考图，查看和比较候选，保存或插入。第二张失败、保存失败也能保住第一张成果。

只交付边框、按钮或提示词不算完成。计划不要求本轮完成全书影响分析、任意图片编辑器、无限画布、视频、模型商店或新数据库。界面提供的能力必须有真实生产链。

## 3. 调研证据与具体取舍

本轮读取官方公开文档和开源项目页面；未登录商业产品做实机操作。以下取舍是 Pinax 的设计判断，尺寸也是候选设计值，不冒充第三方产品规范。

| 一手来源 | 核实的行为/原则 | Pinax 的采用方式 |
|---|---|---|
| [Notion 编辑基础](https://www.notion.com/help/writing-and-editing-basics) | 悬停在页边出现块菜单/移动把手，操作附着内容 | 页边显示块入口；Pinax 单元可含多个段落，不能复制“每段一个业务块” |
| [VS Code Sidebars](https://code.visualstudio.com/api/ux-guidelines/sidebars) | 相关视图分组、容器名称清楚 | 助手内部按任务组织，正文保持主面；不新增重复右栏或另一套全局导航 |
| [Novelcrafter Prompt Types](https://www.novelcrafter.com/help/docs/prompts/prompt-types) | 生成、总结、替换与 Workshop Chat 有不同任务类型 | 问答、审稿、改写使用各自 workflow；不能全部塞进聊天请求 |
| [Midjourney Style Reference](https://docs.midjourney.com/hc/en-us/articles/32180011136653-Style-Reference) | 风格参考用于外观特征，提示词仍需描述目标内容 | 画面内容与风格分开；人物相貌一致性不能由风格选项保证 |
| [Adobe Firefly 官方教程](https://www.adobe.com/learn/firefly/web/generate-image-with-text) | 构图参考与风格参考用途不同，控件和生成结果围绕迭代组织 | 参考用途明确，结果作为主要视觉区域；不复制其参数全集 |
| [Apple Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode) | 深色下须保持内容对比与前后层次，图像也需考虑周围环境 | 中性石墨分层、可辨焦点；预览原图本身不加改变色彩的滤镜 |
| [Tiptap Drag Handle](https://tiptap.dev/docs/editor/extensions/functionality/drag-handle) | 官方提供拖动把手扩展 | 先做兼容/许可核验；任何拖动必须经过 Pinax 结构事务，默认仅交付块菜单及上移/下移 |
| [社区 Global Drag Handle](https://github.com/NiclasDev63/tiptap-extension-global-drag-handle) | 存在可研究的开源块把手实现 | 仅备选；冻结版本、核对许可证和 Tiptap 3 peer dependencies 后才准引入 |

Adobe 一条 style-reference 帮助路径抓取失败，改用上述官方教程；不把失败链接计作证据。不依赖第三方商业源码，也不复制产品截图作为风格素材。

### 3.1 开源复用清单

- 优先使用项目已安装的 Tiptap 3 / ProseMirror decorations、Vue、Lucide、autosize、Dexie 和现有菜单/面板/媒体库，避免再装一套编辑器或组件库。
- 文本块只增加视觉装饰和调用既有事务，禁止直接拖 DOM 改正文顺序。第三方把手绕过 scene/annotation 迁移时不引入其默认拖动行为。
- 方法与退化检查继续用已经适配的 Oh Story 固定 SHA/MIT 版本，不重复抄入第二份规则。
- 图片预览先复用当前 lightbox；若缩放/键盘/对比确需新依赖，先列现有缺口、固定版本、体积与许可，交接时说明实际复用文件。
- 不安装包只是为了计划。正式移植时记录上游 URL、版本/SHA、许可全文、改造点和反例。

## 4. 三处共用的交互与视觉约束

1. **正文连续**：正常写作没有整块卡片背景；显示/隐藏块边界不改变正文宽度、段距、选区和保存状态。
2. **作用范围可见**：助手、生图、重写打开后保留同一目标标识与正文标记；鼠标悬停另一块不改变已冻结任务。
3. **一个主要动作**：每个当前工作面最多一个高强调主按钮；危险操作在菜单内，图标始终有可读名称和键盘焦点。
4. **同一尺寸体系**：沿用 `control-*`、既有右栏宽度和主题 token；桌面控件建议 32–36px，触屏命中区至少 44px，图标 16–18px。正文排版不随工具调整。
5. **少而清楚**：助手首屏只含任务、范围、一个要求输入及主动作；图片常用参数与高级参数分层，解释在必要位置展开。
6. **深浅主题成对**：暗色工作面、输入层、浮层有明确层次；活动态不只靠颜色，焦点和禁用态不混同。普通 UI 文本对比以 4.5:1、必要控件/焦点以 3:1 为验收目标。
7. **保留上下文**：关闭、最小化、查看证据、切候选后可回到原处；长结果首次从开头显示，用户回读时不自动滚到底。
8. **屏幕变窄即重排**：1440 保留正文与右栏；900 空间不足时用现有覆盖式面板；390 单工作面+返回，不同时压缩出三栏；软键盘不能盖住确认操作。

实施先做三个代表性切片截图：当前块与块菜单、助手一条审稿意见、生图一张候选。尺寸与材质待截图验证再推广。用户明确要求详细计划，因此本文列执行包；不将其视为视觉已经认可。

## 5. 文本块显示恢复

### 5.1 定义与显示模式

块指 canonical `writingUnit`，不是每个 `p`。一个单元可以有对白、描述等多个节点。没有多块的旧章仍是一块；不得为制造视觉分隔自动重分段。

新增写作显示偏好：**当前块（默认）／全部边界／隐藏**。复用现有写作偏好 owner，旧用户缺字段时默认当前块，不迁移正文；切换偏好纳入现有备份。专注模式暂时隐藏辅助边界，退出恢复原偏好。

| 状态 | 正文显示 | 操作 |
|---|---|---|
| 未激活 | 连续稿面，保留原有段间距 | 不占正文行内空间 |
| 当前块 | 页边 1–2px 细线覆盖完整单元，起止有短端点 | 顶部页边一个菜单入口 |
| hover 其他块 | 该块临时浅边界 | 不覆盖当前块与任务范围，不改变 selection |
| 全部边界 | 各块淡边界，当前块较强 | 不重复显示常驻工具条 |
| 冻结任务 | 任务涉及的块/选区保留区别于 hover 的范围标记 | 标签写“本次审稿范围”或“生图来源”，不展示内部 ID |
| 目标过期/删除 | 旧结果仍可查看，目标不再冒充有效 | 提供重新选择/开始新任务 |

超长块跨屏：侧线跟随真实容器，不能用浮动大框覆盖正文；需要时在工具范围入口显示首句摘要和字数。引用节点、标题、图片块分别按实际 DOM 边界计算，不能把内部 paragraph 错当独立 writingUnit。

### 5.2 块菜单

常用动作：“审稿此块”“重写此块”“为此块生图”；结构子菜单：“在此拆分”“与上一块合并”“与下一块合并”“上移”“下移”。沿用现有右键菜单 owner，不保留两套命令实现。

结构命令只有目标与光标有效时可用；无邻居、只读、待采用草稿、IME、媒体块不支持的动作有明确禁用原因。菜单打开时冻结目标，菜单关闭恢复光标。移动经过既有 scene/annotation/history 事务；不跨书、不凭文本相似度选块。完整块删除等已有危险动作继续沿原确认策略。

触屏通过可点击页边入口访问，不能只依赖 hover；键盘从编辑器现有命令菜单抵达，不新增冲突快捷键。批注/搜索/审稿高亮与活动块共存时，文字引用高亮优先，块标记只留页边。

## 6. 助手前端：把已完成的底层能力接出来

### 6.1 工作面

沿用现有助手右栏，简化为“问资料 / 审稿”两个首批可用任务。现有提取、起名、校对等快捷入口继续调用原 owner，可进入更多菜单；不无故移除已有功能。“按意见修改”是意见的动作，不要求用户再切任务并复述意见。“检查影响”待 S13–S16 真正接通后才开放。

```text
助手                  [本章 ▾] [任务记录]
[问资料] [审稿]
审稿重点：动机与行动 ▾
┌ 作者要求（一个自动增高输入） ┐
└───────────────────────────┘
资料与限制 ▸                    [开始审稿]

已检查 2/4 批 · 1 批失败            重试失败批
意见摘要 · 位置
原文引用 → 定位
原因与建议
生成修改候选 · 忽略
```

“审稿重点”采用简单下拉：动机与行动、铺垫与兑现、节奏与冗余。方法 ID、版本、budget 只放技术详情。选中方法可带一条可编辑的默认目标，允许作者写自己的要求；不是复制上游长提示词。

### 6.2 范围与资料

- 初次打开优先当前选区，否则当前块/当前章由入口明确决定；块菜单显式选当前块。页顶只出现一个范围选择器。
- 默认任务不自动扩大为全书。全书审稿必须有遍历章/批与预算的真实实现才开放；“问全书”检索不代表全文已审。
- 使用活动主/副编辑面，含尚未自动保存的内存稿。切换书/章或修改范围时取消旧请求并保留其只读结果；新的请求单独冻结。
- 资料折叠区列已纳入来源及未读取原因；当前场和书级规则保留出处。文本锁与语义要求分别表达：文字锁保护具体区间，语义要求由模型参考，不承诺数学保证。

### 6.3 S06–S12 必须完成的前端闭环

1. 在 `useAuthoringReviewWorkflow` 组装并发送规范化的 `options.writingSkill`，目标/方法/范围/版本一致；服务端 ack 与客户端请求版本对账。未知、不匹配或 validated-only 不能标“方法审稿完成”。
2. 真实批次状态驱动进度；保留成功批次，重试只发失败/剩余批次；预算耗尽显示待续。终止不清掉已有意见，不以虚构百分比遮掩模型等待。
3. 意见按正文位置和明确类别显示：事实冲突、推断、风格建议、资料不足；风格不挂红色错误。引用、定位、依赖去重由 S07 校验，不能直接展示未经校验的 provider 文本为可操作 finding。
4. 展开一条意见即可查看依据并定位正文；回到助手保留意见、滚动和展开状态。一次展开的详细候选占据现有右栏，不叠加第二个侧栏。
5. “生成修改候选”直接携带 finding 与 frozen target 调既有 rewrite，1–2 个候选，原文/候选差异可比较；默认不把证据所在其他章节一起修改。
6. 采用前复验正文/依据/锁定；采用成功才显示“已修改，待复核”。保存失败保留候选，只重试保存；双击幂等；撤销同步意见状态，不触发重复 observer。
7. 结果修改、忽略和重新检查有稳定身份；重试不重置作者已处理的意见。删除目标、同句多处出现、UTF-16/emoji/跨段输入要有独立反例。

本轮前端交付不能停在 S08。验收最小终点是 S11 完整作者旅程及 S12 确定性验收；真实稿件质量作为独立 gate，未运行就保留未验状态。

### 6.4 状态与恢复

用户可见：准备资料→检查第 n/m 批→核对结果→完成/部分完成；后续候选生成→待采用→保存中→已保存/保存失败。取消、来源已变、目标已删除各自有下一步动作。

现有 session 为主。若本轮需刷新保留最小任务记录，应先提取原 S17 必需切片：只落盘任务元信息、已完成批次与结果引用；刷新显示中断，继续前重验依赖，不自动调模型。完整 run 系统、全 Agent 恢复仍归原 S17/S18。禁止为任务历史直接复制另一份正文数据库。

## 7. 生图工作台：画面优先与迭代闭环

### 7.1 布局和常用动作

保留现有宽抽屉，避免迁移成新全局标签页。1440 原型参数列建议 300–340px，右侧图片区占剩余空间；900 使用“设置 / 结果”切换，390 全屏单面。具体断点按容器实测，不固定照搬截图像素。

顶部只有标题、来源摘要、最小化/关闭。左侧顺序：画面描述→风格→参考图→模型/画幅/数量→生成。负面提示、参考强度、技术参数进入高级区；不支持的参数不提供可用假控件。

右侧首屏放大图预览；未生成时显示简洁说明和来源摘要，不放巨型空白卡片。生成后主预览+底部候选缩略条；参数列的风格大预览不能与生成结果争主位。

提供“沿用参数”“作为参考”“与上一张比较”“下载”“保存素材”；插入正文作为明确动作，预告插入位置。两个候选用并排/切换比较即可，本轮不做独立无限画布或复杂擦除编辑器。

### 7.2 正文转画面描述

打开时冻结来源，允许作者直接编辑画面描述；提供可选“从原文整理画面”，单独调用现有文本渠道并先给草稿。抽取主体、动作、场景、光线和构图，不把心理活动直接当画面物体，不默默新增人物外貌。采用描述后才生图，能恢复原描述。

没有文本模型时仍可手写生图。不得因为打开窗口就自动产生额外模型调用。角色入口沿用 `openForCharacter` 的引用和头像参考，场景来源需显式选取，不能把全书秘密自动发往生图渠道。

### 7.3 风格和参考图真实性

风格预设用已有有来源的缩略图，选中有勾选/标签，悬停可放大；明确是“风格示意”，不是当前模型的生成保证。若仅附加文本，显示“通过风格描述应用”，不声称上传了示意图。

参考卡片允许标记用途：人物/外观、风格、构图、通用参考。能力分为：

| adapter 实际支持 | UI 行为 |
|---|---|
| 专门风格/构图/身份输入且映射已验证 | 开放对应用途与真实强度参数 |
| 只有通用 image-to-image | 显示“通用图像参考”；用途仅是文字要求，提示不保证独立控制 |
| 只有 text-to-image | 图片不能伪装为已提交；生成前明确提示不发送图片，作者选择切模型或按文字继续 |
| 配置/能力未知 | 不默许成功，提供配置检查；保留作者当前输入 |

`getImageProviderCapabilities` 需结合 model/endpoint/HTTP template 和 adapter 实际分支；声明与实际 payload 不符视为失败。保存有效参数和实际参考 ID，而非只记用户勾选值。切模型先复核参数兼容性，不静默丢掉参考。

上传沿用既有媒体入口：支持格式/容量以 decoder 和 adapter 为准，校验损坏文件、MIME 不符、超限、重复；本书参考不会串到其他书。参考图删除前查已有任务/媒体引用，不能顺手删掉被正文使用的资产。

### 7.4 结果、失败与持久化

每张候选有稳定 jobId/itemId，状态为 queued/generating/generated/persisting/saved/persist-failed/failed/cancelled。单张成功立即可见且可保存；后续失败不删除已完成图片。停止只阻止未完成项，保留已经完成的结果并准确计数。

采用现有 mediaAssetStore 和图片库，增加必要的工作记录而非 base64 复制到多个 localStorage。可研究漫画“只重试保存”的公共部分；抽取后必须回归漫画原消费者。存储失败时保留内存结果，允许下载和重试保存；浏览器存储本身不可用时不能承诺刷新后恢复未保存图片。

重试生成只针对失败项，重试保存不得请求 provider。晚到结果和切书通过冻结 session 隔离，不写入新书；删除候选与已入正文/素材的引用分开处理。刷新后显示中断，可恢复已落盘成果；不自动重发付费请求。

图片浏览提供自然比例、适应窗口和放大，切图不改 prompt；查看旧结果不会自动覆盖当前编辑中的参数，只有“沿用参数”才覆盖。过期来源图片可下载或保存在其原项目，插入旧锚点必须重新选择并校验目标。

## 9. 验收样本与拒收条件

### 9.1 固定样本

- 正文：单块整章、多个多段块、长对白、长引用、标题、图片块、空章、重复句、emoji/代理对、中文 IME、同章双栏与异章双栏。
- 助手：三种方法各有确有问题/无问题/缺资料；选区/当前块/本章；一批失败、取消、正文和资料分别过期；候选编辑后碰锁定区、保存失败、双击和撤销。
- 图片：无模型、纯文生图、通用图生图、已验证专门 reference adapter；0/1/3 张参考；损坏/超大文件；第一张成功第二张失败；生成成功归档失败；切书、来源删除、停止后晚到、刷新与配额满。

### 9.2 浏览器旅程

1. 正文块可见 → 审稿此块 → 定位意见 → 生成候选 → 采用 → 撤销 → 关闭助手恢复位置。
2. 副栏选区 → 生图 → 本书角色参考 → 生成两张 → 第二张失败 → 保存第一张 → 回原编辑面。
3. 生图完成但归档失败 → 下载/只重试保存 → 生成调用计数不增加 → 刷新看到已存结果。
4. 开始审稿后切书/改稿 → 晚到结果不能变成新书建议；打开旧结果为只读。
5. 全部边界模式 → 拆分/合并/移动 → 场景/批注引用跟随 → 撤销重做 → Markdown 导出不含装饰。

视口：1440、1024、900、390；三处代表性状态都做明暗配对，关键路径补 200% 缩放、reduced-motion、Tab/Escape 和软键盘。截图须人工审阅正文行宽、文本截断、滚动归属、焦点和动作可见性，不用“无 console error”替代视觉验收。

### 9.3 工程与真实质量分开

复用 `scripts/authoring-ui/f2-knowledge-assistant-check.mjs`、`f2-review-search-history-check.mjs`、`writing-skills-baseline-check.mjs` 和实际存在的生图 gate。新增综合脚本名在实施时登记；旧计数仅作历史，不能复制为本轮结果。旧 UI 断言需随新的明确产品合同更新，同时保留数据安全断言。

核心 Vitest 仍 ≤20 文件/200 用例；反例并入现有用例或显式 scripts/eval，不能通过隐藏目录规避预算。正式完成执行 `npm run verify:full`，不为每个 CSS 微调重复运行。

真实质量：助手沿用原 S12 的保留集标准；图片至少覆盖角色、场景、不同画幅和参考开/关的受控对照，记录模型/参数/输入、实际参考使用、耗时、失败率和作者评价。不以确定性 mock 或风格示意证明真实模型效果。缺渠道时继续确定性实现，质量项留未运行。

以下任一发生即拒收：视觉标记改动正式正文；助手只有 UI 没有真实 task 接线；validated-only 显示审稿完成；引用越界仍可修改；生成成功图片因后续失败丢失；保存重试再次生成；模型没收到参考却说已使用；窄屏主要动作不可达；切书结果串写；缺资料显示“无问题”。
