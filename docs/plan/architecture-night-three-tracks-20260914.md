### A4 自审与代表验证（预算 60–90 分钟）

代表旅程：新素材 → 编辑 → 快速切换 → 返回/刷新；勾选/归档/删除后选择；合并来源保留；送入画布重复操作；含图素材模式切换；异步结果晚到仍归原来源。1440/390、亮暗各抽查一个代表状态；重构保持视觉一致，截图只服务于验证。

### C5 储备（约 90–150 分钟）

1. 若 C3 选了图片来源链，继续完成顾问 apply/undo 的 revision/receipt 协调；反之亦然。
2. 迁出图片呈现的纯计算和描述符解析，DOM 命中/拖拽保留专属 adapter。
3. 把本线独有辅助服务归入 materials/media 目录；逐个核对消费者，跨域文件不移动。

最低交付：C0–C2；目标交付：C0–C4。页面减少约 600–1,000 行 script 是参考；单独挪 CSS 或大模板不得计入业务职责减量。

## 9. 每线交付格式

输出路径：`docs/agent-runs/architecture-night-20260914/{a,b,c}/summary.md`。摘要控制在约 500 字，详细证据放同目录表格或小 JSON。必须包含：

1. baseline SHA、交付 commit SHA、实际起止时间、实施与验证耗时。
2. 主包逐项状态：done / partial / not-started / blocked；不得只写“全绿”。
3. before/after：文件总行数、script 行数、页面/store 自有状态、timer/watchers、公开接口与 adapter 数量。
4. 旧职责 → 新 owner → 生产调用入口的对应表；列出保留在旧页面的重逻辑。
5. 具体执行命令、退出码、浏览器报告位置、已知失败与是否基线已有。
6. 自审发现与修复；未验证部分；供 O 直接查看的危险 diff 位置。
7. 提前结束原因和储备执行情况；不要把较短执行时间改写成 8 小时。

worker 自审至少回答：是否有两份可变状态？是否用大量 callback 把业务逻辑重新送回页面？持久化失败能否保持作者输入？旧请求能否写入新对象？导出的新接口是否真的被生产调用？

## 10. O 集成与晨间验收

O 持有 main 和共享文档。workers 使用本地分支提交，遵循 commit skill，不 squash 已公开历史，不 push。按项目协作规则由 O 管理提交动作；手动独立会话交付时也必须留出明确提交边界。

1. 冻结三线 SHA，记录相对基线 diff；确认没有越界文件、缺失 untracked 模块或未运行依赖。
2. 在独立 integration worktree 依次集成 B → C → A。顺序是默认值，若实际 diff 证明有依赖则调整并记录。
3. 每次合入只做必要启动/接口检查，全部组合后再跑 full 与代表旅程。共享断言修订单独审查，不能用测试改动掩盖行为回归。
4. 审查 A 的 Agent/编辑器边界、B 的 session timer/存档、C 的 dirty/异步回投。检查三线是否共同依赖某个被冻结的私有实现。
5. 组合树 full exit 0；核对预算、build、diff、docs。对保存、取消、切对象、采用与撤销执行代表旅程。
6. 更新架构图、STATUS、PLAN、LOG 和任务板。当前事实写实际结果，不按计划预计值回填。
7. 满足用户执行授权后才把已验证组合纳入 main；若主工作树仍有新 WIP，则保留组合分支和具体 SHA，不能覆盖或强行 reset。远端 push、开源发布与 server-version 同步留作独立动作。

### 通过标准

| 维度 | 必须能给出的证据 | 拒收情况 |
| --- | --- | --- |
| 生产接线 | 入口真实调用新模块，旧状态机已删除 | 新模块没有调用方，或页面仍运行旧实现 |
| 状态唯一 | 每项可变状态有一个 owner，数据快照有用途和时效 | 页面与模块同时持有可变正文/session |
| 接口清楚 | 输入/输出/错误/取消/清理可解释 | 传整个页面/store，靠隐含 this 或全局变量 |
| 数据安全 | 保存失败、切对象、迟到响应、撤销旅程 | 丢输入、写错书/素材、重复采用或伪 fresh |
| 简化有效 | 迁出职责与剩余职责清单，适配代码可读 | 只减行数、压格式、挪样式、扩新抽象层 |
| 验证真实 | 实际 SHA/命令/退出码和失败记录 | 转述旧数字、跳过失败、mock 直接改结果状态 |

### 起床后 15 分钟验收建议

- 写作：输入一段 → 触发行内候选 → 采用/撤销 → 打开搜索再关闭 → 正文仍可继续写。
- 推演：两步 → 换路 → 试稿 → 采用/撤销，检查路线和正文归属。
- 素材：编辑后立即切换再返回，刷新确认；选择两项送入画布，核对来源与重复操作。
- 体验：加载已有合成会话、切换另一个再回来，恢复一次历史，核对消息与状态。
- 阅读 O 的剩余职责表，决定下一轮是否继续 document surface/原子历史、剩余 game runtime 或画布整理。

## 11. 失败与交接规则

单包卡住 30–45 分钟仍无进展，记录原因并转本线不依赖该包的主包/储备；对数据保存或页面启动回归则优先修复，不能把红项留到晨间。跨线依赖必须发给 O，worker 不能自行修改邻线文件。

O 若自身暂停或 worker 进程退出，任务板记录最后提交、下一动作与恢复命令。不能只留下聊天日志。无法在预算内安全集成时，交付经过验证的可恢复分支与阻断列表，明确“分线完成、组合未完成”。

本计划的停止线是三条目标交付和组合验收完成。其后剩余文档 surface、原子历史、Notes 图片 DOM、game generation runtime 与 ProseEssay 仍按实际证据排队；不据一晚成果宣称架构完备。

## 13. 扩充的第二批实作：第一批完成后继续

以下不是新增产品功能，而是将当前剩余职责向明确模块迁移。每包先确认真实消费者，复用现有 owner；已被第一批完整覆盖的包可标记 absorbed，但必须指向代码与验证证据，并领取下一包，不能把同一改动重复计成绩。原 A5/B6/C5 中重叠项由这里细化取代，不重复实施。

默认目标提升为：第一批目标交付 + A6/B7/C6 各自第一接续包 + 各线文档供稿。其余包按队列持续领取；超出窗口可以 partial，但必须指出尚未迁出的具体职责。时间区间只用于判断能否在冻结前完成。

### A6 显式参考与来源预检生命周期（目标，60–120 分钟）

- 盘点当前书参考选择、来源刷新/删除、资料变更后的失效及 scope 清理；优先扩展已有引用 owner，而不是再建平行状态。
- 页面只发出选择/移除/刷新意图，来源身份与请求前可用性由同一个模块协调；canonical manifest builder 和预算语义保持不变。
- 交付证据：选参考 → 切书 → 返回；删除参考 → 再触发助手；旧来源加载晚到不污染新书。清除对应旧 watcher 与页面镜像。

### A7 主副编辑面来源适配（接续，60–120 分钟）

- 核对当前主栏/双栏 document、unit、node、caret、revision 读取的重复代码，统一到现有 surface 能力；不新建编辑器，不强制迁移全部文档事务。
- 同一请求始终捕获一个明确 surface，不能在异步结束时用当前主栏替代原副栏；只读快照与可写能力分开传入。
- 交付证据：副栏发起操作 → 切焦点 → 结果仍归正确来源；关闭副栏后迟到结果不写正文。保留编辑器插入与历史 owner，不搬进通用工具函数。

### A8 页面装配依赖收口（接续，45–90 分钟）

- 对本轮新增及相邻 workflow 列出依赖方向，消除 A1–A7 引入的反向状态镜像、重复 scope watchers、无业务意义 wrapper。
- 把真正同一领域的只读派生放回对应 owner；不得仅为缩短 import 数增加全量 barrel 或巨型 useAuthoringEverything。
- 页面应能顺着“来源 → 工作流 → 展示事件”阅读。保留复杂度清单，至少说明最重的三个未迁出领域及下一次入口。

### A9 本线遗留路径清扫（末段低风险，30–60 分钟）

核对已迁出入口遗留的无消费者 import、分支、注释和局部样式。删除生产不可达部分并给出引用证据；动态导入、模板事件、兼容迁移必须一并查，不以单次文本零命中判死。不得扩展到其他页面或改布局。

### B7 Observer 订阅与回执归属（目标，60–120 分钟）

- 收口 observer result 的注册、派发、取消与异常隔离；确认组件卸载及 store/session 切换后的订阅寿命。
- Authoring 现有公开入口、回执身份与失败语义保持不变；一个监听器异常不能阻断其他消费者，也不能吞掉正式保存失败。
- 交付证据：重复进入/离开页面不累积订阅；旧 session 回执不挂到新 session；正常采用/撤销仍能收到原合同结果。

### B8 Journal 与创作来源投影（接续，60–90 分钟）

将 plot journal、creative source refs、恢复摘要的纯投影归入 experience 领域。统一同一事实的转换路径，保留 id/revision/sourceRefs 和顺序；不重建历史系统，不改 worldbook。以现有合成存档对比迁移前后结果和未知字段策略。

### B9 Turn 编排的一个完整阶段（接续，90–150 分钟）

先画剩余生成流程，选择请求准备、结果应用或失败清理中的一个完整且内部可闭合的阶段，复用现有 runtime。将阶段输入/结果/异常写清并生产接线，不复制模型执行器。若需改被冻结的 shared/server 文件或超过冻结窗口，停止该包，转 B10；不得产出未接线的新框架。

### B10 私有服务归域与无用代码（末段低风险，30–60 分钟）

仅移动 B 线独占、消费者已列全的 helper，更新所有导入并删除旧路径。保留需要兼容的公开入口，不以“文件小”为理由拆散事务。处理本线无用变量与过时注释，不承诺清零全仓 191 条 warnings。

### C6 第二条异步采用/撤销链（目标，60–120 分钟）

C3 若收口媒体迁移/图片回投，本包接顾问 apply/undo；反之接媒体来源链。捕获素材 id/revision，保持结果归属和撤销回执，处理编辑后再收到旧结果；取消只能清理自己的操作。禁止一律写到 selectedChapter 或无条件覆盖当前正文。

### C7 图片呈现与交互适配（接续，60–120 分钟）

将图片描述符、尺寸/位置计算等纯逻辑与 DOM 命中、拖拽事件生命周期分开。使用既有媒体仓储，不改变二进制归档和 Markdown 表达。含图素材切换/卸载后不留事件监听；1440/390 验证选择、预览及关闭不回归。若必须改视觉布局，按 UI skill 小切片处理，不能整页重写。

### C8 目录视图与编辑面组件边界（接续，60–120 分钟）

在 C1/C2 业务 owner 稳定之后，评估并抽取一块高内聚目录/编辑展示组件：props 传展示数据，events 表达作者意图，保存仍归现有 owner。禁止子组件再次加载相同仓储或镜像整套编辑状态。保持模板语义、焦点、空态和样式作用域；有组件复杂度收益才抽，不按模板行数切块。

### C9 素材来源交接与清扫（末段低风险，45–75 分钟）

核对本页到画布的来源描述、幂等反馈和已删除素材选择清理；只整理 Notes 侧 adapter，不改画布协议。删除迁出后残留入口/样式/无消费者转换，保留导入旧素材兼容。对需要下一轮改仓储的问题给出定位与最小方案。

完成证据：生产调用只经过一个路由；IME、粘贴、undo/redo、主副栏焦点和连续输入各有代表复现；迁出后页面中重复条件与过期注释删除。若 A1 已完整覆盖触发部分，本包只处理尚存的输入/焦点职责。

完成证据：切换前未保存正文不丢；切换瞬间不显示旧候选；返回原章可继续编辑；旧请求晚到不污染新章。输出顺序图和剩余非 A owner，避免建立“万能切换 controller”。

### B11 分支回合图与重新生成事务

完成证据：从历史消息重生成产生 sibling 而非错误 child；两次切换后消息/状态一致；GC 不删活动链或保留无主 turn；旧存档缺字段仍能加载。不可只迁出 `collect*` 函数而保留两套分支判定。

完成证据：同一合成回应迁移前后得到等价状态；单类解析失败不留下半写状态或静默吞掉关键错误；重复应用保持原有幂等/追加语义。记录仍属 legacy heuristic 的部分，避免把它写成正式结构化合同。

完成证据：切项目与 reset 后旧任务取消；同章不同 unit 队列互不覆盖；撤销只失效对应来源；页面重复挂载不重复创建 runtime。若消费者涉及 A 锁文件，只交窄接口请求，由 O 串行接线。

完成证据：冷启动、加载旧会话、开始新会话、只重置 runtime、完整重置的差异可解释；写作全局素材不会被错误会话操作删除。任何数据删除路径保持原确认和可恢复边界。

完成证据：第一次/重复送入、合并已在画布的素材、删除来源后的提示、从画布返回定位均不串对象；不改变画布协议或布局算法。

完成证据：刷新和切项目后恢复范围正确；无效旧值安全降级；偏好失败不影响素材正文保存。删除页面里的重复读写和魔法默认值。

### C12 历史命名与素材领域语言收口

页面内部仍以 chapter 表示素材的历史命名容易把书稿章节与素材混淆。只在新 owner、私有参数和局部派生中逐步使用 asset/material 语言；正式 schema、持久化 key 和公开兼容入口不机械重命名。给出术语表，标记必须保留的 legacy 名称和以后迁移条件。

完成证据：代码 review 能分清稿件章节与素材条目；没有全仓搜索替换、存档迁移或双别名层。相关 README/架构文档使用用户可理解的“素材”。

### C13 模板与样式的领域组件收口

在 C1–C8 业务 owner 稳定后，从 Notes 模板选一至两个高内聚 surface（目录批量栏、素材编辑头或来源/顾问结果区）抽为受控组件。组件不直接访问仓储，不镜像正文，不自行创建 timer；样式随组件迁移且复用现有 token。只有真实复杂度下降才实施，不按行数平均切模板。

完成证据：props/events 和 owner 对应清楚；1440/390、亮/暗、长标题、空态、键盘焦点无回归；父页面删除旧模板和样式。未实际看图时只报告交互/几何验证，不写视觉通过。

第三批领取顺序：A10 → A11 → A12 → A13；B11 → B12 → B13 → B14；C10 → C11 → C12 → C13。涉及相邻 worker 写集时跳过并报告给 O，不抢锁。T+6:30 后只完成已开启且可安全封板的包，不新开第三批状态机。

## 19. 八小时持续运行协议

### 19.1 启动与监控

- O 记录统一 `T0`、目标 `T+8h`、代码冻结 `T+6:30` 和最终验收截止；三个 worker 在同一核验基线启动，任务板写明当前包与后两个候选包。
- O 每 45–60 分钟读取短状态/提交，不等待整份最终报告。检查项只有：当前包、生产接线、阻断、实际用时、下一包；不要求长叙述。
- worker 提前返回 final 只代表本次调用结束。若仍早于 T+6:30 且队列未耗尽，O 使用同一 worker、同一 worktree 续派下一包；必要时重新启动 worker，并附上最近提交和未完成点。
- 某线阻塞 30–45 分钟后改做同线无依赖包；其他线不得因一线阻塞一起停止。O 自己持续做组合审查、D/S 公共文件和共享补丁，不只等待三线。

### 19.2 深度门槛

T+6:30 前，每线不能以“focused/full 通过”作为停止理由，必须满足以下之一才可进入只修复状态：

1. 第一批目标、第二批目标、skill/文档必交和至少两个第三批包均完成并生产接线；或
2. 所有剩余包都存在已记录的真实写集冲突、危险 schema/外部授权阻断，且同线低风险清扫与文档队列也已耗尽。

这不是要求所有包必然完成，而是禁止只做最小交付就结束。若实际吞吐很快，继续第三批；若前面包暴露缺陷，修复和复验优先，修复时间算有效工作。不能为达到门槛把包标 absorbed，除非列出新 owner、调用位置和覆盖的完成条件。

### 19.3 时间真实性

- 回执记录 active implementation、self-review、verification、blocked/waiting 的实际区间。模型调用返回很快不等于虚构更多工时；等待用户、sleep、重复跑同一 full、重排格式和扩写回执不计 active work。
- 每线至少在第一次完整迁移后做一次独立消费者复查，在交付前做一次“新模块是否真被调用、旧实现是否删除”的反向核查。这两次复查针对不同问题，不是重复测试。
- full 默认在基线、组合候选和最终树运行；worker 使用 focused/定向 build 反馈。除修复全局回归外，不让三线循环跑 full 消耗夜间。
- 真实模型、远端 push、公开发布、许可证决定、server-version 和用户视觉裁决不用于填满本夜；这些仍是外部门禁。

### 19.4 最后 90 分钟

- T+6:30 各线停止领取新状态机，只完成/回退未封板切片，提交可单独集成的产品改动、skill 改动和文档供稿。
- O 依次组合，先数据/运行时，后页面，再 skill/公共文档；每次确认未覆盖主树新 WIP。冲突修复归 O，worker 可在原分支提供有界补丁。
- T+7:15 后只处理组合回归、文档事实错误、链接、diff 和验证。最终 full 若失败，优先恢复可用组合，不为保住包数留下红树。
- 到 T+8h 如实交付：已组合、已冻结未组合、partial、未开始四类。墙钟完成不能覆盖行为不完整；反过来，有足够任务但安全提前耗尽也要说明证据，不假装运行了八小时。

### 19.5 晨间拒收条件

出现下列任一项，不能写“八小时架构计划完成”：三线在 T+6:30 前无阻断而停止续派；只有新文件没有生产消费者；旧可变状态仍与新 owner 并存；只有行数下降；D1–D8 或 S0–S8 被整体跳过；只提供分线测试没有组合树；回执把 waiting 写成实施时间；STATUS/README 继续陈述互相冲突的现状。

晨间摘要首先报告实际运行区间、每线完成包和组合 SHA，再报告行数/测试。用户应能直接看到“为什么这晚没有两小时结束”，也能区分任务池很大与真正完成很多不是一回事。

## 20. 第四层溢出队列：主线全部超预期完成后启用

本层不属于 T+6:30 前的默认最低深度，也不应越过未完成的第一至三批。只有某线已完成自身深度门槛、D/S 供稿及自审，且距离冻结仍有足够窗口时，O 才把一个溢出包连同新增独占写集显式转交。一次只启用一个；预计不能形成可回退完整提交时，改做低风险清扫和复核。

### A14 Authoring 非活动工具的加载边界

编制时生产构建的 Authoring chunk 约 1.58 MB。先用构建/import 证据找出初始写作不需要、但被页面静态加载的重量组件或编辑器工具；只选择一个不改变状态 owner 的边界做已有 Vue lazy surface/异步组件接线。加载失败需要可恢复提示，不能让初始正文依赖网络拆包才能编辑。

验收看初始路由可写、首次打开工具、关闭再开、失败恢复和构建 chunk 变化。若体积来自共同运行时或拆分会导致状态重建，不实施，交分析并领取 A15。不能单纯调整 warning 阈值。

### A15 Authoring 装配层剩余职责审计与下一刀

对迁移后的页面重新生成 import/refs/watchers/timers/事件 owner 表，选剩余最重的一个完整领域，完成一次“是否值得现在迁出”的代码级预检。若可在冻结前闭合，O 决定是否实施；否则提交精确入口、写集、调用链和拒绝继续原因，供下一夜直接开工。预检不得生成无人使用的 scaffold。

### A16 触及文件的局部质量清扫

对 A 本轮修改和新增文件运行定向 lint，修本轮引入及近邻无争议 warnings、错误注释、重复 import、无消费者 adapter。存量全仓 191 warnings 不是清零目标；不得为消 warning 改公开参数或删除动态调用。把仍保留的 warning 按兼容/待重构/误报分类。

### A17 Authoring 恢复/取消故障注入复核

复用现有 fixture 对本轮新 owner 注入三类故障：provider 迟到、编辑器/saver 拒绝、surface 在响应前销毁。核对作者文本、候选、取消和重试回执；把断言并入已有测试或脚本预算，不新开大框架。此包用于发现实现漏洞，不重复跑相同成功旅程。

验收至少覆盖加载/切换会话、发送或继续、一次分支切换、返回 Authoring 的现有行为。禁止恢复被产品收口的独立欢迎/Opening 方向或扩张 legacy Experience。

验收包括用户取消、超时、一次可重试失败、切会话迟到、成功后可见消息；没有真实 key 也应能以现有离线 runner 验证合同。

1. O 先检查该 worker 是否有生产 diff、旧路径删除、自审和当前包证据。
2. 不合格：同一任务直接返工，不计一个完成包。
3. 合格但早于冻结：从该线队列取下一包，用 follow-up/续接会话发送“上一包 SHA + 下一包完成条件 + 写集”，保持已有上下文；不重新做全库调研。
4. 原 worker 无法续接：在同一 worktree 从最近提交启动替代 worker，读短 summary 和 diff；任务板记录换手，不把重新阅读算成功能交付。
5. 所有本线队列都耗尽：O 先进行独立反向审查；确实无遗漏才启用 §20 或借给共享 D/S/O 审阅，不能去碰另一 worker 活跃写集。

### 每次续派的最小消息模板

“继续在同一 worktree/branch 工作。上一包 `<ID>` 已由 O 初审到 `<SHA>`；现在执行 `<next ID>`，写集仅 `<paths>`。先读任务书对应小节和上一包 summary，不重做全库调研。完成条件是 `<production owner/call-site/old-path removal/failure case>`。完成后自审、跑 focused 验证、提交独立 diff，并报告实际用时与下一候选。早于 T+6:30 完成不退出，等待 O 续派。”

### 晨间时间证据

任务板为每线保留 `started_at / last_progress_at / frozen_at / active_minutes / blocked_minutes / packages`。active_minutes 只按有进展区间粗略记录，不追求伪精确；提交时间仅作辅助，不能证明一直工作。O 的晨间报告列每个检查点是否执行、发生过几次续派、哪些包因冻结未开。这样能验证“计划确实持续执行”，同时避免把墙钟本身当成果。

本计划最终拥有每线至少四层队列，正常情况下远多于单个 worker 两小时容量。若仍在两小时内结束，默认视为调度未续派或只做了浅层迁移，需要按 §21 检查，而不是再把下一份计划的工时数字写得更大。
