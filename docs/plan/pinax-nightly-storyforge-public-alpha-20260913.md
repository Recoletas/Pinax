## 1. 起床后应当得到什么

这一晚的目标是形成一个**可本地验收的 Public Alpha 候选版本**，同时完成三类实际交付：

1. 推演记得本路已经发生的秘密暴露和承诺，第二步继承本路后果；作者在现有右栏直接看到两路的具体差别，并能把所选路线转成正文试稿。
2. 首次作者从进入、导入、设定人物到推演、试稿、采纳有连续指引；返回作者优先回到作品；导入、保存、备份失败时能找到下一步，正文和手工改过的标题不会被异步旧结果覆盖。
3. 仓库具备准确 README、贡献入口、数据/AI 边界、安全报告方式、可复现环境和有效 CI；公开风险、许可证选择及未验项有真实清单。交付候选分支，仓库可见性和许可证保持现状。

**推荐三条实施线并行，另有一个持续调度、集成和复验的 owner。** A 推演内核、B 开放工程、C 作者体验分别有 10 个主包与 4 个储备包，合计 42 个 worker 包；owner 另有 O00–O05 六项职责。主包目标约24个worker小时，逐包区间合计约20.5–28.5小时，储备约10–15小时。这是容量估算，不是模型必然工作时长；八小时是本轮墙钟时间目标和截止窗口，不能同时承诺每个上界工作量均在截止前完成。

## 2. 这次如何处理此前两小时结束的问题

此前任务书已经写过长队列和续接。用户仍多次反馈不足两小时结束，说明“文档上说持续八小时”没有保证运行真的继续。当前没有足够进程日志把每一夜唯一归因为任务少、配额不足或调度退出；本轮同时处理这些风险。

| 可能导致提前结束的环节 | 本轮约束 |
|---|---|
| 把最小合同当完整交付 | A 必须通过服务端真实归一化、composable、右栏、试稿；离线 reducer 不是整包完成 |
| worker 交一份 summary 就退出 | owner 验收后继续派下一 ready 包；三线都有无跨线依赖的备用工作 |
| 没实际运行续接 | O00 留下一次“首包退出→领取下一包”的记录；运行平台能力不足时诚实标注普通会话，不冒称已安排无人值守 |
| 等接口、等截图、等用户把整线等停 | 契约在前 45 分钟冻结；用允许的合同 double 做 UI，转独立包；无法公开只阻断发布动作 |
| 测试和回执占掉整夜 | 一个行为切片完成后集中验证，冻结时全量；禁止无改动反复全量来凑时间 |
| 最后才发现三线拼不起来 | T+2h 交第一组接口，T+3.5h 做第一轮完整纵切，T+5.5h 第二次集成 |
| 达到小目标就宣布整轮完成 | 必做主包未交付时只能报局部完成；核心完成且有时间，按排序领储备，不提前写 final |
| 所有“加深”都是测试组合 | 储备含物品后果、显式记忆候选、真实 lint 缺陷、导入性能、示例书和目录编辑改善 |

不能保证人为拖足八小时。若全部主包和就绪储备经复验确实耗尽，可提前交付，并列出用时和队列状态。若两小时停止，回执必须逐项交代剩余包为何无法领取；“已写回执”“等早晨验收”不构成理由。

### 已发现的新缺口

1. `authoringRehearsal.js` 的 `change` 是自由文本；服务端 `buildAdvisorResult` 只保留既有四个字段，新增后果若不贯穿后端会丢失。
2. 人物 action 使用姓名，参与者已有稳定 ref；同名和 planned/present 的区别尚需生产反例。
3. 首访指引在 `rehearsal.run` 出现时 dismiss，尚未见回应/试稿便离场；关闭与重开缺少按书归属。
4. 导入缺少完整异步 ticket，重解析可能覆盖书名/章名的作者修改。
5. 设置的备份面以原始存储键为中心；作者看到“导入 N 个键”，不容易判断作品恢复结果；弹窗焦点循环和回程不完整。
6. README 推荐 Node 22≥22.13，CI 用 Node 20；缺统一运行时声明。lint 存量问题包括重复布局规则噪音及可定位真实错误。
7. 已有第三方 notices/OFL，覆盖范围需要核查；贡献与安全入口尚缺。当前 `LICENSE` 是 PolyForm Noncommercial。

## 8. 验收：必须经过的十四条旅程

| ID | 可观察行为 | 失败判定 |
|---|---|---|
| J01 | 干净浏览器无 Key 新建，立即输入/刷新，回到同章 | 被迫配置模型、正文丢失、指引误完成 |
| J02 | 原有作者从首页继续最近作品，原书/章正确 | 最近作品被大新建入口挤到首屏外且无直接入口 |
| J03 | 导入→改书名/章名→换编码/模式→确认 | 有对应关系的作者修改被无提示丢弃；边界已变仍错误套用旧章名 |
| J04 | 选文件 A 后选 B，A 后返回；解析时取消 | A 反向覆盖 B、关闭后创建书、重复提交建两本 |
| J05 | 指引串起人物→现场→首次回应→Ghost→采纳/主动结束 | 创建 run 就结束，切书串指引，关闭后反复弹回 |

| J07 | 有条件承诺被第二步继承，换行动者对象仍正确 | 承诺无来源、角色同名绑错、尚未入场者无授权回应 |
| J08 | A 写草稿→切 B→B 提交→回 A；不同深度对照 | 丢草稿、比自己、改变旧路线状态、切路发模型请求 |
| J09 | 网络失败/取消/迟到/来源更新 | 重复推进、晚结果落到新路、stale 仍发请求或可采纳 |
| J10 | 选 B 写成试稿，编辑后采用与撤销 | A 内容进入 B 稿、自动写世界书、试稿修改被再生成覆盖 |
| J11 | 设定修改→回准确 writingUnit→旧推演 stale→新推演读新资料 | 错库、错章、旧冻结结果仍可继续 |

## 9. 验证与成本控制

- 一个完整行为切片做一次聚焦验证，发现失败集中修复；final 在候选树运行 `npm run verify:full`，必须打印预算、全量测试、Vite、diff、VitePress 结果。各线独立封板按 `testing-verification` 执行，O 不因单个文字或颜色变动频繁重跑整套。
- 优先扩充现有 F1、推演右栏、设定联动、Web beta 脚本；只有 B 的可移植 CI smoke 有明确独立用途时新增。不得拆出第二套 Vitest 绕过 20/200。
- CI/browser 验证使用合成稿件和独立 browser context，拦截所有非目标生成请求；未匹配请求使 mock Gate 失败。截图里所有名称/内容来自合成 fixture。
- 真实模型由 A 单一 owner 发起；保持既有授权 MiniMax 配置，密钥在服务端注入，不进入浏览器、命令、截图或日志。默认本轮上限 **30 次实际 provider attempts**，包括结构修复和重试；每次记录用途/成功失败/耗时。不做大量自动评审与隐藏重抽。
- 推荐 4 次基线诊断 + 12 次最终步请求（三场×两路×两步）+ 3 次所选路试稿，余 11 次只用于有记录的修复后定向复验。若额度耗尽，将未验证质量列出，转其他包。
- 不安装重型新调度平台；不全量 TS 迁移、不大规模搬代码、不重写 storage/编辑器、不升级框架大版本，不为测试数量或行数目标做机械改造。
