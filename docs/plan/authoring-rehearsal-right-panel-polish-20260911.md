# 推演右栏接入与体验打磨计划

日期：2026-09-11。状态：计划待执行；用户已确认同屏形态，不代表生产视觉已验收。

归属：Authoring 文本工作台 G1.4 / F1、F3 的交互收口，不另立产品主线。工作区为 `/home/recoletas/jiuguan/pinax-integration-20260906` 的 `main`，保留当前未提交实现；不得回旧 integration 工作区覆盖代码。本文接管此前“专注推演页”与右栏局部精修的后续 UI 方向，不接管协作 C2、知识 K 或永久历史系统。

## 1. 这次必须解决什么

用户确认的是：**把同屏原型的故事阅读与就地操作放进现有右栏，正文一直能写，试稿回正文。**

此前失败不是缺少又一套布局，而是右栏像工具清单、正文回应不像故事，随后又把空间问题过度纠正为独立页面。此次不再让作者在写作页、推演页、对照页和试稿页间往返。

目标体验：从落笔处打开右栏 → 安排一个行动 → 读到人物回应 → 继续或换一种走法 → 在正文编辑试稿。过程中没有路由切换、没有第二个编辑器、没有额外工作区。批注处理“已写文本怎么改”；推演处理“人物接下来怎么做、会发生什么”。区别靠内容与交互体现，不靠夸张装饰。

## 3. 冻结的界面合同

### 3.1 布局与进入退出

- 唯一入口仍是现有右侧工具栏“推演”及正文落笔处入口；进入同一个 panel 实例，不创建独立页面。
- 原章节、正文编辑器实例、滚动容器与选区书签不重建。打开只改变工具区，除主动“定位起点/查看试稿”外，不滚动正文。
- 关闭叫“收起”，不是“退出推演”。重开恢复本次路线、输入、展开状态与右栏阅读位置；切其他工具不能清空会话。
- 普通收起不暗中取消生成；生成可继续，重开可见结果；“停止”是独立动作。换章/换作品/离开页面遵守现有取消和失效规则，不跨章复活。
- 不默认抢占半屏，不自动折起左侧目录；若后续确需宽阅读，只提供作者主动触发的栏宽扩展，不能盖住正文或变成新页面。首片不做拖拽布局系统。

### 3.2 右栏信息层级

1. 栏头只保留现有“推演”、收起与更多；不得再叠一层大标题。
2. 起点是可定位的一行出处，超长可查看完整标题；不重复整段原文。正文不在视野内时，允许按需展开短摘录，不常驻第二份稿件。
3. 当前走法的连续故事是主体，作者行动用轻量行标记，字号与颜色低于故事。
4. 下一步建议最多三条，简短文本行；自由行动输入与唯一提交按钮相邻。
5. 换路、对照、写成试稿按当前状态出现；资料、人物信念对照、重开、临时保存说明归入更多。

删除项：宣传文案、每步“试演/假想/回应”重复标签、重复章名、常驻模型/引用 ID、装饰性卡片框、虚构进度和关系数值。错误、过期与未采用状态不能为了简洁删除。

### 3.3 阅读、行动与趣味

- 当前四步默认连续呈现，不默认只剩最后一步。旧步骤可由作者主动收起，但追加结果不重置其选择。
- 故事建议 16–17px、行高 1.85–2；正文宽度取决于真实栏内净宽，先以 420–440px 栏验证，再决定是否微增。行动/工具文字约 12–13px；手机触控至少 44px。
- 保留真实段落，避免空行放大、逐句卡片化、对白气泡化、对响应内容做不可靠的语义重写。
- 行动说明必须是具体行为，如“问他为什么不进来”，不要变成“推进剧情”“增加冲突”等后台指令。
- 点击建议只填入输入并聚焦，可改后提交；不改成点击即消耗一次模型请求。Enter 换行，Ctrl/⌘+Enter 提交，IME 不误发。
- 兴趣来自“行动→人物反应→可察觉的代价→下一次尝试”。局面变化默认按需看；不强制替故事解释一遍，不把所有选项提前包装成胜负答案。
- 当前 parser 不流式产出故事时，展示真实等待与停止即可；不假装逐字输出、不编造阶段百分比。

### 3.4 换路与对照

- 从某步换路的语义明确为“从这次行动前另试”，保留此前前缀与旧路。回到根起点和改中途行动不能混叫“重来”。
- 走法名字优先取分歧处的具体行动，而非统一第一步或“分支 1/2”。长名字截断但有完整可访问文本。
- 当前路和一条其他路即可轻量切换；更多旧路按需展开，不能把最多四条挤成多层标签栏。
- 对照在右栏内展开/收起，正文不动。默认比较共同前缀后的分歧行动及最新后果，完整路径按需阅读。
- 不等长路径标明各自推进到第几步，不把一边第一步和另一边第四步当成同一时刻。
- 右栏内采用上下对照，不在 420px 再套两个窄列；关闭对照回原阅读位置，不重新生成。
- 路径列表会归档与截断，不能把易变化的数组索引当长期选中身份。使用本会话最小稳定标识或不可变比较快照；不升级项目存储格式。

### 3.5 正文试稿

- “写成试稿”继续复用既有生成链，结果是正文落笔处唯一 Ghost；不在右栏新增可编辑稿件。
- 生成就绪只滚动正文到 Ghost；桌面右栏保持可见，路径/输入不清空。需要时点“查看试稿”再次定位，零模型请求。
- 明确草稿来自哪次推演/哪条走法。切换右栏走法不能暗中替换已手改的 Ghost，也不能把另一种工具产生的草稿称为当前路试稿。
- 已有同源稿：查看。已有异源稿：显示“正文已有待处理试稿”，提供定位；采用、留作构思、放弃沿用现有操作，不建立草稿队列或强制弹窗链。
- 采用前不写正式正文或设定；采用保持现有原子事务与一次撤销边界。采用导致来源变化后，旧试演只能回看或显式重定起点。

### 3.6 窄屏与焦点

- 1440/1280：正文和现有右栏并排，章节名不被保存/切换图标挤掉；其他工具栏宽不受影响。
- 1024/900：检查现有覆盖布局的实际可写区域。推演优先使用同工作区的顺序展开降级，不用遮罩阻断正文；断点沿用 1180/980/720，具体切换由实际几何验收决定，不添一套全站断点。
- 720/390：同一工作区正文后顺序展开推演，不做全屏路由、强制专注模式或盖住整页的半屏浮层。复用同一逻辑 owner，不双挂载 panel/编辑器；手机方向仍需真实页面确认，不能把原型长截图视为软键盘验收。
- 桌面故事滚动与底部输入分区；窄屏优先单一纵向滚动，必要的 sticky 仅在推演区内生效，不压住正文、底部 rail 或键盘。
- 新结果仅在作者接近故事底部时自动跟随；正在回读则给轻量“有新回应”入口，不抢滚动、不抢输入焦点。
- 关闭按钮回工具入口，定位正文回编辑目标；不能每次更新都 focus 标题。选区恢复用既有 ProseMirror bookmark，不直接操作裸 DOM Range 充当生产方案。

## 4. 执行任务包

顺序：R0 → R1 → R2 → R3 → R4 → R5 → R6 → R7 → R8 → R9。R1 是唯一需要先看截图定局部比例的切片；用户已确认同屏方向，不再重复询问是否放右栏。所有任务默认同一个实施 owner，避免与 C2 同时修改 `Authoring.vue`。

### R0 · 建立生产基线与写集

- 记录 branch、dirty diff 和未跟踪文件，不把现有工作误删；核对其他会话是否正在改 Authoring。
- 用同一作品/落笔处采集当前生产 1440、900、390、720×450：初始、两步回应、Ghost 三态。
- 记录正文净宽、推演净宽、顶部占用、输入区高度、滚动 owner；以真实数据确定 R1 比例。
- 梳理入口→run→step→Ghost 的现有 owner，确认收起工具是否卸载展示但保留 composable。
- 交付：简短基线表与截图；不另写几十页调研。不改 provider、不修 unrelated WIP。

### R1 · 将确认形态放进真实右栏

- 主要文件：`AuthoringRehearsalPanel.vue`、`Authoring.block-native.css`；`Authoring.vue` 只做必要 class/slot 连接。
- 保留现有 inspector chrome；去除重复栏头与大块介绍；故事区无层层卡片。
- 只对推演施加样式，亮暗色使用现有 token，禁止拷入原型全局 `button/body/.prose` 规则。
- 先用真实组件的两步固定 provider fixture 拍 1440/390，验证正文与故事哪个是主次。
- 验收：不用进入另一页；正文可输入；章名可辨；工具图标不压主文字；故事不是小号表单正文。
- 此片若仍像“工具配置面板”，就在此修正，不继续堆换路/比较装饰掩盖问题。

### R2 · 连续阅读与低干扰滚动

- 改掉每次只展开末步的默认结构；以稳定步骤身份保存主动折叠状态。
- 合并每步次要工具，换路入口不占整行空白；局面变化不复制进正文。
- 修正 watcher 无条件滚到新步：分别处理首次进入、自己提交、回读时追加、恢复旧路。
- 收起/重开及临时切其他工具保留阅读位置；故事与编辑器的滚动不得互相牵动。
- 验收：读完两步像同一场戏；读第一步时新结果不拉走；键盘焦点留在原操作处。

### R3 · 行动输入与生成状态

- 保留自由行动与最多三条候选；选中反馈、输入修改后取消过时高亮、IME 和快捷键一致。
- 固定底部区只保留当前输入、试演/停止与必要试稿入口；矮屏先压缩辅助间距，不先缩小可读正文。
- 空行动禁发、重复提交阻断；失败保留输入和旧回应；停止后可继续输入，迟到结果不追加。
- 四步上限后保留换路与试稿出口，简短解释限制，不显示失效的输入框。
- 验收：从建议到改写到提交是一条路径；“查看”不生成、“选择”不生成，等待期间确有停止出口。

### R4 · 路线切换与就地比较

- 用现有 `rewind/restore/paths` 建立轻量走法条与更多旧路；先查归档导致索引漂移再接比较状态。
- 比较内容只来自已生成结果，不额外请求总结模型；共同前缀确定性去重，分歧处、推进深度明确。
- 换路操作对尚未提交的输入给出可恢复策略：优先按路保留草拟行动，若清除则先明确告知，不静默丢字。
- 生成中不可偷偷切到另一条归属；只允许既有停止后换路流程。
- 验收：两路切换和比较均不重跑模型；同前缀路线可区分；恢复已归档路不恢复错路。

### R5 · 试稿归属与正文交接

- 检查 `draft-ready=Boolean(blockPreview)` 与来源信息；优先使用现有 run/target/receipt 身份，缺字段只加会话元信息。
- 区分本路已有稿、其他路已有稿、其他工具已有稿，不用一个“查看试稿”暗示同源。
- 定位 Ghost 不收起桌面推演；窄屏在同一文档流定位，不开启独立编辑页。
- 切路不改 Ghost 内容；再次点击查看零生成；已有稿不自动覆盖。重新确定起点保留现有保护。
- 验收：A 路手改稿→看 B 路→查看已有稿，仍是 A 的修改；采用后一次撤销能撤回整次写入。

### R6 · 窄屏与编辑连续性

- 推演工具单独处理非模态顺序展开；不改变角色、设定、批注及普通双栏的现有展示。
- 覆盖 1280/1024/900/720×450/390，补 200% 缩放下的关键入口。
- 处理长章名、三条长建议、300 字输入、四步长回应、菜单出界与软键盘收缩；不通过裁掉按钮伪造无溢出。
- 同源推演变 stale 时，保留故事与手改稿，仅关闭不安全的继续/生成；提供定位起点和显式重新开始。
- 验收：推演展开时正文仍可达；输入/停止/收起可达；无双重固定底栏遮挡。真实设备键盘若未测，单列待验，不用桌面尺寸模拟代替。

### R7 · 趣味与文字精修

- 在现有 fixture 与用户允许的样例中检查三类场景：隐瞒/坦白的信任代价、合作/拒绝的利益选择、追问/离开的信息选择。
- 每场走两路、每路两步，人工读“第二步是否承接第一步”“人物是否有自己的反应”“两路是否只是同义改写”。不增加几十场批量评测。
- 先修界面是否藏住好内容、动作是否难理解、选项是否剧透；若真实模型内容本身空泛，另记生成质量缺口，不能声称 CSS 已解决趣味。
- 允许在既有请求文案范围做小幅纠偏；不改返回 schema、不增加工具链、不制造角色知识隔离已实现的假象。
- 真实模型调用须使用明确授权的数据/渠道；无授权则用确定性样例完成 UI 验证并标记内容质量待验。
- 验收：能读出两个选择带来的不同关系或处境，而不是满屏“变化+1”；不加入积分、成就、卡牌、装饰动画或预设胜负标签。

### R8 · 小范围清理与回归

- 删除此次替换后确实无引用的旧模板/局部 CSS/派生状态；不顺手拆分整个 `Authoring.vue`。
- 原型不进入生产依赖；标明其为方向记录。若保留原型，去除失效页说明，不能继续把旧专注页当默认方向。
- 复用 `scripts/authoring-ui/f1-scene-lab-check.mjs` 加关键断言，核心断言并入现有用例；不得增加核心文件/用例预算。
- 检查人物 IF 入口仍可达、A/B 稿独立保护不退化；检查批注/助手/角色/设定/双栏没有被推演样式波及。
- 验收：无死入口、无两套 owner、无样例数据漏进生产、无为了截图而关闭数据校验。

### R9 · 最终交付与用户验收

- 跑 `npm run verify:full`，确认 exit 0、20 文件/200 用例预算、应用与文档 build、diff 检查；focused 不代替全量。
- 最终只保留必要证据：1440 连续两步、1440 右栏比较+正文 Ghost、390 顺序流、720×450 输入可达、900 深色。过程截图不充当完成量。
- 给出真实页面入口、完成任务 ID、实际未完成项、已知限制与一次完整体验路径。
- 更新 STATUS/LOG；“实现通过”“真实模型质量通过”“用户视觉通过”分开标记。
- 未经新请求不 push、不合并生产适配分支；不因测试全绿宣布审美已获认可。

## 5. 状态与验收矩阵

| 场景 | 必须保留 | 可用动作 | 禁止行为 |
|---|---|---|---|
| 尚未开始 | 正文与选区书签 | 从当前落笔处开始 | 空跑一次模型只为打开面板 |
| 准备中/生成中 | 旧故事、作者输入 | 停止；收起不等于停止 | 重复请求、迟到串路 |
| 一到三步 | 连续故事、当前路线 | 继续、换路、试稿 | 追加后自动折掉作者正在读的旧步 |
| 四步 | 全部故事与旧路 | 换路、比较、试稿 | 死输入、自动重开 |
| 比较中 | 正文、原阅读位置 | 选择查看、关闭对照 | 新路由、额外总结请求 |
| 已有手改稿 | 来源与改动 | 定位、采用、留构思、放弃 | 切路替换草稿 |
| 来源变化 | 旧故事与未采用稿 | 回看、定位、显式重定起点 | 绕过 stale 继续生成/采纳 |
| 请求失败/停止 | 已完成步骤、未提交意图 | 修改后重试 | 清空整场、泄露底层异常栈 |
| 收起/切工具 | 本会话状态 | 恢复 | 按展示生命周期清 run |
| 换章/离页 | 现有项目保存语义 | 明确关闭本次会话 | 把迟到结果写进新章 |

## 6. 优先级、时间与停止条件

- P0：R1 同屏真实接入、R3 可操作、R5 不串稿、R6 不遮挡及既有安全语义。
- P1：R2 连续阅读、R4 路线/对照、R7 趣味表达、R8 清理。它们是本轮目标，不因 P0 通过就宣布全部完成。
- 可推迟：主动扩宽右栏、额外阅读快捷键；不影响已确认主流程。永久历史、设定数据库、tool call 可视化、多角色引擎不属于本计划。
- 粗估：R0–R1 1–2h，R2–R3 1.5–2.5h，R4–R5 2–3h，R6 1–2h，R7–R9 1–2h；合计约 6.5–11.5h，含适量修正，非执行时长保证。
- 用任务和证据定义完成，不用“熬够八小时”。若两小时确实做完所有目标，报告实际结果；若只做完布局，不得把剩余包默默降为后续。
- 任一包受阻先处理其余不依赖任务，交接注明具体原因；方向已定，不以反复重新写原型替代接线。只有需要新增数据架构/破坏存储合同/占用他人写集时停下请求决策。
- 本轮完成最低条件：生产页能走通“正文打开推演→两步→另一路→就地比较→正文手改稿→采用”，且正文不中断、稿件不丢、窄屏不被盖住。缺少比较或草稿归属只能算部分完成。

## 7. 给实施者的最后约束

别再发明一个推演页面。先把已经确认的故事阅读形态放进真实右栏，再解决真实状态和细节。宁可少一个附属按钮，也不要多一个工作区；宁可如实标记模型质量待验，也不要用精心编写的固定样例冒充生产趣味。
