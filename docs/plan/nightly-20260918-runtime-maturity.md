## 交付目标与持续执行合同

目标是持续补齐记忆、跑团与 Agent 的生产能力，而不是做完一个最小闭环就结束。G 批是第一道验收点，M/R/T 全部属于本轮可自动领取的实施队列，不是另等用户启动的储备。任务量有意超过一个短工作时段，不承诺所有工作一定一夜完成，也不人为限制只做几小时。

执行开始后遵守以下调度规则：

1. 每完成并验证一项，记录证据，立即领取依赖满足的下一项；完成 G4、一次 commit 或一次全绿门禁均不是停止条件。
2. 默认单执行者按下文领取顺序推进；只有明确安排多人时才并行，不能把三方向任务表当作启动 worker 的授权。
3. 单项受阻，记录具体原因、已尝试路径、解锁条件和可继续任务，转做后者。不因没有付费模型、真机或某个共享接口而停掉整个队列。
4. 估时只用来检查拆分是否合理，不是截止时间。超出估时先报告原因、缩小当前提交范围，保留完整任务为进行中或 blocked，继续修复或切换，不把原定交付降级为 done。
5. 用户未给停止时刻，不自行设置“六小时”“天亮”“首片完成”终点。允许结束实施的条件只有：用户叫停/指定截止到达；全部范围完成；或所有剩余任务确实依赖外部输入且安全替代路径已耗尽。后者需列出逐项阻塞证据，不能写笼统“需要确认”。
6. 阶段汇报后继续工作；不以“下一步可以……”把已经在本队列内的工作交回用户。上下文压缩后从任务板的 nextReady 继续，不重复调研和已完成门禁。

硬规则：**有成熟实现先复用其代码**。任务不得直接从空文件实现；先给出上游文件/固定 SHA/许可/依赖闭包/移植范围，再动代码。因语言、数据库或模型不同不能复用时记录具体原因，只自研必要适配层。复用后必须跑上游适用反例及本地生产链，不能仅包装空壳接口。

### R：从规则演示走向一场可继续的 AI 跑团

- R1：适配复用 StoryForge KP 阶段协调代码，接现有规则端口；先支持 director → narration → 一个 companion，预算默认最多 3 个 AI 动作。真人选择/待回应/暂停/结局立即停，不把无限续写当主持。
- R2：同伴由模型在白名单中提出 actionId、target、理由；应用程序验证身份/资源/场景/revision。复用可移植投影与信息边界模块；不合法输出保留诊断后停下，不偷偷改为第一个动作并称“AI 决策”。
- R3：一个既有原创场景跑 20 轮，含失败推进、线索、消耗、结局、保存继续、正文收集；所有骰子和资源计算仍归确定性规则。先做好一场，不增剧本数量冒充成熟度。

### T：工具和长期运行的推广

- T1：工具执行处统一核验 task、phase、scope、revision 和 effect。读工具/计划提交/候选采用分开；禁止工具返回文本改变权限。复用 StoryForge registry/schema 的可独立校验部分，保留本项目 provider adapter。
- T2：持久 budget 与副作用结果回执；刷新/失败不重置预算。同幂等键不同参数拒绝，执行成功但响应丢失进入 unknown/reconcile。对纯读可重试，对不确定写先查回执；不承诺跨外部服务 exactly-once。
- T3：诊断页显示步骤、耗时、来源、用量、停机原因和恢复入口；脱敏，不存 token/密钥，不默认复制全文。先扩展现有轨迹，不新增庞大监控平台。
- 写集：`src/services/agents/`、必要 server adapter；数据库 schema 和 production 接线需单 owner。不要为了统一一次迁移全部 Agent 任务。

## 冻结接口与复用回执

G2a 必须先确定以下最小接口，M/R 不自建同名 store：

1. `RunIdentity`：runId、taskId、scope（book/session/branch）、contractVersion、resourceRevision。
2. `RunStatus`：running / awaiting-human / interrupted / unknown / completed / failed / cancelled；候选、确认、采用分开，不能只有一个 completed 布尔值。
3. `StepReceipt`：stepId/attempt、inputHash、status、resultRef/resultHash、预算消耗、errorCode；副作用另带 effectKey 与 commitReceipt。
4. `KnowledgeRead`：actor scope + storyAt + recordedAsOf → facts/provenance/exclusions/completeness；不得默认扩大到作者权限。

## 必须失败得正确的场景

| 类别 | 最低反例 |
|---|---|
| 记忆 | 跨书读取；单主体高版本量；recordedAt 大账本；旧相关事实被新无关项挤出；unknown 被显示为 open |
| 恢复 | 工具成功后刷新；候选保存后刷新；确认后采用前退出；采用成功但返回前中断；checkpoint 损坏/旧契约 |
| 权限 | 角色读作者秘密；工具参数伪造 scope；正文阶段调用规划工具；资料文本诱导额外工具；切书后迟到响应 |
| 预算 | 429 重试；刷新不清零；取消后迟到结果；重复点击/双标签；预算耗尽仍保留可检查结果 |
| 结算 | 同 command 重放；同 key 不同参数；revision 改变；配额/归档失败；重复采用不重复骰子/资源/事实 |

专项用 `scripts/` eval，复用适用上游 fixture；核心 Vitest 保持总量 ≤20 文件/200 用例，扩展既有用例，不改排除规则绕预算。完成前 `npm run verify:full` exit 0，报告 files/tests/build/docs/diff；另给生产入口与真实 IndexedDB 的故障回执，mock 成功不能代替。

真实模型评测是独立质量 Gate，本轮未执行：建议以后明确可用渠道和费用上限后，用 12 个固定样本（记忆/主持/工具各 4）记录重复调用、证据支持、违规动作和秘密泄漏；扩展到 20 轮跑团时单列消耗。结构/泄漏关键项要求 0 次错误，叙事质量由人工评阅；这些是计划阈值，不是现有成绩。无额度不阻塞离线工作，但不能宣称模型效果通过。

## 最终交付与完成判据

交付：代码复用清单、实际 diff/提交、门禁退出码、场景逐项结果、失败截图或回执、数据库/备份兼容证据、未完成项和下一切片。不默认提交整个脏树、不推送、不部署；是否合并依据后续实施授权与验收结果。

若时序/角色知识/自主 KP 只做了接口，明确标 partial；仅 G0/G1 完成时只能报告“记忆可靠性阶段已完成”，并继续领取任务，不得以此结束执行或写“Agent 架构升级完成”。没有跑真实模型时，最多称确定性工程闭环，不能称成熟 AI 跑团。全部本地任务通过但真实模型 Gate 受额度阻塞时，报告工程完成与外部质量未验收这两个独立事实。
