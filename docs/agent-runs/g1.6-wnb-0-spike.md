# G1.6 WNB-0 Spike

日期：2026-08-10

## 目标

验证写作 Notebook 计划的第一道门槛：旧 Markdown 章节可以导入为带稳定块标识的结构化文档，导出时不丢失原文；单块发生编辑后，只让该块退出原始 Markdown 快速路径，邻接块仍保持原文；长章性能可以被实际测量。

## 产物

- `src/services/writing/writingDocumentSchema.js`
- `scripts/fixtures/writing-notebook-r0-samples.js`
- `scripts/writing-notebook-r0-spike.mjs`
- `npm run spike:writing-notebook`
- `src/components/writing/WritingNotebookEditor.vue`

数据层先以独立 spike 形式实现，没有修改默认 `Writing.vue`。支持的首批块类型为正文、场景标题、分隔线、作者注和来源引用。每个块包含 `blockId`、`revision`、`kind`、原始 Markdown 和原始文本；编辑器接入时这些字段会成为 transaction、批注和候选校验的基础。

随后补充了隔离的 Vue 编辑器入口：`/writing?notebookSpike=1`。它使用单一 Tiptap editor instance，默认写作入口仍保持原编辑器；该入口只用于验证编辑器生命周期、JSON doc 形状、中文输入和响应式布局。

## 通过结果

| fixture | 字符数 | 块数 | 导入耗时 |
| --- | ---: | ---: | ---: |
| 空章 | 0 | 0 | 0.66ms |
| 多人对白与批注 | 97 | 7 | 13.64ms |
| 5k 中文章节 | 5,000 | 51 | 2.00ms |
| 20k 中文章节 | 20,000 | 191 | 2.13ms |
| 100k 中文章节 | 100,000 | 992 | 7.69ms |
| 混合 Markdown | 97 | 6 | 5.68ms |

上述数值来自一次本机 Node 运行，用于 spike 记录，不替代浏览器输入 P95 门禁。6/6 fixture 通过结构校验、块 ID 唯一性和 Markdown 往返；短章单块修改断言通过，未修改邻块内容保持不变。

浏览器冒烟：现有 `127.0.0.1:5173` 服务在 `1440x900` 和 `390x844` 加载 Notebook spike，均成功挂载并输入中文；`document.scrollWidth` 分别为 1440 和 390，没有 page error、console error 或横向溢出。单块输入会产生新的 document revision，并保持邻接块文本。

## 取舍与遗留

- 已引入 Tiptap/ProseMirror 开源核心依赖并完成最小 Vue 挂载验证；还没有把它替换到默认写作编辑器，也没有启用商业 Cloud/Comments/Version History 扩展。
- `marked` 只负责一次性 Markdown 词法解析；编辑器接入后，正式 document schema 仍由编辑器 transaction 管理。
- 当前块 ID 是导入期生成的迁移 ID，不承诺重复 Markdown 导入后保持同一身份；进入 WNB-1 后由编辑器节点 ID 插件接管。
- 中文输入、挂载和窄屏几何已完成首轮验证；下一阶段仍需验证 IME composition、跨段选择、撤销、粘贴、拖动、100k 字符输入延迟，并完成 Tiptap 依赖许可证与产物体积审计。
