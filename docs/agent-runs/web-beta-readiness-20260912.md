# Web 小范围内测就绪回执（2026-09-12）

## 结论

当前 `main` 已具备邀请 3–5 位作者做第一轮受控 Web 内测的产品闭环：从空白或旧稿进入，写作并刷新，建立随书人物/设定资料，调用内置模型完成推演，最后导出备份；出现问题时可带低敏诊断反馈。

这不是“公开发布就绪”。真实作者是否愿意继续第二步推演、对照是否帮助决策、试稿需要改多少，必须由本轮内测回答，不能由自动化或代理样本替代。

## 本轮补齐

- 旧稿导入从仅 UTF-8 / 2 MB 扩为常见中文编码 / 5 MB；自动识别 UTF-8、GB18030、Big5、UTF-16，置信度不足时允许在预览页切换编码。
- 空书第一次新建人物或设定会自动建立并绑定当前书的资料库；原先看似可点、实际只能打开空关联选择器的首旅阻断已消除。
- 内置 MiniMax 详情增加可见的“测试连通性”和结果反馈；设置文案不再无条件宣称开箱即用。
- 修复 `/api/chat/test` 的服务器密钥传递：文本探测与结构化探测现在都使用服务器注入后的有效密钥。
- Web 门禁加入作品备份的真实 UI 往返：导出、清空浏览器数据、读取备份、确认恢复、刷新复核正文。

## 证据

- 全新浏览器：新建《纸上灯塔》→正文输入→立即刷新→打开角色→新建“守塔人岑禾”→自动建库、绑定、保存，全部通过。
- 中文旧稿：真实浏览器用 GB18030 TXT 导入两章，预览显示编码，改章名后创建，刷新仍在。
- 长篇代表样本：GB18030、751,451 字符、1,502,171 bytes、120 章；自动识别高置信度，解码、拆章和建书数据约 44ms。该项是合成长篇规模检查，不冒充真实作品人工审读。
- 备份：真实 UI 完成“导出→清空 localStorage→导入预览→确认→刷新”，书名与首章正文一致。
- 模型：真实部署密钥下内置 MiniMax 文本可用，结构化设定为 `native-json-schema`；模型详情页显示“连接成功”。P2 已另有 12 次真实推演与 3 份试稿样本。
- 诊断：导出合同明确为不含正文、标题、ID、模型密钥、提示词或模型回复。
- 回归：Web beta 浏览器 Gate 全绿；`npm run verify:full` exit 0（20/20 文件、200/200 用例、Vite/VitePress build、diff check）。

## 首轮内测范围与停止条件

只邀请 3–5 位愿意直接反馈的作者，统一走 `Web 内测说明` 中的 15 分钟任务。每人结束前导出一次作品备份。

出现以下任一情况即暂停扩招并优先修复：正文刷新后丢失；备份无法恢复；全新用户无法独立建立人物并进入推演；内置模型在同一部署连续不可用；页面错误导致无法返回正文。

## 已知边界

- 手机中文输入法、软键盘、Safari / 微信内置浏览器尚未系统验收；首轮优先桌面 Chrome / Edge。
- 数据仅在当前浏览器，不提供账号、云同步或跨设备一致性。
- JSON 备份不包含 IndexedDB 中的来源文件和媒体原件。
- MiniMax 探测中首个工具调用可达，但工具结果往返能力未通过；本轮只承诺现有写作、设定和推演链，不承诺未来的通用多工具 Agent。
- P4 的五次真实作品主观观察尚未发生；它就是首轮受控内测的核心任务，而不是可由脚本提前盖章的发布门禁。
