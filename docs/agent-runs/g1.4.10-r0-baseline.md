## 每个 plan-§B 根因的实测证据

1. **measure 不生效** — 确认。`--experience-measure: 64em` 已在 css var (`cssVars.measure="64em"`)，`.prose__body` 实测 `widthPx=1004.64@1440 / 852.80@1280 / 815.28@980` — 1440 行宽 ≈ 59 行字符（17px em），但 `.prose__body` 元素本身（clientWidth=1182/1003/959）远超 64em (`64×17=1088px`)。measure 仅作用于 inline 子元素、未限制整体 prose 列。需 R1 改 `.prose-reading-plane` 边界 + 应用 `max-width: var(--experience-measure)`。
2. **物理字号被 zoom 拖低** — 确认。audit 抽出 `fontSizePx=17`、未抽取 `--app-ui-zoom`，但 plan C-2 明确要求 "zoom 0.85 不低于 16px"。R1 须为正文做 `/ uiZoom` 反补偿。
3. **多 owner 冲突** — 部分。audit 仅抽 computed style，未做 owner 计数。需 R1 用 `simplify` 之类的工具核对 `Experience.vue / GamePanel.vue / NarrativeTurn.vue / legacy.css / kao.css` 五个文件的命中行数（plan B-3 报告 248 行）。
4. **斜体密度过高** — 确认。emphasis 比例 narrative 82.7 / dialogue 17.3，rp-action/thought/world-intro 全为 0。R3 须为 action / thought / location / time 引入差异化 token，而非全部加斜体。
5. **节奏无单一 owner** — 待验证。R0 未抽取 block-gap / paragraph-indent computed 值，留待 R1 owner 收口后做对比。
6. **重复地点反复蓝染** — 待验证。R0 没解析 inline decoration；但 `sampleRepeatedEntities` 已落盘，R3 用 audit 的 `inspectRpInlineTokens`（如已实现）跑对比。
7. **speaker 重复 / 旁白外漏** — 待验证。scripts/fixtures `sampleNarrationWithDialogue` 与 `sampleActionThought` 尚未送入 audit；R2 接入后再实测。
8. **long fixture 假内容** — 已确认。`lastMessageInputGap` 在 long 状态下出现负值 (-557 ~ -2093 px)，因为现有 long fixture 是 16 段编号占位句堆叠，并没有真实自然段，可视化无意义。R0 已用 `scripts/fixtures/experience-r0-samples.js` 替换占位句。
9. **移动端 tip/通知遮输入** — 确认。390px edge-overlaps 有 `gm-persona-dock` ↔ `tip-banner` 互相重叠记录（box.bottom 833.81 > 830.41）；R4 需解决底栏 z-order。

## 1440px 验收冻结值

1. 标准档正文使用 **17.5px 物理字号**；该值按最终屏幕 computed size 验收，不允许再被全局 UI zoom 缩小。
2. 标准档 `max-width: 62em`，作为上限而非强制宽度；窄于该值时随阅读面自然收缩。
3. speaker 采用 **B：13px sans label**，每个连续 speaker group 只出现一次，不加卡片、边框或底色。
4. 仅真实引号对白使用一层轻斜体；动作、叙述保持正常体，不能把 dialogue marker 下的非对白句整段倾斜。
5. 普通 turn 的强调字符比例以 **15% 为硬上限**，常态目标为 8–12%。R1 先把审计口径改为“实际装饰字符 / 全部正文字符”；基础 narrative block 不计入强调字符，避免现有分类占比被误读为强调预算。
