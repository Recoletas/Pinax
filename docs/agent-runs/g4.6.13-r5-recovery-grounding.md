# G4.6.13 R5：叙事工具恢复与 grounding

日期：2026-08-11

## 完成项

- `runNarrativeAgentLoop()` 继续沿用同一 `requestId` 和 transcript；上游空响应、坏工具调用和非法参数最多一次同 transcript 修复。
- provider retry 仅覆盖 deadline 内的 timeout、408、429、5xx、network 和协议空结果；401/403/API key/configuration 不重试。
- 工具执行使用独立 `AbortController`，工具超时会把 abort 传递给 registry。空条目和查询期间 revision 变化以 `isError=true` 的 typed tool result 回到 transcript。
- 采用规范化工具名、canonical 参数与 resource revision 的重复调用计数；第三次相同调用以 `NARRATIVE_AGENT_DOOM_LOOP` 结束本轮。
- 新增 `narrativeAgentPolicy`。历史/时间追溯、路线空间关系、已有规则核验和明确事实调查为 `required`；普通当前动作和轻量续写为 `optional`。required 没有成功条目证据时禁止提交正文。
- provider adapter 将 401/403 转为 `NARRATIVE_PROVIDER_CONFIGURATION_INVALID`，避免把鉴权问题当成可重试上游故障。
