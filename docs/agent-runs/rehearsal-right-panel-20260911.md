## 0. 验收后修复（2026-09-11 第二轮）

验收指出两个实质缺陷，均已复现、修复并固化为断言：

1. **走法身份不独立**（会丢输入、误判试稿归属）。根因：只有"归档路"才有 id，"当前工作路"的身份固定是空串，于是 A、B 两条新路共用一个草稿槽——B 提交时清掉的是那个共用槽，A 的字随之丢失；试稿归属的 id 比较也因此失去意义。
   修法：走法改为会话内一等对象，每条路自带稳定 id、自己的步骤和自己的未提交草稿；输入就是"当前路草稿"的读写视图（writable computed，不再有"改了还没同步"的窗口）；`rewind` 从旧路派生新路并保留旧路，`回到起点` 复用同一条空路，避免每按一次多出一段"第 0 步"。`Authoring.vue` 的草稿归属改为比较稳定的走法 id。
2. **对照可能自己比自己**。修法：比较候选 = 排除当前路之后的路（`otherRoutes` 结构性保证），候选多于一条时给出显式选择器；当前路变化后自动重选候选；只有一条路时对照区块不出现。
   同时按验收意见让展开的对照**进入视野**（展开即滚动到比较内容），并给顺序展开（≤1180）加了"回到正文"回程入口，减少读对照时的长距离往返。

对应断言：`rehearsal-panel-check.mjs` 新增"走法身份独立且各自保留草稿""换路不丢未提交输入（验收复现）""对照候选排除当前路""显式选另一条路后对照两侧不等长""展开的对照进入视野""顺序展开可一键回正文且不丢会话"；核心用例新增每条路身份不同、A 路草稿不被 B 覆盖、当前路不进比较候选。

## 1. 作者现在能做什么

从落笔处打开右栏「推演」→ 安排一个行动 → 读到人物回应 → 继续或换一种走法 → 就地对照 → 在正文编辑试稿。没有路由切换、没有第二个编辑器、没有额外工作区。

一次完整体验路径（1440）：

1. 正文里点一个段落，右侧工具带点「推演」。
2. 「从当前段落开始」→ 冻结当前场，输入「莉娜先隐瞒缺页，自己去看暗格」→「试演」（或 Ctrl/⌘+Enter）。
3. 读到人物回应；三步默认连续可读，点行动行可折叠该步。
4. 第一步「从这里换路」→ 走法条出现「回到起点」和一条旧路（按分歧处的具体行动命名）。
5. 「对照两条走法」在右栏内展开：共同前缀、分歧行动、各自推进到第几步。
6. 「写成试稿」→ 正文落笔处出现唯一 Ghost；右栏保留路径与输入，显示「查看试稿」。
7. 切到另一条走法 → 同一 Ghost 标注为「正文已有另一条走法的待处理试稿」，不会被称为本路试稿，也不会被替换。
