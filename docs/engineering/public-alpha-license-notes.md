## 1. 当前状态：PolyForm Noncommercial 1.0.0

准确用语：

- 允许：任何人**非商业目的**使用、复制、修改、再分发（含修改后的版本，需遵守同许可证）。
- 限制：**"商业目的"覆盖以获取报酬/商业优势为目标的用法**（详见 LICENSE 第 2 节定义）。
  给别人收费部署、把它当付费服务的一部分、在工作中为公司产品使用，都在"商业目的"范围内，
  需要另行获得授权。
- 因此：PolyForm NC **不是 OSI 定义的开源许可证**，也不是 FSF 定义的自由软件许可证。
  README 与宣传语中不得称其为"开源（open source）"；准确说法是
  "**源码可得（source-available）**"或"非商业许可"。

影响：

| 场景 | 当前许可下 |
|---|---|
| 个人作者本地使用、写作 | 允许 |
| 教学演示、研究 | 允许（非商业） |
| 公司内部作为写作工具使用 | 通常**不允许**（商业目的），需授权 |
| 收费托管 SaaS / 商业集成 | **不允许**，需商业授权 |
| 修改后再分发 | 允许，但仅限非商业且同许可 |

## 2. 备选对照：AGPL-3.0 与 Apache-2.0 / MIT

| 维度 | PolyForm NC（现状） | AGPL-3.0 | Apache-2.0 / MIT |
|---|---|---|---|
| OSI 开源 | 否 | 是 | 是 |
| 商业使用 | 需授权 | 允许 | 允许 |
| 网络服务源码义务 | 无 | 有：用户可通过网络交互的服务须提供对应源码（第 13 节） | 无 |
| 常见误读 | "NC=不许商用软件用过就感染"（错：它只是限制许可对象本身被商用） | "AGPL 禁止 SaaS"（**错**：AGPL 允许商业经营；它只是要求提供修改后源码，不禁止收费、不要求交出私人数据） | "MIT 无条件"（有：须保留版权与许可声明；Apache 另含专利授权与 NOTICE 要求） |
| 再许可兼容 | 不可单方面变更他人贡献 | 换证需全体版权人同意 | 同左 |
| 收入模式 | 收商业授权费 | 双许可/服务/托管 | 服务/托管/赞助 |

## 3. 换证的版权结构问题

- 仓库现有提交的版权在作者（与可能的协作贡献者）手中。**换 LICENSE 需要每一位版权人同意**；
  已外部贡献的 commit 不能被单方面再许可。
- 因此若未来考虑 AGPL/Apache/MIT，需在**接受外部贡献之前**完成换证，或逐个取得贡献者再授权。
- 常见配套制度的准确区分：
  - **DCO（Developer Certificate of Origin）**：贡献者声明"我有权按当前许可提交这些内容"。
    `Signed-off-by` 即可，**不转让版权、不是 CLA**。
  - **CLA（Contributor License Agreement）**：贡献者向项目授予权利（可能含再许可权），
    是独立的法律协议，与 DCO 是**两种制度，不能混用表述**。
  - 当前仓库**两者都未采用**；公开后若接受外部 PR，这是另一个待决策项。

## 4. 与本仓库其他文件的边界

- `THIRD_PARTY_NOTICES.md`：第三方许可登记（依赖、改编源、算法参考、资产权属清单）。
  换主许可证**不影响**第三方部分的许可义务（如 OpenLayers BSD-2、Azgaar MIT、字体 OFL）。
- `docs/demo/` 中 unknown 资产：换证不解决素材权属；见 notices 的资产清单。
- 演示截图若含 unknown 美术，无论何种许可证都必须先处理素材本身。
