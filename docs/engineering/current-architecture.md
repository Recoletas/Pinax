# Pinax 当前架构与代码边界

核对日期：2026-10-16。实现基线为 main 的 `cb6ee525`，发布记录见 [2026-10-15 回执](../agent-runs/release-20261015.md)。本文描述代码职责；运行检查和模型质量证据见[验证状态](../src/test-status.md)。


## 1. 运行结构

Pinax 是 Vue 3 工作区、浏览器本地数据和 Express 服务的组合。文本模型由独立 Storyflow / pi-agent 运行器提供，图片和视频使用各自的渠道适配器。

```text
浏览器 Vue 工作区
  ├─ 书稿 / 设定 / 素材 owner → localStorage、IndexedDB
  ├─ 普通文本、推演 → Express → kitModelGateway → Storyflow 任务面
  ├─ 助手多轮工具 → /api/storyagent → Storyflow 任务面（loopback 8451）
  │                                       ↓ 提议 / planned 生成请求
  │                    浏览器复核授权、原文修订 → 正式写入 / 撤销
  ├─ 图片 / 视频 → Express 或已配置媒体适配器
  └─ 本机项目 → /api/localmirror、/api/knowledge（公网禁用）
```

普通文本调用和助手工具循环共享运行器与当前文本模型，但保留各自的任务协议和 UI。不是把所有功能都变成同一个聊天 Agent。运行器缺失时返回不可用，不回退成浏览器直连文本模型。

服务器部署需要前端 `dist`、后端生产依赖和编译后的运行包；只更新前端无法更新正在运行的工具。构建、启动和回滚见[运行包发布](./agent-runtime-deployment.md)。

模型配置统一在 SettingsPopup 的 models 分区。`useSettingsPopup.open('ai'/'media')` 保留旧调用别名并定位文本/图片；工作区快速选择通过 `ModelPickerMenu` 复用对应 store，`modelConfigEvents` 在同页同步增删改与默认选择。重新生成不重置当前权限。助手发送前复制模型和权限，`prepared.modelConfig/modelSettings` 只在内存及请求链中使用，不进入消息或任务日志；正文委托将模型快照传入原推演 executor。Express 的 AsyncLocalStorage 将本次配置传给 complete/stream/capability，运行器 `requestScopedRuntimeConfig` 复制 cfg 后运行，不调用全局 applyModelPatch、不持久化密钥。公网拒绝请求自定义文本配置；旧运行器缺少 requestModels 能力时，自定义模型请求明确拒绝，避免静默用错模型。

## 2. 工作区、路由与视图

| 职责 | 当前入口 | 边界 |
| --- | --- | --- |
| 应用启动 | `src/main.js`、`src/App.vue` | 全局主题、路由、平台适配 |
| 工作区外壳 | `src/layouts/AppShell.vue`、`WorkspaceContentGroups` | 活动栏、目录、中央和旁区标签、视图挂载 |
| 资源与实例 | `workspaceViewContract`、`useComposableWorkspace` | 区分资源身份、视图实例、主/旁位置和当前选项 |
| 路由兼容 | `workspaceRouteAdapter`、`workspaceTabsStore` | 旧地址与导航恢复；不保存第二份书稿 |
| 左栏状态 | `useWorkspaceDirectory`、`useAuthoringDirectory` | 文件/搜索/书稿/扩展模式、桌面显隐和宽度 |
| 编辑与返回 | `useAuthoringWorkspaceNavigation`、`useAuthoringPersistence` | 选区、滚动、保存及离开检查 |
| 写作右栏 | `useAuthoringInspectorState`、`AuthoringDualPane` | 工具选择与原有可编辑双栏 |

中央使用一组内容标签，旁区可打开对照内容。章节主区复用原 Authoring 编辑会话；旁区的章节阅读视图不等于原可编辑双栏。后者继续保留，不能为简化布局而删除。

视图移动保留实例；同作品切换不应重新发送模型请求。关闭、换资源、切书仍需调用对应保存和任务守卫。布局最多保留 32 个视图，超限要求显式关闭，不自动淘汰未保存内容。任意嵌套分组、跨作品并行编辑和多个编辑组共享撤销尚未实现。

桌面进入文章或构思会展开目录；作者手动收起后普通切章不反复展开，回首页保留当前显隐。手机抽屉独立管理，不把选完文件后的关闭写成桌面偏好。

应用内文档通过 `useWorkspaceHost.bindDirectorySurface` 把章节/页内目录交给同一个左栏宿主，正文仍由 `DocsPage` 负责加载。目录模式与桌面显隐属于文档页，离开时解绑，不改作品的文件/书稿模式；宽度、手机抽屉和焦点管理复用工作区。

旧设定、资料、媒体和体验路由保留适配。`src/router/index.js` 是页面注册入口，不能靠删旧路由绕过保存检查。

### 项目目录

`ProjectDirectory` 从既有 owner 读取章节、构思、绑定世界书、来源、素材和漫画页。默认文件夹为正文、构思、设定、资料、素材、漫画；世界书下的人物等分类是派生视图。

`src/services/workspace/projectDirectory.js` 只保存文件夹、归档位置、排序和同书资源关联。持久键 `pinax-project-directory:v1:<bookId>` 及显示偏好已纳入备份。资源 ID 不由名称或路径生成；移动目录不改变章节叙事/导出顺序，也不改变资源类型和作品归属。移除文件夹把内容移到上一级，不删除原件。

项目文档仍是只读集合入口，并未把所有磁盘文件逐个注册成可写资源。漫画页用稳定 pageId 进入现有漫画编辑 owner；格、阶段、候选仍由漫画存储维护。跨作品移动和共享世界容器不能按普通目录节点处理。

### 内置扩展

`workspaceExtensions` 注册可信内置视图的类型、标题、图标和异步加载器。UI 加载器由 AppShell 注入，服务层不导入页面。启停影响新视图打开，已打开的视图和任务不因此销毁。

扩展列表不展示这些内置工作台，也不再允许通过旧禁用偏好关闭核心视图。当前没有第三方脚本市场或远程插件热加载。Skill、Tool 和工作区视图是不同能力；启用前端视图不授予工具读写权限。见[扩展接口](./workspace-extensions.md)。

## 3. 数据所有者

| 数据 | 唯一写入边界 | 保存与限制 |
| --- | --- | --- |
| 书稿、章节、writing units | `writingBooksRepository`，由编辑事务调用 | `writing_books`；页面不能维护平行书稿 store |
| 世界书与条目 | `worldStore` durable mutation owner | 浏览器缓存与绑定文件接缝并存；不能描述为全量磁盘唯一真源 |
| 世界书文件 | `worldbookFileRepository`、服务端 local mirror | 从 bookId 解析项目绑定；文件身份/解析错误阻断，合法空文件不回填 |
| 当前场、推演和干预 | `services/agents/authoring/` 会话与事务 | 正式场景有限持久化，草稿/运行状态不等于正式事实 |
| 助手对话 | 每书助手会话与 `authoring_assistant_conversation:` 存储 | 宿主持有运行会话，页面提供可释放编辑绑定 |
| 来源归档 | `worldbookSourceArchive` | IndexedDB 中解析内容和出处，不保证保存输入文件原始二进制 |
| 素材与媒体 | `narrativeAssets`、`mediaAssetStore` | 素材元数据与媒体 Blob 分域保存 |
| 记忆与事实 | 浏览器 memory/ledger owner | Dexie/IndexedDB 的事实、证据、决定、修订；不连接外部 Utopia 服务 |
| 画布 | `proseCanvasRepository` | 按作品保存；旧全局数据只做保守迁移 |
| 跑团 | `gameStore` 与 experience coordinator | 保留原存档和剧情 owner，不成为书稿真源 |
| 地图 | `geographyStore` 与 world-map 服务 | 地图几何、世界书地点与历史投影有各自边界 |
| 模型配置 | 原文本/图片/视频 store，共用设置分区与快速选择器 | 选择只更新偏好；发送时冻结快照，Express 请求上下文及运行器按任务隔离，公网不开放自定义文本配置 |
| 工作区布局 | workspace host、标签与目录状态 | 只存身份、定位、尺寸等，不存正文、授权或模型密钥 |

助手运行会话由实装 `@earendil-works/pi-agent-core@0.87.1` 的 `AgentHarness` 和 `JsonlSessionRepo` 管理，原生日志保存在运行器任务目录的 `pi-sessions`。普通追问本就沿原任务 resume；本轮补齐持久会话和原生压缩，删除首次启动/重答历史的6条、2400字截断及浏览器60条消息上限。原生自动压缩按模型上下文容量触发；“压缩上下文”调用同一会话的 compact，成功后保留 taskId 和可见消息，不另开任务。正在运行或等待作者回答时不手动压缩；失败保留原会话。旧非 agent 路径仍使用摘要兼容逻辑。

助手外层任务与正文推演共用绑定世界书的世界概述、文风、禁写边界和示例提取；外层也收到本轮命中的创作规则，空章不再只提供目录。写作生成器直接使用作者原话、此前实际讨论和执行中已消费的作者追加消息；不再把外层助手自行改写的 instruction 当成新写作要求。有原话时忽略二次转述，无原话的兼容调用才使用 instruction。未采用候选不自动成为既定背景。这里不增加关键词封禁或生成次数限制。

助手每份成功候选在本地按原任务基线及权限校验后，立即保存在原回答；后续修订失败不能抹掉上一份完整稿。已停止任务的完整候选仍走原位置审阅和正式写入，未完成残段只作保稿；自动修改只处理正常完成的交付。续接与采用先核对远端执行状态，取消回执必须确认停止；409按实际错误码处理，不统一解释为任务忙碌。

持久化使用 `durableMutationResult` 的 `{ ok, reason, retryable }` 合同。调用方须检查保存回执，不能先发布“成功”再异步补写。正文、世界书和画布已有失败回滚与恢复路径，不能另开直接数据库写入捷径。

助手设定事务在浏览器日记中同时保存正文、条目和修改回执，再由 worldStore 的既有文件队列发布。待文件同步标记随条目存档保存；同步未成功时重新载入使用已确认的本地版本，不能被旧文件覆盖。同步成功后清除标记；失败保留条目及可重试状态。队列按本次推送冻结的修订确认完成，旧请求不能清掉新修改的待同步标记。

推演通过 `generatedDraftRecovery` 按作品和文稿保留最新文字恢复副本，不持久化旧写入授权。关闭或切换不等于丢弃；采用后校验正文持久化结果再清除副本。助手采用继续走 `assistantEditJournal`，写入后读回核对再提交回执。恢复副本只是保稿，不是正式书稿或跨设备同步。

完整 ZIP 包含书稿、设定、来源归档、已落盘媒体及记忆历史；轻量 JSON 不含 IndexedDB 原件。模型密钥不进入两种备份。HTTP、HTTPS、主机或端口变化会切换浏览器存储来源；布局恢复也不是跨设备同步。

## 4. 设定、资料与知识检索

### 设定编辑

`WorldbookContentWorkspace` 由旧路由或 `WorkspaceSettingsView` 挂载，使用显式 bookId/worldbookId。中央编辑标题与自由正文；旧集中字段在创作基调。右侧提供同类、场景与经历、表格、关系和管理，关系图保留在右栏，默认显示当前条目和直接关联。

`AuthoringWorldbookPanel` 在正文右栏提供无框条目编辑；正文高度随内容、编辑节点重新挂载和可用宽度更新，短内容收回，不在输入框内另开滚动。聚焦以底部细线提示，原保存与助手原位审阅流程不变。

`EntryProfileEditor` 保留模板、自由字段和正文投影裁决。结构字段与手改正文冲突时，作者选择只存字段或覆盖正文；不得静默丢弃 profile、富关系、未知 frontmatter、来源指针、userTouched 或 tombstone。

`SettingUsagePanel` 按名称/别名派生正文提及；同名匹配不等于实体确证。插入动作经原编辑绑定在光标处插入名称，选区存在时不覆盖原选区，并支持正文撤销。

`settingContextModel` 读取正式章节场景锚点和当前世界书 geoHistory，按章节/单元顺序展示出现记录。字面提及、待审记忆和跑团全局状态不用于猜测人物当前位置。地图定位复用原地点与历史 ID，未新增每书独立地图存储。

### 三种资料能力

1. **浏览器来源归档**：导入浮窗解析文件，确认后保存来源与片段；提取出的设定仍需审阅。旧 sourceDocuments 迁移保留 archiveRef、sourceRefs、chunkIds 和 contentHash。
2. **助手快照检索**：当前章保留完整编辑稿，其他章节及整体资源仍按已声明的快照范围读取。人物原文与属性可经 get 分段读取，搜索摘要不代替原文。
3. **本机知识检索**：`/api/knowledge` 调用 `knowledgeRuntime`，在工作线程执行固定版本 Storyflow 知识内核；按注册项目生成派生索引并检查来源修订。需要独立知识运行包，公网关闭。

本机知识内核已接通，旧文档“完全未接 RAG”不再成立；它也不等于接了公网外部向量数据库。索引有摘要而缺原文时须报明确状态，不能补造原文。`assistantKnowledge: true` 只表示工具已装入，不证明运行包、项目绑定和查询依赖全部就绪。

助手资源读取：当前章使用发送时的完整编辑稿，空正文不回落旧持久化文本；设定快照包含正文及属性。`manuscript_get` 与助手的 `world_lookup.get` 支持字符范围读取，返回来源、修订、`nextOffset` 和快照缺失标记。搜索仍返回摘要；读全文不再经过摘要截断。其他章节节选和整体请求容量继续声明覆盖范围，不承诺未装入快照的原文可读。

## 5. 助手、推演与正式写入

助手的只读、审阅修改、自动修改决定能否提出及采用修改，两个修改模式默认允许本书设定和大纲，章节范围单独控制正文。自动模式仍需有效授权、目标未变化和 durable 保存成功；模型没有直接写正式书稿的权限。范围菜单以当前章节、全部章节和自定义细选映射 scope/chapterIds；前端偏好统一生成显式 worldbook/outline 授权，审阅和自动为 true，只读为 false。服务端仍检查实际签发的布尔授权，不按模式推断或扩大旧任务权限。当前章节 ID 由轻量 destination 取得，自定义初选不误用第一章。权限菜单只更新下一次发送的本地偏好，不调用 revoke/authorize；每次 ask 在首个异步准备前冻结权限与会话 ID，prepare/enrich/health/authorize/生成及自动采用均沿用本次快照。运行中更改显示“下次发送生效”，不使当前 SSE 断流；停止操作仍走显式 cancel。手动采用按采用时的偏好重新授权，自动采用按本次发送快照重新授权；采用前 `permissionContext()` 只取得作品/章节目标。权限菜单章节列表使用仅含 ID/标题的 `chapterOptions()`；正式发起助手请求仍由 `prepare()` 建立完整冻结上下文。

助手发送时附带轻量 project-state 和协作建议指导。资料库未读到时计数为未知，不宣称为空；来源计数仅覆盖导入资料。模型在正常回复中结合当前任务提出必要的设定整理、保存讨论或参考资料建议，作者同意后沿原工具与权限继续，不通过输入入口代替对话主动性。空输入框的灰字候选由本书状态与最近完成的回复生成，不调用后台模型；Tab（不含修饰键）或显式采纳按钮仅填入草稿，不发送、切权限或写入。Esc略过当前候选，Shift+Tab、已有文字、@引用及输入法组合输入保持原行为；运行中、待回答、待采用及资料未读到时不提供候选。

人物、设定和大纲的助手修改由 `useAssistantObjectEdits` 在原编辑组件内生成只读增删标记；原目录、字段和位置不被独立审阅层替代。待新建对象仅加入视图目录，不走普通自动保存。预览复用纯 `applyAssistantProposal` 计算小范围投影，实际采用仍调用既有授权／修订／durable 事务；投影不是正式数据。采用后“完成”将对象的确认状态写入同一修改回执，切换工具重挂或重新载入会话不再重复确认；同一对象又有新修改时重新展示。本轮设定条目在采用后仍保留在相关目录，不因待采用占位消失而被筛掉。“撤销本轮修改”沿用整轮回执撤销，不声称单对象撤销。作品／世界书绑定不符或已撤销时不投影；后续手工改动不应标为助手新增。


当前章节的续写/替换/插入通过 `generate_narrative_draft` 调用浏览器持有的 `AuthoringRunSession → narrativeKernelExecutor → runNarrativeAgentGeneration`。运行器发出 `narrative.request`，浏览器按冻结目标生成并通过作用域内的 `narrative-result` 返回实际草稿；运行器的原生工具调用等待结果，助手随后可继续处理任务。nonce、callId、bookId 和客户端 capability 共同关联请求，取消沿原 signal 传播，不设新的工具次数或任务总时限。页面关闭不承诺恢复仍在执行的生成。旧运行器缺少 `assistantNarrativeExchange` 时前端明确提示更新，避免执行半套协议。

正文增量走 Pi `models.stream → /complete/stream → kitModelGateway → /agent-step/stream → onDraftUpdate`，与非流式补全共用模型参数。运行器最终回执保留工具调用、停止原因、用量和完整正文；收到若干字不等于生成成功。规划仍先于写作，规划参数与工具前言不展示为稿件。助手在原回答区、直接推演在原草稿区显示生成文字；预览不直接写入作品。可见状态最多每100ms更新，恢复副本最多每秒保存；停止时从完整已收文本补齐尾字，不把旧请求显示到新作品。已收到正文后断流会保稿，不自动重发同一整稿；正常完成仍进入既有候选、采用和撤销路径。

正文生成的冻结上下文包括本书绑定库的世界概述、文风、禁写边界与风格示例，以及入选设定、正文、大纲和场景。顶层背景使用独立 `worldbook-foundation` 身份与内容修订，不冒充可查阅条目。`narrative-long` 将当前落笔正文及背景/创作规则作为必要输入，独立计算可选参考的条目和字符预算；长正文不会耗尽相关人物等可选参考的额度，receipt 的 `usedChars` 仍记录实际总量。其他资料由 compiler 选择。Kernel 与 provider 原样发送已编译文本及来源/规则身份，不再逐条320字、lore1400字、provider2400字重复裁剪。真实模型上下文容量仍由渠道决定，资料也可能只提供节选。

冻结编译保留正文 position（章节与单元位置）。作者侧正文调用将资料以原始段落放入独立参考消息，保留来源、用途与修订回执；同一章节的正文按单元顺序阅读，相关性排序只用于选材。不同章节仍是分开的参考，不拼成连续事件。系统运行信息不再重复携带 turn 的作者要求，当前任务只在最后一条用户消息中出现。

上下文区分正式正文、未采用候选、规划与参考来源。正式原文提供事件进度；改写另标目标前后的保留正文，后文不当作已发生事件。未采用草稿不自动成为事实或作者认可的文风；大纲描述计划。`source` 条目以 `imported-reference` / `inspiration` / `hypothesis` 传入，工具快照保留其参考身份，不升级为正式设定证据。文风沿用作者明确说明、指定样文和正式正文；普通参考作品不自动成为文风要求。

同书切换右侧工具或内容页只释放编辑绑定，宿主持有的助手请求继续运行。主动停止、切换作品、工作区销毁/重载分别记录停止原因，迟到的 abort 不覆盖该原因；最后收到的文字即使没有运行中工具也保存。恢复旧会话不再把原因不明的中断猜成“离开写作页”，也不自动重发未知任务。整页关闭或开发热更新销毁宿主时，浏览器委托的生成仍会停止。

助手委托正文生成时复用本轮资料检索结果：检索同时参考作者问题和冻结的当前正文尾部；正相关片段及显式选中文档进入 `prepared.writingReferences`，不依赖模型先调用查阅工具。输入保留资料标题、原文段落、文档/分块ID、内容哈希与定位；已展开的资料用原文片段替代短预览。普通参考不升级为本书事实，文风借鉴以作者要求为准。检索仍为本书绑定归档的本地匹配，不代表全库语义检索或自动改写设定；独立右栏推演的冻结资料机制本轮未扩展。

`shared/assistantWritingMethods.js` 是产品写作方法目录，与开发用 agent-skills 分开。`writing_methods` 提供 list/load，助手按本次目标选择适用方法，作者已选方法保留并按目标类型传给执行环节；不为每次生成套用同一组方法。方法说明各自需要读取的材料、产物和可选技法，已加载方法、显式参考及本轮读取结果传入实际推演输入。写作指导默认使用自然、顺畅的现代中文，交代必要的指代、物件用途与判断依据，允许直接说明事实和心理；作者指定文风优先。不另定古典语域、短句、比喻配额或每段功能，不增加可读性复审模型调用。正文解析按原有换行保存段落，不再每两句自动拆段；无换行文本不会按句数切开。

已生成草稿的措辞/段落修订可以通过原提议工具替换同一候选，无需重新生成；重复推演默认修订候选，明确 draftAction=extend 才接写，避免把重做结果叠成重复正文。提交设定候选后可以继续查阅、提问或生成正文，待采用设定作为明确标记的草稿上下文；依赖这些设定的正文与修改组成同一采用组，尚未采用的内容不写入正式世界书。

设定提议可附 details：补充别名和来源、按 key 更新 profile.values、按 to+type 合并富关系。保留未知属性、既有来源指针及关系附加数据，不从 profile 静默重写 content。准备阶段校验关系目标属于当前世界书或本批新条目；采用与撤销同时核对结构快照，角色/设定原位展示结构差异。右栏人物补全与设定补全复用相同方法文本，但仍走各自既有生成工作流，尚未改为完整助手循环。正文生成仍限当前章节，没有扩成跨章或新建章节工具。

修改建议在原正文展示；采用/自动采用经事务保存并记录回执，撤销再次检查后续修订。页面绑定变化时自动提案转待审，返回原目标后复核。不会因切到新书而把旧结果写入当前选中文档。

局部改写通过 `rewriteText` 指定替换片段；前文继续参与上下文，但不要求模型重写保留部分。`rewrite-range` 使用冻结目标的场景投影校验，避免编辑器焦点变化误报场景过期。工具声明的 `inputSchema` 在 Express 转发时保留；Anthropic 强制工具选择由运行包适配，补全失败不能作为空成功返回。

推演默认写下一段，可空指令续写；情节试演在右侧比较走法，选定后再生成正文草稿。当前场识别在使用边界准备候选，作者确认后入场，不在每次输入时更新正式角色状态。

对话与运行任务分开：普通追问留在当前会话；编辑提问、重新生成和换参数重答保留原会话并保存最多 8 个问答版本；fork 始终另开对话。切版本不自动撤销已采用的正文。完整回答与工具完成摘要分开保存，不能用完成摘要覆盖流式全文。 运行器由 Pi 原生循环处理工具及后续模型回复；正式 text 自然交付。兼容旧 complete_assistant_task 调用时只返回确认，不将其摘要当作正文，也不以该工具强制结束。最终完整回答、最终 delivery 与 proposalChanges 一起回传，前端不让早期工具回执覆盖最终状态。

取消、超时、迟到响应和原文变化均由所属 workflow 检查。模型生成失败会尽量保留可读内容，但不得把不完整或未通过检查的结果标成可采用。

助手区分世界内容与情节规划：设计开局、试探方向不默认触发写入。世界书整理已确定或作者明确委托补定的设定，不把备选方案和开篇编排固定成事实；作者要求保存情节规划时使用大纲。明确要求保存为设定的创作规则仍可记录。此边界通过任务指导与工具说明传达，不用关键词硬过滤正式条目，也不改变现有权限和采用事务。

### 助手持续执行（2026-10-22，本机已启用原生会话）

助手复用 Pi AgentHarness 的循环、steering/follow-up 队列、重试与压缩；finishTurn 仅整理 Pinax 的交付元数据，不控制原生循环结束。request_user_input 是显式等待作者的暂停点；提交候选和权限拒绝通常为普通工具结果，模型可以据此继续。正文工具显式声明 finishTask=true 且成功、没有待消费补充时，通过 Pi after_tool 的 terminate 结束纯写稿任务；多步任务保持正常循环。取消由作者停止或真实服务错误产生；助手请求不设6次工具、8步、4分钟整轮倒计时，也不在额度将尽时隐藏工具。Express 对助手不注入这些限制，也不在250秒切断代理。部分批次后仍可读取下一批所需资料。模型输出使用所选供应商的默认能力，不额外固定为6000 token。

委托正文生成继续复用原场景、规划和正文链，不设100秒整轮计时、阶段倒计时、资料查询轮数/调用次数/重复次数强停，也不以累计token用量冒充当前上下文窗口；请求合同不再用28条消息、24k总字符或默认12秒拒绝后续步骤。10-23 本地补修：写作执行器不再自动创建模型验收合同或抽样影子检查；草稿交作者审阅，跑团显式授权合同仍有独立含义。补全漏斗移除4096固定缺省，使用请求明确值或注册模型能力；length/max_tokens结束从同一转录断点接续，不因补写次数改为整章重写。转录文本、消息数量与总字符不再按8000/32/32000拒绝，长作者指令完整保留；资料摘录与模型实际上下文仍独立处理。失败和取消携带已生成文字并存入原会话的恢复草稿。 后续真实任务继续暴露了旧提示边界：Authoring 现在显式使用写作表面，当前完整指令不经历史摘要或turn块裁剪，规划和行文不继承跑团的单拍/600–950字提示。缺少额外工具命中不再因“时间线”“规则”等词拒绝草稿，实际来源报告和授权/修订检查保留。

用量和调用日志仍记录；单条资料输出压缩、实际模型上下文容量、错误返回、权限和修订校验各有独立语义。自动压缩与已保存的对话恢复走原生会话。进程中断留下的未结束操作在下次作者发送时由原生 abort 结算，不能重放未知的修改调用；浏览器委托的未结束正文生成仍不承诺跨刷新后台完成。

### 助手新建建议的身份

`reserveAssistantCreateIds` 对新建建议与当前资源、同批其他目标的 ID 去重；已有条目的修改仍使用原 ID。运行器先按读取快照分配冲突的新 ID，前端准备建议时再按完整资料复核。ID 重分配只针对 create，不把新建改成对原条目的更新，原文匹配、权限、采用事务与撤销仍生效；分配后的建议再次检查权限，不能通过更换 ID 扩大章节授权。


批量修改可分批提交，不设每批8处、整轮32处或96k字符硬上限。`submit_edit_proposals.final` 仅兼容旧请求，不提前结束任务。同一目标/字段/原文的候选可修订，后续工具仍可执行；成功批次随 tool.result 保留，正式采用仍走原事务。候选与问题可共存，等待作者时不自动采用。回答问题后恢复尚未处理的候选，核对当前权限与目标；已采用、放弃或撤销的回执会传回模型，避免再当成未处理。续接失败不删除原候选；流中断保留可复制文字，不自动采用。运行中补充接原生 steering，即使已经生成候选也可在后续边界消费，不通过修改偏好中止旧任务。

运行器对 Anthropic 协议的 MiniMax-M3 系列按请求注入 adaptive thinking，链式保留原 onPayload；其他模型不变。续跑丢弃 error/aborted 的助手消息和未配对的工具调用/结果，避免把截断参数当成下一轮有效历史。

## 6. 媒体、跑团与任务生命周期

漫画、编导及跑团通过既有工作台组件接入资源宿主，数据继续归原 Repository。移动视图不复制项目数据或重跑生成；没有后台能力的操作仍会阻止关闭，不应先删除 busy guard。

旧素材页面通过兼容壳转到正文画师或原素材阅读；正文选区收集后留在收件箱，编导工作台直接选素材。素材本身未迁移或删除。

漫画单张显示活动进度和计时，批量显示处理数；内置 MiniMax 批量最多两格并行，其余保留上一格参考依赖。请求结果核查只能用同一请求和目标的已归档图片解除占用。

漫画生图先分配当前画面、摄影设计和画幅的提示词预算，再加入背景，避免长资料截断本格要求。上一格只提供显式剧情节拍，不复写其完整画面。空镜与局部特写只继承结构化线条、色板和渲染规则，避免全页人物名单污染取景；旧全页自由说明保留存储，不在这些局部镜头中注入。分镜脚本／分页方案到正式页保留规范化 direction。普通生图和分阶段制作共用显式图片绑定与已确认人物引用的解析、模型能力／数量、本书与绑定设定库归属及图片可读性检查；局部镜头不继承人物图片。

视频任务区分提交、轮询、保存链接和保存原件。浏览器标签页记录可以续查已有任务，服务器内存任务不能保证跨重启恢复；只有已保存的原件能脱离临时链接播放和进入 ZIP。

单人跑团是常驻 `game-editor`；隐藏时暂停后续自动推进，已发起回合仍由原 owner 收尾。联机用完整 `online-editor` 持有连接。单人和联机不能同时创建 game owner；活跃房间须显式离开。布局持久化不承诺跨刷新恢复网络请求。

## 7. 公网与本机部署边界

公网浏览器只经 Express 访问运行器；8451 绑定 loopback。`PINAX_PUBLIC_ORIGINS` 配合来源校验、能力令牌、并发和预算限制；这些措施降低滥用，不等同于免登录环境无法被模拟请求。

公网禁用 `/api/localmirror`、本机知识能力和模型写接口。本机启用文件能力后仍须绑定项目；世界书提交校验修订和文件指纹，保留未托管文件，省略其他域不等于删除它们。

2026-10-15 公网已更新前后端与运行器，但 HTTPS 尚未配置完成。切换 HTTPS 需要同时处理用户原 HTTP 来源下的备份和恢复，不能直接跳转后误导用户以为稿件丢失。

## 8. 开发落点与验证

- 页面和组件负责展示、交互；任务、异步归属和取消放在既有 composable/workflow。
- 纯业务合同、事务与投影进入对应 `services/<domain>/`；不要再往 services 根层堆文件。
- shared 合同不能依赖 Vue/DOM；密钥和服务端代理放在 `server/`，不进入 `VITE_*`。
- 正式数据由表中 owner 写入；兼容路由、旧快照和派生索引不能成为第二个 owner。
- 结构预算、循环依赖和构建体积用实际命令确认，不把历史文件行数写成当前测量。

### 正文写作指导的资料依据（2026-10-24）

`narrativeVoicePolicy.buildNarrativeVoiceContract({ surface: 'authoring' })` 是助手正文工具和独立推演共用的行文指导；运行时仍采用本书原文、背景和作者本次要求。这次融入的是写作教学资料所提炼的方法，不是新增作品资料检索。指导覆盖动作与物件、观察与判断、人物信息的交代时机、对白主语和衔接、细节取舍；中文示例为本项目自写，仅说明方法，不是故事事实或应复用的样文。

资料与取舍：Teddy Wayne 的 [Tips for Writing Dialogue](https://centerforfiction.org/writing-tools/tips-for-writing-dialogue/) 提醒用人物词汇和节奏体现声音，避免对白只承担信息说明；本项目落实为接话目的、说话人辨认及必要的叙述交代，不照搬“每句都要有潜台词”。Patricia Park 的 [Scenes & Summary](https://centerforfiction.org/writing-tools/scenes-summary/) 说明逐项展开日常动作可能使场景臃肿，概述与场景需要配合；落实为按当前作用选择细节、允许直接交代和过渡概述，不规定句长、细节数或强制冲突。物理动作、中文搭配与证据推断示例来自本项目失败样例的分析，不冒充外部资料的原话。

方法直接进入现有正文调用，不新增自动审稿、改写调用或生成限时。代码检查证明接线与旧流程兼容，不能证明文学质量稳定；真实样例需另评语言、动作、背景和承接，不能用禁词命中率替代阅读。

### 2026-10-23 写作执行方式

作者 turn 的 planning 与 intent 分开：明确要求/局部改写默认 direct，已选方向走 reuse，开放任务或助手显式请求走 plan；体验页规划语义保持。rewrite-unit 明确作为文字编辑并提供完整替换原文；助手没有选定方法时按操作补续写/润色方法。方向与资料仍由既有冻结 session、目标及修订校验管理，不新建计划存储。正文工具只返回一份 proposalChanges，候选和最终任务交付仍用原事务。完整候选可在运行中查看，采用仍等待任务及本地收尾；已结束的纯写稿无需额外模型总结。
