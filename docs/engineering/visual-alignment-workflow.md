# 视觉对齐工作流

本文定义 Pinax 前端视觉任务的协作流程。视觉任务包括页面构图、控件位置、材质、动效、角色立绘排布、背景融合、响应式适配和整体气质。

核心原则：早期少文字、多截图、小切片、强约束；方向未证明前，不做整页大改。

## Pinax 化参考规则

外部 Ark UI skill 只作为方法论参考，不作为 Pinax 的视觉主题、组件库或代码依赖。Pinax 的设计语言仍以蓝白档案、纸页/活页、叙事阅读和创作工作台为主；外部参考只能提供结构判断和验证方法。

本节是主题2的当前设计规范。主题2内部 variant 名为 `legacy`，但产品语义是正在推进的蓝白档案主题；主题1内部 variant 名为 `kao`，保留较早的米色游戏化设计并暂时冻结。视觉任务必须显式确认当前 variant，不能根据内部命名、默认值或无状态截图猜测主题归属，也不能用主题2规范反向改造主题1。

### Pinax 的正向视觉主张

Pinax 应该呈现为一册正在运行的现代创作档案：文字、人物、地点、历史和媒体不是被装进后台卡片，而是在同一册活页中被阅读、编排、引用和生成。它需要同时具有编辑出版物的文化感与创作工具的精确性。

用户第一眼应感到：

- **内容在舞台中央**：正文、地图、素材、节点和当前回合占据连续的大工作面，不被装饰性面板切碎；
- **状态沿边缘工作**：页签、来源线、短色条、刻度、页码和局部仪表贴近边缘，为主内容提供方向和状态；
- **纸页具有空间**：深度来自前景纸页、中层工作面、背景档案场三层关系，而不只是阴影或边框；
- **创作链可被看见**：设定、地点、历史、冒险、素材、写作和分镜通过一致的引用标记、来源色条和过渡动效保持连续；
- **安静但不平淡**：大面积浅蓝白负责阅读，墨蓝建立结构，钢青和矿物黄在关键状态上形成短促而明确的节奏；
- **精致来自编排**：不靠堆装饰，而靠不对称构图、基线、裁切、材质层次、字号对比和真实状态共同形成辨识度。

### 可主动使用的构图语法

1. **连续内容场**
   - 主工作区优先使用一块连续表面，让正文、整页漫画、地图或画布真正展开；
   - 工具沿顶部、页边或副阅读台布置，不能侵占主内容轴；
   - 宽屏增加主内容宽度或关系距离，不用居中窄列制造两侧空白。

2. **档案三层空间**
   - 背景层：极浅蓝白雾面，只承载局部等高线、点阵、长斜线或页册轮廓；
   - 工作层：主要纸页或画布，保持稳定明度和舒适阅读对比；
   - 前景层：当前选择、拖动对象、结果托盘、通知和临时工具，通过轻叠纸边、短阴影或局部遮罩抬起；
   - 三层应能在截图中直接辨认，但任一层都不能依赖厚重卡片框。

3. **不对称编辑构图**
   - 使用“主内容 60%-75% + 辅助 rail 25%-40%”或“窄索引 + 宽工作面 + 副阅读台”的结构；
   - 辅助 rail 通过错位标题、短色条、页签和留白平衡主内容，不与主区争夺视觉中心；
   - 页面标题可以贴近页边、基线或内容轴，不默认放入居中标题栏。

4. **信息信号系统**
   - 墨蓝：结构、当前方向、主要选择；
   - 钢青：关联、来源、次级状态和跨页连接；
   - 矿物黄：需要注意、等待确认、时间锚点和关键变化；
   - 暗玫瑰：只用于风险、冲突或少量叙事强调；
   - 信号优先表现为 3-5px 色条、页角、短下划线、进度段或小面积填充，可以比当前更大胆，但不能变成长正文底色。

5. **字体角色系统**
   - display/serif 负责作品名、章节名、叙事标题和重要引文，提供文化感；
   - sans 负责导航、按钮、表单、状态和解释，提供现代精确性；
   - mono 只负责版本、坐标、时间和真实技术数据；
   - 正文以可读性为最高优先，字号和行距稳定；视觉对比由标题、边注和状态层承担，不随意改变正文风格。

6. **有方向的动效**
   - 页面衔接使用抽页、滑片、遮罩揭示或沿内容轴移动，表达“进入下一册/下一层”；
   - 直接操作使用 180-350ms 的短位移、裁切和色条推进；背景流纹只能缓慢局部运动；
   - 新结果、选中来源和状态变化应从其逻辑来源方向出现，让动效解释关系，而不是只做淡入淡出。

7. **密度随任务变化**
   - 写作与体验把空间让给阅读，工具 hidden-first；
   - 素材和设定强调扫描、比较与来源，允许更紧凑的索引密度；
   - 画布和分镜强调空间关系，减少固定面板，让选择后的工具就近出现；
   - 同一视觉语言通过密度和层数适配任务，不要求每页长得完全一样。

### 可复用的 Pinax 视觉原件

- `FolioSurface`：稳定纸页、页边、层级和弹层基面，是档案空间的基本单位；
- `ArchiveStrip`：缩略索引、来源链、时间序列和跨页导航，承担横向或纵向节奏；
- `Source Signal`：短色条 + 来源/状态，用于把素材、历史、地点、正文和生成结果连接起来；
- `Edge Instrument`：页码、刻度、版本、时间、连接状态等真实边缘信息；
- `Contour Field`：局部等高线、点阵、坐标网格和流纹组成的背景场，只在空白处建立空间深度；
- `Reading Plane`：无框正文、对话和章节内容面，保护行距、段距、角色识别和长时间阅读；
- `Review Tray`：需要比较、应用、撤销或确认的结果层，允许明确边界和 diff，但不变成普通聊天卡片；
- `Page Transition`：让路由、模式和对象切换体现抽页、归档、展开和进入关系。

### 空间场纹理语言

等高线、点阵与网格不是用来填满空白的通用背景。它们分别表达世界的连续变化、内容的可索引单位和工作面的空间尺度，共同让 Pinax 的蓝白档案具有“正在生长的创作世界”这一识别度。纹理必须服从内容层级：先有语义和方向，再决定形状、位置与动效。

#### 1. `Contour Field`：叙事地形

- **语义**：表示地理起伏、可能性空间、叙事压力、人物关系或尚未完全显形的世界结构；不能只是因为角落空而添加。
- **形态**：使用不完全同心的椭圆、偏心曲线或局部裁切环线，从页面边缘或角落进入。轮廓应像被工作面截取的一段地形，不做居中的完整靶心。
- **位置**：通常覆盖工作面的局部 `38%-68%`，由左上、右下或真实内容来源一侧进入，并用 mask 渐隐；禁止全屏均匀铺满，也不穿过长正文、输入框、主按钮和高密度索引。
- **尺度**：相邻主轮廓间隔约 `40-72px`，线宽 `1px`；窄小区域可以减少环数，但不能把间距机械缩小成密集波纹。
- **颜色**：优先由 `--archive-olive`、`--archive-ink-soft` 或当前页面关系色与透明色混合，单线 token mix 约 `6%-10%`，纹理层最终 `opacity` 约 `0.22-0.36`。矿物黄和暗玫瑰不能成为大面积等高线底色。
- **层级**：轮廓位于背景场和工作面之间，不得影响正文对比度；纸页覆盖它时应有明确但轻微的前后关系，而不是把线条印在每张纸上。
- **实现基准**：现有素材页和画布页的 `repeating-radial-gradient` + `mask-image` 是基线实现。需要更自然的曲率时，可以叠加至多两组不同焦点的径向轮廓，或使用原创静态纹理；不能引入外部官方资产。

#### 2. `Point Field`：索引坐标

- **语义**：表示坐标、可编辑单元、素材索引、节点定位和可被引用的档案颗粒；它比等高线更精确、更安静。
- **形态**：使用 `1px` 点，间距通常为 `18-24px`，纹理层最终 `opacity` 约 `0.16-0.26`；点阵不得伪装成技术遥测或充当正文行底纹。
- **组合**：一般放在等高线邻近但更小的区域，覆盖约 `24%-44%`，两者通过不同 mask 交叠或接续，形成“连续世界 -> 可编辑单位”的过渡。
- **位置**：优先位于索引、节点来源或页面边缘的空白区。工具密集区、输入区和移动端主要操作区周围应主动退让。

#### 3. `Engineering Grid`：工作尺度

- **语义**：只用于画布、地图、分镜和需要拖拽定位的空间工作面，帮助判断距离、对齐和视口移动。
- **尺度**：主网格建议 `72-96px`；必要时可加入更细的子网格，但子网格必须比主网格更低对比，缩放时不能产生摩尔纹或抢夺节点边界。
- **边界**：叙事正文、素材阅读面和体验对话区禁止铺工程网格。网格不能成为“高级感”的默认背景，也不能把纸页变成方格纸。
- **视口关系**：网格应跟随真实画布坐标移动和缩放；固定在浏览器视口上的网格只适合作为极淡的外围工作台结构层。

#### 4. `Archive Route`：来源与方向

- **语义**：长斜线、弧线或短暂流线用于连接素材来源、历史阶段、页面切换或已选择对象，表达真实的引用和流向。
- **起点**：线条必须从内容边缘、选中项、时间锚点或页面转场入口出发，不能悬空出现；没有真实关系时不画连接线。
- **表现**：常态只保留低对比局部线段，选中或转场时可沿方向短暂增强；不要与画布中有业务含义的节点连线混淆。

#### 5. 纹理动效

- 动效只作用于背景纹理，正文、控件、节点和纸页保持稳定；默认静态也必须成立。
- 等高线或路线可使用 `18-28s` 的缓慢单向漂移或往返呼吸，位移不超过容器尺寸约 `1.5%`，缩放控制在 `1.00-1.04`，极少数欢迎场景上限为 `1.06`。
- 不允许快速波动、无限旋转、光扫和跟随鼠标大幅扭曲。动画不能暗示并不存在的加载、生成或连接状态。
- `prefers-reduced-motion: reduce` 下移除位移与缩放，仅保留静态纹理；切换页面或滚动时不得造成纹理跳位。

#### 6. 页面组合规则

每个长期可见的工作面最多使用两套持续纹理，信号色条和真实业务连线不计入背景纹理数量：

| 页面 / 区域 | 推荐组合 | 空间意图 |
| --- | --- | --- |
| 素材 | 局部等高线 + 小范围点阵 | 让资料夹既连接世界，又保持可索引性 |
| 画布 | 宽工程网格 + 边缘等高线 | 网格负责操作尺度，等高线负责世界压力和方向 |
| 写作 | 稿页基线 + 极淡边缘等高线，或只保留稿页 | 纹理不进入主要行文列，不削弱长时间阅读 |
| 体验 | 现场索引或场景边界附近的单组等高线 | 暗示事件场与关系变化，不把对话做成 HUD |
| 欢迎 / 路由入口 | 等高线 + 缓慢方向漂移 | 建立世界入口与翻页方向，内容和入口保持静止 |
| Agent / 结果托盘 | 不铺背景等高线；来源项可带短轮廓片段 | Agent 依赖证据和任务状态，不另造一套空间背景 |

#### 7. 响应式与验收

- 移动端减少覆盖面积和轮廓数量，把纹理移向顶部标题外缘或内容末端；不能按桌面比例整体缩小后留下密集噪声。
- 侧栏折叠后，原本服务侧栏的点阵或等高线不应移到正文背后；纹理的语义 owner 消失时，纹理也随之隐藏。
- 在 `1440 / 900 / 390px` 截图中分别检查：第一眼是否仍先看到内容、纹理是否有明确来源、是否穿越文字或动作、局部层次是否可见但不形成第三个视觉中心。
- CSS 审查至少确认纹理使用项目 token、带渐隐边界、支持 reduced motion，并且同一工作面没有超过两套持续纹理。

### 继承的方法

- **风格与深度分开**：先确定该页面的 Pinax 角色和视觉深度，再决定装饰层数。素材与写作通常使用 `moderate`，画布和体验的状态舞台可局部达到 `complex`；深度增加不等于增加卡片、颜色或文字。
- **舞台与仪表分开**：主内容是正文、素材、地图、节点或回合；边缘的刻度、短色条、点阵和等高线只表达方向、选择、来源、状态或空间层次。
- **信息所有权**：每个标题、状态、数量、动作和说明只设置一个视觉 owner。结果详情不重复列表已有的统计，浮层不复制页面主区的正文。
- **证据锁**：每轮先记录参考对象、Pinax 继承点、明确不继承点和验收视口；只改一个代表性区域，截图前后对照后再扩展。
- **响应式重编排**：窄屏将侧栏、阅读台和工具区改为折叠、底部工具带或顺序流，不把桌面绝对坐标机械缩小。
- **真实状态优先**：只显示真实的来源、生成状态、选择状态、版本、连接状态和任务进度，不为了“技术感”制造编号、协议名、负载条或假遥测。
- **审查闭环**：每轮检查信息层级、留白、对比度、键盘焦点、`prefers-reduced-motion`、横向溢出和交互后的真实状态，不以静态 CSS 看起来合理作为完成标准。

### Pinax 的视觉边界

- 不把黑白青、黑白黄或霓虹色当作全局主题；Pinax 以浅蓝白中性面为底，蓝色负责结构与选中，暖色只做短促状态信号。
- 不把 Ark/Endfield 的斜切、校准圆、编号、英文微标和工业刻度逐项搬入页面；只有当它们能解释真实内容时才使用，并优先使用纸边、页签、来源短线、局部等高线和轻点阵。
- 不让每个功能都成为有边框的卡片。正文、对话、阅读区和主画布保持开放；只有需要比较、编辑、确认或隔离风险的对象才使用框、底色或明确边界。
- 不复制官方图片、字体、logo、截图、生产 CSS 或第三方 starter。只提炼构图、层级、运动方向和信息归属，并使用项目已有 token 与原创 CSS。
- 不用双语标签填充空白。英文只在确实能区分模式、来源或技术状态时出现，且不能挤压中文主信息。

### 页面映射

| 页面 | 目标第一印象 | 主动强化的视觉系统 | 禁止的误用 |
| --- | --- | --- | --- |
| 写作 | 一张展开、可持续书写的现代稿页 | 宽阅读面、页边章节索引、轻状态线、低干扰补全、结果托盘 | HUD 化正文、密集英文编号、把每段包成卡片 |
| 素材 | 一册可翻检、可钉选、能追溯来源的资料夹 | 立体纸条、来源信号、缩略索引、主素材舞台、局部等高线 | 用装饰填满空白、重复显示素材统计 |
| 画布 | 一张具有方向、距离和真实关系的创作地图 | 连续空间、局部工程网格、选择邻域、关系色线、边缘视口仪表 | 全屏工程噪声、无意义编号、所有节点同权 |
| 体验 | 正在发生的叙事被记录进一册现场档案 | 宽叙事流、角色/语义排版、现场索引、时间锚点、短促状态提示 | 把对话做成 HUD 卡片、用颜色代替角色信息 |
| Agent | 一位嵌在工作流里的编辑，而不是独立聊天机器人 | 上下文来源、任务状态、diff、应用/撤销、窄侧托盘 | 每页一个不同顾问壳、装饰性 persona 面板 |

### 外部审查脚本的定位

Ark UI 的审查脚本可以作为人工验收的启发式补充，重点借用响应式、焦点、reduced motion、颜色 token、ARIA 引用和硬编码颜色检查。它不能替代 Vue 模板、Pinia 状态、真实交互和截图验收，也不能因缺少 `data-ark-*` 属性就判定 Pinax 不合格。

## 用户标注语义

用户提供 direct、红笔、橡皮擦或截图标注时，按以下规则解释：

- 红框 = 必须落入的位置范围。
- 红线 = 必须跟随的角度、透视或曲线方向。
- 红圈 = 视觉焦点或需要重点处理的对象。
- 橡皮擦 / 擦除区域 = 不应被主要 UI 占用。
- 未标注区域 = 不主动重设计，除非为完成标注目标必须调整。
- 用户写下的“不对”“太平”“像 PPT”“不适配” = 需要转化成可验证的视觉约束，而不是直接让 worker 自由发挥。

## 硬约束

- MUST: 视觉任务开始前，Codex 必须把用户反馈翻译成 5-8 条可验证硬约束。
- MUST: 有 direct / screenshot 标注时，标注优先级高于文字推测和历史实现。
- MUST: 视觉早期必须先做小切片 prototype，不得直接全页重构。
- MUST: 每轮视觉实现后必须给出截图路径或说明无法截图的原因。
- MUST: Codex 必须按截图、标注和用户反馈验收，而不是只看代码 diff。
- MUST: 视觉任务应拆为背景、标题、CTA、右上控件、角色 strip、信息文字、动效等独立切片。
- MUST NOT: 不允许多个 worker 同时改同一个视觉区域或同一核心样式文件。
- MUST NOT: 不允许 worker 未经明确要求主动重做未标注区域。
- MUST NOT: 不允许在方向未确认前写长 spec、长调研或整页实现计划。
- MUST NOT: 不允许只用“倾斜一点”“高级一点”“更细节”等模糊词作为实现 brief；必须落到位置、角度、层级、比例、形状、材质或动效。

## 标准流程

1. 用户提供参考、截图或 direct 标注。
2. Codex 提炼硬约束。
3. Codex 拆 3-5 个视觉切片。
4. 每个 Claude worker 只做一个切片，或 Codex 亲自做高风险精修。
5. worker 交付截图、summary、diff、测试结果。
6. Codex 合并可用部分，丢弃不合格部分。
7. 用户按评分反馈。
8. Codex 把低分项转成下一轮硬约束。

## 视觉切片示例

- 标题嵌入背景弧度。
- 左下 CTA 透视位置与不规则形状。
- 右下角色立绘按小端圆弧排布。
- 右上控制组的斜向层级、描边、材质和 hover 状态。
- 背景动态壁纸：只让局部元素动，不让整图漂移。
- 介绍文字跟随同一透视面，不悬浮成 PPT。

## 反馈评分格式

用户验收时优先用短评分：

```text
标题嵌入：3/5，角度对了但弧度没贴背景
CTA 位置：2/5，还没进 red box
CTA 透视：1/5，缺近大远小
角色 strip：4/5，方向对，需更靠边
右上控件：3/5，倾斜对，细节不足
```

Codex 必须把评分低的项转成下一轮 brief，例如：

```text
CTA 必须移动到 direct 新红框内。
近端按钮 scale 1.08，远端按钮 scale 0.88。
整体旋转方向为向下，不得使用向上角度。
按钮外形使用 clip-path 不规则四边形，不使用普通圆角矩形。
```

## 何时使用 Claude Worker

适合派 Claude：

- 单个视觉区域边界明确。
- 有 screenshot / direct 可对照。
- 文件范围小。
- 可以用截图和契约测试验收。

不适合派 Claude：

- 用户刚刚给出高密度 taste feedback。
- 需要判断多处视觉冲突。
- 需要合并多个 worker 的 CSS。
- 需要最终微调到“差一点点”的阶段。

这些情况应由 Codex 亲自处理，或者只派一个 worker 做候选后由 Codex 手工整合。

## 用户需要提供什么

用户不需要写长需求。优先提供：

- 一张当前页面截图。
- 一张 direct / 红线标注。
- 1-3 个最不满意点。
- 参考项目或参考截图。
- 每轮 1-5 分评分。

用户反馈越短越好，但必须指出位置或对象。比如“右下角色 strip 再靠边，按我画的小端圆弧排”比“整体再高级一点”更有效。
