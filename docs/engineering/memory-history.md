# 记忆历史：Web 第一阶段

2026-09-16，G1.2/G3 历史与记忆 H0/H1 的第一条可写链，已实施；验收结果见 STATUS。不等于完整 Utopia、历史模拟或双时态查询引擎。

## 开源复用与边界

- 数据库直接使用 Dexie 4.4.6（Apache-2.0）的 schema、查询、事务和批量操作；不维护自制 IndexedDB 驱动。
- Utopia 参考冻结在 `e879b7a1694c9e4eb78d2f048da361fe03905330`，主要依据 `migrations/0003_graph.sql` 和 `0018_a_fact_awaiting_a_nod.sql`。其 PostgreSQL 的实体、事实、证据及双时间字段适合作为后续结构化事实模型；本轮借鉴修订、未知时间、来源和候选隔离语义，没有把其 Rust/PostgreSQL 服务嵌进浏览器，也没有复制其源码。
- 许可证和依赖见仓库 THIRD_PARTY_NOTICES.md。后续数据库/检索/图谱优先评估上游可用模块，只有作品绑定、小说纪年、原文来源和现有 owner 的适配留在本项目。

## 数据所有权

`memoryCandidates` 仍是当前候选/召回列表的唯一写入入口。`memoryHistoryStore` 经 Dexie 持有 `pinax-memory-history/revisions`，每个不可变版本包括稳定候选 ID、父版本、记录时间、故事时间标签（未知保持未知）、操作、前后内容和来源版本。

兼容现有同步 API：一次 localStorage 写入同时保存当前候选和 `_historyPending` 恢复队列；只有数据库事务成功后才清除对应队列项。数据库失败保留队列，界面显示失败并允许重试。重复归档按版本 ID 幂等，同 ID 不同内容整批拒绝。失败的本地修改不能报告成功。

数据库历史与当前投影各有职责，不是两个可独立编辑的真源。历史不参与模型直接召回；公开候选 API 剥离队列和历史头字段。未确认、过期和拒绝的记忆继续被现有召回过滤器排除。旧版本恢复创建新的待确认修订，不自动升级为正式事实。

升级启动时保留旧候选，并记录迁移基线。迁移前已丢失的修订无法重建；基线记录时间是迁移时间。原有 `runtimeEvents` 的 200 条窗口未改，本数据库目前只覆盖记忆生命周期，不自动收录整个游戏历史。

## 用户入口与备份

全局悬浮 MemoryIndicator 不再挂载。设置的“记忆与历史”按作品、会话或作者偏好显式选择；Authoring 助手栏有“本书记忆与历史”。可确认、拒绝、查看来源、编辑故事时间标签及恢复旧版本。存量没有来源的作品记忆不能直接确认。

完整工作区 ZIP v3 增加可选 `memory-history/revisions.json` 与域版本/数量，文件仍受 SHA-256 和路径白名单校验；旧 v3 包保持可读。恢复事务追加历史，后续本地存储失败会补偿删除本次新增版本，不清空已有历史。轻量 JSON 只包含当前列表及未归档恢复队列，不包含已归档历史。

## 尚未完成

- 当前候选主存储尚未全面迁移至 Dexie；跨标签同时编辑仍受既有同步 localStorage 的并发限制，不能宣称全域 ACID。
- 小说纪年目前是明确填写的标签，不支持任意纪年的有效区间查询，也没有自动推断角色知情时间。
- Utopia 式实体/关系/事实与证据表、冲突裁决、按过去时点查询、角色认知传播和永久运行事件账本仍需后续纵切。
- 桌面 SQLite 历史 adapter 尚未实施。清理全站数据/删除项目时的历史保留与显式删除政策需要后续产品接线；数据库不会因当前记忆条目不可见就静默删掉其历史。
- 真实作者的旧库与长期模型收益尚待内测；本轮只在隔离浏览器使用合成资料验收，不接触作者当前浏览器存档。
