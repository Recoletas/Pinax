# 游戏地图信息架构调研：从《原神》《终末地》反推 Pinax 地点显示

日期：2026-08-29

状态：完成；作为地图平台 v2 P1.5-P4 的设计证据

范围：地图默认态、地点显隐、缩放层级、筛选、选中详情、分层地图与写作上下文；不复制游戏美术资产

## 1. 结论

Pinax 当前四张 P1 主题图的问题，不是聚合圈、颜色或字号还不够精致，而是地点信息没有经过产品语义筛选：生成器原生聚落、作者地点、绑定候选和当前写作相关地点几乎被当成同一层数据，世界档以数字聚合倾倒，地方档再一次性展开为全部名称。

《原神》和《终末地》的共同做法可以概括为：

1. **底图先保持可读**：地形和少量区域名承担定位，不让全部兴趣点常驻；
2. **点位按任务开启**：传送、资源、设施、威胁等由用户筛选，而不是默认全开；
3. **范围先于细节**：先选择世界/地区/子区或楼层，再在该范围内浏览点位；
4. **选择先于详情**：地图上主要使用图标，名称和说明集中给当前选中目标；
5. **上下文可以触发显隐**：任务追踪、当前位置和附近目标可以临时提升相关点位，不改变全局默认密度。

Pinax 不应照搬游戏 UI，而应把这些原则转译成写作工具：默认地图优先显示当前场、当前落笔处和当前章节已经引用的地点；完整世界书地点、引擎地点和待审候选通过筛选或审阅模式按需出现。

## 3. 对两款地图的实际观察

### 3.1 《原神》：底图与兴趣点目录分离

官方互动地图的默认地图主要展示地貌、海陆边界和区域名称。左侧先选择点位大类，再选择具体子类；未选择的类别不会为了证明“数据很多”而铺在地图上。

开启“传送锚点”后，世界档仍可能出现大量图标，这说明《原神》并没有从根本上消除全量点位的拥挤。值得学习的不是“全部打开后也很干净”，而是：

- 默认关闭非必要点位；
- 每类点位有稳定图标，不用无语义的小圆点；
- 区域名属于底图定位层，不与普通点位使用同一文本样式；
- 用户能快速切换地区和点位类别；
- 自建标点、游戏内标点和官方兴趣点来源分开；
- 多层地形由专门层级切换处理，不靠在一张图上猜地下/地上。

对 Pinax 的含义：世界书地点、地图原生聚落、章节引用、历史事件和待审绑定必须是可独立控制的来源层；“全部地点”只能是用户主动进入的浏览模式，不能成为默认画面。

### 3.2 《终末地》：区域、类别、楼层、选择四步收敛

官方地图工具先提供世界/地区和子区选择，再提供资源、设施、探索、威胁等分类。官方分层地图截图中，底图保持强烈地形结构，但常驻点位很少；点位主要以图标存在，当前选择和任务信息集中在边缘详情区。

更有价值的是它对“上下文显隐”的处理：官方更新说明提到，实时位置同步后，角色附近的特定点位会自动激活并出现在地图工具中。这不是把全部点位永久铺开，而是由当前任务和位置临时提升相关信息。

对 Pinax 的含义：

- 当前场地点、当前 writingUnit 提及地点和当前章节相关地点可以形成临时上下文层；
- 远方、未使用的世界书地点不应与当前场争夺视觉权重；
- 城市、建筑或复杂内部空间应允许进入 child map / floor map，而不是无限放大一张世界位图；
- 选中详情应由固定 inspector 承担，地图不需要给每个点常驻长名称。

### 3.3 两者共同的“减法顺序”

```text
选择地图范围
  -> 选择信息类别
    -> 地图只显示当前类别的可行动对象
      -> 选中一个对象
        -> 边缘详情展示名称、状态和动作
```

Pinax 应增加写作上下文，形成：

```text
当前书 / 世界书 / 地图资产
  -> 世界 / 区域 / 地方 / 场所范围
    -> 当前写作 / 探索全部 / 绑定审阅模式
      -> 语义筛选与标签预算
        -> 选中地点详情、世界书和正文回链
```

## 4. P1 四张图的逐张诊断

### 4.1 `theme-light-world-1440.png`

失败点：

- 世界档被大量数字聚合圈覆盖；数字只表达数量，不表达地点种类或写作价值；
- 聚合圈的白底和边框对比高于地形、国家和主城，视觉主次反转；
- 少量城名与大量数字圈混在一起，但没有当前场、当前章节或作者确认地点的明确层级；
- 用户不能判断点击一个“35”会得到什么，也没有默认筛选的产品依据。

代码根因：`ClusterSource({ distance: 36 })` 对全部 `narrativePlaces` 聚合，并对所有多成员 cluster 永久绘制计数圆；显示策略发生在业务语义投影之前。

### 4.2 `theme-light-local-1440.png`

失败点：

- 到地方档后聚合距离瞬间变为 0，全部名称同时出现；
- 所有名称近似同字号、同字重、同 halo，城市、村落、作者地点和候选地点无法分层；
- 重复名称来自压力 fixture，但视口没有对重复、同名父区域和不重要地点进行降级；
- 部分点视觉上落入水面或海岸过渡带，说明“落在陆块 polygon 内”不足以作为地点可用性校验；
- 河流和地点文字同时高对比，底图放大后又缺少地方级细节，文字像漂浮在模糊色块上；
- 单个硬阈值造成缩放前后信息量骤变，连续导航会闪烁和跳变。

代码根因：`resolution <= 0.9` 同时承担解除聚合和显示全部标签；没有进入/退出阈值、标签预算或语义 rank。

### 4.3 `theme-dark-world-1440.png`

结构问题与浅色世界档完全相同，且深色 cluster 对比更强。海岸浅色带和极地白块让“深色主题”变成局部反相，而不是一套统一的夜间制图层级。

### 4.4 `theme-dark-local-1440.png`

地方底图的 Voronoi cell 边界、低对比地貌和高对比文字互相冲突。仅替换 token 不能解决底图细节不足、地点语义缺失和标签过量。

## 5. 当前实现的合同缺口

### 5.1 `displayPriority` 不是地点语义

当前 `MapFeatureProperties` 只有 `featureType / displayPriority / bindingStatus / label / icon` 等最小字段。它无法稳定表达：

- 地点种类：首都、城市、城镇、村落、地标、建筑、房间；
- 空间范围：世界、区域、地方、场所；
- 上级地点：某村属于哪个区域，某房间属于哪个建筑；
- 是否值得常驻：基础地理、当前上下文、按需探索、仅审阅；
- 当前写作相关性：当前场、当前 writingUnit、当前章节已引用、远方背景。

`displayPriority` 应变成从稳定语义和当前上下文派生的渲染分数，而不是生成器随意写入的事实字段。

建议最小扩展：

```ts
interface MapFeatureProperties {
  // 已有字段省略
  kind?: 'capital' | 'city' | 'town' | 'village' | 'landmark' | 'site' | 'interior'
  scope?: 'world' | 'region' | 'local' | 'site'
  parentFeatureId?: string
}
```

写作相关性、筛选状态和标签是否显示属于视口 projection，不持久化进 feature：

```ts
interface MapContextSignal {
  featureId: string
  reason: 'selected' | 'current-scene' | 'current-unit' | 'chapter-reference' | 'search-result'
  sourceRef?: string
}
```

### 5.2 压力 fixture 不能承担视觉基准

当前注入 2,000 个作者地点时：

- 名称从 20 个词循环生成；
- 几乎所有点的 priority 是 45 或 60；
- `bindingStatus` 按序号机械分配；
- 没有地点种类、父区域或章节上下文。

它适合验证 2,000 features 的性能和泄漏，不适合验证地图是否像成熟产品。P1.5 必须新增一个“作者真实语义 fixture”，保留 dense-2k 作为单独的主动全量层压力测试。

### 5.3 固定位图无法支撑无限地方缩放

P1 的 `ImageCanvasSource` 从固定宽高 terrain Canvas 裁切并放大。OpenLayers 让矢量标签保持屏幕尺寸，但不会凭空产生地方级地形细节。继续放大会出现模糊海岸、大块 cell 和稀疏直线河流。

因此必须二选一或组合：

1. 同一世界资产保存多分辨率 terrain levels / tiles；
2. 在世界、区域和地方之间切换不同 render recipe；
3. 对城市、建筑和内部空间打开 child map，而非继续 overzoom 世界图。

### 5.4 OpenLayers 的 cluster/declutter 只是工具

OpenLayers 10.10 的官方 dynamic cluster 示例在聚合后仍需要：点击 zoom-to-extent、重叠时 circular expansion、hover hull。`declutter` 只负责避免图标或文字互相覆盖，不负责判断一个地点是否与当前任务相关。

此外官方 Cluster API 明确指出：dispose 包装 source 时需要先 `setSource(null)` 移除 listener reference。正式 P3 生命周期实现必须纳入这一点，不能只依赖一次 heap 快照推断无残留。

证据：

- [OpenLayers Dynamic clusters](https://openlayers.org/en/latest/examples/clusters-dynamic.html)
- [OpenLayers Vector label decluttering](https://openlayers.org/en/latest/examples/vector-label-decluttering.html)
- [OpenLayers Cluster API](https://openlayers.org/en/latest/apidoc/module-ol_source_Cluster-Cluster.html)

## 6. Pinax 地点地图的目标信息架构

### 6.1 三种用户模式，而不是一张图常驻全部数据

#### 写作模式（默认）

只突出当前场、当前 writingUnit、当前章节已引用地点和少量基础地理。它回答：“我现在写到哪里，这一段与哪些地方有关？”

#### 探索模式（用户主动打开）

按来源和类别查看完整世界书地点、聚落、道路、河流、历史事件等。它回答：“这个世界里还有什么？”聚类只允许在此模式作为导航工具存在。

#### 审阅模式（任务驱动）

只显示待落图、冲突、stale 和 remap 候选。它回答：“哪些地点需要我确认？”审阅结束后自动回到原模式。

### 6.2 五类图层

```text
Base geography  地形、海岸、区域、主河
Reference       国家/区域标签、首都、主城
Writing context 当前场、当前单元、当前章节引用
On-demand       用户主动开启的地点/资源/历史类别
Task overlay    搜索、选中、放置 ghost、冲突和审阅
```

前三层不能被聚成数字；`On-demand` 层在过密时才允许聚合。`Task overlay` 永远位于最上层，但除当前任务外不铺满文字。

### 6.3 优先级顺序

```text
当前选中
> 当前场
> 当前 writingUnit 明确提及
> 当前章节已经出现
> 搜索结果 / 当前任务候选
> 作者确认的宏观地点
> 首都 / 主城 / 区域名
> 普通已确认地点
> 地图原生地点
> candidate / stale / conflict（仅审阅模式）
```

优先级相同再根据空间冲突、label cost、与视口中心距离决定。不能让引擎地点数量压倒作者上下文。

## 7. 建议的语义缩放合同

以下数量是 1440×900 视觉基准，不是硬编码业务上限；窄屏按可用地图面积缩减。

| 层级 | 基础地理 | 常驻地点 | 写作上下文 | 标签预算 |
|---|---|---|---|---|
| 世界 | 大陆、国家/大区、主河 | 首都、极少量宏观地点 | 当前场 + 当前章节 3-8 个相关锚点 | 约 8-14 个地理名 + 3-8 个上下文名 |
| 区域 | 区域边界、主路、河流 | 首都、城市、作者确认地点 | 当前场 + 当前单元/章节相关 | 总计约 16-24 个常驻标签 |
| 地方 | 道路、水系、聚落轮廓 | 城镇、地标、站点图标 | 当前场及相邻一跳 | 约 12-18 个常驻标签，其余 icon-only |
| 场所 | child/floor map 结构 | 建筑、房间、局部锚点 | 本场人物/事件位置 | 由场所图单独预算 |

规则：

- 选中地点和当前场可突破预算，但其他低优先项必须让位；
- 普通候选只显示图标，hover/focus/selection 后才显示名称；
- 同名地点必须显示父区域或在列表中消歧，不能靠颜色区分；
- LOD 使用进入/退出双阈值，避免临界缩放反复闪烁；
- 地图停止缩放后再做一次有界 label plan，连续缩放中不频繁重排；
- 标签预算先筛选后交给 OpenLayers declutter，不能反过来把所有标签交给碰撞器碰运气。

## 8. 视觉语言建议

### 8.1 浅色 `atlas-clean`

- 地形比地点图标更低对比，但必须保留海岸、主河、区域形状；
- 区域名使用更大但更淡的字，不加厚白色 halo；
- 城市/地点使用原创 Pinax 图标族，通过形状表达种类；
- 当前场使用单一明确的定位环或短脉冲，不用持续动画；
- 当前章节引用使用钢青短信号，待确认使用矿物黄，冲突使用暗玫瑰；
- 选中后其他图标降低对比，详情在固定 inspector 出现。

### 8.2 深色主题

深色不是对浅色 token 逐项反相。底图应压缩生态色差，以地貌轮廓、海岸和水系建立结构；地点 icon 维持有限亮度等级。深色主题必须在浅色信息层级获批后实现，避免同时调结构和色彩。

### 8.3 不复制游戏皮肤

不复制《原神》的羊皮卷颜色、图标或字体，也不复制《终末地》的工业黑白编码、图形字或界面资产。学习范围只包括信息显隐、范围切换、选中详情和任务上下文。

## 9. 决策

1. P0 数据合同和 P1 OpenLayers 技术 Gate 保留；
2. P1 的“世界/区域聚合计数 + 地方全部标签”视觉策略废止；
3. 在 P2/P3 正式接入前增加 P1.5“地点信息架构与视觉校准 Gate”；
4. `dense-2k` 只作为主动全量层压力测试，不再作为默认视觉截图；
5. 正式视口先实现语义筛选、上下文投影和 label budget，再接 cluster/declutter；
6. child/floor map 进入后续架构，不承诺世界底图无限地方缩放；
7. P1 技术报告必须区分“性能/生命周期通过”和“地点视觉未通过”。
