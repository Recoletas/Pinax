## 结论

本轮完成了同一 provider、同一模型、同一 fixture 集和同一生成预算下的三架构真实运行，但人工盲评在 6/26 个成功输出后因样本重复度高和评审时间不足而提前停止。现有证据足以定位共同质量缺陷，不足以完成预先规定的全量人工评分、正式排名或 winner 选择。

因此：

- 不把未评样本补分，也不使用模型代替人类评审；
- 不运行官方 `report` 来伪装完整门禁；
- 不选择 winner，不执行 winner-only portability；
- 下一步先修订关系真实性与无效悬念合同，再决定是否重跑，而不是直接进入 Experience MVP 实现。

## 跨架构质量发现

人工 notes 指向的主要问题不是“角色口吻完全相同”，而是更深层的真实性缺失：

1. **口吻可区分，但关系不真实。** 母女、同事或对立角色缺少共同历史、身份习惯、权力差、亏欠、默认称呼、回避方式和无需说透的共享信息，导致对白像不同声线的陌生人。
2. **无因果兑现的神秘化。** 文本会强调复杂目光、莫名不安或“另有隐情”，但这些信号既不是已给伏笔，也不在截面内形成因果或兑现，产生“谜语感”和假悬念。
3. **局部行为与对白缺少动机桥梁。** 有些片段粗看顺畅，细看会出现人物突然转向、节奏过快或对白莫名其妙。
4. **角色塑造仍有机器性。** voice profile 能制造表层差异，但不能替代具体社会关系、互动惯性和场景前状态。

根因与 fixture 合同一致：角色只有 `desire / contradiction / voiceProfile / temperament / knownFactIds / forbiddenFactIds`，没有关系字段。与此同时，秘密、矛盾与信息纪律被强调，模型容易用悬疑语气填补缺失的关系与因果细节。

## 下一步合同要求

下一份计划应先定义并验证以下输入，而不是直接实现产品 UI：

- 角色关系：公开身份、亲疏与权力差、共同经历、当前亏欠或张力；
- 互动惯性：称呼、打断、回避、默认分工、只有双方理解的具体细节；
- 场景前状态：双方原本期待什么、什么变化会被对方立即察觉；
- 悬念约束：被强调的异常必须来自作者提供的未决线程，或在本截面内产生因果与兑现；禁止凭空制造“似乎另有隐情”；
- 评审诊断：在既有五维之外记录 `关系失真 / 对白身份感弱 / 假悬念 / 行为无因 / 节奏过快 / 机器腔` 标签。

修订后可以使用盲化 pairwise preference 作为辅助相对判断，但仍须保留绝对质量门禁，避免从两个不可用输出中强行选 winner。
