# 体验与写作工作区融合设计

**日期：** 2026-08-23  
**状态：** 已与用户确认，可进入实施计划  
**目标页面：** `src/pages/Authoring.vue`  
**现有兼容页面：** `src/pages/Experience.vue`、`src/pages/Writing.vue`

## 1. 目标

把体验页与写作页融合为一个以持续可编辑正文为中心的创作工作区，同时保留体验页真正有价值的交互循环：

```text
选择行动者与对象
  -> 输入行动、对白、心理或场景意图
  -> AI 写出下一拍正文
  -> 人物、关系、地点、时间与事件状态更新
  -> 用户继续写作或决定下一步
```

融合后的页面必须同时满足：

1. 正文编辑器仍是唯一主要工作面，AI 生成结果直接成为普通、可继续编辑的正文。
2. 体验能力不能退化为一排不同名字的“续写”按钮。
3. 人物、地点和当前事件需要在页面上有简洁、直观、常显的存在。
4. 右侧平时保持安静，默认服务批注；只有用户明确点击左侧现场条目后才显示相应详情。
5. 局部编辑、故事推进、现场观察三种任务各有清晰 owner，不重复提供同一能力。
6. 独立体验页在等价能力、恢复和响应式验收通过前继续保留。

## 2. 当前实现审计

### 2.1 九指令横条的问题

当前 `AuthoringCommandBar.vue` 把以下能力做成同级常驻按钮：

- 续写；
- 推进；
- 人物反应；
- 推演场景；
- 插入；
- 改写选区；
- 下一步；
- 对话选项；
- 涌现。

这套映射存在四个结构性问题：

1. 它按旧页面能力来源分类，而不是按用户当前正在做的事分类。
2. `续写` 与编辑器内联补全、`/` 命令菜单重复；`改写选区` 与批注改写、选区工作流重复。
3. 直接写入正文的任务与只产生候选的任务混在一起，结果预期不清楚。
4. 体验页原本的身份、对象、自由输入、回合反馈和现场状态被压缩成若干固定提示词，角色参与感消失。

视觉上，它还引入了一套独立的圆角 pill 语言，与既有 `editor-toolbar`、`tool-btn`、稿页和检查器体系不一致；窄屏依靠横向滚动隐藏按钮，不能建立清晰层级。

### 2.2 左侧栏的容量没有被有效利用

当前左栏固定约 248px，只渲染：

- 最多 4 本书：`books.slice(0, 4)`；
- 最多 6 个章节：`chapters.slice(0, 6)`；
- 新书、新章；
- 纯装饰的“未展开稿纸卷”。

它既没有完整承载稿件导航，也没有提供当前章节的人物、地点和事件方向。这个区域适合从“章节书架”演进为“稿件导航 + 本章现场”，而不是继续添加装饰或另建常驻仪表盘。

### 2.3 体验页真正需要迁移的是回合循环

体验页现有价值不只来自快捷按钮，还包括：

- 自由输入行动或对白；
- 对话角色选择；
- 场景、心理与一次性导演注；
- 空输入继续上一回复；
- 有界半自动推进及暂停条件；
- 人物、地点、时间和事件现场索引；
- 下一步行动、对话选项与涌现候选；
- 生成中停止、失败重试和本回合上下文回执；
- 速记、素材收集、机制反馈与历史回看。

这些能力应重新分配到统一工作区的合适位置，不能逐组件搬运，也不能逐按钮翻译。

## 3. 设计定位

按照 `ui-style-check` 的四个定位问题，本设计采用以下答案：

| 问题 | 决策 |
| --- | --- |
| Narrative role | 持续写作与故事推进共用的编辑工作台，不是仪表盘、聊天页或功能启动器 |
| Viewing distance | 以笔记本和桌面近距离长时间使用为主，移动端承担查看、短写与推进 |
| Visual temperature | 安静、编辑性、轻度沉浸；状态沿边缘工作，正文保持视觉中心 |
| Capacity check | 左栏连续分为可滚动稿件区和有界现场摘要；右侧详情按需替换，不同时堆叠 |

视觉实现继续使用当前 Pinax 蓝白档案主题的 token、稿页、短色条、下划线和边缘状态，不新增渐变 AI 品牌色、圆角卡片墙、emoji 图标或 HUD。

## 4. 最终信息架构

```text
┌────────────左栏────────────┬────────────正文工作面────────────┬────右侧检查器────┐
│ 稿件                       │ 编辑工具栏                     │ 默认：批注       │
│  当前书                    │                                │ 次级：版本       │
│  完整章节列表              │ 章节正文                       │                  │
│                            │                                │ 点击左侧后临时： │
│ ── 本章现场 ──             │                                │ 人物详情         │
│ 地点 · 时间                │                                │ 地点详情         │
│ 莉娜 · 视角                │                                │ 时间详情         │
│ 艾德加 · 在场              │                                │ 事件详情         │
│ 收债人 · 对象              │                                │                  │
│ 未决：伪造印章             │ ┌──── 推进下一拍 ────────────┐ │                  │
│                            │ │ 行动 对话 心理 场景         │ │                  │
│ 全部人物 / 世界设定        │ │ 输入意图……          生成  │ │                  │
└────────────────────────────┴─┴──────────────────────────────┴─┴──────────────────┘
```

四个区域分别只有一个主要职责：

- **左侧：** 导航稿件，并回答“当前是谁、在哪里、什么尚未解决”。
- **中央：** 编辑唯一正文。
- **中央底部：** 回答“下一拍让谁做什么”。
- **右侧：** 默认处理批注，按用户点击临时查看现场详情。

## 5. 左侧栏设计

### 5.1 稿件区

左栏上半部分继续承担书籍与章节导航，但要先修正现有截断：

- 不再对书籍和章节使用固定 `slice()` 隐藏其余内容；
- 默认只展开当前书，完整章节列表在稿件区内部滚动；
- 保留章节排序、新书、新章与当前项高亮；
- 删除“未展开稿纸卷”等不承载真实状态的装饰；
- 切换章节时保持现场区可见，不让长章节列表把它推到视口外。

桌面布局建议将左栏设为两行：

```css
grid-template-rows: minmax(180px, 1fr) auto;
```

稿件区滚动，现场区有界；不通过扩大整个页面宽度解决容量问题。

### 5.2 本章现场

现场区默认常显，但只展示高频摘要：

1. 当前地点与时间；
2. 当前视角人物；
3. 当前行动者；
4. 本场在场人物；
5. 对话模式下的当前对象；
6. 一条最高优先级未决事件；
7. 未查看变化的轻量计数。

示例：

```text
本章现场                         +1

旧港税务所 · 深夜

莉娜                       视角
艾德加                     在场
收债人                     对象

未决：伪造印章的来源
```

明确不在左栏展示：

- 完整人物卡；
- 长背景和人物描述；
- 多组属性条；
- 整个世界书的全部人物；
- 完整关系图；
- 所有事件历史；
- 可编辑设定表单。

### 5.3 左侧条目的直接操作

左侧现场条目既是摘要，也是明确导航入口：

| 点击对象 | 默认行为 | 对下一拍输入的影响 |
| --- | --- | --- |
| 人物 | 右侧显示该人物详情 | 单击可设为行动者；对话模式下可继续选择对象 |
| 地点 | 右侧显示地点详情 | 不改变行动者 |
| 时间 | 右侧显示时间详情 | 不改变行动者 |
| 未决事件 | 右侧显示事件详情 | 可显式“以此推进”，填入下一拍输入 |
| 全部人物 | 打开受控人物选择/完整设定入口 | 允许选择不在场人物，但不把其自动标为在场 |

人物选择必须有可见状态：`视角`、`行动者`、`对象`、`在场`。不能只依赖颜色区别，也不能让一次点击同时产生无法预期的多个状态变化。

## 6. 下一拍输入区

### 6.1 位置和常显程度

下一拍输入区位于正文编辑器下方，与稿页正文同宽。它是体验循环的主要入口，因此有章节时默认显示精简状态，而不是完全藏进工具菜单。

默认形态只占一到两行：

```text
行动 · 莉娜                     旧港税务所
描述她接下来做什么……                         生成下一拍
```

它不放入顶部 `editor-toolbar`，顶部最多保留一个现有 `tool-btn` 风格的“推进”跳转/聚焦入口，用于长章节中快速回到输入区。

### 6.2 输入类型

输入类型使用文本和短下划线建立选择，不使用九个圆角 pill：

```text
行动　对话　心理　场景
────
```

四种类型的语义如下：

#### 行动

用户描述行动者的意图或动作，NarrativeKernel 负责写出承接、反应、发展和落点。输入是控制意图，不作为正文复述。

#### 对话

显示“说话人 -> 对象”。用户可以输入具体台词，也可以只输入交谈目的。运行时必须使用双方关系、当前目标、最近冲突和说话口吻。

#### 心理

只允许当前视角可知的信息。用户给出心理方向，模型将其转为符合视角的动作、身体反应、感官或意识活动，不直接总结情绪。

#### 场景

用户提供环境变化、调度、进入者、压力或节拍方向。它替代体验页“场景”与一次性导演意图的高频部分，但不让模型机械复述控制语句。

### 6.3 主动作

- 输入为空：主按钮为“继续下一拍”。
- 输入非空：主按钮为“按此推进”。
- 生成中：同一位置变为“停止”。
- 请求失败：保留输入、行动者、对象和导演注，提供“重试”。
- 文档 revision 过期：不写入正文，保留输入并提示重新执行。

“续写”因此成为空意图下的默认行为，不再与推进、人物反应、场景推演并列。

### 6.4 低频增强

以下能力放入输入区的“更多”，而不是常驻按钮：

- 本轮导演注；
- 有界半自动推进；
- 查看本次参考摘要；
- 请求下一步方向；
- 请求对话说法。

半自动沿用体验页安全边界：最多连续三拍；用户输入、直接提问、地点切换、机制触发、异常审阅或手动停止时暂停。

## 7. 右侧检查器设计

### 7.1 默认状态

右侧平时保持现有写作检查器的低干扰职责：

- 默认视图是“批注”；
- “版本”保留为次级入口；
- 不增加一排常驻“人物 / 地点 / 时间 / 事件”页签；
- 没有批注时使用简洁空状态，不用人物或事件填满空间。

正文生成、关系变化、涌现候选和新事件都不能自动抢占右侧。

### 7.2 临时详情导航

只有用户点击左侧现场条目时，右侧才原位切换到对应详情：

```text
← 返回批注

人物 · 莉娜
当前目标
当前心境
本场关系
最近行动
口吻依据

设为行动者
打开完整人物设定
```

详情是临时 inspector route，而不是新常驻 tab。建议状态结构：

```js
{
  baseView: 'comments' | 'versions',
  detail: null | {
    kind: 'character' | 'location' | 'time' | 'event',
    id: 'stable-id'
  },
  returnFocusRef: 'left-rail-item-id'
}
```

交互规则：

1. 点击另一个左侧条目时，右侧原位切换对象，不叠加抽屉或 modal。
2. 点击“返回批注”或关闭详情后，恢复之前的 `baseView`、滚动位置、批注选择和左侧焦点。
3. 详情只提供查看和少量现场操作；完整编辑跳转现有世界书、地图或设定 owner。
4. 派生状态更新只在左侧显示短色条、圆点或 `+N`，不自动打开详情。
5. 当前详情对象失效或被删除时，安全返回默认批注并显示一次短提示。

### 7.3 各详情的最小内容

#### 人物详情

- 当前目标和心境；
- 本场身份：视角、行动者、对象或在场；
- 与本场其他人物最相关的 1-3 条关系；
- 最近行动；
- 有界口吻依据；
- “设为行动者”和“打开完整人物设定”。

#### 地点详情

- 当前地点及父级区域；
- 本场相关环境事实；
- 当前控制者/势力；
- 最近地点变化；
- “打开地图/地点设定”。

#### 时间详情

- 当前时间锚点；
- 与上一节拍的推进量；
- 时间来源；
- “打开时间设置”。

#### 事件详情

- 未决问题或事件；
- 已知起因和当前压力；
- 相关人物、地点；
- 最近兑现；
- “以此推进”和“加入章节纲要”。

## 8. 候选与涌现

下一步、对话选项和涌现不再是三个常驻命令。

### 8.1 下一步方向

输入区为空时，用户可请求 2-4 个方向。候选显示在输入区上方的短列表，操作为：

- 填入输入框；
- 直接按此推进；
- 加入章节纲要；
- 忽略。

### 8.2 对话说法

只在对话模式提供，必须带说话人与对象。选择后填入输入框，用户仍可修改，不直接写入正文。

### 8.3 涌现候选

涌现候选是状态提议，不是正文：

- 左侧只显示待查看 `+N`；
- 用户点击后在右侧显示候选详情；
- 可确认、忽略、加入纲要或打开来源；
- 不自动覆盖 locked/canonical 设定，也不自动抢占检查器。

## 9. 生成与正文事务

一次下一拍生成遵循：

```text
读取现场投影与当前文档 revision
  -> 构造有界回合意图
  -> 统一 Authoring runtime
  -> NarrativeKernel 生成可见正文
  -> 规划协议与元话语过滤
  -> stale 检查
  -> 原子插入一个 writingUnit
  -> 显示瞬时来源与请求级撤销
  -> 调度人物/关系/地点/事件/记忆观察器
```

硬约束：

- 用户的行动、导演注和隐藏控制提示不进入正文；
- AI 正文进入一个新的 `writingUnit`，不建立第二份体验稿；
- 生成后可以立即编辑、拆分、合并和删除；
- 手动编辑使请求级撤销回执按现有规则失效；
- 完整 prompt、展开上下文、规划 transcript、流式碎片和未采用候选不永久保存；
- 观察器失败不回滚正文；
- 常规派生保持安静，只有 locked conflict、identity ambiguity、destructive retcon 进入异常审阅。

## 10. 共享现场投影

左栏、下一拍输入、右侧详情和 NarrativeKernel 必须读取同一个现场投影，不能分别从多个 store 猜测状态。

建议新增只读投影：

```js
{
  schemaVersion: 1,
  projectId,
  chapterId,
  sceneId,
  revision,
  viewpointCharacter: null | CharacterSummary,
  activeActor: null | CharacterSummary,
  dialogueTarget: null | CharacterSummary,
  location: null | LocationSummary,
  time: null | TimeSummary,
  presentCharacters: CharacterSummary[],
  activeRelations: RelationSummary[],
  unresolvedEvents: EventSummary[],
  emergenceCandidates: CandidateSummary[],
  unreadChanges: {
    characters: 0,
    location: 0,
    time: 0,
    events: 0,
    emergence: 0
  },
  sourceRefs: []
}
```

投影来源：

- 当前章节和 schema-v3 writing units；
- 旧体验回合的来源引用；
- worldbook 人物、关系和地点；
- gameStore 当前运行时快照；
- authoring observers 的人物、关系、事件、时间线和记忆派生；
- 地图和时间状态；
- 当前章节纲要。

规则：

1. 所有实体使用稳定 ID，名称只用于显示。
2. `presentCharacters` 只包含有确定依据的在场人物；不因一次候选选择自动写回在场状态。
3. 无法确定视角、地点或身份时显示“未指定”，不得猜测。
4. 投影不成为新的持久化真源；其状态可由 canonical 数据和当前 revision 重建。
5. 左侧点击、输入模式和右侧详情只保存轻量 UI 选择，不复制实体正文。

## 11. 现有体验能力的归属

| 体验页能力 | 统一工作区归属 |
| --- | --- |
| 自由行动/对白输入 | 下一拍输入区 |
| 继续 | 空输入下的主动作 |
| 场景、心理 | 输入类型 |
| 对话角色选择 | 左侧人物 + 输入区说话人/对象 |
| 一次性导演注 | 输入区“更多” |
| 半自动 | 输入区“更多”，有界三拍 |
| 下一步选项 | 输入辅助候选 |
| 对话选项 | 对话模式输入辅助 |
| 人物/地点/时间/事件索引 | 左侧摘要，右侧按需详情 |
| 涌现 | 左侧计数，右侧按需审阅 |
| 速记 | 现有批注、收为素材和素材收件箱 |
| 分支 | 写作版本、快照和来源链 |
| 压缩上下文 | 运行时自动策略，不作为日常按钮 |
| 导出 | 现有书籍/章节导出 |
| Prompt/上下文详情 | 现有 Context Inspector |
| 机制触发 | 正文结果、现场事件或异常，不做顶部命令 |

## 12. 组件边界

建议的新增/调整边界如下，具体文件名可在实施计划中微调：

- `AuthoringSceneRail.vue`
  - 只渲染左侧现场摘要与选择状态；
  - 不直接编辑完整人物/地点；
  - 发出 `select-actor`、`select-target`、`open-detail`。
- `AuthoringTurnComposer.vue`
  - 管理输入类型、文本、导演注、自动推进和请求状态；
  - 不直接拼 prompt；
  - 发出标准下一拍请求。
- `AuthoringInspectorDetail.vue`
  - 根据 `kind + id` 渲染人物、地点、时间或事件详情；
  - 复用现有检查器容器和返回逻辑。
- `authoringSceneProjection.js`
  - 纯函数构建共享现场投影；
  - 不读写 DOM，不持久化第二份状态。
- `authoringTurnContract.js`
  - 规范行动、对话、心理、场景意图及角色选择。

不要直接把体验页的 `StatusBar.vue`、`GeographyPanel.vue`、`TimeQuickRail.vue` 整块挂进 Authoring。可以提取其 selector、摘要格式和 detail adapter，但不能继承体验页专属 modal、demo mode、玩家角色或 CSS 壳。

## 13. 视觉语言

### 13.1 应保留

- 当前稿页和 `editor-toolbar` 的安静编辑语言；
- `tool-btn` 的尺寸、焦点和分组节奏；
- 左栏档案索引的文字层级；
- 检查器已有的批注密度和边注语义；
- 项目 token、现有主题和响应式断点；
- 瞬时来源、撤销和状态短线。

### 13.2 必须删除或避免

- 九个常驻圆角 pill；
- 每个人物、地点、事件一个完整卡片；
- 右侧常驻故事仪表盘；
- emoji 作为模式图标；
- 为“AI 感”新增渐变或高饱和强调色；
- 在正文背后增加工程网格或 HUD；
- 同一状态在左栏、输入区和右栏重复完整展示。

### 13.3 层级

第一视觉中心始终是正文；第二视觉中心是当前输入焦点；左侧现场是可扫描索引；右侧详情只有在显式打开时才提高层级。颜色只表达真实选择、来源、未读变化和风险。

## 14. 响应式

### 桌面（>= 1100px）

- 左栏持续显示；
- 稿件区滚动，现场区固定在下部；
- 右侧默认批注，按需显示详情；
- 下一拍输入与稿页同宽。

### 中等宽度（760-1099px）

- 左栏变为现有章节抽屉；
- 抽屉仍按“稿件 / 本章现场”连续排列，不新增 tab；
- 右侧详情保持覆盖式检查器；
- 输入区保留类型、角色和主按钮，低频项收起。

### 移动端（<= 759px）

- 顶部章节按钮打开包含稿件和现场的全高抽屉；
- 点击现场条目关闭左抽屉并打开右侧详情底部抽屉；
- 关闭详情后恢复左抽屉滚动位置与触发焦点；
- 下一拍输入保持常显的单行摘要，聚焦后扩展为顺序流；
- 对话角色选择使用同一抽屉内列表，不横向滚动胶囊；
- 不产生页面横向溢出。

### Zen

- 隐藏左右栏、章节导航和非必要工具；
- 保留正文；
- 下一拍输入折叠为一条安静入口，用户聚焦后展开；
- `Escape` 先关闭当前详情/菜单，再按既有规则退出 Zen。

## 15. 可访问性与键盘

- 左侧现场使用语义列表和按钮，不用仅带 click 的 `div`；
- 状态同时用文字表示，不只依赖颜色；
- 人物选择提供 `aria-pressed` 或等价可读状态；
- 输入类型使用可键盘操作的 tab/segmented semantics，但视觉上不做 pill；
- 右侧详情标题与返回按钮可被读屏明确识别；
- 打开详情后移动焦点到详情标题，关闭后恢复到左侧来源项；
- 生成、停止、失败、stale 和撤销使用现有 live status 模式；
- 所有 transient layer 遵守 Escape、焦点陷阱和 body scroll lock 规则；
- reduced motion 下取消抽页位移，只保留即时状态切换。

## 16. 错误与恢复

- 无角色：允许行动/场景继续，但显示“未指定行动者”；对话模式必须选择说话人和对象。
- 角色被删除或失效：清空相应选择，保留输入并提示重新选择。
- 地点或事件来源 stale：显示来源已变化，不把旧状态注入下一次请求。
- Provider 失败：保留输入、模式、角色、对象和导演注。
- 用户在请求期间编辑正文：结果按 revision gate 丢弃，不覆盖正文。
- 观察器失败：正文保留，现场投影继续使用上一个有效快照并标记待刷新。
- 页面重载：恢复正文和 canonical 状态；未提交的完整 prompt、模型流和候选不恢复。
- 旧体验会话：继续通过幂等投影导入 writing units，并保留来源回跳。

## 17. 分阶段交付边界

### Phase 1：结构与单一投影

- 共享现场投影；
- 左栏完整稿件导航；
- 左栏本章现场摘要；
- 右侧人物/地点/时间/事件临时详情状态；
- 不改生成链。

### Phase 2：下一拍输入与正文事务

- 行动、对话、心理、场景请求契约；
- 下一拍输入区；
- NarrativeKernel 接入；
- 一个生成结果对应一个 writingUnit；
- stale、停止、重试和撤销。

### Phase 3：体验等价能力

- 下一步和对话候选；
- 导演注；
- 有界半自动；
- 涌现候选按需审阅；
- 旧体验会话迁移与来源回跳。

### Phase 4：清理与退役门禁

- 删除九指令横条和重复入口；
- 桌面、中宽、移动和 Zen 审计；
- 真实 provider 与恢复验证；
- 用户等价验收；
- 满足门禁后另行决定独立 Experience 路由是否退役。

Phase 1-3 期间独立 Experience 保持可用，不能在新入口仅有静态壳或部分等价时提前删除。

## 18. 明确不做

- 不把左栏扩展成完整世界书编辑器；
- 不在右侧常驻人物、地点、时间、事件四个 tab；
- 不保存第二份体验 transcript 作为正文镜像；
- 不让模型自动选择身份不明的说话人；
- 不让涌现候选自动成为正式事实；
- 不增加无限自动续写；
- 不重新设计整个写作页主题；
- 不直接复用体验页的大型组件壳；
- 不把所有 Agent 任务都放进下一拍输入；
- 不在本设计中退役 Experience 路由。

## 19. 验收标准

### 信息架构

1. 默认页面没有九指令横条。
2. 左栏同时可访问完整稿件结构和本章现场摘要。
3. 人物、地点、时间和一个主要未决事件无需打开工具菜单即可看到。
4. 右侧默认仍是批注，不因生成或状态变化自动切换。
5. 点击左侧现场条目后，右侧显示对应详情；返回后恢复批注状态和焦点。

### 体验循环

6. 用户可选择行动、对话、心理或场景，指定行动者与对话对象。
7. 输入为空可以继续下一拍，输入非空可以按意图推进。
8. 用户控制文本不进入正文；生成结果作为一个可编辑 writingUnit 插入。
9. 下一步、对话说法和涌现不再作为常驻按钮。
10. 停止、失败、stale、重试和请求级撤销行为明确。

### 状态一致性

11. 左栏、输入区、右侧详情和生成上下文使用同一个现场投影。
12. 无依据的人物不会被标记在场，无依据的身份不会被猜测。
13. 常规派生不打断写作；异常保持现有 typed review 边界。

### 视觉与响应式

14. 1440px 下正文仍是第一视觉中心，左栏和右栏不形成卡片墙。
15. 900px 下稿件、现场、正文和详情均可达，无重叠或横向溢出。
16. 390px 下角色选择、下一拍输入、详情返回和键盘输入均可完成。
17. Zen 仍能专注写作，并可按需展开下一拍输入。
18. 所有新增颜色、间距、焦点和响应式行为使用现有 token 与断点。

## 20. 研究依据与 Pinax 取舍

- Dabble 把 Manuscript、Plots、Characters 和 Notebook 放在同一左侧导航中，并明确区分可出版正文与支持材料。Pinax采用“稿件导航与故事支持信息同栏”的原则，但只常显本章现场，不复制全部支持材料树：<https://www.dabblewriter.com/docs/planning-story-notes/how-dabble-organizes-your-story>
- Scrivener 的 Binder 可容纳稿件、Characters 和 Setting sheets。Pinax采用稳定左侧项目索引，但不把人物详情本身变成中央文档切换：<https://scrivener.tenderapp.com/help/kb/features-and-usage/project-and-document-templates>
- Novelcrafter 的 Codex 把人物、地点和 lore 贯穿构思、写作与审阅，并参与 AI 上下文。Pinax采用同一现场投影服务 UI 和生成的原则，但保留有界上下文、来源与权威门禁：<https://www.novelcrafter.com/>
- Dabble 的 Manuscript Plot Grid 会把场景顺序和场景 notes 连接起来。Pinax采用“当前章节现场与正文同步”的原则，但不在本工作区引入完整 Plot Grid：<https://help.dabblewriter.com/quick-guide-to-dabble/exploring-dabbles-plot-grid/>
