# 小说真实性局部编辑器设计

## 目标

在现有小说截面戏剧消融工具中，验证一次生成后的局部真实性编辑是否比继续扩充首次生成提示词更有效。重点处理两类已由人工反馈确认的问题：

- 关系设定没有落实为称呼、照顾惯性、打断、回避、试探或拒绝；
- 推断被重复解释、人造金句、破折号顿悟、无兑现的神秘句和替人物解释心理的比喻。

本切片不进入 Experience 生产链，不建立 RLHF、评分平台、多 Agent 流水线或新的人工评测任务。

## 方案取舍

1. 继续扩充首次生成提示词：调用最少，但已经证明只能压制特定句式，容易换一种形式复现。放弃。
2. 整篇二次润色：实现简单，但容易抹平人物口吻、改动事件和制造新的统一润色腔。放弃。
3. 有界局部编辑：编辑器同时读取原 fixture、关系材料和初稿，先诊断，再最多修三处。采用。

## 数据流

```text
fixture + relation pack + generated draft
  -> authenticity editor request
  -> typed edit verdict
  -> validate facts / event boundary / edit count
  -> normalize edited prose
  -> original + edited artifacts
```

编辑器是实验后处理器，不是第四个戏剧条件。原始三条件输出保持不变；只有显式启用时才增加一次 provider 调用。

## 编辑合同

输入包含完整初稿、角色合同、可见性事实和可选极小关系包。编辑器只检查：

1. 关系是否改变动作、称呼、打断、回避、照顾或拒绝；
2. 推断或结论是否被旁白重复解释；
3. 是否存在无兑现的神秘句、格言句或破折号顿悟；
4. 比喻是否只是在替人物解释心理。

输出采用 typed JSON：

- `status`: `unchanged` 或 `edited`；
- `findings`: 最多三项，每项含问题类型、原句和修订理由；
- `editedText`: 完整 Pinax marker 正文。

硬边界：最多三处局部修改；不得新增事实、改变人物选择、改变场景退出点、删除关系承载细节或整体重写。没有可靠改法时返回 `unchanged`。

## 失败处理

编辑调用失败、JSON 无效、超过三项、出现未授权事实或正文无法规范化时，保留原稿并记录 typed failure；不能静默把失败稿当成修订成功。原始生成结果始终可追溯。

## 最小验证

- 合同测试覆盖提示词边界、`unchanged`、最多三项、非法输出回退和原稿保留；
- CLI 只增加一个显式开关，不改变默认 24-attempt 矩阵；
- 真实 provider 只回放用户已看过的第 1、5 组，不要求新增人工评分；
- 结果输出为正常换行的 TXT，并并排保留原稿与局部编辑稿。

## 成功标准

第 1 组不恢复“唯独……——假的”式揭示；第 5 组减少替人物解释心理的比喻，同时不改变关键事件、人物选择和结尾。若局部编辑仍持续制造代词错误或统一润色腔，则记录为方案上限，不继续叠规则。
