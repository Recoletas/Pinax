# 体验页段落与引号规范化设计

## 背景

体验页的叙事展示已经会把多数多句叙述拆成较短段落，但仍有三个未覆盖边界：模型用逗号连接整段文字时没有可用的句末断点；一对引号包住的长独白被解析器视作不可拆分整体；生成协议同时允许 `「……」` 与 `“……”`，导致同一场景内格式混用。

## 目标

- 新生成的中文小说正文统一使用外层引号 `“……”`，嵌套引用使用 `‘……’`。
- 叙述、动作、心理和长独白默认每段一至两句，并为异常长的单句提供保守兜底。
- 不改变人物、事件、措辞和说话人归属；只规范展示结构与标点样式。
- 已保存的稠密内容在现有展示迁移入口重新解析，不要求用户清空存档。

## 方案

### 生成协议

`buildNarrativeFormatInstructions()` 只声明一套正文引号规范，明确禁止最终可见正文混用直角引号。继续要求一至两句一段，并补充长独白也必须分段。

### 解析兜底

`narrativePresentation` 在结构化块进入展示模型时执行两类确定性处理：

1. 对 `dialogue` 块规范成中文双引号。完整外层 `「……」`、`『……』` 或 ASCII 双引号都转为 `“……”`，其中嵌套的直角引号转为 `‘……’`；不替换普通叙述中的书名号或不成对符号。
2. 对完整引号包裹的长独白，在引号内部按句末标点分组，每组一至两句，再分别补回规范外层引号并保留 speaker。

对 narration、action、thought 的异常长单句增加保守二级边界：优先在分号处分段；仍超过长度阈值时，选择接近阈值的逗号作为边界。逗号边界只用于展示分块，原有文字和标点保持不变，避免擅自改写模型内容。

### 旧内容迁移

扩展现有 `presentationHasDenseProse()` 判定，使混合引号、长独白和异常长单句触发一次选择性重新解析。正常的既有短段落不重写，避免无关内容抖动。

## 边界与非目标

- 不做通用文学润色，不重写句子，也不校正模型事实。
- 不处理用户手工输入的书名号、引用符号或非 dialogue 块中的风格选择。
- 不通过 CSS 假装分段；复制、收进稿件和恢复后的结构必须一致。
- 本次不调整体验页布局、字号或响应式样式。

## 验证

先新增失败用例，覆盖混合引号、直角引号独白、四句长独白、分号长句、无句末标点的逗号长句以及旧 v5 内容选择性刷新。实现后运行 focused integration tests、叙事 recovery smoke、production dry-run 和全量 `verify:full`。
