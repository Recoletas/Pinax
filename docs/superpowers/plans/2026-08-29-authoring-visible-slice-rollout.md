## 0. 计划要纠正的问题

上一轮确实修复了 Ghost、长推演、记忆、撤销、批注和跨章作用域等真实错误，但实施切片横跨状态机、数据事务、组件接线、CSS 和测试，导致“内部改动很多，真实页面第一眼变化很少”。甚至 Authoring 最终样式仍把核心 `flex/grid` 骨架寄托在旧 scoped 样式上，运行态样式层失效时整页退化为普通文档流。

本计划不再以“完成多少函数、接通多少 props、增加多少测试”衡量进展。唯一推进单位是：

```text
一张真实页面
+ 一个作者任务
+ 一组可见状态
+ 一次截图确认
+ 一条可操作闭环
```

服务层只在当前可见闭环缺少数据或事务时修改。尚未进入当前截图的后台能力不扩建。

## 1. 与旧计划的关系

本计划不推翻已经正确的底层工作：

- 保留 schema v3 writingUnit、稳定 `unitId + nodeId`、批注迁移、历史与恢复；
- 保留唯一交互 owner、IME 门禁、cursor-dwell、Ghost 事务和可编辑长推演；
- 保留世界书、当前场、大纲、上下文 compiler 和 observer 的既有真源；
- 保留 AppShell workspace tabs、现有图标、字体、token 和可复用编辑器；
- 保留素材、画布、Experience 的独立完整页面，但不让它们占据文本工作台主流程。

本计划替代旧计划中宽泛的“Phase 0 真实原型”“Phase 2 左树与稿面”“Phase 12 视觉收口”和可靠性计划 Slice 4/5 的剩余视觉实施方式。旧文件继续保存数据合同与历史决策，不再拿它们的大阶段直接开工。

## 2. 用户反馈转成八条硬约束

1. **正文永远是最大舞台。** 页面第一眼必须先看到章节标题和正文，不先看到卡片、统计、Agent 状态或工具说明。
2. **宽屏保持稳定横向结构。** 左导航、中央稿面、右工具 rail 和已打开详情同处一行；正文滚动不能带着左右栏移动。
3. **只有文本锚定层跟随正文。** Ghost、命令菜单、选区工具、批注位置和长推演锚点可随目标文本重定位；右栏壳、大纲、设定、现场概览不能随正文滚动。
4. **章节与中文排版朴素。** 使用“第一章　魔力异常”，不加 `01`、协议号、英文微标或装饰性章节卡；标题必须位于稿面内部。
5. **writingUnit 不是自然段换皮。** 一个单元可含一段或数段完整文字；常态不把每段画成块，只有 hover、选中、拖动、批注或生成时才显露单元边界。
6. **短 Ghost 与长推演是两种清晰工具。** 短 Ghost 贴 caret、轻量、可渐进采纳；长推演位于目标 writingUnit 下方，可修改后再纳入，不能变成右侧聊天卡或整块突兀表单。
7. **当前场必须串起世界书和推演。** 左侧显示简报；点击在右侧打开详情；作者可从绑定世界书添加人物/地点，再以此条件推演当前片段，采纳后更新正文和明确选择的现场变化。
8. **公开工具和视觉证据都必须真实。** 批注、大纲、设定、现场、历史和上下文保留；角色并入当前场，素材移出默认 rail；没有闭环的入口先隐藏。每个切片只做一个代表区域，截图方向未确认就不向整页扩散。

## 4. 冻结后的页面构图

### 4.1 桌面 1440px 及以上

```text
AppShell：项目/书/完整功能页签（唯一页签 owner）
┌──────────────────────────────────────────────────────────────┐
│ Authoring 工具条：撤销 格式 排版 取名 打字机 聚焦 专注 查找 更多 │ 42–44px
├──────────────┬──────────────────────────┬────┬───────────────┤
│ 构思 / 章节   │                          │工具│  当前工具详情  │
│ 220–252px    │      连续中央稿面         │44px│  300–340px     │
│              │                          │    │               │
│              │      正文唯一滚动         │固定│   内部滚动     │
├──────────────┤                          │    │               │
│ 当前场简报    │                          │    │               │
└──────────────┴──────────────────────────┴────┴───────────────┘
```

- AppShell workspace tab 是“打开哪本书/哪个完整功能页”的唯一 owner；Authoring 内部重复书页签在路由同步确认后退役。
- 左右侧使用接近白色的工作面，中央外围使用很浅的蓝灰，稿面与周边只保持小幅明度差，不做反色大块。
- 中央正文列不缩成过窄卡片；1440px 下正文有效行宽以约 42–50 个中文字符为基准，剩余空间用于呼吸和文本锚定层。
- 右详情关闭时正文获得空间；打开时不让正文小于可读下限。双栏只作为检查器头部布局动作，不占一个永久 rail 图标。

### 4.2 1024px

- 左栏收至约 200–220px；正文保持可读宽度；工具 rail 仍固定。
- 右详情采用覆盖式阅读台，贴 rail 左侧出现，不重排正文、不清空 selection、不改变 scrollTop。
- 当前场简报仍留左下；若高度不足，只让章节列表内部滚动，不把当前场推走。

### 4.3 390px

- 正文是唯一默认面；章节树、当前场和右详情都是互斥 sheet。
- 顶部工具保持单行横向访问；仅 200% zoom 的极窄有效视口允许可访问换行。
- 工具 rail 固定底部；打开 sheet 不重建编辑器、不丢 caret。
- 不把桌面三栏按比例缩小，不让章节列表和正文同时纵向串联。

## 5. 统一视觉与排版基线

### 5.1 顶栏

- 两层最多：AppShell 页签层 + 紧贴其下的 Authoring 工具层；中间不插空白带或重复书名卡。
- 工具按作者频率分组：`撤销/重做`、`粗体/斜体/分隔线`、`排版/取名`、`打字机/聚焦/专注`、`查找`、`更多`。
- 素材收件箱、完整素材库、导出、回到冒险进入“更多”或独立 workspace tab，不长期挤压写作工具。
- 保存状态只在状态变化后短暂显示“已保存”或失败；稳定保存态不永久占位。

### 5.2 稿面

- 标题位于稿面内部，距工具栏视觉间隔约 36–52px；不使用原生输入框边框。
- 正文章节标题为 `第一章　章名`；探索文档只显示文档名，不伪装章号。
- 正文默认物理字号目标约 17–18px，行高约 1.8–1.95；具体值以 Windows 中文实图确认，不用 CSS 数字自行宣布好看。
- 普通正文首行两字缩进；标题、列表、引文、空段、分隔线不缩进。
- 中文 `“”「」『』`、标点避头尾、选区和 IME 必须在真实字体下检查。
- 底栏与中央背景同色，默认只留字数/字符/修订；“已保存”仅短暂出现，不永久写“已签”。

### 5.3 writingUnit

- 一个 writingUnit 表示可被移动、批注、推演、回溯和引用的完整写作片段，可包含一至数个自然段。
- 常态无卡片、无整块底色、无持续边框；段落之间由排版节奏表达。
- hover 只在页边出现轻刻度；当前 unit 只用低强度页边信号；拖动/拆分时才显完整边界和落点。
- 新生成多段正文默认组成一个 writingUnit，不按自然段自动拆成多个块。

### 5.4 同屏强调预算

同一时刻只允许一个主强调：

1. Ghost 或长推演草稿；
2. 当前选区/批注；
3. 当前 writingUnit；
4. 世界书词汇匹配。

顺序靠前者出现时，后面的强调必须降低。不得让蓝底当前行、蓝色 unit rail、蓝色 Ghost、黄色设定词和批注选区同时争夺正文。

## 6. 代表性真实 fixture 与证据规则

所有切片复用同一组本地虚构数据，不用空页面判断成品：

- 书：《雾港纪事》；
- 5 个正文章节，当前第五章约 3500–5000 中文字；
- 3 个探索文档：未编排速记、莉娜视角、艾德加视角；
- 世界书人物：莉娜、艾德加；地点：旧港税务所；规则：星图回应；
- 当前 caret 位于第五章中段一个含 3 个自然段的 writingUnit；
- 当前场初始有人物莉娜、地点税务所、一个未决事件；
- 至少 2 条批注、1 个大纲节点、3 个章节快照；
- 提供 short Ghost、long draft、provider error、stale 五种可控状态。

成功截图预算：

- 每个切片最多保留 3 张评审图：1440 主状态、1024 关键重排、390 关键 sheet；
- 只有涉及文本锚点的切片额外允许 1 张局部放大图；
- 每张优先裁到必要区域，单图建议不超过 1.5MB；
- 用户确认后清理失败图和过期图；过程截图不入 Git；
- 自动几何报告与截图分开，截图只判断层级、密度、排版和协调性。

这里的“最多保留”不是限制校对次数。实现期间可以反复截图、比较和修正，直到功能通过；每轮只保留基线图、当前最新版和必要失败证据，上一轮已被替代的截图立即清理。

### 6.1 每个功能都必须走完的验收合同

任何按钮、菜单、面板、编辑动作或自动状态，都必须逐一完成下面四层，不能因为所属大切片整体可用就跳过：

| 层 | 必须回答的问题 | 最低证据 |
| --- | --- | --- |
| UI | 入口在哪里；默认、hover、focus、active、disabled 如何区分；与相邻组件是否同一基线、密度和视觉语言 | 当前功能的真实页面截图，含入口和展开结果 |
| 完整性 | empty/loading/ready/error/stale/success 是否齐全；主动作、取消、返回、撤销/恢复、持久化是否形成闭环 | 状态清单 + 一条真实作者任务 |
| 鲁棒性 | 长文本、快速连点、切书/切章、请求迟到、保存失败、重复打开、Escape、IME、zoom、窄屏是否安全 | 边界操作结果 + 必要失败截图/计数 |
| 协调性 | 打开和关闭是否改变正文宽度、scrollTop、caret、selection；是否与 Ghost、批注、当前场或其他 sheet 争 owner | 前后几何记录 + 校对后的代表截图 |

单功能状态使用以下进度，不允许从“已实现”直接跳到“完成”：

```text
未开始
→ 真实页面原型
→ 主路径可操作
→ 完整状态补齐
→ UI 第一次校对
→ 鲁棒性边界通过
→ UI 第二次校对
→ 用户截图确认
→ 完成
```

若用户在截图确认后指出问题，该功能退回“UI 第一次校对”或“完整状态补齐”，修正并再次截图；不限校对轮数，不能以已跑过测试为由拒绝视觉返工。

### 6.2 逐功能截图与反复校对闭环

每个功能的实现循环固定为：

1. **基线截图**：使用真实 fixture 截取功能入口、目标内容和周边关系，标出当前问题；
2. **结构原型**：只完成信息编排、位置、尺寸和主动作，截图判断方向；
3. **第一次校对**：逐项检查对齐、留白、字体、颜色、层级、点击热区、正文占比和与左右栏联系；
4. **完整状态补齐**：实现 empty/loading/ready/error/stale/disabled/success 中适用的状态；
5. **鲁棒性校对**：用长内容、慢请求、失败、快速切换、重复操作、缩放和窄屏实际操作；
6. **第二次视觉校对**：边界状态加入后重新看主页面，确认没有为了错误提示或 loading 把成品布局撑坏；
7. **用户截图验收**：提交当前功能的 1440 主图和确有重排价值的 1024/390 图，等待具体反馈；
8. **按反馈返工**：只修当前功能和必要相邻关系，再次截图；重复 3–8 直到确认；
9. **收口**：记录最终状态、删除过期图、再运行所属切片的一次 focused Gate。

截图校对不是“看起来差不多”。每轮必须逐项对照：

- 主内容是否仍是第一视觉焦点；
- 顶栏、正文、左右栏基线是否连续；
- 是否出现廉价卡片、重复标题、无意义状态胶囊或大面积底色；
- 中文标题、正文、说明、数字和图标是否各用正确字体角色；
- hover/focus/selected 是否能区分但不过度强调；
- loading/error/empty 是否改变稳定布局；
- 打开、关闭、切换后正文宽度、scrollTop、caret 和 selection 是否保持；
- 1440、1024、390 和 200% zoom 是否是重新编排，而非机械缩放；
- 截图中是否还有本轮未处理但已被改动波及的区域；
- 与上一轮截图比较，问题是被真正解决，还是被新覆盖规则暂时遮住。

### Slice V4：长推演成为正文中的“临时写作层”

#### 领域语义

当前场修改必须先区分：

| 意图 | 作用 | 是否立即改变当前现场 |
| --- | --- | --- |
| 纠正当前 | 修复当前落笔处已经成立但漏检/错检的事实 | 是，写 author anchor |
| 安排下一段 | 约束接下来的推演和大纲 intent | 否，采纳后才兑现 |
| 仅作用选段 | 只给本次改写/推演参考 | 否，run-only |

#### 工作

1. 左侧点击“人物”在右侧打开现场人物详情，不跳去完整设定页。
2. 详情顶部先显示已在场人物和角色；“添加人物”打开绑定世界书的角色选择，不复制世界书编辑表单。
3. 选择人物后要求明确“纠正当前 / 安排下一段 / 仅作用本次”；默认推荐“安排下一段”，但不静默替作者决定事实。
4. 人物详情可展开世界书摘要和当前文本证据；编辑完整设定时打开对应世界书 workspace tab。
5. 设定词匹配范围以 caret 之前的当前段 + 前几个相关 writingUnit 为主；不扫描后文，不以“调用远近”等技术术语直接展示。
6. 匹配到的莉娜、艾德加、税务所只在正文中轻下划线/页边信号；点击词汇打开右侧对应详情，常态不铺彩色底。
7. “以此推演”把人物、作用范围和作者指令传给 V4 composer；作者仍可修改生成稿。
8. 丢弃时当前场和大纲零变化；采纳时正文 + 明确选择的 scene delta + outline fulfillment 使用既有原子事务。
9. 采纳后左侧当前场简报更新人物/事件，右详情保留来源回执；保存失败保留可重试草稿，不重新调用模型。

#### Gate

- 完整完成“左侧人物 → 世界书选择 → 下一段入场 → 推演 → 编辑 → 采用 → 当前场更新”；
- 纠正当前和安排未来不会混淆；切回前文不读取后文 anchor；
- 世界书条目只有一个详情 owner，不在当前场复制维护页面；
- SW-01 至 SW-07 逐项完成 UI、完整性、鲁棒性和用户截图验收；
- 一张 1440 全链截图 + 一张正文词汇局部图 + 一张 390 人物 sheet。

### Slice V6：右侧工具逐个收口

右 rail 首轮只保留六个真实内容入口：

```text
批注 / 大纲 / 设定 / 现场 / 历史 / 上下文
```

- `角色` 合并进现场人物；
- `素材` 移入“更多”或独立素材 workspace tab；
- `双栏` 移到 inspector 头部，只有支持双栏的面板可见；
- 不删除底层数据和完整页面，只调整文本工作台默认入口。

每个工具是一个独立子切片，完成前不同时重画另一个面板。

#### V6.1 批注

- 右栏壳固定，只有批注条目按正文 anchor 重新定位；滚动时外壳不移动。
- 无批注时只给一句空态；选区后 composer 出现在对应边注位置。
- 条目采用开放边注排版，编辑、按批注改写、删除靠近条目；不把每条变成完整卡片。
- 批注详情、改写候选和 diff 使用同一 Review Tray 语言；关闭后焦点回到原选区。

#### V6.2 大纲

- 默认展示当前章节邻域和项目层级，不把全部节点平铺成条目墙。
- 列表负责选择和编排，详情负责意图、关联探索、章节映射和状态；双栏模式才并列。
- 草稿探索可挂到未归章节点；正文映射显示 `第一章　章名`。
- 调整大纲不直接改正文；已采用/待采用/搁置使用短状态线，不使用大面积卡片。

#### V6.3 设定

- 第一层显示当前落笔处真实命中的条目；范围说明使用作者语言，例如“当前段与前 2 个片段”。
- 第二层按人物、地点、规则和其他分组；组内优先显示当前文本命中、当前场引用、作者钉选，再显示其他候选。
- 详情显示摘要、匹配词、证据片段和“用于本次/加入当前场/打开完整设定”；不把所有条目一次铺开。
- 设定词高亮只来自实际 match receipt；没有命中不伪造强调。

#### V6.4 现场

- 复用 V5 的同一 projection，不在右侧重新实现一份当前场。
- 概览按人物、地点、时间、未决事件分区；点击进入单条详情，提供纠正、安排和推演动作。
- 机器检测与作者确认分层；机器结果不能伪装成已成立事实。

#### V6.5 历史

- 默认只显示当前修订、未保存恢复稿、最近三份章节快照和最近相关片段历史。
- 创建快照、恢复、删除保持明确；恢复前说明影响范围并自动保留当前状态。
- 长列表内部滚动，不改变正文位置；探索与正文章节作用域明确。

#### V6.6 上下文

- 不做 Agent 聊天壳，只显示本次生成真实使用和排除的来源。
- 第一层用作者语言概括：当前正文、当前场、世界书、已采用探索、相关前文章节。
- 章节参与上下文必须可见：当前章自动；相关前章可包含；未来章节默认排除；作者钉选未来内容只作为“计划参考”，不能伪装已发生。
- 第二层才展示具体来源、字符预算、截断/排除理由和 receipt；技术字段放折叠详情。
- 没有真实 compiled manifest/receipt 时显示“本次尚未生成”，不根据页面状态猜 ledger。

#### V6 Gate

- 每个入口都有 empty/loading/error/success 和一个真实主动作；
- 切书、切章、切探索后不显示旧作用域；
- rail 图标数量和分组稳定，所有 tooltip/name 与详情标题一致；
- RT-01 至 RT-09 与相应 AI/SW 功能逐项走完基线、两轮校对、边界状态和用户确认；
- 每个子切片只保留最多 2 张最终成功截图，但允许反复截图返工；用户逐个确认密度、层级和完善性；
- 六个子切片完成后才跑一次右栏 focused Gate，不逐面板跑全量。

### Slice V7：固定侧栏、响应式与缩放

**作者任务：** 在 5000 字章节中滚动、打开各工具、缩放、切换宽度，再回到原 caret。

#### 固定/跟随矩阵

| 对象 | 正文滚动时 | resize/zoom 时 | 窄屏 |
| --- | --- | --- | --- |
| 左导航壳 | 固定；内部独立滚动 | 保持列宽策略 | chapter sheet |
| 当前场简报 | 固定左下 | 高度不足时压缩摘要 | scene sheet |
| 右工具 rail | 固定 | 始终贴边 | bottom rail |
| 大纲/设定/现场/历史/上下文 | 外壳固定，内部滚动 | overlay/停靠重算一次 | mutually exclusive sheet |
| 批注条目 | 右栏壳固定，条目随 anchor 重排 | 合法则重排，否则收起 | sheet 内顺序列表 + 回到原文 |
| Ghost/命令/选区条/长推演 | 跟随文本 anchor 或关闭 | 重新定位或关闭 | 正文内/底部受控层 |

#### 工作

1. 将 `.wall__dossier-scroll` 固定为桌面正文唯一纵向滚动 owner。
2. 页面壳结构继续由 `Authoring.block-native.css` 负责；≤720/980/1180 断点只在此处定义一次。
3. 子组件不再通过父页面的旧 scoped selector 偶然获得 `display`、尺寸或定位。
4. 统一 visualViewport、CSS zoom、caret rect 和 overlay bounds；滚动时无法合法重排的临时层直接关闭并恢复焦点。
5. 1024 inspector 覆盖正文但不改 grid；390 章节、现场、工具详情互斥，底部 rail 不遮正文最后一行。
6. 200% zoom 保持所有核心动作可达；允许极窄有效视口重排，但不能在宽屏物理截图中误退化为普通文档流。

#### Gate

- 1440/1024/390 × normal/200% zoom 无整页结构崩塌；
- 左右工具不随正文移动；文本锚定层位置正确；
- 无横向页面滚动、正文双滚动、rail 遮挡和 sheet 焦点泄漏；
- RS-01 至 RS-08 必须逐项验收，不能只用三张静态截图代表全部响应式与竞态；
- 代表截图外再输出几何报告，不用肉眼猜 fixed/anchor 是否正确。

#### 最终验收故事

作者从 AppShell 中打开《雾港纪事》，直接进入第五章。顶部只有紧凑的写作工具，左侧能快速在构思和正文之间切换，中央是一张连续、安静、排版正确的中文稿面。作者回看前文时没有联想闪烁；停在某句数秒后出现轻量 Ghost，可逐段采纳。作者在当前 writingUnit 下打开“推演”，先修改生成的多段草稿。

发现现场漏了艾德加后，作者从左侧当前场人物进入右详情，从世界书选择艾德加并安排下一段入场，以此重新推演。丢弃不改变事实；采用编辑稿后，新 writingUnit、入场变化和大纲兑现一次保存。批注、大纲、设定、现场、历史和上下文都从同一右 rail 进入，左右栏不随正文滚动，只有真实锚定内容跟随文字。

- 用户逐切片确认 V1、V2、V4、V5 和 V6 代表截图；
- Windows 原生中文输入法 30 分钟耐久：输入、回看、上下移动、Space、`/`、Ghost、批注、推演；
- 真实 provider 只跑短 Ghost 与长推演 canary，空返回单列 provider failure；

## 8. 实施与验证节奏

| 阶段 | 允许动作 | 验证 |
| --- | --- | --- |
| 计划/设计 | 只读代码、真实截图、状态表、硬约束 | 不跑测试 |
| 一个切片实现中 | 连续完成数据选择、交互、主要布局和失败状态 | 静态检查与人工浏览，不因小改反复启动测试 |
| 切片 Gate | 当前作者任务形成闭环 | 一次 focused test + 最多 3 张代表图 |
| 用户视觉确认 | 根据截图只调当前区域 | 按功能反复校对直至确认；只保留基线与最新版 |
| 2–3 个切片阶段组 | 清理相邻回归 | 一次组合 journey，不跑全量 |
| V8 最终交付 | 文档与代码收口 | 一次 `verify:full` |

实现过程中，如果测试提前暴露编译失败、schema 无法加载或页面白屏，可以立即跑阻断检查；除此之外不把测试频率当质量指标。

## 9. 文件所有权与修改边界

### 页面级 owner

- `Authoring.block-native.css`：Authoring 页面高度、顶栏、主 grid、列宽、背景、断点、固定/overlay/sheet 结构；
- `Authoring.vue`：页面编排、领域状态接线、跨组件事务；不继续承载新组件内部视觉细节；
- `Writing.global.css`：只保留 Notebook/ProseMirror 真正跨组件共享的排版和文本标记；
- `Writing.scoped.css`：现有旧规则按切片迁出或删除，不再作为 Authoring 结构安全前提。

### 组件级 owner

- `WritingNotebookEditor.vue`：正文 surface、writingUnit、caret/selection、Ghost、命令菜单；
- `AuthoringBlockComposer.vue` / `AuthoringBlockDraft.vue`：长推演输入、生成、review 和动作；
- `AuthoringSceneRail.vue` / `AuthoringInspectorDetail.vue` / `AuthoringSceneCuration.vue`：当前场简报、详情和编辑；
- `AuthoringOutlinePanel.vue`：大纲列表/详情；
- `AuthoringWorldbookPanel.vue` / setting components：当前落笔处匹配和设定详情；
- 批注、历史和上下文若继续留在 `Authoring.vue`，先稳定视觉职责；只有职责确认后再抽取，避免边做设计边搬状态。

任何切片不得让两个实现者同时修改 `Authoring.vue`、Notebook 或核心 Authoring CSS。视觉方向需要连续判断，默认由一个 owner 完成当前区域。

## 10. 暂停条件

1. V1 中央稿面截图未获用户确认，不进入左右栏；
2. V2 左导航/当前场层级未确认，不实现完整现场闭环；
3. writingUnit 可见语法未稳定，不继续增加块级动作；
4. V4 长推演仍像卡片或造成段距跳变，不接世界书/现场；
5. V5 未区分纠正当前与安排未来，不允许 scene delta 自动写入；
6. 某右栏工具没有真实 owner/状态/主动作，先隐藏，不用占位补齐；
7. 真实页面和自动 fixture 表现不同，先查运行 branch、数据和 CSS 产物，不用更多覆盖规则掩盖；
8. 用户指出当前切片方向错误时，只回退或调整该切片，不借机重做未确认区域。

## 11. 完成定义

本计划完成不是“页面看起来比以前整齐”，而是以下事实同时成立：

- 作者打开书后第一眼看到可持续写作的中文稿面；
- 构思、正文和当前场在左侧形成紧凑、连续、可理解的关系；
- writingUnit 真正承载一段或数段完整文字，但不把正文切成卡片墙；
- 短 Ghost、空行命令、长推演和批注互不抢输入，且在正文中位置自然；
- 当前场可以从世界书添加人物/地点，并真实驱动可编辑推演和采纳事务；
- 六个右侧工具逐个具备真实内容和统一视觉层级，外围素材不干扰核心；
- 左右栏固定，文本锚定层跟随，1440/1024/390 与常用缩放都不崩；
- 每一个完成结论都有对应真实页面、作者任务、截图和操作结果，而不是只有测试或代码说明。
