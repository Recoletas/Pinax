## 0. 执行结论

F2 不再独立设计一套“看起来像 AI 写作软件”的工具栏、双栏、便签、资料 AI 或生图入口。凡阅文作家助手已经稳定验证的文本编辑器能力，Pinax 直接对齐其功能入口、任务顺序、默认层级、关键状态和移动端降级；底层继续复用 Pinax 已有 repository、上下文 manifest、revision/stale 门禁、Ghost 草稿和媒体资产链。

“完全复刻”在本计划中的准确含义是：

- 同类任务放在相同层级：写作动作在顶栏，章节/大纲/角色/设定/便签可快速切换，资料问答在助手，图片生成在画师；
- 同类动作采用相同短路径：正文中打开多窗即可边看大纲或另一章边写，不再借用检查器内部布局冒充双栏；
- 同类默认态保持克制：编辑器不常驻展示上下文统计、内部 profile、候选 ID 或 token 信息；
- 同类结果可核查：问全书回答展示原文片段和来源，点击可跳回章节或设定；
- 同类移动端能力不缩水：多窗转悬浮窗或 sheet，快捷词贴近输入区，章节/大纲/角色/设定/便签保持快速切换；
- 不复制阅文商标、吉祥物、宣传插画、字体、品牌皮肤或像素级视觉资产；界面继续使用 Pinax 的蓝白档案主题、现有图标和设计 token。

F2 的目标不是增加更多工具，而是把已经存在但位置错误、入口缺失或交互不完整的能力收束为成熟编辑器工作流：

```text
速记准备资料
  → 正文写作 / 多窗对照
  → 快捷词、校对和实体高亮就近工作
  → 资料助手查全书、设定、伏笔、线索、角色和数值
  → 画师读取当前选区/场景并生成候选
  → 结果只有显式采用才进入正文、设定或素材
```

## 1. 调研基线

### 1.1 采用的主参考

本计划只把官方或第一方公开信息作为作家助手能力基线：

1. [阅文集团 NovelBuddy 作家助手产品页](https://www.yuewen.com/app/?type=appzj)：明确列出大纲设定、全文检索、精准纠错、妙笔辅助查资料、语音优化、快捷词、历史版本与多端创作。
2. [Apple App Store 作家助手](https://apps.apple.com/cn/app/%E4%BD%9C%E5%AE%B6%E5%8A%A9%E6%89%8B/id1044537226)：5.0 产品说明明确列出悬浮多窗、灵感便签、全文搜索、纠错、快捷词、界面和工具栏定制；妙笔辅助明确覆盖查设定、找伏笔、算数值、理线索、挖角色。
3. App Store 5.12.0 更新记录：正文提及角色/设定高亮；章节、大纲、角色、设定、便签快捷切换；“妙笔通鉴·问全书”回答增加原文片段。
4. App Store 5.23.0 更新记录（2026-08-26）：历史版本增加按字数间隔保存，作品大纲增加总纲与章纲字数。
5. Apple 官方 Lookup 元数据与商店移动端截图：确认当前版本为 5.23.0；移动端“多窗写作”可从正文顶部悬浮大纲/上一章；“智能快捷词”包含导入角色、导入设定、智能提取，并在输入区附近提供词条与中文标点。
6. 用户提供的作家助手桌面端实机截图（2026-09-01）：`双栏`位于最右侧竖向工具栏；打开后在工具栏左侧出现第二章节工作区，工作区由可编辑正文和独立章节搜索/目录组成。桌面端没有顶栏“多窗”入口。

以下资料只用于交互交叉验证，不覆盖作家助手作为主参考：

- [Scrivener 官方手册的 Split Editor](https://www.literatureandlatte.com/docs/Scrivener_Manual-Mac.pdf)：双编辑器用于同时查看同文档不同位置、两个文档或参考资料，支持从文档树直接在另一栏打开。
- [NotebookLM 官方资料问答](https://support.google.com/notebooklm/answer/16164461)：基于资料回答并展示可核查引用；只用于补足作家助手未公开的桌面来源呈现细节。

### 1.2 从官方截图冻结的交互事实

F2 不依赖宣传文案猜测布局，冻结以下可见事实：

- 桌面端 `双栏` 是最右侧竖向工具栏的一级功能；打开后第二章节工作区出现在 rail 左侧，并带独立章节搜索/目录；
- 移动端多窗才使用悬浮内容，具有自己的标题、关闭动作和正文/大纲内容，不替换主编辑器；
- 快捷词贴近输入区域，候选是短词条，不使用卡片墙；
- 快捷词来源至少分为角色、设定和智能提取三种；
- 章节、大纲、角色、设定、便签属于同一快速切换体系；
- 问全书的回答必须能展开原文片段，而不是只给模型结论；
- 自动保存、同步状态、撤销、重做、校对/纠错和发布类动作位于编辑器顶层；Pinax 不复制发布，只保留编辑相关动作。

### 1.2.1 2026-09-03 角色 / 大纲实机截图补充合同

用户提供的桌面端角色与大纲截图优先于此前抽象描述，冻结以下可见约束：

- 角色与大纲都不是 300px 单列检查器，而是 rail 左侧的双栏资料工作台：宽内容/详情区在左，窄搜索目录区在右，两区之间只有一条细分隔线；
- 目录区顶部保持相同操作顺序：搜索框 → “新建 / 提取”双动作 → 目录标题与筛选 → 分组文件夹 → 当前选中行；选中态为低饱和蓝底，不使用卡片墙；
- 角色详情顶部显示人物名与轻量上下文，正文区使用“角色 / 提及章节”页签；角色页依次呈现生图/上传入口、背景、性格、外貌、其他四段连续编辑面，底部显示字数；
- 大纲详情顶部显示节点标题、文本模式和历史入口；正文是连续长文编辑面，底部显示字数。目录明确分为“总纲 / 章纲”，项目节点与当前章节点保持原有来源和关系语义；
- 桌面宽屏最终按用户视觉复验统一为 420～440 CSS px，编辑内容区约占 62%，目录区约占 38%；不能把正文主稿压缩到不可读。1180px 以下改为覆盖层，720px 以下使用单栏 drill-down / bottom sheet；
- “新建、提取、编辑、删除、生图/上传、打开提及章节”必须连接 Pinax 现有 worldbook、章纲、画师、章节定位与媒体 owner，截图未展示的云发布、阅文账号和品牌资产不复刻。

首轮实现回执（尺寸已由下方第二轮纠正取代）：角色与大纲共用 661px 级双栏工作台（真实页面约 409px 内容区 + 252px 目录区），1180px 以下覆盖、390px 使用 42/58 受控上下分区。角色 CRUD 写入绑定世界书，图片上传随角色资料显式保存，生图复用 Authoring 画师；大纲保留章纲 CRUD/排序/插入、项目显式关系、冲突与失效引用保护。亮色/暗色的 1440/390 页面矩阵各 18/18，通过且无横向溢出和控制台错误；截图保存在 `/tmp/pinax-f2-catalog-workbench/`。

首轮用户验收纠正（2026-09-03 09:17）：

- rail 中除画师等独立全屏层外，各资料工具必须使用同一工作面宽度，不能让助手/设定/现场是窄栏、角色/大纲单独变宽；
- 角色资料是随时可编辑的连续稿面，不出现“编辑 / 保存 / 取消”模式，也不在空字段中放教学型 placeholder；修改按现有本地持久化边界自动保存；
- 点击角色生图时，姓名、背景、性格、外貌、其他必须完整进入画师初始画面描述，不能只打开一个仍依赖正文光标的空白画师；
- 修复历史 tab 状态越权：历史内容只能在历史工具或批注的版本页出现，切到角色/大纲/设定/现场后不得继续覆盖当前工具内容。

首轮纠正回执（“全部 662px”已由下方第二轮纠正取代）：角色、大纲、助手、现场、设定、历史曾统一到 662px；角色四段字段始终可编辑，静默防抖保存按角色串行落盘，切换工具时会刷新未到期保存。角色生图初始描述完整包含姓名/背景/性格/外貌/其他，已上传角色图同时进入画师并默认选中。

第二轮用户验收纠正（2026-09-03）：上一回执把“角色与大纲同宽”错误扩大到了所有 rail 工具。重新用运行中的作家助手 5.15.0 窗口级抓取和用户双栏截图复核后，冻结为三类尺寸，而不是一种尺寸：

- 批注、设定、现场、助手、历史属于普通检查器，恢复约 280～320px，不得占用资料工作台宽度；
- 角色、大纲、设定和双栏都使用与其余右侧工具相同的外层宽度。按用户提供的作家助手截图及其显示缩放换算，桌面检查器为约 420～440 CSS px（最右 rail 另计），不能把截图物理像素直接当成 CSS px；
- 带详情/目录的工作面内部保持约 62/38；1440px 下目标约为 `内容 272px + 目录 168px`。1180px 以下使用同宽覆盖面，不得自行膨胀；
- 目录中的文件夹标题是操作控件，必须支持点击展开/收起并暴露 `aria-expanded`，不能只画文件夹图标；
- 同级文字必须共用排版标尺：详情标题 17px、页签/主动作 14px、目录标题 14px、文件夹与文件名 13px、摘要/数量 10px、字段标签 12px、正文 14px；角色、设定、大纲和双栏不得各自继承出不同字号；
- 设定目录有内容时，顶部使用与作家助手一致的“搜索框 + 单独加号”单行入口；不再在下方重复放“新建”，也不放跨工具的“角色”按钮。角色切换只归最右工具 rail 所有；
- 作家助手截图确认大纲、角色、设定存在“新窗口打开”能力，但 Pinax 当前 Electron 明确拒绝所有 `window.open`，且 localStorage 编辑 owner 尚无跨窗口同步。不得只增加失效图标；必须先建立同源窗口白名单、稳定详情路由和跨窗口 revision/冲突处理，再接入真实入口；
- 作家助手双栏目录默认只有搜索、卷组和章节行。Pinax 已支持的大纲、角色、设定、便签来源不删除，但不得继续横塞成五个等宽页签；收进单一紧凑来源选择控件。

第二轮 600～620px 实现回执已被用户视觉复验否决：它误把参考截图的显示像素当成 CSS px，并造成正文被过度挤压。后续验收以统一 420～440 CSS px、内部约 62/38 和目录文件夹可折叠为准；旧截图只保留为问题证据，不再作为通过基线。

第三轮角色详情截图纠正（2026-09-03 10:06）：

- 背景、性格、外貌、其他属于同一连续文档流。每段输入区只保留较小空态高度，文字换行增加时按真实内容高度向下增长，并把后续字段整体下推；不得固定三行高度、在字段内部滚动或暴露浏览器右下角 resize 把手。
- 图片入口默认只显示一个居中的“生图/上传”动作面；鼠标进入或键盘聚焦时，原位展开为“生成角色图 / 上传角色图”两个动作。上传动作提示仅说明 `jpg/jpeg/png` 与单张 5MB 限制，不常驻占用详情空间。

第三轮实现回执：四段 textarea 已移除固定 `rows`、浏览器 resize 和内部滚动，初次载入、切换人物与每次输入都会按真实内容重算高度。隔离页面中九行背景由 54px 增至 227px，后续“性格”同步下移 173px。“生图/上传”默认保持单一合并态，hover/focus 后原位展开蓝色生成动作与次级上传动作；上传提示脱离滚动裁剪边界显示，文件校验同步限制 JPG/JPEG/PNG 和 5MB。亮/暗 1440/390 Gate 各 32/32，均无横向溢出或 console error。

第四轮角色卡与世界书合同纠正（2026-09-03）：

- Authoring 角色面板不是第二份角色数据库；每张卡必须直接对应绑定世界书中一个 `type=character` 的 entry。姓名就是卡/文件名，背景、性格、外貌、其他既保留分字段编辑，也序列化进该 entry 的正式 content，确保世界书高级页、检索和生成读取同一内容。
- 结构化设定中的“主角 / 重要配角 / NPC”只表示生成来源或标签，不能成为世界书角色条目的名称。合法角色卡必须按解析到的姓名逐人 materialize；旧聚合条目在归一化时迁移，姓名缺失则不伪造“主角/配角”文件。
- 角色目录按世界书 entry 的真实 `injection.group` 形成文件夹，未分组人物归入“角色”；文件夹下每一行只显示角色姓名。当前场身份可作为排序/状态依据，但不得改写真实目录分组。
- 自动保存更新绑定世界书的同一 entry，重新载入仍保留修改；删除结构化派生卡必须留下有界 tombstone，不能在下一次归一化时复活。结构化角色字段再次显式保存时才清理对应来源的 tombstone 并重新 materialize。
- 点击或 Tab 进入背景、性格、外貌、其他时保持详情滚动位置。textarea ref 重绑、自动保存回投和高度重算都不得先折叠内容再触发 scroll anchoring；切换到另一张卡才允许回到卡片顶部。

第四轮实现回执：角色目录已改为世界书 group 文件夹 + 人物姓名条目；结构化角色字段按解析姓名逐卡 materialize，旧聚合条目迁移并为显式删除保留 tombstone。四段资料序列化到同一世界书 entry 的正式 content，高级页直接修改 content 时同步重建 Authoring profile；角色面板可直达当前 entry。输入元素只在真实 DOM 节点变化时重新登记，保存回投按同一 entry 恢复 scrollTop。亮/暗 1440/390 实页门禁各 37/37，聚焦与自动保存滚动实测 478→478，角色入口选中高级世界书同名条目；`verify:full` 为 20/20 文件、200/200 用例、Vite/VitePress build 和 diff check 全绿。最终视觉仍等待用户确认。

第五轮角色 / 设定能力迁移合同（2026-09-03）：

- Authoring 右侧“角色”和“设定”接管原结构化设定页与高级世界书中的日常编辑、AI 补全和草稿审阅能力；原页面逐步收缩为首次创建、批量导入导出、分组和高级维护，不再作为日常写作必经跳转。
- 作家助手实机界面继续作为角色/设定的布局与交互基线，Pinax 的 AI 补全只能作为当前编辑对象上的次级动作与可审候选加入，不能把原设定页的大卡片工作台原样塞进右栏。
- 所有 rail 工具打开后的外层工作面尺寸统一；不同工具只改变内部信息架构，不得再用“普通窄栏 / 资料宽栏”的主观分类改变正文占用宽度。画师仍是独立覆盖工作台，不受 rail 尺寸约束。
- 角色工具以一人一条 `worldbook.entries[type=character]` 为唯一日常真源。AI 针对当前人物生成结构化候选并经用户采纳后更新同一 entry；“主角 / 配角 / NPC”聚合文本与 `parseCharacterCards` 只保留为旧数据导入兼容，不参与日常创建、编辑或 AI 补全。
- 设定工具默认保留“当前落笔处”索引；同一工作面可切到完整目录和正式条目编辑，并复用原设定生成 workflow、草稿 revision/stale 门禁与世界书 CRUD。角色条目从完整设定目录打开时转交角色工具，不在设定里维护第二份人物表单。
- 现场不参与本轮迁移。它继续只持有当前 writingUnit 的 sceneAnchor 与人物/地点 entry ID，绝不解析角色文本或创建角色卡。
- 上下文继续通过现有 Project Knowledge Facade、唯一 manifest、revision/stale 与 receipt 架构进入助手和写作任务；迁移只改变入口和编辑 owner，不新增上下文 store。

### 1.3 不纳入本轮的作家平台能力

以下也是作家助手能力，但不属于 Pinax Authoring 编辑器对齐：

- 阅文站点发布、定时发布、预审和风险发布流程；
- 订阅、追读、收藏、打赏、稿酬与读者画像；
- 作家社区、拼字星球、征文和消息中心；
- 阅文账号、作品签约和云端平台同步。

Pinax 已有的本地保存、桌面项目、联机和导出仍按各自计划推进，不为“功能完全复刻”伪造平台能力。

## 2. F2 的十条硬约束

1. **成熟能力不重命名成内部术语。** 作者只看到“构思、正文、当前场、双栏、快捷词、校对、画师、助手、历史”，不看到 manifest、receipt、profile、candidate 或 packing。
2. **双栏只表示两个内容窗格。** 它保留在桌面右侧工具 rail；检查器内部的列表/详情响应式布局不得继续占用“双栏”名称。
3. **构思直接显示速记。** 删除“未编排 1”这种 repository 状态标题；未关联章节只是速记属性，不形成永久导航层。
4. **参考在速记处准备。** 推演器和当前场详情不再挂载完整参考选择器；选择状态汇总在构思区的“推演夹”，为空时隐藏。
5. **助手默认有资料依据。** 默认读取当前项目允许的正文、设定、大纲、当前场、速记和记忆；自由讨论是显式次级模式。
6. **回答必须带可定位原文。** 查全书、设定、伏笔、线索、角色和数值不得只返回自然语言结论。
7. **画师是顶栏一级入口。** 不藏进素材页深处，不塞入 300px 检查器；复用现有生图 workbench 和媒体资产存储。
8. **正文仍是视觉中心。** 工具栏、悬浮窗、检查器、助手和画师均不能默认压缩正文到不可读宽度，也不能改变 caret、selection 或 scrollTop。
9. **AI 只产出建议或草稿。** 助手回答、校对建议、画师候选和智能提取都不能自动写正文、世界书、大纲、当前场、素材或记忆。
10. **不继续膨胀 Authoring.vue。** 页面只做路由、选择状态和组件编排；多窗、构思架、资料助手、画师抽屉分别拥有薄 controller/composable。

- 章节、速记：独立可编辑文档窗；
- 大纲、角色、设定：资料窗，按其原有编辑权限呈现，不能把资料查看能力冒充第二个正文编辑器。

5. 左侧主章节、速记和大纲节点菜单增加 `在双栏打开`，效果等同先选中 rail `双栏` 再在副章目录定位。

### 回答合同

```text
AuthoringKnowledgeAnswer
  answer
  claims[]
    text

  evidence[]
    sourceRef
    label
    excerpt
    revision
    locator
  missingInformation[]
  calculations[]
```

## 11. F2-6：校对、全文搜索与自动历史

### 11.1 校对

顶栏 `校对` 是一次只读扫描任务，不打开聊天：

- 拼写/错别字；
- 标点和异常引号；
- 重复词、病句和明显语病；
- 人物/设定称谓不一致；
- 时间、数值和当前场冲突；
- 发布风险不在本阶段复制，避免冒充阅文审核规则。

结果按正文顺序显示，支持“跳到、采用、忽略”；批量采用必须形成单一可撤销事务，来源 revision 变化后结果 stale。

### 11.2 全文搜索

- 顶栏 `查找` 从当前编辑器查找升级为统一入口；
- 默认当前章，可切全书、构思、设定；
- 结果显示标题、片段、命中词和位置；
- 点击跳到稳定 unit/node 或条目；
- 替换只对正文开放，跨章全部替换必须预览影响数量并原子失败；
- 世界书和速记第一阶段只搜索、不批量替换。

### 11.3 自动历史

对齐作家助手 5.23 的按字数间隔保存：

- 复用 `writingSnapshots`，不创建第二套版本库；
- 用户可关闭或选择字数间隔；默认值在实现前通过现有长文 fixture 测量，不在计划中伪造作家助手的未公开默认值；
- 仅跨越区间且正文 revision 已持久化后创建一次；
- 删除、整块重写、Ghost 批量采纳前继续创建保护快照；
- 空保存、来回删字和同 revision 不重复创建；
- 历史面显示触发原因：手动、字数里程碑、重写前、采纳前、恢复前。

### Gate

- 校对结果可逐项处理并一次撤销；
- 中文双引号、嵌套引号、段首缩进不被误修；
- 全书搜索能跳到另一章并返回原位置；
- 自动历史只在真实区间跨越后生成一次；
- 恢复版本不会污染多窗副栏或助手旧回答。

## 13. 固定验收旅程

至少完成以下十二条真实页面旅程：

1. 新建速记，不经过“未编排”，将其带入推演夹并完成一次推演。
2. 推演夹为空时，推演器中看不到任何参考统计或空选择器。
3. 在第五章写作时打开上一章副窗，分别修改两章；两边保存、光标、滚动和撤销历史互不串写。
4. 从章节菜单把第三章替换到副窗；未保存的上一章先完成明确保存/保留处理，当前主章不变。
5. 移动端打开大纲悬浮窗，边看大纲边继续输入正文。
6. 点击正文人物高亮，打开其世界书/当前场详情，再准确返回原文。
7. 从角色与设定导入快捷词，使用中文 IME 输入并点击候选插入。
8. 连续生成十批名字，候选不整批重复，选择后只插入光标。
9. 助手询问一个跨章角色问题，回答展示至少两个可定位原文片段。
10. 助手询问不存在的设定，明确报告缺失；自由问提供建议但不伪造来源。
11. 从正文选区打开画师，生成后保存为素材；放弃另一候选，正文零写入。
12. 校对当前章，应用一项、忽略一项并撤销；跨过字数区间后只生成一个自动版本。

另外专门验证：

- 多窗、助手、画师不能同时抢占 selection owner；
- 资料副窗的只读操作不触发 Ghost、observer 或记忆；章节副窗只有在其成为活动窗且正文真实变化时，才触发绑定本章 revision 的保存与观察链；
- 助手回答、画师结果和校对结果在来源修改后均 stale；
- 关闭任何 sheet/抽屉后焦点回到原触发点或正文原选区；
- provider 空返回、超时、失败或取消不丢失速记、推演夹、画师 prompt 和助手问题；
- 保存失败的正文事务不能通过助手或画师重试再次请求模型。
