# 当前产品计划

## 推演等待与流式显示（2026-10-23，本地已启用）

正文增量贯通运行器、Express与原有助手/推演草稿区；规划、写作方法和采用链保留。停止保住完整已收尾字，工具前言不落草稿，空白章整章写作不先报replace失败。真实短段样例26.6秒出字、51.1秒整轮完成，前置规划仍占18.6秒；流式显示不等于模型总耗时消失，不通过缩短作者要求或删除方法假装提速。实际验证及后续边界见LOG。

### 流程优化调研与实施（2026-10-23）

**结论：保留同一套写作能力，把固定的“重新规划→写正文→回助手总结”改成按任务需要执行。** 独立规划不是 Pi 的要求，也不是加载 Skill 的必然代价。此前把保留写作方法等同于每次单独规划，范围过大。润色、已有方向的续写和开放构思应使用不同的方法，但不必再给作者增加一组模式开关。

调研基于 `main` HEAD `b0f1b830` 加当前未提交修复，不能只用该提交复现本地实现。读到的源码行为与真实模型实验分别记录如下；以下保留调研阶段证据；本地实施结果见本节末。

**现有流程的四个具体问题**

1. **明确方向仍被重新规划。** 助手 `generate_narrative_draft` 的非空指令进入 `respond`，随后 `requiresBeatPlanFor` 强制独立规划；局部替换也走这条路径。“按已选方向写”的提示要求不要重新规划，执行器却仍会调用规划模型。候选的 `draftAction: extend` 只是连接草稿，不代表复用先前计划。定位：`assistantNarrativeGeneration.js`、`authoring/narrativeKernelExecutor.js`、`narrativeAgentOrchestrator.js`。
2. **推进情节的计划不适合所有编辑任务。** BeatPlan 要求回应、变化、结束条件和因果推进，而 `line-polish` 要求保留事实。对润色一句对白而言，这两套指导会产生冲突。计划是写作方法的一部分，不能与权限、原文修订等程序校验混为一谈。定位：`shared/narrativeBeatPlanContract.js`、`shared/assistantWritingMethods.js`。
3. **工具结果重复带全文。** 已完成任务的1348字符候选，在工具返回的 `changes[].after`、`proposalChanges[].after`、`text` 中出现三遍，整个 JSON 回包5192字符。减少重复不会自动等于三倍提速，但可以减少助手后续阅读和历史膨胀。定位：`runtime-extensions/assistantTask.js`。
4. **有完整候选仍要等外层结束。** 前端已经提前保存完整候选，但查看和采用还受助手 `busy`、整轮收尾等条件阻挡；普通正文工具完成后，Pi 继续一次模型调用，才能生成最后说明。这个等待不是正文仍在生成。定位：`authoringAgentTurn.js`、`useAuthoringKnowledgeAssistant.js`、`runtime-extensions/assistantSession.js`。

当前作者写作链已关闭自动模型验收及抽样 critic；查阅工具在同一批里也已并行执行。不能把这些当作本轮仍待删除或并行化的耗时步骤。独立规划与正文有依赖，直接同时发出两者也不是合理提速。

**成熟产品与框架的启发**

- [Pi 的 Agent 循环](https://github.com/earendil-works/pi/blob/f07218c4d4bbc12bef056a7058c3dd49dfe41abe/packages/agent/src/agent-loop.ts#L162) 根据模型的文字、工具及结束结果推进，没有强制的独立规划模型。实装版本为 `@earendil-works/pi-agent-core@0.87.1`。它的 Skill 是提供给模型的工作方法；将任务委托给另一个模型时，需要显式传递选定方法，不能假定子调用自动继承。
- [Codex 的 update_plan](https://github.com/openai/codex/blob/de06fd0be4f465bc28c3111bdadaabda5dfdebcd/codex-rs/core/src/tools/handlers/plan.rs#L65) 更新计划状态并返回确认，本身不额外调用模型；这与 Codex 的 Plan 模式是不同概念。可借鉴计划作为可用工具，而不是每次写作必须经过的一站。
- [Sudowrite Write](https://docs.sudowrite.com/using-sudowrite/1ow1qkGqof9rtcyGnrWUBS/write/pvxUvbQqYybfEosqx1sXjY) 与 [Scenes & Draft](https://docs.sudowrite.com/using-sudowrite/1ow1qkGqof9rtcyGnrWUBS/scenes--draft/49p5MTVxTKkVFEC5rVUzpY) 区分接续写作和组织场景后成章；[Novelcrafter](https://www.novelcrafter.com/help/faq/write/scene-beat-vs-continue-writing) 则允许作者提供 Scene Beat，继续写作只是另一种指令入口。这支持复用作者已有方向；公开产品文档不证明它们后台究竟调用了几次模型。
- [NovelAI 的故事设置](https://docs.novelai.net/en/text/editor/storysettings/) 将记忆、作者说明与编辑操作分开。Pinax 也应分别保留背景、风格参考、正式稿与本次操作，避免用统一“推动剧情”的指令覆盖所有任务。

**隔离真实模型对照**

同一模型 MiniMax-M2.7、同一自建学院背景与原文；两边都加载对应写作方法，唯一干预是在独立浏览器上下文里跳过强制 BeatPlan。续写按原流程→跳过规划运行，润色反向运行。没有修改应用源码或用户作品。

| 任务 | 原流程：首字 / 完成 | 跳过独立规划：首字 / 完成 | 观察 |
| --- | --- | --- | --- |
| 按明确事件续写 | 14.1s / 25.9s | 4.8s / 17.5s | 两边都承接分班方向；原流程1164字符，实验流程979字符，各有文风问题 |
| 润色指定对话 | 21.0s / 23.6s | 4.4s / 10.5s | 原流程226字符；实验流程533字符，擅自增加登记规则和人物经历，不符合要求 |

这只证明固定规划存在可省的等待，**不证明全局关闭规划能保持质量**。实验用执行器的显式上下文分支，未走完整 UI 的冻结清单；续写实验的两次查阅返回空结果，随后依据已有上下文写作，不是检索成功样例。每任务只有一组有效对照，输出长度、模型随机性、缓存及服务负载也不同，不能承诺固定提速比例。原流程同样出现多余身世设定、文字瑕疵和润色遗漏，慢不等于质量已合格。详细方法、失败尝试和计时见 LOG。

**建议落实的行为**

| 作者正在做什么 | 默认处理 | 何时需要独立规划 |
| --- | --- | --- |
| 润色或替换一段原文 | 明确编辑目标，带相邻上下文与所选方法直接改；不注入“必须发生新变化” | 作者同时要求改结构、重排情节时，再采用相应方法 |
| 已说明接下来发生什么 | 结合正文、相关设定和写作方法续写，缺资料时正常查阅 | 任务需要先解决多场景组织或作者要求先讨论时 |
| 按已选方案、大纲或已有草稿接写 | 复用方向，并核对对应的文稿与资料版本 | 方向失效、作者改变目标或需要重新组织时 |
| 没有方向的整章创作、复杂情节设计 | 在现有 Agent 循环里先组织必要计划，再执行 | 独立计划对后续创作确有用途时；计划只做一次 |

这里的“直接改/写”是省去独立规划调用，不是取消模型内部思考、方法或查阅工具。正文目标、权限、版本检查、原位审阅和撤销继续走已有流程。字数与段落遵从作者要求，不以压短成品换速度。

实现分五个有边界的改动，不重建 Agent：

1. **把是否规划与 `intent` 分开。** UI 已知操作使用明确默认值；助手在现有工具选择中表达是否需要计划或复用方向，不为分类再加一次模型调用。不要把所有任务改成内部 `extend` 来绕过规划：该分支会替换原指令，而且目前没有完整 BeatPlan 复用。先验证润色任务不会继承推进情节的提示，再接续写。
2. **计划与方法只传一份有效依据。** 作者确认的方向、外层助手形成的计划与内层计划使用已有资源/修订信息；相关内容改变时按实际影响更新。相同目标不让外层解释一遍、内层再推翻重做。作者没有采纳的设想仍是计划或候选，不升格为正式设定。
3. **正文工具去重。** UI 继续保存完整结构化候选；模型可见的工具内容只提供一份正文及必要位置、状态。拆清 UI 交付与模型回包，不再把三个兼容字段一起重复送入历史，也不建立新的正文存储。
4. **完整候选及时可见，完成任务及时收尾。** 完整稿已保存即可原位查看，助手后续说明不能阻止阅读。采用必须针对已完成且依赖明确的一组修改，继续核对原稿版本；尚在修订的同一候选不能被抢先采用。纯写稿任务完成后可使用 Pi 已有结束能力，是否继续由剩余工作与作者补充决定，不能一见正文工具成功就结束多步任务。
5. **上下文复用放在重复读取处。** 已知的本书、当前章、人物和选定方法直接进入写作上下文；查询缓存按作品、资料版本及权限有效期复用。现有同批查阅已经并行，不重复建设。固定提示放稳定前缀、动态输入放后面，并补缓存命中观测；[MiniMax 官方缓存](https://platform.minimax.io/docs/api-reference/text-prompt-caching)支持自动前缀缓存，但当前漏斗没有完整保留缓存用量，尚不能把缓存当成已测得的收益。

以“明确方向续写、局部润色、按已选方案写、开放整章”作为回归任务。记录首字、完整候选可查看/可采用时间、整轮结束、模型调用与失败重试，同时看背景一致性、润色忠实度、已有情节是否重演，以及采用/撤销是否一致。真实全链路结果与启用范围分别记录；不增加检查模型、自动反复改稿或新的时长/轮数门槛。

**本地实施结果**：已接入独立 planning 选择，明确任务直接写、选定方向复用、复杂任务可规划；改写明确编辑身份和完整原文，助手无选定方法时补对应默认方法。正文工具回包保留一份 proposalChanges；完整候选可在运行中查看，采用按钮在仍处理修改时不可用。纯写稿通过 finishTask 与 Pi 原生工具结束能力交付，有其他工作或补充消息时继续循环。既有版本、权限、采用与撤销保留。独立跨任务查询缓存及缓存收益测量尚未实施，本轮不新增缓存真源。组合检查、真实样例与服务启用见 LOG；真实单例不代表稳定文笔保证。

**已本地实施**：页面计划收掉重复素材/页目录，保留作品目录；素材在计划内折叠多选，方案和页码紧凑切换。分镜标题、画面与对白无框编辑，补充字段按需展开，保存/视觉规则裁决仍走原 owner。它只完成计划页这一块，不代表整套漫画制作界面已达到目标。

**调研依据及后续方向**：参考 ComfyUI 的任务、画布、结果组织。其 [App Mode](https://blog.comfy.org/p/from-workflow-to-app-introducing) 暴露选定输入/输出，底层仍执行同一工作流；适合 Pinax 把作者常用操作做简单，把高级节点工作流作为后续可选入口。当前没有替换 Pinax 前端、安装 ComfyUI 或复制其源码。

- **中央画布**：漫画页保持主要空间；选格后在原位置操作，再次生成和候选比较围绕该格展开。布局、排字与生成共享同一选中对象，避免三个表单各维护一套当前格。
- **右栏**：选中格时只显示画面描述、人物/场景参考和当前模型；选中文字时显示排字。高级采样/工作流参数按模型能力展开，空白页与未选中格不铺出全部字段。[官方工作区分区](https://docs.comfy.org/interface/overview)证实其右栏服务于当前选择。
- **生成队列**：统一展示等待、运行、完成、失败和待恢复，并标明作品/页/格。主按钮有固定位置，执行状态不随面板卸载消失。ComfyUI 的 [queueStore](https://github.com/Comfy-Org/ComfyUI_frontend/blob/main/src/stores/queueStore.ts) 与 [executionStore](https://github.com/Comfy-Org/ComfyUI_frontend/blob/main/src/stores/executionStore.ts) 分管任务历史和运行进度；Pinax 需要先把当前内存登记与媒体落盘串成可恢复任务合同，不能仅画一个队列。
- **图片结果**：借鉴[结果预览与分组](https://docs.comfy.org/interface/assets)，在漫画内按页/格显示候选缩略图，打开大图、比较、采用；批次有明确归属。复用现有媒体资产和 take，不恢复独立素材旧页面，也不另建图片存储。
- **进度与恢复**：ComfyUI 的 [/prompt、/history、/ws](https://docs.comfy.org/development/comfyui-server/comms_routes) 支持任务 ID、查询与运行事件。Pinax 已有 `generateWithComfyUi`，但仅提交、轮询并取首张输出，未把 promptId 持久化、未接 WebSocket 进度，且参考图入口明确拒绝。因此已有 adapter 不等于完整工作流接入。MiniMax 同步接口不能凭空显示采样百分比，也不能保证客户端断线后找回供应商未返回的图片。

**本轮本地实施**：画面描述、模型和生成/上传收成一个输入区；候选缩略图先预览，支持原图大小视图、与当前画面对比和明确选用；阶段产物复用预览，保留选候选与阶段确认的区别。重复取景预览折叠；一键补齐移到画面标签旁。画布下方本页状态由原页/格 pending、阶段状态和共享在途身份派生，点击定位到对应格/阶段；没有新增队列真源。

**2026-10-20 本地补充**：当前格描述、景别与画幅优先，上一格不再整段复制；空镜和局部特写隔离全页人物上下文，沿用结构化画风。脚本与分页方案保留镜头字段；普通生图接通原本仅精修使用的显式参考及已确认人物引用，按模型能力、图片归属与可读性检查。独立漫画页补满宿主宽度。已完成 10 次真实图片请求及 v19 补拍合成，完整门禁 exit 0；失败尝试和第四格背影远景未完全遵从的限制见 LOG，不将选用成功镜头称为稳定保证。
