# 第一部分内测说明

本文档用于当前版本的第一轮内部测试。测试重点是“结构化设定中的地点目录”以及它与地图的衔接，不是全面验收所有写作、联机、漫画和视频功能。

## 当前版本的核心变化

世界书仍然是作者事实的来源，但地理概述和正式地点已经分开：

- “地理环境”用于保存世界观叙述、地形背景和整理依据，不会直接被地图当作地点清单。
- 城市、城镇、区域、河流、路线等地点，要在结构化设定的地点目录中作为独立 `location` 条目保存。
- 从概述整理得到的内容先进入待审草稿，只有逐项采纳后才会成为正式地点。
- 地图只消费正式地点、明确的地点关系和已确认的地理历史，不再根据一句普通叙述猜测地点。
- 正式地点的来源证据、别名、类型、上级区域、所属势力、地形提示和地图绑定会一并保留。

这意味着“AI 提取出了很多候选”不等于“地图已经新增了这些地点”。内测时应重点确认候选是否准确，以及用户是否能控制哪些内容进入正式设定。

## 推荐测试顺序

### 1. 准备世界书和模型

1. 打开“设置”，进入结构化设定对应的世界书。
2. 确认当前使用的是目标世界书，而不是默认空世界书或另一份旧世界书。
3. 在“世界观 / 地理环境”中填入一段包含多个真实地点的说明。建议同时包含城市、区域、河流和道路，并保留上下文，例如：

   ```text
   北境的灰锤堡是一座依山而建的矿镇，位于穹脊山脉北麓。
   中央盆地的虹镜湖向东汇入银脉河，南岸的学城通过月桂商道连接教廷城。
   ```

4. 确认文本模型配置可用。若页面出现 `/api/generate/structured` 404，通常是当前 3001 后端仍在运行旧进程，需要重启后端再测试。

### 2. 测试地点目录

在“地理环境”下方找到地点目录，先进行手工操作：

1. 新建一个地点，填写名称、类型、描述和别名。
2. 编辑该地点，补充上级区域、所属势力、地形提示和地点关系。
3. 刷新页面，确认修改仍然存在。
4. 删除一个地点，确认界面会先显示影响范围；取消删除后，地点不能消失。
5. 删除确认后，确认正式条目、地图绑定和相关关系按提示处理，没有静默覆盖其他地点。

### 3. 测试“从概述整理”

1. 点击“从概述整理”。
2. 观察生成是否按批次返回，而不是一次把整段长文本塞给模型。
3. 检查每个草稿是否包含：名称、地点类型、描述、原文证据和分类信息。
4. 重点检查以下错误候选是否被拦截或标为低置信：
   - “这片大地的每一寸都……”这类叙述片段；
   - “常被学院……”这类句子残片；
   - “某个小村”“一个地下城”这类泛称；
   - `沃土 11`、`边境荒域 1` 等地图诊断占位名称；
   - 只因出现“城、河、山”字样而被误识别的普通句子。
5. 编辑一个候选的名称或描述后再采纳，确认修改后的内容写入，而不是被模型原稿覆盖。
6. 只采纳其中一个候选，确认同批其他候选仍可继续审阅，不会因为一次写入就全部过期。
7. 忽略一个候选，确认它不会进入正式地点目录和地图。

### 4. 测试地图衔接

1. 打开地图页，确认资料区显示当前世界书和正式地点数量。
2. 确认已采纳的地点能出现在地图资料或标记中，并保留来源信息。
3. 确认被忽略的候选、地理概述中的普通句子和地图随机生成的临时名称不会自动进入正式地点目录。
4. 切换到另一份世界书，再切回原世界书，确认地点来源随世界书切换，不会只读取第一本。
5. 刷新浏览器后重复检查正式地点、地图绑定和来源证据。
6. 若地图生成失败，确认旧地图仍可查看，错误不会清空已有地点或覆盖世界书。

## 本轮通过标准

第一部分可以进入下一阶段，至少应满足：

- 真实地点能从世界书概述中被识别为候选，并带有可回看的原文证据。
- 明显的句子片段、泛称、编号占位名和随机地图名不会进入正式地点。
- 用户可以逐项编辑、采纳和忽略，采纳一项不会错误地让整批失效。
- 正式地点刷新后仍存在，地图读取的是正式条目而不是概述正文猜测。
- 世界书切换、页面刷新和地图生成失败不会造成地点静默丢失或串库。
- 浏览器控制台没有新增异常，页面没有横向溢出，390px 窄屏仍能完成地点审阅。

## 当前已知边界

- 真实外部 provider 的长地理概述质量 Gate 仍需要使用保存的实际模型配置执行；本地夹具和契约测试不能替代这一步。
- 地图的复杂父子区域、相邻关系、标签避让和大规模重生成仍属于后续地图阶段，不应作为本轮地点目录失败来判断。
- 自动整理只生成待审草稿，不承诺一次识别出所有隐含地点。漏掉的地点可以直接在目录中手工新建。
- 主题1的米色游戏化界面暂时冻结；本轮主要观察主题2的蓝白结构化设定和地图界面。

## 问题记录格式

提交内测问题时，尽量附上以下信息：

```text
页面：结构化设定 / 地图
世界书：名称或脱敏标识
操作：点击了什么，之前已有几个正式地点和草稿
预期：希望发生什么
实际：实际显示或写入了什么
模型：provider / model（不要提供 API Key）
是否刷新或切换过世界书：是 / 否
控制台或网络错误：原文
```

不要把 API Key、完整私密世界书或未脱敏的个人创作内容贴到问题记录中。
