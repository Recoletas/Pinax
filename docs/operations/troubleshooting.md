# 运维与故障排查

先保留报错和用户数据，再定位页面、Express、运行器或存储层。不要先清空浏览器、任务日志或模型配置。

## 连接与部署

| 现象 | 先检查 | 处理方向 |
| --- | --- | --- |
| Edge 提示连接不安全 | 地址是否为 HTTP，HTTPS 证书链和监听是否正常 | 2026-10-15 公网仅 HTTP 正常；配置证书、续期与跳转前先安排用户数据迁移 |
| 更新后页面仍旧或 JS 404 | 当前静态目录、HTML 中哈希资源、代理/浏览器缓存 | 核对发布产物；保留上一版资源供已打开页面使用，不清除用户站点数据 |
| 页面能开，文本生成不可用 | `/api/storyagent/healthz`、运行包、模型配置及 Express 日志 | 只传 dist 不够；更新匹配的后端和运行器 |
| 更新工具后仍报旧错误 | 当前 8451 是否为旧进程，健康协议和能力标志 | Express 会复用已有任务面；有计划地更新运行器，不能只刷新网页 |
| `ERR_LOCAL_ONLY` 或本机接口 403 | 是否公网部署、请求来源及能力配置 | 公网禁用本机文件/知识接口是预期行为，不要开放端口绕过限制 |
| 所有请求都被来源校验拒绝 | `PINAX_PUBLIC_ORIGINS` 与实际协议、域名、端口 | 配置真实来源；不要改为任意来源放行 |
| 原生模块加载错误 | Node ABI、CPU 架构、Linux glibc 和候选生产依赖 | 在兼容平台准备产物，隔离加载确认后再切正式服务 |
| 知识索引总是 `never-indexed` / `stale` | `PINAX_KNOWLEDGE_CACHE_ROOT` 是否被设置、服务端与调用方是否同根 | 服务端与 MCP 侧现按同一环境变量解析缓存根；**若历史 `.env` 里残留该变量，索引缓存根会迁移，旧缓存变孤儿**，需重跑一次 `pinax_project_index action:"sync"` |
| `/mcp` 返回 403 | `PINAX_PUBLIC_ORIGINS`、请求是否经反代、Host 头 | 公网部署整组禁用是预期行为；本机入口只接受回环 + localhost Host + 无 Origin，且**拒绝经反代转发的请求**（带 `x-forwarded-*` 一律拒） |

非敏感探针可使用：

```sh
curl -I http://pinax.cc/
curl -I https://pinax.cc/
curl -fsS http://127.0.0.1:3001/api/storyagent/healthz
```

端口与主机按实际配置替换。HTTPS 握手失败时不要用 `-k` 的结果证明证书正常。运行器健康只说明可响应，真实生成和修改采用是另一条检查。

完整步骤见[运行包发布](../engineering/agent-runtime-deployment.md)。生产配置与回滚位置见对应发布回执，不能拿历史 PID 当当前进程。

## HTTPS 切换后作品为空

HTTP 与 HTTPS 是不同浏览器来源，localStorage 和 IndexedDB 不共享。域名、IP、端口、浏览器配置变化也一样。

让作者回原地址导出完整工作区 ZIP，再在新地址恢复。强制跳转前应留导出窗口；不要建议清数据，也不要据此判断服务器删了书稿。

## 助手与知识检索

| 现象 | 核查顺序 |
| --- | --- |
| Edge 显示 `STATUS_BREAKPOINT` | 记录切换权限等触发动作、Edge 版本和 `edge://crashes` 对应时间；这是浏览器进程崩溃证据，不是模型错误。不要清除书稿所在的浏览器数据；当前权限轻量路径的修正尚待原现场复核 |
| 回答里有文字，正文没变 | 当前权限 → 是否有修改提议 → 提议目标/状态 → 是否采用 → 保存回执 |
| 工具“未成功执行” | 展开具体工具错误；核对请求目标、授权、运行包协议、输入格式和来源修订 |
| 编辑后重答出现新会话 | 确认点击的是重新生成而非另开对话；记录 conversationId 与运行任务 ID，它们不是同一个东西 |
| 回答结束突然缩成摘要 | 核查消息正文与 complete_assistant_task.message 的存储/渲染；两者应分开 |
| `assistantKnowledge: true` 但查询失败 | 能力标志仅说明工具存在；继续检查本机权限、知识运行包、项目绑定和原文 |
| `KNOWLEDGE_RUNTIME_MISSING` | 构建知识运行包并核对 Express 的 `PINAX_KNOWLEDGE_RUNTIME` |
| 来源已更新或 `KNOWLEDGE_CHANGED` | 重新检索；不得把旧偏移定位的内容当新证据 |
| 索引命中却读不到全文 | 检查原件是否实际存在；已发布卡片/摘要不能补造全文 |

普通助手查阅本书快照不要求外部向量数据库。本机知识链通过工作线程执行，不依赖旧 kit-guard 拉起 8421/8431；排障时先确认走哪条链。

## 保存、切换与布局

- **保存失败**：先复制输入或保留恢复副本，确认存储配额与 owner 回执；不要先刷新。
- **切换被阻止**：查看正文、属性、表格是否有未处理输入，是否存在生成或待采用结果。新目录切换也要走 guard，不能删守卫消除提示。
- **旧任务写错书**：追踪发起时 bookId、resourceId、revision、runId 和编辑绑定；不能只查看响应回来时的 activeBook。
- **右栏/对话无法滚动**：查父级高度、min-height、overflow 和弹窗滚动锁，避免多个全屏容器互相截断。
- **移动端输入遮挡**：检查软键盘视口、固定工具栏和弹层层级，并在真实输入法环境核查；桌面缩窗不等同真机。

正文历史、助手对话、运行器任务日志和记忆账本各有 owner。删除其中一种不应被用来“修复”其他数据。

## 媒体

生成任务与保存任务分开处理。图片已生成但保存失败，使用保存重试；视频已提交但查询中断，查询原任务，避免重复计费。

视频只有显示“原件已保存”才可脱离临时 URL 播放。服务器重启可能丢失内存任务，浏览器清数据会丢本地原件；完整 ZIP 才包含已落盘媒体，轻量 JSON 不包含。
